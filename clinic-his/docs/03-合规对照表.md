# 合规对照表（法规/国标 → 系统落地）

> 适用对象：社区诊所/社区卫生服务站门诊信息系统（单机构、内网部署）。
> 验证方法均为系统内可操作项，可在管理端「系统管理 → 合规自检」或冒烟脚本中复核。

## 1. 等级保护（GB/T 22239-2019，按第二级设计）

| 控制项 | 要求摘要 | 系统落地 | 验证 |
| --- | --- | --- | --- |
| 身份鉴别 a | 唯一身份标识、口令复杂度 | 账号唯一；口令 ≥10 位且含大小写/数字/符号；PBKDF2-SHA256(12 万次) 存储 | 登录页策略提示；改密接口校验 |
| 身份鉴别 b | 登录失败处理 | 连续 5 次失败锁定 15 分钟并审计 | 连续输错后提示锁定 |
| 身份鉴别 c | 远程管理防窃听 | 生产须 HTTPS（本机演示 HTTP，文档声明） | 部署检查表 |
| 访问控制 | 最小权限、主体客体授权 | 9 角色 RBAC 服务端强制，越权 403 | 冒烟脚本越权用例 |
| 安全审计 | 覆盖重要操作、防删除修改 | 全量写操作 + 敏感读 + 登录事件；哈希链（prev_hash→entry_hash） | `/api/v1/audit-logs/verify` |
| 入侵防范 | 最小服务、输入校验 | 参数化 SQL、请求体 ≤1MB、CSP、X-Frame-Options=DENY、登录限速 | 安全响应头检查 |
| 恶意代码防范 | — | 纯标准库、零第三方依赖，无外部 CDN | 依赖清单为空 |
| 数据完整性 | 防篡改 | 病历锁定 + 更正留痕；处方/收费/检验状态机；事务 | 状态冲突返回 409 |
| 数据保密性 | 敏感数据保护 | 证件/手机号不存明文（后 4 位 + 加盐哈希）；队列/列表姓名脱敏；日志不含姓名 | 数据库抽查 |
| 数据备份恢复 | 定期备份 | `scripts/backup.py` 在线备份 + 时间戳文件 | 执行后生成 `backups/` |
| 剩余信息保护 | 会话失效 | 退出即吊销；Token 仅存哈希；8h/30min 双超时 | 注销后旧 Token 401 |

## 2. 个人信息保护（个人信息保护法 / 数据安全法 / GB/T 35273-2020 / GB/T 39725-2020）

| 要求 | 系统落地 |
| --- | --- |
| 最小必要 | 只采集诊疗必需字段；不存明文身份证号/手机号 |
| 目的限定 | 数据仅用于诊疗、收费、公卫上报、质控；无营销用途 |
| 告知同意 | 建档时登记同意状态；互联网预约仅限复诊 |
| 访问控制与审计 | 病历详情查看留审计；角色最小权限 |
| 去标识化 | 列表/队列脱敏；对外接口回执只存患者姓名脱敏值与哈希 |
| 数据分级 | 患者身份信息、病历、处方、报告均为敏感个人信息，限授权角色 |
| 不出境/不共享 | 无第三方共享接口；对外仅院方↔平台受理回执（不含诊断信息） |

## 3. 电子病历（《电子病历应用管理规范（试行）》/《医疗机构病历管理规定》）

| 要求 | 系统落地 |
| --- | --- |
| 病历创建后不可删除 | 无删除接口；数据库层不提供物理删除 |
| 修改留痕、可追溯 | 完成后的修改走「更正留痕」：原因 + 修改前后快照 + 操作人/时间，版本号递增 |
| 时间可信 | 服务端时间戳，所有状态变更带时间 |
| 保存期限 | 门诊病历自患者最后一次就诊起不少于 15 年（文档声明，系统不清理） |
| 权限与审计 | 医生仅本人病历可写；医务科只读；查看留痕 |
| 数据标准 | 诊断使用 ICD-10 编码（WS 375.9-2012 口径） |

## 4. 处方与药品（《处方管理办法》/《抗菌药物临床应用管理办法》）

| 要求 | 系统落地 |
| --- | --- |
| 处方权 | 仅 `DOCTOR` 角色可开方；处方与医生、患者、诊断关联 |
| 药师审核 | 处方提交后须药师「通过/驳回」；驳回必填理由 |
| 抗菌药物分级 | 非限制级不限；限制级需主治及以上；特殊级拦截（需会诊审批，未开放） |
| 麻醉/精神药品 | 标记 `controlled=1`，普通门诊一律拦截并提示专用处方流程 |
| 处方保存 | 处方与明细永久保留，不提供删除；作废走状态变更 |
| 发药核对 | 药师发药前校验药费已缴、库存充足，原子扣减 |

## 5. 传染病与公共卫生（《传染病防治法》）

| 要求 | 系统落地 |
| --- | --- |
| 法定传染病 24h 上报 | ICD-10 中标记 `infectious=1` 的诊断自动生成上报任务，截止时间 +24h，公卫角色闭环 |
| 慢病管理 | 高血压（I10）、2 型糖尿病（E11.9）等慢病诊断自动生成随访任务 |
| 任务留痕 | 任务完成人、时间、说明入审计 |

## 6. 医疗质量安全核心制度（摘要）

| 制度 | 系统落地 |
| --- | --- |
| 首诊负责制 | 挂号绑定接诊医生；病历仅接诊医生可写 |
| 病历书写规范 | 主诉/现病史/体格检查/诊断/处置结构化字段 |
| 处方点评 | 审方记录（审核人、结论、意见）可检索 |
| 危急值/异常报告 | 检验报告 `abnormal` 标记，医生站可见 |

## 7. 接口与互联互通

| 要求 | 系统落地 |
| --- | --- |
| 接口鉴权 | HMAC-SHA256 + 时间戳窗 + nonce 防重放 |
| 幂等 | `Idempotency-Key` 唯一约束 + 重放返回首次结果 |
| 最小数据 | 受理接口不传主诉/诊断等健康敏感信息（与主项目红线一致） |
| 失败语义 | 任何失败不得返回成功单号；补偿撤销幂等 |
| 预留标准 | 字典与资源命名对齐 HL7 FHIR R4（Patient/Encounter/MedicationRequest/DiagnosticReport/AuditEvent），为后续 WS/T 500 共享文档留扩展位 |

## 8. 演示环境与生产差异声明（必须随交付说明）

1. 演示初始口令统一为 `Clinic@2026` 且未强制改密；**生产必须启用首次登录强制改密**（`users.must_change=1` 已预留）；
2. 演示使用 HTTP + 本机端口 8310；生产要求 HTTPS、独立数据库账号、网络分区（诊区/办公区/对外 DMZ）；
3. 演示未接医保结算、未接 CA 电子签名；生产按当地卫健/医保要求补接；
4. 系统管理员演示账号拥有全部权限；生产应岗位分离、双人复核高风险操作。
