# 康诊云社区诊所信息系统（Clinic HIS）设计方案

> 版本：V1.0（2026-11-19）
> 定位：本仓库的院方侧模拟 HIS —— 用于验证本项目预留的 `HisClient` 受限接入（REQ-14）在"真实院方系统"下的效果，同时自身是一套可独立运行的社区卫生服务站/诊所门诊信息管理系统。

---

## 1. 背景与目标

### 1.1 问题

主项目 `backend/business-service` 预留了医院 HIS 接入边界（`appointment/his/HisClient`），但：

- 默认 `app.his.enabled=false` → `LOCAL_DEMO`，零外部调用；
- 开启后仅支持 `mode=mock`（`MockHisClient` 只生成 `HIS-MOCK-` 单号）；
- 因此**无法观察"接入真实院方系统"后的完整效果**（受理失败回滚、单号回写、补偿撤销等）。

### 1.2 目标

新建 `clinic-his/` 子系统，提供：

1. 一套**可运行、有真实数据、有管理界面**的社区诊所 HIS（8 医生 / 14 护士 / 6 行政 / 2 医技）；
2. 一套**对外对接接口**（`/openapi/v1/*`，HMAC-SHA256 签名 + 幂等），覆盖本项目 `HisClient` 的"受理 + 撤销"语义，可作为 `HIS_LIVE` 联调目标；
3. **合规完备**：等保 2.0 二级、电子病历管理规范、处方管理办法、传染病防治法、个人信息保护法/数据安全法、GB/T 39725-2020 等要求在系统内有可验证的落地。

### 1.3 明确不做（范围边界）

| 不做 | 原因 |
| --- | --- |
| 真实医保结算 / DRG 结算 | 需医保专网与定点资质，演示系统不伪造结算结果 |
| 住院、手术、急诊、体检 | 社区诊所门诊为主，超出范围 |
| 互联网诊疗首诊 | 《互联网诊疗管理办法（试行）》规定不得对首诊患者开展互联网诊疗 |
| 明文存储身份证号/手机号 | 最小必要原则，只存脱敏值 + 不可逆校验值 |
| 真实 SSDP / 投屏 | 与本子系统无关 |

### 3.1 技术选型与理由

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 运行时 | Python 3.12 **纯标准库** | 诊所内网零依赖部署、无供应链风险、等保审计简单；`python app/main.py` 即可启动 |
| 数据库 | SQLite（WAL 模式） | 单机构门诊量级足够；单文件便于备份与演示；事务语义清晰 |

| 端口 | **8310**（可用 `CLINIC_PORT` 覆盖） | 避开主项目 8000/8001/8088 |

## 5. 核心业务流程

### 5.1 门诊主链路

```
建档 → 挂号(生成挂号费) → 收费 → 签到(录生命体征, 生成队列号)
     → 护士叫号 → 医生接诊 → 诊断(ICD-10) → 开处方/检查申请
     → 药师审方 → 收费 → 发药 → 医技出报告 → 完成就诊 → 公卫任务(如需)
```

### 5.2 状态机

**挂号（registrations.status）**

```
BOOKED ──checkin──► CHECKED_IN ──visit start──► IN_PROGRESS ──finish──► FINISHED
   └──cancel──► CANCELLED（回收号源）
```

**处方（prescriptions.status）**：`SUBMITTED → APPROVED → DISPENSED`；`SUBMITTED → REJECTED`

**收费（charges.status）**：`UNPAID → PAID`；`UNPAID → VOID`

**检查申请（lab_orders.status）**：`APPLIED → SAMPLED → REPORTED`

**处方开具限制规则（服务端硬校验）**

1. 管制药品（麻醉/精神药品）普通门诊**一律拦截**（需专用处方与专门资质，演示系统不开放）；
2. 限制级抗菌药物需**主治医师及以上**职称；
3. 特殊级抗菌药物需会诊与审批，系统**拦截**；
4. 处方必须经**药师审核通过**方可收费/发药；
5. 发药要求药品费已缴、库存充足，扣减为原子操作。

### 5.3 一致性红线

- 号源扣减：`UPDATE ... SET booked=booked+1 WHERE booked<capacity` 原子判定，失败即 409；
- 库存扣减同理；任一步失败**不得显示成功**；
- 医疗记录不物理删除；完成后修改只能走"更正留痕"（`emr_amendments` + 版本号）；
- 审计日志只追加（哈希链，可校验）。

## 7. 安全设计（等保 2.0 二级映射摘要）

| 控制点 | 实现 |
| --- | --- |
| 身份鉴别 | 账号唯一；口令 ≥10 位含大小写/数字/符号；PBKDF2-SHA256；连续 5 次失败锁定 15 分钟；登录留审计 |
| 访问控制 | RBAC 服务端强制；越权 403；医生仅能操作本人接诊病历 |
| 会话管理 | Bearer Token（仅存哈希）；8h 绝对超时 + 30min 空闲超时；退出即吊销 |
| 安全审计 | 全部写操作 + 敏感读（病历/患者详情）+ 登录事件；哈希链防篡改；仅管理员/院长/医务科可查 |
| 数据完整性 | 病历锁定 + 更正留痕；处方/收费状态机；SQLite 事务 + 原子扣减 |
| 数据保密性 | 传输侧建议 HTTPS（生产）；存储侧口令不可逆、证件/手机号不落明文、日志不含姓名 |
| 个人信息保护 | 最小必要；目的限定；脱敏展示；不提供患者数据导出接口（防批量泄露）；病历按法定年限保存、不物理删除 |
| 接口安全 | HMAC-SHA256 签名、±300s 时间戳窗、nonce 防重放、Idempotency-Key 幂等、错误响应不透出内部细节 |
| 入侵防范 | 请求体 ≤1MB、参数化 SQL、CSP `default-src 'self'`、X-Frame-Options DENY、登录限速 |
| 数据备份 | `scripts/backup.py` 在线备份（sqlite backup API），保留策略由运维配置 |

> 完整条款对照见 `03-合规对照表.md`。

## 8. 接口设计摘要

### 8.1 内部接口（管理端，`/api/v1`）

统一响应包：`{ "code": "OK", "message": "成功", "requestId": "...", "data": ... }`；
错误：`{ "code": "SLOT_FULL", "message": "号源已满", "requestId": "...", "details": [...] }`。

鉴权：`Authorization: Bearer <token>`。

### 8.2 对外接口（`/openapi/v1`，院方→平台）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/openapi/v1/ping` | 健康检查（无需签名） |
| GET | `/openapi/v1/departments` | 科室字典（签名） |
| GET | `/openapi/v1/doctors` | 医生字典（签名） |
| POST | `/openapi/v1/appointments` | 预约受理（签名 + `Idempotency-Key`） |
| GET | `/openapi/v1/appointments/{hisOrderNo}` | 受理单查询（签名） |
| POST | `/openapi/v1/appointments/{hisOrderNo}/cancel` | 撤销受理（签名 + 幂等） |

签名算法（详见 `02-接口契约.md`）：

```
stringToSign = METHOD \n PATH \n appId \n timestamp \n nonce \n sha256(body)
signature    = hex(HMAC-SHA256(appSecret, stringToSign))
```

### 8.3 与主项目 `HisClient` 的映射

| HisClient 语义 | clinic-his 实现 |
| --- | --- |
| `book(command)` → `HisBookingResult(hisOrderNo, "HIS_LIVE", false)` | `POST /openapi/v1/appointments` 返回 `hisOrderNo=CLN{yyyyMMdd}-{seq}` |
| `cancel(hisOrderNo, reason)` 幂等 | `POST /openapi/v1/appointments/{hisOrderNo}/cancel`，不存在/已撤销均按成功处理 |
| 失败必须 503、不落单 | 受理接口对校验失败返回 4xx，对内部故障返回 5xx，绝不返回"假成功" |

> 主项目 V1.20 仍固定 `mode=mock`；clinic-his 作为"沙箱/预演"目标，待主项目完成 HIS_LIVE 评审后可直接接入。

## 9. 非功能设计

- 目标并发：社区诊所 ≤20 并发窗口；SQLite WAL 足够；接口 P95 < 100ms（本机）；
- 可用性：单进程 + 启动自检；数据损坏可用备份恢复；
- 可维护性：模块化路由 + 统一错误码 + 冒烟脚本一键回归；
- 可审计性：所有状态变更均可通过 `requestId` + 审计日志回溯。

## 10. 验收清单

1. `python clinic-his/app/main.py` 启动成功，浏览器可打开管理端；
2. 9 类角色均可登录，菜单按权限显隐，越权接口返回 403；
3. 完整门诊链路跑通：挂号→收费→签到→叫号→接诊→诊断→处方→审方→收费→发药→完成；
4. 管制药品/限制级抗菌药拦截生效；
5. 传染病诊断自动生成 24h 上报任务，慢病诊断生成随访任务；
6. 病历完成后不可直接改，更正留痕可追溯；
7. 审计日志哈希链校验通过；
8. `scripts/smoke_test.py` 全绿（含 openapi 签名/幂等/防重放用例）。
