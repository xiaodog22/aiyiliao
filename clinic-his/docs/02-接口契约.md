# Clinic HIS 接口契约（V1.0）

## 1. 通用约定

### 1.1 统一响应包

```json
{ "code": "OK", "message": "成功", "requestId": "REQ-20261119-000001", "data": { } }
```

错误响应（HTTP 4xx/5xx）：

```json
{ "code": "SLOT_FULL", "message": "该号源已约满", "requestId": "REQ-...", "retryable": false,
  "details": [{ "field": "slotId", "reason": "号源已满" }] }
```

- 所有接口均返回 `requestId`，与审计日志可关联；
- 错误文案为中文；不返回堆栈、SQL、内部路径；
- 金额单位：元（保留 2 位小数）。

### 1.2 内部接口鉴权

`Authorization: Bearer <token>`；Token 仅存服务端哈希，8h 绝对超时 + 30min 空闲超时。

### 1.3 对外接口鉴权（HMAC-SHA256）

必带请求头：

| 头 | 说明 |
| --- | --- |
| `X-App-Id` | 应用标识（默认 `wechar-mini`） |
| `X-Timestamp` | Unix 秒级时间戳，允许 ±300s |
| `X-Nonce` | 一次一用的随机串（8~64 字符），10 分钟内不可重复 |
| `X-Signature` | 十六进制 HMAC-SHA256 |
| `Idempotency-Key` | 写接口必填，8~128 字符；重试复用同一键 |

签名串（UTF-8）：

```
stringToSign = METHOD + "\n" + PATH + "\n" + appId + "\n" + timestamp + "\n" + nonce + "\n" + sha256hex(body)
signature    = hex(HMAC-SHA256(appSecret, stringToSign))
```

- `PATH` 不含 query string；
- GET 请求 body 为空串（sha256 为空串哈希）；
- 校验顺序：时间戳 → nonce 防重放 → 签名（常量时间比较）→ 幂等键。

错误码：`INVALID_APP_ID` / `INVALID_TIMESTAMP` / `REPLAY_DETECTED` / `INVALID_SIGNATURE` / `MISSING_IDEMPOTENCY_KEY` / `INVALID_IDEMPOTENCY_KEY` / `VALIDATION_FAILED` / `NOT_FOUND`。

## 2. 对外接口（`/openapi/v1`）

### 2.1 GET /openapi/v1/ping

无需签名。`data: { "service": "clinic-his", "status": "UP", "version": "1.0.0", "time": "..." }`

### 2.2 GET /openapi/v1/departments

签名校验。`data: [{ "departmentId": "QK", "name": "全科医学科", "type": "CLINICAL" }]`

### 2.3 GET /openapi/v1/doctors

签名校验。可选 `?departmentId=QK`。

```json
[{ "doctorId": "D001", "name": "陈志远", "title": "主任医师", "departmentId": "QK",
   "departmentName": "全科医学科", "specialty": "高血压、糖尿病等慢病管理" }]
```

### 2.4 POST /openapi/v1/appointments —— 预约受理

请求（`additionalProperties=false`）：

```json
{ "appointmentId": "A20261119000001", "slotId": "SL...", "patientName": "陈志远",
  "doctorId": "D001", "departmentId": "QK",
  "slotDate": "2026-11-23", "slotTime": "09:30" }
```

- `appointmentId`、`doctorId`、`departmentId` 必填；`patientName` 在**落院内挂号**口径下同样必填
  （缺失返回 400：院内挂号必须有患者档案，不接受匿名受理单）；
- `slotDate`（`YYYY-MM-DD`）/`slotTime`（`HH:mm`）选填：就诊日期时间，**决定院内挂号日期与队列**。
  缺省按当天处理；平台号源是 UTC Instant，调用方须按医院时区（Asia/Shanghai）换算后下发；
- `patientName`：受理台账（`openapi_orders`）**只存脱敏值与哈希**；但**院内挂号需要可用患者档案**，
  实名仅落 `patients` 表（按 `appId+姓名` 派生 MRN，重复预约复用同一档案），
  对外接口（受理详情、挂号列表、叫号列表）一律只返回脱敏姓名；
- **受理成功即落院内**：`registrations` 一行（`source=WECHAT`、`status=BOOKED`、`his_order_no` 关联）
  + `queue_tickets` 一行（`status=RESERVED`，不参与叫号；到院签到复用该票并转 `WAITING`）；
  院内号源外键 `slot_id` 留空（平台号源与院内 `doctor_slots` 不同源，不伪造）；
  不生成 `charges`（挂号费仍由院内收取）；
- 幂等：同一 `Idempotency-Key` 重放返回首次结果（`replayed: true`），**不重复建挂号**；
- 校验失败返回 400/404，内部故障返回 500；**任何失败都不得返回成功单号，也不得留下院内挂号**。

成功响应 `201`：

```json
{ "code": "OK", "message": "受理成功", "requestId": "REQ-...",
  "data": { "hisOrderNo": "CLN20261119-000001", "status": "ACCEPTED",
            "source": "HIS_LIVE", "mock": false,
            "departmentName": "全科医学科", "doctorName": "陈志远",
            "registrationNo": "RG20261123-00082", "queueNo": "XH001",
            "visitDate": "2026-11-23", "visitTime": "09:30",
            "acceptedAt": "2026-11-19 10:21:33", "replayed": false } }
```

### 2.5 GET /openapi/v1/appointments/{hisOrderNo}

```json
{ "hisOrderNo": "CLN20261119-000001", "status": "ACCEPTED|CANCELLED",
  "appointmentId": "...", "doctorId": "D001", "departmentId": "QK",
  "createdAt": "...", "cancelledAt": null, "cancelReason": null,
  "registrationNo": "RG20261123-00082", "queueNo": "XH001",
  "visitDate": "2026-11-23", "registrationStatus": "BOOKED|CANCELLED" }
```

> 院内挂号被撤销/已签到后，`registrationStatus` 与受理单状态可能不同步：
> 受理单 `CANCELLED` 只会作废仍为 `BOOKED` 的挂号，已 `CHECKED_IN`/`IN_PROGRESS` 的走院内退号流程。

### 2.6 POST /openapi/v1/appointments/{hisOrderNo}/cancel —— 撤销受理

请求：`{ "reason": "患者取消" }`（reason ≤200 字）

- **幂等**：单号不存在或已撤销 → 200，`status: "CANCELLED"`，`idempotent: true`；
- 撤销后再查询状态为 `CANCELLED`。

| HTTP | code | 场景 |

| 401 | AUTH_REQUIRED / AUTH_EXPIRED | 未登录/会话过期 |
| 403 | FORBIDDEN | 无权限 |
| 403 | ACCOUNT_DISABLED / ACCOUNT_LOCKED | 账号停用/锁定 |
| 404 | NOT_FOUND | 资源不存在 |
| 409 | SLOT_FULL / SLOT_CLOSED | 号源满/停诊 |
| 409 | REG_FEE_UNPAID | 未缴挂号费不可签到 |
| 409 | STATE_CONFLICT | 状态机非法流转 |
| 409 | EMR_LOCKED | 病历已完成，须走更正留痕 |

| 403 | CONTROLLED_DRUG_BLOCKED | 管制药品普通门诊拦截 |

| 400 | EMR_INCOMPLETE | 完成就诊未通过质控 HIGH 项（主诉/诊断/开方须有诊断），message 列出缺项 |
| 400 | VISIT_NOT_FINISHED | 就诊未完成时审方/发药被拒 |

| 400 | INVALID_VITALS | 体征/分诊数值超出合理范围（体温 30~45、脉搏 20~250、呼吸 5~60、收缩压 50~300、舒张压 20~200、SpO₂ 50~100） |

### 3.2 幂等与并发

- 号源：`UPDATE doctor_slots SET booked=booked+1 WHERE id=? AND booked<capacity AND status='OPEN'`，影响行数 0 → 409；
- 发药库存：`UPDATE drugs SET stock=stock-? WHERE id=? AND stock>=?`；
- 对外受理：`openapi_orders.idem_key UNIQUE`，并发重复键回查首次结果。

### 3.3 病历可见范围（B-1）与退费（M-1 / M-2）

权限：新增 `clinical.read`（读取完整病历文本）与 `patient.read.all`（跨医生读取）。

| 角色 | clinical.read | patient.read.all |
| --- | --- | --- |
| DOCTOR / NURSE | ✅ | — |
| DIRECTOR / MEDICAL_AFFAIRS | ✅ | ✅ |
| CASHIER / TECHNICIAN / PHARMACIST / PUBLIC_HEALTH / ADMIN | ❌ | — |

- 统一判定：具备 `clinical.read` 且（具备 `patient.read.all` 或本人在该患者存在就诊记录）才可见完整病历；
- `GET /patients/{id}`：不满足 → 姓名 `mask_name` 脱敏、去掉 `address`，保留性别/年龄/MRN/掩码电话/过敏标记；
- `GET /patients/{id}/visits`：不满足 → 仅 `visitNo/日期/科室/医生/状态/诊断名称`，不含主诉、现病史、体格检查、处理意见与处方明细；
- `GET /patients/{id}/overview`：同一规则；报告仅给「有无异常 + 日期」不给结论，留观只给床号与状态，处方药品明细置空；
- `GET /patients/{id}/reports`：同一规则，无临床全文权限时 `findings`/`conclusion` 置空；
- `GET /visits/{id}`：`visit.read.all` 或 `patient.read.all` 旁路；非本人接诊医生读 EMR → 403 `FORBIDDEN`。

退费：

- `POST /charges/{id}/refund`（`charge.refund`：CASHIER / ADMIN / DIRECTOR），仅 `PAID` 可退，否则 400 `STATE_CONFLICT`；`{reason}` 必填且 ≥4 字；
- 状态迁移 `UPDATE charges ... WHERE id=? AND status='PAID'` 以 rowcount 判定，写入 `refunded_at/refund_reason/refunded_by` 并审计 `CHARGE_REFUND`；
- 联动：挂号费 → registration `CANCELLED` 且扣回号源；处方费 → 已发药则药品回库、处方 `REFUNDED`；检查费 → `lab_orders.status='REFUNDED'`（已出报告 400）；
- `POST /registrations/{id}/cancel` 遇已缴挂号费自动走同一退费逻辑，再取消挂号（未缴账单仍按 VOID 处理）。

### 3.4 危急值与检查结果回写

数据：

- `lab_items.critical_low` / `critical_high`（REAL，可空）：危急值阈值；内置血钾 3.5/5.5、空腹血糖 3.9/11.1、血红蛋白 110/160、白细胞计数 4.0/10.0；
- `lab_orders.critical`（INTEGER，默认 0）：报告危急值标记。

`POST /lab-orders/{id}/report` 请求：`{findings, conclusion, abnormal, value?}`

- `value` 可选（数值）；项目配置阈值且 `value < critical_low` 或 `> critical_high` → `critical=1`，审计写入 `LAB_REPORT`（含 `value/critical`）并追加 `LAB_CRITICAL`（含危急值与参考区间）；
- 响应：`{ "id": 1, "status": "REPORTED", "critical": true, "value": 6.2 }`。

`GET /visits/{id}/reports` 响应（数组）：

```json
[{ "id": 7, "orderNo": "LB...", "itemCode": "LAB07", "itemName": "血钾", "status": "REPORTED",
   "findings": "...", "conclusion": "...", "abnormal": true, "critical": true,
   "reporterName": "...", "sampledAt": "...", "reportedAt": "..." }]
```

- `GET /workbench`：医生/护士/医技/管理岗返回 `criticalReports` 待办，并追加 `{level:"danger", message:"危急值报告 N 项", view:"lab"}` 告警；
- 医生站「辅助检查」区提供「引用结论」，前端把报告结论追加进 `auxiliaryExam` 并调用 `PATCH /visits/{id}` 回写病历；
- 医技报告列表对 `critical=1` 显示红色「危急值」徽标。

### 3.5 合规自检返回结构（`GET /system/compliance`）

```json
{ "items": [{ "key": "password_policy", "name": "口令策略…", "status": "PASS|WARN|FAIL", "detail": "..." }],
  "summary": { "pass": 5, "warn": 2, "fail": 0 } }
```

真实检测项：口令策略（仍用默认口令账号数）、会话管理（过期未清理会话数）、第三方依赖（扫描 `app/` 导入与标准库名单比对）、电子病历完整性（已完成就诊缺主诉/诊断的条数与占比）。

| POST | `/nursing-records` | nursing.write | 至少一项体征或备注，否则 400 |
| GET | `/nursing-records?stayId=&patientId=` | nursing.read | 倒序护理记录时间线 |

错误码：

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | BED_OCCUPIED | 床位非空闲仍开立留观 |
| 400 | STATE_CONFLICT | 重复执行/取消非待执行医嘱、缺少体征 |
| 409 | PATIENT_IN_STAY | 同一患者已有在床留观 |
| 409 | STATE_CONFLICT | 目标床位不可用、留观已出区 |

### 5.1 角色工作台

### 5.2 患者全视图（统一患者视图）

| 方法 | 路径 | 权限 | 要点 |
| --- | --- | --- | --- |
| GET | `/patients/{id}/overview` | patient.read | 基本资料（性别/出生日期/病历号/脱敏电话/过敏/慢病标签）+ 今日就诊 + 历次就诊 + 处方 + 检查报告 + 留观记录；写 `PATIENT_OVERVIEW` 审计 |

### 5.3 合理用药前置校验

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/rx-check` | rx.write | body `{patientId, items:[{drugId,dosage,frequency,days,quantity}]}`，返回 `{warnings,checked}` |

响应：`warnings[]` 每项 `{level,code,message}`，`level` 取 `HIGH / MEDIUM / INFO`：

| code | level | 规则 |
| --- | --- | --- |
| ALLERGY_CONFLICT | HIGH | 患者过敏文本命中 `drugs.allergy_tags`（`\|` 分隔）任一项 |
| DUPLICATE_DRUG | MEDIUM | 同一处方内重复出现同一药品 |
| CONTROLLED_DRUG | INFO | 管制药品，普通门诊不可开具 |
| ANTIBIOTIC_LEVEL | INFO | 抗菌药物分级，提示等级 |

`drugs` 表新增列 `allergy_tags TEXT NOT NULL DEFAULT ''`（存量库经 `ensure_column` 自动补齐）。

### 5.4 病历质控

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/visits/{id}/qc` | visit.read | 返回 `{items:[{code,label,level,ok}],passRate}` |

检查项：主诉、现病史、体格检查、诊断、处理意见、开方须有诊断（无处方视为通过）。
`level=HIGH` 为必填项（前端红色），`MEDIUM` 为建议项（黄色）；`passRate` 为通过项百分比。
