## 一、项目概况（第 0 步勘察结论）

### 1.1 技术栈（实测确认）

| 层 | 实际实现 |
| --- | --- |
| 前端 | 原生 HTML/CSS/JS 单页应用（hash 路由 `#/doctor` 等），无框架、无组件库，自绘表格/弹窗/抽屉（app/web/app.js 约 2700 行） |
| 后端 | Python 标准库 `http.server` + ThreadingHTTPServer，自研 Router（`app/main.py`），零第三方依赖 |
| 数据库 | SQLite（`clinic_his.db`，WAL 模式），增量 ALTER 迁移机制（`app/db.py` DRUG_MIGRATIONS） |
| 认证 | Bearer Token（内存会话表）+ PBKDF2 口令；对外 OpenAPI 走 HMAC-SHA256 签名（`/openapi/v1/*`） |
| 权限 | RBAC：`app/security.py` ROLE_PERMS 常量（10 角色 × 31 权限码），接口层 `perm=` 声明 + 前端 VIEWS perm 路由守卫 |

### 1.2 页面路由清单（14 个视图，实测全部可达）

`#/dashboard` 工作台、`#/registration` 挂号登记、`#/charge` 收费管理、`#/queue` 分诊叫号、`#/doctor` 门诊医生站（三栏）、`#/beds` 留观床位看板、`#/nursing` 护理执行、`#/pharmacy` 药房管理（处方审核/发药/库存）、`#/patients` 患者档案、`#/lab` 医技检查、`#/ph` 公共卫生、`#/reports` 统计报表、`#/staff` 人员与排班、`#/system` 系统管理（审计/合规/对接密钥）。

### 1.3 数据库模型（重点表）

- 用户/角色/权限：`users`（账号）+ `staff`（人员档案，1:1）+ `roles`；权限不落库，由 `ROLE_PERMS` 常量实时计算（security.py:89-111）
- 药品字典：`drugs`（22 条，含 code/name/spec/unit/price/stock/antibiotic_level/controlled/allergy_tags，本次新增 default_route/default_freq）
- 诊断字典：`icd10`（37 条，code/name/category/chronic）
- 收费项目：`lab_items`（9 条检验检查项目）+ `charges`（账单：挂号费/药品费/检查费）
- 医嘱/处方：`prescriptions`+`prescription_items`（门诊处方）、`nursing_orders`（留观医嘱）、`visits`+`visit_diagnoses`（就诊与诊断）、`registrations`（挂号）、`bed_stays`（留观）、`audit_logs`（审计）

### 1.4 启动与登录验证（真实运行证据）

- 启动：`python -m app.main`（端口 8310），`/openapi/v1/ping` 返回 `{"status":"UP"}`（2026-11-20 实测）
- 登录：doctor01 / admin04 / nurse01 / admin06 等 8 账号全部实测登录成功
- 冒烟测试：`scripts/smoke_test.py` **99 项全部通过**（含本次新增的收退分离 2 项）

## 二、功能覆盖矩阵（对标主流 HIS）

| 功能模块 | 主流 HIS 做法（联网核实） | 本项目现状 | 差距说明 |
| --- | --- | --- | --- |
| 挂号收费 | 预约/现场/急诊多源挂号，号池管理，医保实时结算、退费冲账、电子票据（中拓、卫宁） | ✅ 现场+小程序挂号、号源排班、批量收费、退费/作废、账单三类别 | 无医保结算与电子票据；退费已加收退分离（本次修复） |
| 门诊医生站 | 三栏布局（候诊/病历/医嘱面板），接诊-开嘱-完成闭环，CDSS 提醒（卫宁 WiNEX Copilot、CDSS 6000+ 规则） | ✅ 三栏布局、结构化病历+模板插入、诊断/处方/检查/留观面板、过敏硬阻断、质控评分 | 无 CDSS 知识引擎级提醒（仅过敏/剂量/重复用药规则）；无历史就诊趋势图 |
| 住院医生站 | 入院登记、长期/临时医嘱、病程记录、出院小结、费用清单（东软/创业慧康） | ⚠️ 无住院体系，仅"留观"（床位看板+留观医嘱+护理闭环） | 社区诊所定位下留观≈轻量住院；但缺入院/出院/长期医嘱生命周期 |
| 护士站 | 医嘱校对与执行、三测单、护理评估、输液管理（嘉讯） | ✅ 分诊签到、医嘱执行（开/执行分离，本次修复）、体征记录、床位管理 | 无三测单曲线、无护理评估单 |
| 药房/药库 | 门诊药房发药+药库采购/供应商/入库/效期/盘点/调拨（卫宁智慧药学） | ⚠️ 处方审核-发药-库存原子扣减-退费回库完整；库存管理在药房页 | 无采购/供应商/入库单据/效期管理/盘点，药库与药房未分层 |
| 检验检查 LIS/PACS | 独立 LIS/PACS，HIS 通过接口总线对接，申请-执行-报告全流程（嘉讯/阿里云对接模式） | ⚠️ 内置轻量检验（申请→采样→报告→异常标记），无影像 PACS | 无外部 LIS/PACS 对接能力；无危急值自动通知链 |
| 电子病历 EMR | 国家电子病历评级 0-5 级，结构化文书、质控、修改留痕、打印（嘉和美康） | ✅ 结构化六要素病历、必填强校验（未完成不可结束就诊）、更正留痕、打印视图、质控提示 | 无分级评审对标工具；文书模板量少 |
| 医嘱管理 CPOE | 长期/临时医嘱、医嘱套餐、皮试流程、闭环执行（东软） | ⚠️ 门诊处方 + 留观医嘱闭环（开立→审核/执行），拼音简码检索本次已加 | 无长期医嘱、无套餐套组、无皮试流程 |
| 医保结算 | 医保目录对照、统筹/个账/自付三段结算、实时清算、对账（所有主流 HIS） | ❌ 纯自费 | 最大差距项；无医保字段与结算通道 |
| 系统管理 | 用户/角色/权限矩阵、操作审计、数据字典维护、参数配置 | ✅ 用户/人员/角色权限（常量固化）、审计日志、合规自检、对接密钥轮换 | 权限矩阵不可在线编辑（代码级固化，改动需发版） |
| 统计报表 | 门诊量/收入/科室/医生多维日报月报，领导查询驾驶舱 | ✅ 日报（挂号/就诊/处方/收入）、科室与医生工作量、收入构成 | 无月报/年报、无图表可视化 |

**总体判断**：作为社区诊所级 HIS，门急诊核心闭环（挂号→收费→就诊→处方→审核→发药→检验→留观护理）真实完整，达到小型民营/社区机构可用水平；与二级以上医院主流 HIS 的差距集中在医保结算、住院体系、药库供应链、外部 LIS/PACS 集成四个维度。

## 三、工作流闭环核查（接口+浏览器双实测）

### 3.1 患者链路「挂号→就诊→处方→收费→取药」——✅ 真实走得通

实测记录（2026-11-20，flow_audit.py / flow_finish.py）：

| 步骤 | 接口 | 结果 |
| --- | --- | --- |
| 建档 | POST /api/v1/patients | 200，P000054 |
| 挂号 | POST /api/v1/registrations | 200，RG20261120-00043 |
| 缴挂号费 | POST /api/v1/charges/pay | 200（**发现约束：不缴费不能签到**，409 REG_FEE_UNPAID） |
| 签到 | POST /api/v1/registrations/{id}/checkin | 200 |
| 开始就诊 | POST /api/v1/visits | 200，visit 38 |
| 保存病历 | PATCH /api/v1/visits/{id} | 200 |
| 结束就诊 | POST …/finish | 200（**强校验**：病历不完整时 400 EMR_INCOMPLETE，实测有效） |
| 处方缴费 | POST /api/v1/charges/pay | 200 |
| 发药 | POST /api/v1/prescriptions/{id}/dispense | 200，库存原子扣减 |

卡点核查：发药被拒的唯一真实原因是"药品费未缴"（浏览器实测 step10_dispense_blocked.jpg），属正确业务约束而非缺陷。

### 3.2 处方链路「开立→审核→缴费→发药」——✅ 通，且三道闸真实生效

- 过敏冲突：开阿莫西林给青霉素过敏患者 → 422 ALLERGY_CONFLICT（接口实测）
- 审核前置：医生未完成就诊时药师审核 → 400「就诊尚未完成」（浏览器实测）
- 审核人分离：医生 token 调 rx.review → 403（垂直越权测试 V4）

### 3.3 医嘱链路「开立→审核→执行」——✅ 通（本次修复后）

- 医生开留观医嘱 → 护士执行 → 护理记录，接口+浏览器双实测通过
- 医生执行医嘱 → 403（无 nursing.write）；**修复前**护士可自开自执行 → 修复后 403 SEPARATION_OF_DUTIES（复测记录见 permission-matrix.md）
