## 二、全局 Token 变更（`miniprogram/app.wxss` 的 `page{--*}`）

**这是本轮收益最大的改动**：全仓页面 0 处硬编码色值（已实测），改 Token 即全站生效。

**新增 Token（原先页面各写一份 rgba/hex）**
- `--mint` `#54C8A7` / `--mint-dark` `#3FB08F` / `--mint-soft` `#E0F7F0` / `--mint-text` `#178F6B`
- `--amber-soft` `#FFF4E5` / `--amber-text` `#CC6600`
- `--text-placeholder` `#B0BEC5`

**新增全局类（≥2 页共用，符合 VF-12 收敛纪律）**
- `.btn-mint` / `.badge-mint`：薄荷实心按钮与标签（效果图「已完成 / 查看详情」）
- `.notice-bar-amber`：橙色警示条变体（效果图橙色紧急提示）
- `.seg-tabs / .seg-tab / .seg-tab-on / .seg-tab-count`：页内分段 Tab（选中态 = 主色文字 + 3px 下划线）
- `.stat-skel`：统计骨架条（规范 §六-2「加载中不显示 0」）
- `.sheet / .sheet-handle / .sheet-title`：底部半模态抽屉
- `.group-head / .group-card`：卡片内浅灰分组标题条（效果图 10 / 15）

⚠️ **唯一有意偏离设计规范**：`--text-sub` 保留 `#5064A0` 而非规范的 `#8A9BB8`。
原因：`#8A9BB8` 在 `#F3F8FF` 上对比度约 **2.8:1**，不达正文 4.5:1（KNOWN_ISSUES #27 已立过案）。
`#8A9BB8` 改作 `--text-placeholder` 与 `app.json` tabBar 未选中色的视觉基准。

## 三、逐页改动点

| 页面 | 改动点 |
|---|---|
| **home**（首页） | 症状输入行底色 `--bg` → `--accent-soft`（效果图是浅蓝底板，原白卡上几乎看不见边界） |

| **family**（家庭成员） | ① 说明条由弱文字小字改为**浅蓝底说明卡 + 双人图标**；② 成员卡加**圆形头像**（统一占位图，契约无头像字段时不伪造真人头像）；③ 新增底部授权说明「添加成员需获得对方授权…」 |

| **doctor/personal**（医生个人管理） | 分组标题改用全局 `.group-head`（浅灰条），删除本页重复定义的 `.group-label` / `.group-card` |

## 四、效果图中未能实现 / 需确认的细节

### ① 预约挂号（03）：效果图是「单页 + 底部确认抽屉」，现有是五步状态机
- 效果图：搜索栏 + 院区/科室筛选 + 日期横条 + 医生卡列表常驻，确认信息以**半模态抽屉**浮在列表上。
- 现状：`dept → doctor → time → confirm → done` 分步切换（`appointment.js` 状态机）。
- **未改原因**：改抽屉需要重写步骤流转与返回逻辑，属业务逻辑改动，超出"仅 UI 表现层"边界。
- **待确认**：是否允许改造成单页 + 抽屉？若允许，需同步重做 `test-apt-date` 的步骤断言。

### ② 在线问诊（04）：**无对应页面**
- 效果图是**真人医生图文问诊**（医生卡 + 接诊中状态 + 气泡对话 + PDF 附件卡 + 本次问诊摘要 + 剩余时间）。
- 现状：`consultation` 是 **AI 问诊**（本地导诊引擎），无医患会话后端。
- **未新建的原因**：无可调用的会话接口，新建页面只能造假数据（违反"禁止伪造业务数据"铁律）。
- **待确认**：若后端提供 `POST /api/v1/consultations`（契约已存在但前端未接），可新建 `pages/consult/consult` 并接真实会话。

### ③ AI 问诊（04）：效果图有页内「对话 / 我的」Tab
- 未实现。加 Tab 需新的视图切换逻辑（"我的"要展示会话历史），属业务逻辑改动。
- **待确认**：是否接受"仅对话、无 Tab"的现状（当前已如此）。

### ④ 健康档案（05）：效果图的「报告卡 + AI解读」未实现
- 效果图：报告卡带「已出结果 / 待审核」状态徽标 + 「查看报告」+「AI解读」两个按钮；顶部五分类宫格（检验/检查/就诊/用药/诊断）。
- 现状：分类 chip 由**实际返回的类别**动态生成（不硬编码 5 类），记录以时间轴呈现；`attachments` 已有上传/预览/删除（M9 落地）。
- **未实现原因**：`AI解读` 无后端接口；`已出结果/待审核` 无对应字段；五分类宫格固定 5 类会造假（后端只返回实际有的类别）。
- **待确认**：后端是否提供报告状态字段与 AI 解读接口。

### ⑤ 医生工作台（01）：效果图的「待处理事项」卡未实现
- 效果图有「在线问诊待回复 / 预约签到待确认」两行 + 「处理」按钮。
- 现状：有「今日接诊概览」三列 + 功能面板 2×2 + 侧栏快捷操作。
- **未实现原因**：无待办列表接口。加静态待办 = 假数据。

### ⑥ 个人中心（07）：效果图有三组卡 + 「就诊人管理」按钮
- 效果图：「医疗健康服务」5 行（含报告查询/就诊人管理）+「通用」3 行（消息通知/隐私设置/账号安全）+「协议」2 行 + 版本号。
- 现状：两组卡（医疗健康服务 3 行 / 账户与系统 3 行）+ 退出登录 + 版本号（本轮新增）。
- **未加的行**：消息通知、隐私设置、账号安全、用户协议、隐私政策 —— 这些入口已有对应位置（settings 页内），在个人中心重复加会形成**假入口**（点了没反应）。
- **待确认**：是否接受当前分组（功能齐全、无假入口）。

### ⑦ 适老化首页（08）：效果图 TabBar 只有 3 项
- 效果图：首页 / 就医 / 我的（少 AI 养生）。
- 现状：原生 TabBar 固定 4 项（首页 / AI问诊 / AI养生 / 我的）。
- **未实现原因**：小程序原生 tabBar 无法按主题动态切换项数，需 `custom-tab-bar` 自绘组件（改动面大）。适老化的**字号/触控尺寸**已由 `theme-large` 覆盖。

### ⑧ 床头卡「安排入住」按钮未实现
- 效果图空闲床有「安排入住」胶囊按钮。现状床位卡无操作按钮（契约 `POST /api/v1/beds/{bedId}/assignment` 存在，前端未接）。
- **待确认**：是否接入床位分配（需患者选择器）。

### ⑨ 效果图中的 emoji 图标未采用
- 效果图 05-AI养生用 🌙🍲🏃 作要点图标。项目铁律**禁止 emoji 作图标**（跨设备字形不一致、色彩不可控）→ 全部改用 `utils/icons.js` 的 PNG 线性图标。

### ⑩ 既有失败（非本轮引入，已做对照实验确认）
- `preview-pad-pages.js` 4 组 home FAIL：①「四宫格行数=1」契约**已过期**（`home.wxss` 实为 2 列 2 行，与效果图 01 的 2×2 一致）；② banner 插画高比 0.27~0.77（阈值 0.95）。用 `git show HEAD:app.wxss` 回滚对照，**同样 4 组 FAIL**，仅高比数值差 3%（0.80 → 0.77）。
- 未修原因：修 banner 高比需重算素材比值与容器高度，属独立缺陷；修"四宫格行数"契约需改测试预期值。
