## 1. 本轮回归直接产出的缺陷项（P1，先行）

### 1.1 voice-settings 设默认被迟到目录响应覆盖（本轮新定位）

- **状态：✅ 已修复（2026-11-16，B1-01）**。落地三层守卫：
  1. `services/voice.js` 新增模块级 `_writeGen`，`save()` 每次 +1；
  2. `catalogRemote()` 发起时记录代次，响应回来若代次已变则**跳过 current 复位**（不再用迟到响应覆盖用户写入）；
  3. `catalog()` 目录改为「本地内置 ∪ 最近远端」的**可见全集**（排除已删除），本地不认识远端音色时不再误判为已删除并回写 storage。
  页面侧再加 `_userGen` 双保险（`_apply` 成功后作废飞行中的目录响应）。
  回归：`node tools/test-profile-deep-audit.js` **27/27**（断言①转绿）、`node tools/test-voice-local.js` **25/25**。
- **现象**：test-profile-deep-audit 断言①失败（26 过 1 挂）：`onSetDefault('preset_pro')` 后 `storage.wb_voice` 实得 `preset_gentle`。该失败 2026-11-09 已登记（test-fe-all known:true），本轮补齐了完整归因。
- **根因链**（离线桩环境复现）：
  1. 页面 onLoad 先同步 `_refresh()`（本地 CATALOG）再异步 `catalogRemote()`（voice-settings.js:73-95）；
  2. 用户点「设默认」→ `voice.save()` 同步写 `wb_voice='preset_pro'`（voice.js:223）→ PUT 成功回调里再 `_refresh()`（voice-settings.js:177）；
  3. **onLoad 那次迟到的 `catalogRemote()` 响应**在两步之间落盘：远端目录里没有 `preset_pro` → 触发「current 不在远端目录 → 复位为 visible[0]」（voice.js:156-158）→ `wb_voice` 被改写；
  4. save 成功回调的 `_refresh()` 再走本地 `catalog()`：此时 current 已不在本地 CATALOG → 再复位为 `rows[0]`（voice.js:101-104）→ **最终 `preset_gentle`**，与实测一致。
- **影响面评估**：离线桩远端目录只有 1 条云端音色，真实联调环境远端目录含内置音色，可能不直接复现；但「迟到的异步目录响应覆盖用户刚做的选择」是结构性竞态（无代次/时序守卫），弱网真机上风险真实存在（真机清单 §4-⑪ 验证）。
- **方案**（两选一，倾向 a）：
  a. `catalogRemote()` 回调加**代次守卫**：进入时记 token，返回时若期间发生过 save/remove（voice.js 内部计数器即可）则丢弃这次 current 复位，只合并不回写；
  b. `catalogRemote()` 的 current 复位（voice.js:156-158）改为**只在 current 为空时**兜底，不做「不在目录就改写」——不在目录的音色由页面提示「当前音色已下线」而不是静默换。
- **涉及**：`services/voice.js`、`pages/profile/voice-settings/voice-settings.js`、`tools/test-profile-deep-audit.js`（断言①转绿后 known:false）。
- **验证**：test-profile-deep-audit 27/27 + test-fe-all「新增失败 0」+ 受控时序回归用例（测试计划 §3.2）。
