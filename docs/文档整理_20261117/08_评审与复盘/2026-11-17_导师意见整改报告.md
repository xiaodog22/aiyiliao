## 1. 第一轮意见：架构、安全、适老化、文档

### 1.1 方言 ASR：不做，也不编数据

- 代码事实：`backend/ai-service/app/config.py:217-218`，`AI_ASR_ENGINE` 默认 `none`；可选 `funasr`，需本地权重。
- 现有工具 `backend/ai-service/tools/benchmark-asr.py` **只测首包/复用延迟**，不计算 CER；仓库没有潮汕话语料与标注集。
- 结论：项目从未宣称“支持潮汕话识别”。按 2026-11-17 结项指令，方言 ASR **不实现**。
- 答辩口径：**“普通话语音输入 + 失败退回文字；方言适配未立项，因此没有 CER 可报。”** 这比编一个 98.6% 的 CER 更安全。

### 1.2 RAG 与知识图谱：不要混成“双轨已上线”

- RAG：`backend/ai-service/app/executors/rag.py` 已实现 Qdrant/Redis 向量检索 + Ollama embedding；
  但 `app/executors/__init__.py:80-82` 只有 `AI_RAG_ENABLED=true` 才注册，默认关闭；
  `chat.py` 的问诊主链路**没有调用 RAG**，`citations` 不会凭空出现。
- KG：全仓未发现 Neo4j / 图谱推理实现；架构图中标为“未接入”。
- 真实安全边界（这些是已实现、可演示的）：
  - 15 类红旗规则**先于**大模型执行，急症置顶 + 一键 120（`miniprogram/utils/triage-kb.js`、`pages/triage/result/result.js:64`）；
  - 问诊/养生提示词明确“不输出诊断结论、不推荐药物剂量”（`backend/ai-service/app/executors/chat.py:20,61-92`）；
  - 免责声明由业务侧固定下发，模型不覆盖（`executors/interpret.py:27`）；
  - 日志脱敏 `app/redact.py`；缓存键含 tenantId，敏感原文不进键（`app/cache.py:18`）。
- 答辩口径：**“当前是规则先行 + 大模型补充；RAG 执行器已实现但默认关闭、未接问诊；KG 未接入。”**
  不要把“有 rag.py”说成“RAG 双轨已上线”。

### 1.3 适老化：做到了哪一步，没做到哪一步

- 已实现：
  - 三档字号：正文 30 / 32 / 38rpx，标题 40 / 44 / 52rpx（`miniprogram/app.wxss:67-70,87-90,101-104`）；
  - 高对比色板与统一令牌；`test-a11y-touch` 22 项全过；
  - TTS 播报与语音入口；首页“说一句哪里不舒服”；
  - 触控目标 `--btn-height: 88rpx`（375px 屏宽下 = **44px**，满足微信 44px 最低要求）。
- 未做到：
  - 导师要求的 **48px**（96rpx）未全量达标；
  - 没有社区真实用户测试，因此**没有误触率 / 任务完成耗时 / SUS 数据**。
- 可执行方案（未做）：8~12 位 60 岁以上用户、5 个任务（挂号/导诊/问诊/查报告/拨 120），记录误触次数、完成时间、求助次数、SUS；数据出来前不写“已通过可用性测试”。

### 1.4 API 文档、Docker、WebSocket

- Docker：`backend/docker-compose.yml` + `backend/deploy/docker/*.Dockerfile` 已有；2026-11-17 已把口令/密钥改为 `${VAR:-本地默认}`。
- API 文档：`backend/contracts/business-openapi.yaml` / `ai-openapi.yaml` 是**目标态契约**（AGENTS.md 红线），
  不能当“当前接口事实”。当前事实以 `tools/contract-snapshot.js` 的 5 端点快照为准。
- WebSocket：**未接**。AI 任务用 SSE（网关流式透传），在线问诊仍是双端 2s 轮询；
  因此“心跳保活 / 断线重连”目前没有实现对象，不能写成已有能力。
- 答辩口径：**“Docker 一键编排已有；接口契约是目标态，运行态以快照为准；长连接是 V1.21 候选。”**

## 2. 第二轮意见：逐条核验

### 2.1 “表现层耦合业务逻辑与数据库直接查询”——不成立，仅 1 处 dev 例外

- 小程序：`miniprogram/pages/**` 搜 `wx.request` 为 **0**；页面只调 `services/*`，网络统一走 `services/request.js`。
- Java：Controller 注入的是 Service；Repository 只注入到 Service（全仓 53 处 `private final *Repository` 均在 Service 层）。
- 唯一例外：`backend/business-service/src/main/java/com/wechar/biz/dev/DevAdminController.java:34,55,64`，
  `@Profile("dev")` 下直接注入 `JdbcTemplate` 查号源。它是演示管理端点，生产不装配，但确实是分层瑕疵。
- 整改方案（P1，未做）：新增 `DevAdminRepository`（同样 `@Profile("dev")`），Controller 只保留参数与响应编排；
  验收：`DevAdminController` 不再 import `JdbcTemplate`，现有 dev 端点测试全过。

### 2.2 “端口 / URL / 超时 / 敏感配置硬编码”——部分成立

成立的部分：

- `miniprogram/config/env.js:18` `BUILD_ENV = 'development'` 需要手工改；
- `:31` `DEV_DIRECT = 'http://127.0.0.1:8080'`；
- `:43` 隧道域名 `https://qv56gv32944.vicp.fun` 写在源码；
- `:91` `DEV_LOGIN_KEY` 联调密钥写在源码（注释说明仅 dev 闸门、生产不发，但仍属敏感形态）。

不成立的部分：

- 后端 `application.yml` 已全环境变量化：`SERVER_PORT`、`MYSQL_URL/USER/PASSWORD`、`PHONE_KEY_BASE64`、
  `APP_ATTACHMENT_SIGN_SECRET`、微信 appId/secret、超时与限流窗口等均为 `${ENV:default}`；
- `backend/docker-compose.yml` 已改 `${VAR:-本地默认}`；
- 前端超时集中在一个文件，不是散落各页。

整改方案（P0，未做）：

1. 新增 `miniprogram/config/env.local.js`（`.gitignore`）存放 `BUILD_ENV`、隧道域名、dev key；
2. 入库 `env.example.js` + 启动说明；`env.js` 只保留生产档校验与合并逻辑；
3. 构建脚本在打包前生成 `env.local.js`，生产档缺正式 HTTPS 网关直接 fail-closed（现有校验保留）。

验收：干净 clone 不含真实隧道域名与 dev key；`check-project` 的禁址扫描仍为 0。

### 2.3 “异常处理形同虚设 / e.printStackTrace”——不成立

- 全仓 `printStackTrace` **0 处**。
- Java：`GlobalExceptionHandler.java:21-90` 覆盖 ApiException、Bean Validation 422、JSON 400、
  缺头/缺参 400、405、未实现 501、兜底 500；500 只记日志，响应不带堆栈，统一带 `requestId`。
- 网关：`ApiError` + 全局 handler，429/502/503/504 都有稳定错误码；AI 服务“快降级”返回结构化失败。
- 答辩演示：打开 `GlobalExceptionHandler.java` + 一个 `@Valid` DTO + 一次 422 响应即可。

### 2.4 “命名中英文混用 / a、b、temp”——轻微成立

- 全仓没有 `temp/foo/bar` 这类命名；`a/b/c` 仅 6 处局部变量：
  - `common/AuthInterceptor.java:171`、`indoor/IndoorMapService.java:94,98`、
    `appointment/AppointmentService.java:335`、`home/HomeService.java:97`、
    `doctor/DoctorScheduleService.java:215-216`、`appointment/AppointmentRepository.java:119,234`。
- 定性：算法/映射循环里的短名，不影响可读性主线；不是“大泥球”级问题。
- 整改方案（P2，未做）：统一改成 `segment/nodeA/upcoming/stored/next/count` 等语义名；
  验收：纯改名、`mvnw test` 341 项不变。

### 2.5 “无分页 / 无索引 / 无缓存 / 高并发”——部分成立

- 分页（大部分已有）：
  - `ConsultationController.java:64-71` 列表 cursor + limit；`:93-114` 消息 cursor + limit；
  - `PatientController.java:69-73` 健康档案 limit；`:174-176` 家庭邀请 limit；
  - `AppointmentController.java:101-115` 接受 `cursor` 但注释明确“游标语义在 M2 分页任务展开”，
    **当前只按 limit 截断，cursor 未生效**——这是真实缺口。
- 索引：Flyway 迁移里 `KEY/INDEX` 定义 **162 处 / 17 个文件**（含 `V24__auth_sessions_cleanup_index.sql`），
  不是“没有索引”。
- 缓存：AI 任务有内容寻址缓存（Redis/JSON，`app/cache.py`）；**业务目录/科室没有缓存**，这是缺口。
- 压测：10VU 413.9 RPS / P95 50.7ms；25VU 296.6 RPS / P95 213.7ms；2/4 worker 562/906 RPS（README 实测）。
- 整改方案（P0/P1，未做）：
  1. `AppointmentController` + `AppointmentRepository` 实现 cursor（`created_at,id` 复合游标，SQL 加 `WHERE (created_at < ? OR (created_at = ? AND id < ?))`）；
  2. `CatalogService` 加 Caffeine 本地缓存（科室/医生目录，TTL 5min，更新时失效），不引入新中间件；
  3. 压测基线纳入 `perf-gate`，保持 10VU/25VU 两档。

### 2.6 “输入不校验 / 注入 / 越权”——基本不成立

- 校验：Controller 广泛 `@Valid`；DTO 有 `@NotBlank`、`@Size` 等约束（如
  `consultation/dto/ConsultationCreateRequest.java:14-19`）；422 由全局异常处理器统一返回字段级错误。
- 鉴权：`AuthInterceptor.java:109-141` strict 模式只认 Bearer 会话，忽略 `X-User-Id`；
  越权资源统一 404；401 走统一信封。
- SQL：Repository 用 `JdbcTemplate` + `?` 占位符 + `args` 绑定，未发现把用户输入拼进 SQL 的写法。
- XSS：小程序 WXML 文本绑定默认转义，用户输入不进入 `rich-text`/WebView；因此当前无 XSS 面。
  缺口是“未来若渲染富文本，没有显式 sanitizer”。
- 整改方案（P2，未做）：CI 加依赖漏洞扫描（`npm audit` / OWASP Dependency-Check），
  富文本能力上线前引入服务端 sanitizer。
