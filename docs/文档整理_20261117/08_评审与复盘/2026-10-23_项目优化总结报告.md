## 一、任务一【高危安全修复】生产配置收尾与鉴权加固

### 1.1 关闭网关测试开关（legacyLoginEnabled）与通配跨域

**文件**：`backend/deploy/config.json`

修改后关键值：

```json
{
  "cors": { "enabled": false, "allowOrigins": [] },
  "assets": { "dir": "backend/deploy/resources" },
```

- `compat.legacyLoginEnabled=false`：严禁生产环境经手机号直接无密码换取 dev 微信会话。
- `cors.enabled=false` + `allowOrigins=[]`：生产默认关闭跨域；如需放开，仅允许显式白名单。

**配套代码**（`backend/edge-gateway/app/config.py`）新增受控 CORS 配置字段：

```python
@dataclass
class GatewayConfig:
    # ...
    cors_allow_origins: list[str] = field(default_factory=list)

# 加载逻辑（load() 内）
raw_cors = raw.get("cors", {})
cfg.cors_allow_origins = [
    o.strip() for o in (
        os.environ.get("GW_CORS_ALLOW_ORIGINS", "")
        if raw_cors.get("allowOrigins") in (None, "")
        else ",".join(raw_cors.get("allowOrigins") or [])
    ).split(",") if o.strip()
]
```

**CORS 中间件**（`backend/edge-gateway/app/main.py`）改为「显式白名单非空才注册，否则不开放任何来源」：

```python
if app_config.cors_allow_origins:
    app.add_middleware(CORSMiddleware,
                       allow_origins=app_config.cors_allow_origins,
                       allow_credentials=True,
                       allow_methods=["*"],
                       allow_headers=["*"])
else:
    logger.warning("cors.allowOrigins 为空/未配置：不注册 CORS 中间件，不开放任何跨域来源")
```

彻底移除 `allow_origins=["*"]`。

### 1.2 AI 服务鉴权收尾（static 模式 + 强 token fail-fast）

```python
def install_auth(app: FastAPI, cfg: AiConfig) -> None:
```

### 2.3 单账号物理清除 + 匿名化（DeletionPurgeService，@Transactional）

- 按外键依赖顺序对 19 类关联表执行 DELETE（auth_sessions、consents、user_profiles、user_preferences、health_records、messages、appointments（appointment_status_events 经子查询归属）等）。

```java
UPDATE users SET
    wechat_openid = CONCAT('deleted-', id),
    phone_cipher = NULL, phone_hash = NULL, phone_bound = 0,
    display_name = '[已注销]',
```

## 五、验证阶段附加修复（重要：M5 分页 E2E 暴露的既有缺陷）

**文件**：`backend/business-service/src/main/java/com/wechar/biz/appointment/AppointmentRepository.java`

### 5.1 数据越权级 SQL bug（P0）

`VIEW_SELECT` 以 `LEFT JOIN users u ON a.user_id = u.id` 结尾（**缺 WHERE 锚点**），所有调用方拼接的 `AND a.doctor_id = ?`、`AND a.id = ?` 被 SQL 解析器**吞进 LEFT JOIN 的 ON 子句**——ON 条件只影响 join 匹配、**不过滤主表行**。后果：医生端列表能查到**全医生**的挂号、按 id 查询不过滤（doc-empty 医生返回 7 条他人挂号，M5 暴露）。

修复：VIEW_SELECT 末尾加 WHERE 锚点：

```java
+ "LEFT JOIN users u ON a.user_id = u.id WHERE 1=1 ";
```

### 5.2 东八区 keyset/日期窗口时区错位

`listViewByDoctor` 的日期/游标参数原用 `Timestamp.from(instant)`（UTC 值），与读取侧 `rs.getTimestamp(...).toInstant()`（JVM 本地时区解释存储钟面）在东八区相差 8 小时 → keyset 游标条件永不命中，翻页永远返回第一页（UTC JVM 不触发）。

修复：新增参数自洽转换，任何时区一致：

```java
private static Timestamp toDbTimestamp(Instant instant) {
    return Timestamp.valueOf(instant.atZone(java.time.ZoneId.systemDefault()).toLocalDateTime());
}
```

**验证**：修复前 M5CursorPaginationE2ETest 4 失败；修复后 **8/8 通过**，全量回归 292 测试全绿（无副作用）。
