## 3. 失败项定位与归因（本轮新失败 1 项）

### §3.1 test-profile-deep-audit · 断言①「设默认成功后本地 storage 同步」

- **现象**：`onSetDefault('preset_pro')` 后断言 `storage.wb_voice === 'preset_pro'`，实得 `preset_gentle`。PASS=26 / FAIL=1，exit 1。该失败 2026-11-09 已在 test-fe-all 登记（known:true，注释「余 1 项待查」），本轮补齐根因链。
- **根因**（离线桩环境完整复现链路）：
  1. `voice-settings.js` onLoad：先同步 `_refresh()`（本地 CATALOG，current=preset_gentle），再异步 `catalogRemote()`（voice-settings.js:73-95）；
  2. 用户点「设默认」→ `voice.save()` **同步**写 `wb_voice='preset_pro'`（voice.js:223）→ PUT 成功后回调 `_refresh()`（voice-settings.js:177）；
  3. **onLoad 那次迟到的 catalogRemote 响应**落在这两步之间：远端目录（测试桩仅 1 条 `remote_yunv`）不含 `preset_pro` → 触发「current 不在远端目录 → 复位为 visible[0]」（voice.js:156-158）→ `wb_voice='remote_yunv'`；
  4. save 成功回调的 `_refresh()` 走本地 `catalog()`：`remote_yunv` 不在 CATALOG → 再复位 `rows[0]`（voice.js:101-104）→ 最终 `preset_gentle`，与实测完全吻合。
- **定级**：P1。离线桩目录刻意只有远端音色，真实环境远端目录含内置音色未必直接复现；但「迟到的异步目录响应静默覆盖用户刚做的选择」是**结构性竞态**（回调无代次守卫），弱网/真机风险真实存在。
- **处置**：不修代码（本轮红线）；修复方案与时序回归用例已写入《改进计划_代码与功能逻辑》§1.1 与《测试计划》§3.2，列入 V1.20 批次 T1-1。
