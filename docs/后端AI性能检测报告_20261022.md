## 1. 本次执行的改动清单

### 1.1 配置改动（`backend/deploy/env.local`）

新增两段：
```bash
# P0 性能开关
AI_LLM_STREAM=true
AI_LLM_WORKER_POOL_SIZE=3

# RAG 仍保持关闭（Qdrant 未部署）
# AI_RAG_ENABLED=false
```

### 1.2 代码改动

**`app/executors/rag.py`**：
- `_get_embedding` 签名从 `(ollama_url, model, text, timeout, transport)` 改为 `(settings, text, transport)`。
- 内部从 `async with httpx.AsyncClient(...)` 改为 `async with ollama_client(settings, transport=transport)`，复用全局连接池。
- 调用处同步更新（embedding 阶段）。
- Qdrant 检索仍用独立 client（不同 host，无法复用 Ollama 连接池）。

**`app/executors/chat.py`**：
- `build_chat_executor` 顶层一次性构造 `rag_executor` 和 `_SimpleContext`（之前每次请求新建闭包 + 类）。
- `_retrieve_context` 简化为直接调已造好的 `rag_executor`。

**新增 `scripts/ingest_knowledge_kb.py`**：
- 内嵌 7 篇图文（34 sections）+ 3 个视频（9 tips）= 43 个 chunk。
- 流程：检查 Ollama 模型 → 探测向量维度 → ensure collection → 逐 chunk embedding → 批量 upsert Qdrant。
- 幂等：chunkId 哈希为 point id，重复跑覆盖同 ID。
- 零依赖：只用 Python 标准库（urllib），不需要装 qdrant-client。

### 1.3 模型下载

- `ollama pull nomic-embed-text`（274MB，已完成）。

### 1.4 未改动

- `hospital-knowledge.json` 已是 v2（含 TODO/source 标注），无需再改。
- Qdrant 部署（本机无 docker、无 qdrant.exe 二进制）。

## 5. 回滚方式

- **LLM 流式回滚**：env.local 删 `AI_LLM_STREAM=true`（或改 false），重启。流式失败本就自动回退非流式。
- **worker 池回滚**：env.local 删 `AI_LLM_WORKER_POOL_SIZE=3`（或改 1），重启。supervisor 异常时也会自动回退单 worker。
- **代码回滚**：rag.py / chat.py 改动均为小改，git 可直接 revert。
