## 2. 前端解析逻辑核对（任务 1）

### 2.1 `resolveResource` —— 语义正确，但**原先没有调用点**

```js
// services/resource.js
function resolveResource(key, builtinFallback) {
  const manifest = readCachedManifest()
  const item = manifest && manifest.items.find((it) => it.key === key)
  if (!item || !item.url) return builtinFallback || (item && item.fallbackKey) || ''
  return item.url
}
```

优先级：`item.url`（远端绝对 HTTPS）→ 调用方传入的 `builtinFallback` → `item.fallbackKey`。

**问题**：全仓检索发现 `resolveResource` **没有任何页面调用**——首页仍写死
`doctor: '/assets/home/ai-doctor.png'`、`banner: '/assets/home/banner-hospital.jpg'`。
也就是说后端清单下发了绝对 URL，前端根本没用，**验证 `<image>` 加载后端图无从谈起**。

**修复**（`pages/home/home.js`）：

```js
_applyRemoteAssets() {
  const remote = {
    banner: resource.resolveResource('home.banner-hospital', A.banner),
    doctor: resource.resolveResource('home.ai-doctor', A.doctor)
  }
  const cur = this.data.A || {}
  if (cur.banner === remote.banner && cur.doctor === remote.doctor) return
  this.setData({ A: Object.assign({}, cur, remote) })
}
```

- 在 `onShow` 里调用：清单由 `app.js` 冷启动异步刷新，首屏几乎一定拿不到 →
  **首次用包内图，回到首页自动切远端**，任何时刻都不裂图；
- 兜底值取常量 `A`（包内路径），不是 `this.data.A`（可能已被远端覆盖）；
- `home.wxml` 的 banner 加 `binderror="onBannerError"` → 远端图失败自动退回包内图。

### 2.3 附件 —— **发现并修复一个真机必失败的 bug**

**修复前**：

```js
wx.openDocument({ filePath: url, ... })   // url 是 https 地址
```

`wx.openDocument` 的 `filePath` **只接受本地文件路径**，传 https 地址真机必然失败
（开发者工具偶发"能打开"是它做了容错，不能作为依据）。

**修复后**（`health-records.js`）：

```js
_openPdf(url) {
  wx.showLoading({ title: '正在打开', mask: true })
  wx.downloadFile({
    url,
    success: (res) => {
      wx.hideLoading()
      if (res.statusCode === 410) { wx.showToast({ title: '链接已过期，请重新打开档案' }); return }
      if (res.statusCode !== 200 || !res.tempFilePath) { wx.showToast({ title: '文件下载失败（' + res.statusCode + '）' }); return }
      wx.openDocument({ filePath: res.tempFilePath, fileType: 'pdf', showMenu: true, fail: ... })
    },
    fail: () => { wx.hideLoading(); wx.showToast({ title: '下载失败，请检查网络' }) }
  })
}
```

关键点：**`wx.downloadFile` 对 4xx/5xx 也走 `success`**（只有网络层错误才走 `fail`），
所以必须在 `success` 里判 `statusCode`——这是最容易写错的地方。

图片走 `previewImage`（URL 可直接用），失败提示"图片打不开，链接可能已过期"。

### 5.4 裂图排查顺序（按此顺序，别跳）

1. **URL 是否绝对 HTTPS**：`<image src>` 里必须是 `https://qv56gv32944.vicp.fun/...`，
   不是 `/api/...`（相对路径会被当包内路径）；
2. **端点是否 401**：浏览器/调试面板直接请求该 URL，看状态码；
3. **Content-Type 是否 `image/png`**：若不是（比如 `application/json`），说明打到错误端点；
4. **手机浏览器能否直接打开该 URL**：能打开 → 是 `<image>`/域名配置问题；打不开 → 是链路问题；
5. **是否只看了首屏**：首屏用包内图是预期行为，退出重进才切远端。
