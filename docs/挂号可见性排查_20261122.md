# 挂号可见性排查：患者挂号为什么到了不 HIS / 医生端（2026-11-22）

> 范围：患者端小程序挂号 → 平台 business-service → clinic-his（对外 openapi）→ HIS 院内挂号/叫号；
> 以及患者端挂号/问诊 → 医生端小程序。
> 本文只记录**实测过的事实**；未验证的推论一律标注「待确认」。

---

## 1. 结论摘要

| 目标 | 原状态 | 根因 | 本次处置 |
| --- | --- | --- | --- |
| HIS 收到挂号 | 只落 `openapi_orders`（对外受理台账），院内 `registrations` / `queue_tickets` 一行没有 | 受理接口只做「收单」，没做「落院内」 | **已修**：受理成功即写挂号 + 预排号；撤销同步作废 |
| HIS 挂到正确医生 | 无医生映射时回落 `D001/QK`，单子挂到别的医生名下 | `his_master_data_map` 无 DOCTOR 的 CONFIRMED 映射 + `demo=true` 回落 | 已给出口径：补齐映射 + `demo=false`；**映射数据本身仍需业务确认** |
| 医生端收到挂号 | 30 位医生只有 1 位有登录账号，其余医生端永远为空 | `doctors.user_id` 未绑定；医生端范围判据是任职关系 | **已修**：V9017 为 30 位医生建独立账号并回填任职；新增 `dev-doctor-<id>` 登录入口 |
| 医生端收到问诊请求 | 只能看到「患者指定该医生」的会话 | 产品口径（AI 会话 `doctor_id` 为空） | 不改，已在文档写明边界 |

## 2. 当前链路（改后）

### 2.1 挂号主链路

```
患者端 pages/appointment
  └─ 必须真实会话（session.hasSession()；本地演示登录会被页面拦住）
  └─ 选科室 → 选医生 → 选号源
      POST /api/v1/appointments  {slotId, patientName, symptomSummary}
        └─ AppointmentService.create
             ① 号源校验：未过期 / status=OPEN / 非重复（同用户同号源仅一笔在办，409 DUPLICATE_APPOINTMENT）
             ② 原子扣减 remaining--（0 行 → 409 SLOT_FULL）
             ③ hisGateway.book(HisBookingCommand)      ← HIS 开关决定是否出网
             ④ 写 appointments（PENDING）+ queueNumber（平台侧取号序号）
             ⑤ 给患者发站内消息（消息中心）
```

`bookingSource` 由服务端下发，前端不猜：`LOCAL_DEMO`（HIS 关闭）/ `HIS_MOCK`（demo 档受理）/ `HIS_LIVE`（真实受理）。

### 2.2 HIS 侧（clinic-his `openapi.py`）

```
POST /openapi/v1/appointments（HMAC 签名 + Idempotency-Key）
   ├─ openapi_orders        对外受理台账（姓名掩码 + 姓名哈希 + hisOrderNo）  ← 原有
   ├─ registrations         院内挂号（source=WECHAT，status=BOOKED）        ← 本次新增
   └─ queue_tickets         预排号（status=RESERVED，不参与叫号）            ← 本次新增
```

- 患者档案：按 `appId + 姓名` 派生 MRN（`DEMO-xxxxxxxxxx`），与结算演示口径一致；
- `registrations.slot_id` 留空：平台号源与院内 `doctor_slots` 不同源，不伪造院内号源外键；
- 不建 `charges`：挂号费仍由院内收费处收取（互联网医院侧支付未接此接口）；
- 撤销：`POST /openapi/v1/appointments/{no}/cancel` → 受理单 + 挂号 + 预排号一起 CANCELLED
  （已签到/已就诊的不动，仍走院内退号流程）；
- 签到：`registration.checkin` 优先复用该 `RESERVED` 票并转 `WAITING`，**不会二次取号**。

### 2.3 医生端链路

```
POST /api/v1/doctor/login（按 doctors.user_id + status=ACTIVE 判角色，无任职 → 403）
GET  /api/v1/doctor/appointments   → SQL 条件 a.doctor_id = 本医生 id
GET  /api/v1/doctor/consultations → status=ACTIVE AND doctor_id=本医生 AND 无 assistant 消息
```

## 3. 缺口点与影响范围

| 编号 | 缺口 | 影响 | 状态 |
| --- | --- | --- | --- |
| G1 | openapi 受理不落院内挂号/队列 | HIS 挂号列表、叫号大屏、日报统计看不到互联网医院患者；平台显示成功、院内查无此人 | 已修 |
| G2 | 医生账号只绑了 1 位 | 29 位医生的号患者能约、医生端永远空；这些医生也无法登录医生端（403） | 已修（V9017） |
| G3 | `his_master_data_map` 无 DOCTOR CONFIRMED | 真实档（`demo=false`）必 503；演示档回落 `D001/QK`，**挂到错误医生** | 未修（需业务确认主数据） |
| G4 | `env.local` 里 `APP_HIS_ENABLED=true` | 本机没起 clinic-his 时，所有挂号 503 `HIS_UNAVAILABLE` | 已知，按需改回 false |
| G5 | 平台侧支付与院内收费未打通 | 线上挂号在院内是「未缴费」，到院需窗口缴费后才能签到 | 未接，属后续需求 |

**影响面**：G1/G2 影响演示与验收口径（“挂号成功”与实际可见性不一致）；G3 影响真实对接，属发布阻断项；G4 只影响本地开发；G5 属功能未建，不是缺陷。

## 6. 后续处理建议

1. **主数据治理（发布阻断）**：`his_master_data_map` 的 DOCTOR 映射必须由业务确认后置 CONFIRMED
   （同名同科才可确认；同名不同科按 CONFLICT 保留）。确认前 `APP_HIS_HTTP_DEMO` 只能保持 `true`，
   且页面会标「演示预约」。
2. **HIS 新库主数据补齐**：本地演示库有 `XH 消化内科` / `D009 林建平`（历史手工补录，`seed.py` 未含）。
   重建 HIS 库前先执行附录 A，否则 `dep-gastro→XH`、`doc-gastro-1→D009` 映射会 404。
3. **挂号费**：若要把线上支付接进 HIS，需新增 openapi 收费/支付接口并在 `_ensure_registration` 里建 `charges`；
   在此之前保持「到院缴费」口径，页面文案不要暗示已缴费。
4. **医生站可见性**：`registrations` 已落库，HIS 挂号列表（`GET /api/v1/registrations?date=`）与
   大屏（`GET /api/v1/queue`）可直接看到；`RESERVED` 票需在签到后转 `WAITING` 才会被叫号，
   大屏如需展示「预约未到院」应显式读 `RESERVED`，不要把它并入等候队列。
5. **本地开关**：`backend/deploy/env.local` 的 `APP_HIS_ENABLED=true` 只在 clinic-his 已启动时使用；
   单独调平台时可临时置 `false`，避免挂号全 503。
