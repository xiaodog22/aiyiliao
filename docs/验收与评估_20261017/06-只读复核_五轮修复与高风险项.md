## 4. 表 C —— 确认仍有问题（按危害排序）

### C-01 GET 单飞去重键不含账号/会话维度（隐私，P1）

- **位置**：`services/request.js:169-179`（`inflightKeyOf`）、`:457-462`、`:513-520`
- **证据**：键 = `full + '|' + payload + ('|raw')`，无 `sub`/会话代号；`inflightGet` 只在 Promise settle 时释放，`session.clear()` / `exitToLogin()` 均未清空该表。
- **失败场景**：账号 A 的 `GET /api/v1/me` 因弱网挂起（超时上限 30s）→ 会话失效退出 → 账号 B 登录 → B 打开「我的」命中 A 尚未 settle 的 Promise → **B 看到 A 的姓名/手机号**。医疗场景属跨患者数据串用。
- **最小修复**：`session.js` 增加单调递增 `epoch`（`setTokens` / `clear` 时 +1），键拼上 `session.epoch()`；或在 `clearLoginState()` 内清空在途表。
- **回归测试**：桩测两段——①`epoch` 不变时同 URL 并发只发 1 次 `wx.request`；②两次调用之间 `session.clear()`，断言发 2 次且第二次带新 `Authorization`。

### C-02 挂号幂等键只存在页面内存（重复挂号，P1）

- **位置**：`pages/appointment/appointment.js:275-279`（`this._submitSig/_submitKey`）、`:317-320`
- **证据**：键挂在 Page 实例上，无 `storage` 落盘；`_dropSubmitKey()` 在成功与明确失败时清空。
- **失败场景**：提交 → 服务端已建单但响应超时（`TIMEOUT`）→ 用户按返回键离开 → 重新进入挂号页（新实例、`submitting=false`、`_submitKey` 为空）→ 重新选同一时段提交 → **新键 → 第二笔真实预约**。同理适用于小程序被系统回收。
- **最小修复**：把 `{key, sig, slotId, at}` 写入 `wb_apt_pending`，`onLoad` 恢复并在 `sig` 相同时复用；成功/明确失败/超过 24h 清理。这不改接口契约，只改键的生命周期存储位置。
- **回归测试**：桩测——模拟 `onSubmit` 超时 → 重建 Page 实例 → 再次 `onSubmit`，断言两次 `Idempotency-Key` 相同；成功后重建实例断言换新键。

### C-03 超时被表述为"挂号失败"，且无核对入口（安全，P1）

- **位置**：`pages/appointment/appointment.js:292-312`
- **证据**：`catch` 内对 `TIMEOUT/NETWORK_ERROR` 与其他错误共用 `wx.showToast({ title: '挂号失败：' + ... })`；没有"查看挂号记录"分支。
- **失败场景**：服务端已建单、响应超时 → 用户被告知"失败" → 用户不信任系统，改用其他渠道或重复提交 → 重复挂号/爽约。文案与事实相反，是医疗场景的直接风险。
- **最小修复**：单独 `UNKNOWN` 分支用 `showModal`：`content:'网络中断，本次挂号结果未知，请先核对挂号记录'`，按钮 `查看挂号记录`（`/pages/profile/records/records`）+ `稍后重试`（复用同键）。
- **回归测试**：桩测注入 `TIMEOUT`，断言弹出 modal（非 toast）、文案含"结果未知"、点击首按钮 `navigateTo` 到记录页。

### C-04 清缓存仍是"全量清除 + 恢复"（数据丢失，P1）

- **位置**：`pages/profile/settings/settings.js:111-137`（`wx.clearStorageSync()` 在 :125）
- **证据**：清全量后仅恢复 `wb_role/wb_user/wb_login_at/wb_theme/wb_voice_read/wb_refresh_token`。未恢复且无服务端副本的键：
  - `wb_triage_report`（`triage.js:437` 写、`result.js:28-36` 读）→ 清后「查看报告」进入 `empty` 态；
  - `wb_triage_history` / `wb_triage_quality`（`services/triage.js:160-208`）→ 本地导诊记录与统计；
  - `wb_user_profile` / `wb_doctor` → 缓存类，可由 `/me` 重建（影响小，但属"删除用户资料"）。
- **附带发现（比原问题更值得修）**：`saveSession()` 每次导诊都把**症状原文（≤200 字）明文写入** `wb_triage_history`，而 `listSessions()` / `quality()` **全仓零读取方**——写的是死数据，却把敏感健康文本留在了本地。与 `session.js` 头注释"权威数据不得写入 storage"自相矛盾。
- **最小修复**：①改白名单删除（只删 `wb_resource_manifest_v1`、`wb_tv`、`wb_triage_quality` 等明确缓存键），不动身份/会话/医疗资料；②删除 `saveSession()` 的写入（或整体下线该函数），从根上消掉明文症状留存。
- **回归测试**：桩测——预置 8 个键 → 调 `onClearCache` 确认分支 → 断言 `wb_refresh_token`/`wb_triage_report`/`wb_user_profile` 仍在、`wb_resource_manifest_v1` 已删。

### C-05 care-plan 年龄在非法时被替换成"60 岁"（医疗数据伪造，P0）

- **位置**：`pages/health/health.js:156`（`const age = Number(a.age) || 60`）、`:354-368`（`onSend` 把自由文本写入 `answers[q.key]`）、`services/careplan.js:16-23`（`age` 非法 → `0`）
- **证据**：年龄题的选项是区间（`:22-25`），但用户可用输入框作答，`onSend` 直接把文本当答案：`answers.age = '六十多'` / `'不想说'` → `Number()` 得 `NaN` → `|| 60` → 请求体 `age:60` 且 `user_info` 内含 `年龄：60岁`。
- **失败场景**：用户从未说过 60 岁，后端按 60 岁生成膳食/功法/穴位方案，并在结果页显示 `60岁 · 定制调理`。这是**前端伪造医疗上下文**，触碰项目红线；比"发送 0"更隐蔽，因为 0 至少是显式非法值，60 会被后端当成有效输入。
- **最小修复**：`age` 无法解析为 1~120 的整数时**不发请求**，弹"请选择您的年龄段"并回退到该题；`careplan.buildPayload` 改为非法时 `throw INVALID_AGE`（由页面捕获提示），不再静默送 0。
- **回归测试**：桩测——`answers.age='六十多'` 断言 `careplan.generate` 未被调用且页面回到年龄题；`age=58` 断言请求体 `{user_info:含"58岁", age:58}`；`age=NaN` 断言 `buildPayload` 抛 `INVALID_AGE`。

### C-06 区间年龄被换算成精确年龄（数据精度，需产品决策）

- **位置**：`pages/health/health.js:19-25`
- **证据**：`'40 - 55 岁'` → `48`、`'56 - 65 岁'` → `60`、`'66 岁以上'` → `72`，请求体只发整数 `age`。
- **失败场景**：后端按精确年龄推断（如 48 岁女性围绝经期），用户实际只是选了区间；结果页回显"48岁"会让用户误以为系统记录了精确年龄。
- **最小修复**（不改契约）：`user_info` 里显式写"年龄段：40-55 岁（代表值 48）"，结果页摘要改用区间文案；或契约增加 `ageGroup` 字段（需后端排期）。
- **回归测试**：桩测断言 `user_info` 含区间原文；视觉侧断言结果页 `summary` 不出现裸数字年龄。

### C-07 高对比开关是完全无效的交互（虚假功能，P2）

- **位置**：`pages/profile/settings/settings.js:35`（读 `app.MOCK.SETTINGS`）、`:99-101`（只 `setData`）、`settings.wxml:39`；`app.wxss:352` 的 `.high-contrast`

- **最小修复**：二选一——①短期：开关置灰并提示"暂未开通"（符合"未定能力不伪装"的口径）；②实现：`app.globalData.highContrast` + `wb_contrast` 持久化 + 页根 `class="{{highContrast?'high-contrast':''}}"`（涉及 21 页，独立立项）。
- **回归测试**：静态断言 `settings.js` 不再读 `app.MOCK.SETTINGS`；实现档走真机对比截图。

### C-08 隐私同意链不存在（发布阻断，P0）
