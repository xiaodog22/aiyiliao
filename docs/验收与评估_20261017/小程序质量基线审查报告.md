## 二、最高优先级 10 个问题

### P0-1 挂号提交与接口契约不匹配，真实环境必被拒
- **证据**
  - `miniprogram/services/appointment.js:66-77`：只发 `userName/phone/deptName/clinicName/doctorName/appointTime/description`，且 `post()` 未传 `idempotencyKey`。
  - 契约 `backend/contracts/business-openapi.yaml:1992-2001`：`AppointmentCreate` **required [slotId, patientName]**，`additionalProperties: false`。
  - 后端 `business-service/.../AppointmentCreateRequest.java:11-18`：`@NotBlank slotId`、`@NotBlank patientName`。
  - 后端 `AppointmentController.java:61-66`：`IdempotencyKeys.require(...)`，缺失即 400。
  - 网关兼容层未翻译该路径：`edge-gateway/tests/test_compat.py:33` 断言 `POST /api/v1/appointments` 不匹配 compat。
- **等级** `[静态]`（同类 400 有历史日志旁证：`DEV_LOG.md:4815`）
- **影响**：核心就医链路在真实后端下 100% 失败；而开发档 `withFallback`（`appointment.js:145-153`）会把失败包装成"成功"并写入本地缓存，问题被长期掩盖。
- **最小修复**：改用 `services/user.js:156 submitAppointment`（自带幂等键），入参补 `slotId/patientName`；无号源时不放出"确认挂号"按钮。

### P0-2 挂号页科室/医生/时段全部是前端演示数据，且没有号源概念
- **证据**：`pages/appointment/appointment.js:62,74,83` — `const MOCK = app.MOCK`、`MOCK.DEPARTMENTS`、`MOCK.TIME_SLOTS`；`services/appointment.js:44-55` 已有 `listDepartments()/listDoctorsByDept()`，全仓检索**无页面调用**。
- **等级** `[静态]`
- **影响**：患者看到的科室、医生、可约时间与医院实际排班无关；医疗场景属"伪造业务数据"红线。
- **最小修复**：`onLoad` → `listDepartments()`；选科后 → `listDoctorsByDept()`；时段改为 `GET /api/v1/doctors/{id}/slots` 并回填 `slotId`。

### P0-3 就医进度卡按中文状态判定，契约返回英文枚举 → 永远停在默认态
- **证据**
  - `pages/triage/triage.js:150-162`、`pages/consultation/consultation.js:158-169`：`status === '待就诊' / '就诊中' / '已完成'`。
  - 契约 `business-openapi.yaml:1990`：`[PENDING, CONFIRMED, CHECKED_IN, COMPLETED, CANCELLED, NO_SHOW, EXPIRED]`。
  - 现成映射 `utils/apt-status.js:11-23` 未被这两处使用。
- **等级** `[静态]`
- **影响**：`CONFIRMED/CHECKED_IN/COMPLETED` 全部不匹配 → `step` 恒为 2、`subtitle` 为空，用户看到"有流程但一片空白"的卡片。
- **最小修复**：先 `aptStatusText(status)` 再比较，或直接比较英文枚举。

### P1-4 挂号记录重复展示（远端 + 本地缓存无去重）
- **证据**：`pages/profile/records/records.js:118-119` `remote.concat(saved)`；`pages/appointment/appointment.js:168-170` 每次提交 `unshift` 一条同内容记录。
- **等级** `[静态]`
- **影响**：同一次预约在"挂号记录"出现两条，患者误以为挂重。
- **最小修复**：按 `id`（或 `dept+date+time`）去重；或提交成功后不再写本地缓存，仅失败态兜底使用。

### P1-5 隐私合规链缺失：无官方隐私授权、同意版本号是写死的
- **证据**：全仓 `requirePrivacyAuthorize / __usePrivacyCheck__ / getPrivacySetting` **0 处**（grep 全量）；`config/env.js:55-61` 注释自认"尚无独立同意界面"，`CONSENT_VERSION='v1.0'`；`services/user.js:68-71` 每次登录直接上报该版本；症状上传前的告知是自建 `wx.showModal`（`triage.js:109-127`）。
- **等级** `[静态]`
- **影响**：审核高风险；"用户未同意却上报已同意版本"属实质合规缺陷（医疗健康数据）。
- **最小修复**：接 `wx.requirePrivacyAuthorize` + `__usePrivacyCheck__`；同意页独立，版本号由运营配置签发。

### P1-6 主包图片 882.9 KB，超"图片/音频 ≤200K"基线 4.4 倍；另有 67 个死 SVG
- **证据**：主包实测 1462.8 KB / 2048 KB（排除两分包与 tools）；主包图片 882.9 KB / 297 文件；`assets/icons/` 219 个 PNG（1347 KB 目录占用，每字形蓝/灰/白三份）；`assets/icons/*.svg` 67 个共 22.6 KB，`utils/icons.js` 只登记 219 个 PNG，SVG 在 `<image>` 中不可用且未被引用。
- **等级** `[静态]`（字节数由 `find -printf %s` 汇总）
- **影响**：首屏下载与审核"代码质量"告警；SVG 白占包体。
- **最小修复**：图标字体化（iconfont 不计入图片额度）或按需雪碧图；`packOptions.ignore` 掉 `assets/icons/*.svg`。

### P1-7 首页同时预下载两个分包
- **证据**：`app.json:31-38` `preloadRule` 对 `pages/home/home` 配了 `["packageContent","packageNav"]`；分包实测 `packageContent` 290 KB、`packageNav` 101 KB。
- **等级** `[静态]`
- **影响**：首屏进场即额外拉 ~391 KB，弱网下与首屏接口争带宽；导航页属低频功能。
- **最小修复**：只保留 `packageContent`；`packageNav` 改为点击时下载（首次进入有加载态）。

### P1-8 定时器不随页面销毁清理（退出后仍在 setData）
- **证据**：`pages/health/health.js:170-175` 创建 `stepTimer`，`onUnload`（同文件 86-89）只停语音；`clearInterval` 仅存在于成功/失败回调（191、214）——care-plan 约 100s，期间退出必泄漏。`pages/consultation/consultation.js:442` 打字机 `setInterval(30ms)`，`onUnload`（127-130）未清理。
- **等级** `[静态]`
- **影响**：`setData on unloaded page` 警告、后台 CPU 占用、返回页面后状态错乱。
- **最小修复**：两页 `onUnload`/`onHide` 统一 `clearInterval` 并把句柄置空。

### P1-9 会话失效没有全局出口：refresh 失败后仍显示"已登录"
- **证据**：`services/request.js:186-188` 刷新失败只 `session.clear()`；`app.js:73-82` 只有 `logout()` 才清 `wb_role/wb_user`；`app.js:53-60` `isLoggedIn()` 仅看 72h TTL；全仓检索无 `AUTH_EXPIRED → reLaunch` 处理（页面仅在 `onShow` 做角色守卫）。
- **等级** `[静态]`
- **影响**：access/refresh 双双失效后，页面仍呈现登录态，所有受保护请求报"登录已过期"，用户无路可走，只能杀进程重进。
- **最小修复**：request 层暴露 `onAuthExpired` 回调 → `app.logout() + reLaunch(login)`（节流一次）。

### P2-10 适老化/无障碍缺口集中
- **证据**：24 个 WXML 中 `aria-role` = 0、`aria-label` = 0、`role=` 仅 2 处；`<image>` 188 个中 180 个未写 `mode`；`bindtap` 143 处，`pressable` 仅 47 处，`hover-class` 全仓 0。
- **等级** `[静态]`
- **影响**：读屏不可用；点击无任何视觉反馈，老年用户容易"点了没反应→重复点"；未设 `mode` 的图片在异形尺寸下拉伸变形。
- **最小修复**：可点容器统一加 `.pressable`（已有全局类）；列表项/图标按钮补 `aria-role="button"` + `aria-label`；图片补 `mode="aspectFit|widthFix"`。

## 四、值得肯定的基线能力（影响评分的加分项）

- 页面层 `wx.request` 直连 **0 处**；唯一地址源 `config/env.js`，路径唯一源 `config/api.js`，无 `8001/8088` 残留。
- 401 处理是"单飞刷新 + 同幂等键重发一次"（`request.js:367-372`），并有本地前置守卫（`ensureAccessToken`），未登录不发无谓请求。
- 429 带 `Retry-After` 结构化返回；错误文案统一 `utils/err-text.js`，页面 0 处直出 `err.message`。
- 生产构建硬门禁：非 HTTPS 或临时隧道域名直接抛错（`env.js:63-70`）。
- `consultation.js:229-239` 的增量 setData + 60 条上限是全仓最佳实践；6 个列表页有 skeleton + `paginate` 首屏 20 条。
- 设计令牌集中（97 个变量），页面 wxss 与 app.wxss 同名类仅 `card-title` 1 处冲突，样式纪律优于同类项目。
