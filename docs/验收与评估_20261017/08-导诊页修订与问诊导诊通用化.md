## B. 导诊页布局调整

### B-1 三个阶段的头部

| 阶段 | 组成 | 高度目标 |
|---|---|---|
| 首屏（`messages.length <= 1`） | 导航 88 + hero **200** + 就医人 **88** + 完整进度卡 **208** | ≈ 584rpx ≈ 292px（现 ≈464px） |
| 开始对话后 | 导航 88 + 紧凑条 **64** + 就医人 **88** + 进度单行 **72** | ≈ 312rpx ≈ 156px（现 464px） |
| 键盘弹起 | 同上 + 输入条 112 + 安全区 | 对话区仍 ≥ 屏高 45% |

实现全部走**已有 data**：`wx:if="{{messages.length <= 1}}"`（hero / 完整卡）与 `wx:else`（紧凑条 / 单行），`progress.step` 已有。**零 JS 改动。**

### B-2 结果区只留一个主操作

```
┌ tri-card ─────────────────────────────
│ 常规 · 建议门诊就诊            近期内
│ 🏥 建议就诊：全科医学科
│    门诊楼 1F · 症状不典型…（2 行内）
│ 匹配度：中等（胶囊）
│ ┌ 判断依据 ──────────────
│ · 你提到了「难受」…
│ └
│ 可按门诊时间预约就诊…
│ [ 去挂号 ]  ← 满宽 88rpx，唯一实心蓝
│ 院内路线 · 完整报告  ← 第二行文字链 72rpx
│ · 本次为本地规则结果        👍 👎
└
```

- navask 卡保留（对话式追问是导诊的优点），但主按钮降为 **outline**（白底蓝框），不再与「去挂号」抢权重；同时**删除结果卡内的「院内路线」**，路线只保留 navask 这一个入口（解决 V-10）。
- 若 `navigable=false`：navask 不出现、结果卡也不显示路线 → 只剩「去挂号 + 完整报告」，与真实能力一致。

### B-3 底部三层压成两层

| 现状 | 调整 |
|---|---|
| 合规提示（两行） | 文案**逐字不动**，行高 1.5、padding 4rpx → 从 60px 压到 48px |
| 采集条 `collect-bar` | 保留，但文案随状态：`{{canReport ? '重新生成' : '生成结果'}}`；`canReport=true` 时按钮改 ghost 样式（浅底蓝字） |
| 快捷服务 `quick-services` | **移入滚动区末尾**（DOM 移动，`bindtap` 不变），不再常驻 |
| 输入条 `input-bar` | 高度改 `var(--btn-height)`，`padding:12rpx 24rpx`，`gap:12rpx` |

### B-4 输入条（与问诊页对齐）

- 三个圆/框统一 `var(--btn-height)`：88 / 108 / 128（standard / large / xlarge）。
- `.input-field` 由 `height` 改 `min-height`，`padding: 0 28rpx`。
- `.ph` 改 `var(--text-weak)`（#828CA0，≈4.6:1）。
- `<input>` 增加 `cursor-spacing="20"`（键盘不压输入框）。

## C. 问诊 ↔ 导诊 通用化规范

### C-1 迁移策略：先对齐数值，再搬文件

1. **第 1 批**把导诊页的输入条/滚动区/占位色对齐问诊页（视觉会有变化：80→88，属预期修复）。

3. 页面差异块留在各自 wxss 末尾，并以 `/* triage-only */` `/* consultation-only */` 注释标出，禁止再复制第三份。

> 先对齐再搬，是保证第 2 批「零视觉变化」的前提；顺序反了会把两套参数一起搬进共享文件。

### C-3 页面专属（不进共享文件）

| 页面 | 专属块 |
|---|---|
| 导诊 | `.emg-bar`（急诊常驻条）、`.collect-bar`、`.navask-*`、`.tg-hero`、`.user-strip`、`.slots-card`、`.ask-card`、`.tri-card` |
| 问诊 | `.nav-clear`、`.flow-minbar`（本轮导诊也要用 → 上移到共享或 app.wxss）、`.consult-side`、`.msg-replay`、`.bubble-ai` 内重播按钮 |

> `.flow-minbar` 目前只在问诊页定义。导诊要复用 → 移到 `app.wxss`（它本质是进度卡家族的一员，已在全局 `.flow-*` 里）。

### C-4 命名与覆盖顺序

- `@import` 必须写在页面 wxss **第 1 行**（与 `auth-common.wxss` 先例一致）。
- 页面专属规则写在 import 之后 → 天然覆盖共享值，不需要 `!important`。
- 新增共享类一律进 `chat-common.wxss`，**禁止**再在页面里复制同名类（`check-styles.js` 只能查"有没有定义"，查不出"定义了几次"，需人工守）。

### C-5 差异清单（允许不一致的三处）

1. 导航右侧：问诊有「清空」，导诊无。
2. 导诊有急诊常驻条，问诊没有（问诊的急诊在会话卡里）。
3. 问诊有右侧「就医助手」双栏布局，导诊永远单列。

### C-6 报告内容的单一来源（第 3 批）

`tri-card`（inline）与 `result` 页目前是两套 DOM、两套类名。建议：
- 统一前缀 `rp-*`：`rp-head / rp-badge / rp-window / rp-dept / rp-conf / rp-basis / rp-advice / rp-ops`；
- inline 版用 `.rp--inline`（紧凑、无页面头、按钮一行）；
- 报告页用 `.rp--page`（大字号、固定底栏）；
- 内容字段共用（`dept / deptFloor / deptIntro / confidenceText / reasons / alternates / levelAdvice`），**不改数据结构**。

这一步动 `result` 页，建议独立一批做，并用「同一份报告在会话内与报告页的标题/科室/依据文案逐字一致」作为验收。
