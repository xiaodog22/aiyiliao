# 模拟器「统一网关 · 未连接」根因诊断（2026-10-17 · 零代码改动）

> 结论先行：**后端是活的**（实测 `/api/gw/health` → HTTP 200）。
> 显示「未连接」是**前端在请求发出之前就把它拦下了**，外加一处响应结构漂移。
> 本轮只做检测，未修改任何代码。

---

## 一、现象

设置页 → 后端服务状态面板 → 显示：

```
统一网关   ✗ 未连接，请确认后端已启动
```

该文案唯一来源：`miniprogram/pages/profile/settings/settings.js:70`
（`gateway.health()` 的 `catch` 分支）。凡是看到这句，说明 `health()` **reject** 了。

---

## 二、证据链

### 证据 1：后端网关健康，实测 200（排除"后端没起"）

```
$ curl -s -o /dev/null -w "http=%{http_code}" http://127.0.0.1:8000/api/gw/health
http=200

{
  "code":"OK","message":"OK","requestId":"r_2a02a40aedbe4b55",
  "serverTime":"2026-10-16T16:13:17.198Z",
  "data":{
    "status":"ok",
    "upstreams":[
      {"name":"java","reachable":true,"latencyMs":17},
      {"name":"python","reachable":true,"latencyMs":9}
    ]
  }
}
```

端口实测：`127.0.0.1:8000`（网关）、`127.0.0.1:8001`（ai）、`0.0.0.0:8088`（business）全部 LISTENING。
→ **网络层、进程层、HTTP 层均正常。**

### 证据 2：后端这条路径是**匿名**的（前端却按"受保护"处理）

- `backend/edge-gateway/app/main.py:164-167` —— `/api/gw/health` 是网关自身路由，**未挂任何鉴权依赖**；
- `backend/edge-gateway/app/ratelimit.py:76` —— `EXEMPT_PATHS = {"/health", "/api/gw/health"}`，连限流都豁免（因为编排器要轮询）；
- 证据 1 的 curl **未带任何 Authorization**，仍然 200。

### 证据 3：前端在发请求之前有"会话守卫"，而白名单里没有这条路径

`miniprogram/services/request.js:355`：

```js
return requireSession(method, finalSpec).then(() => new Promise(...wx.request...))
```

`requireSession()`（125-129 行）→ 非匿名就走 `ensureAccessToken()`（106-118 行）：

```js
if (session.getAccessToken()) return Promise.resolve(true)
if (!session.getRefreshToken()) return Promise.reject(makeError('AUTH_REQUIRED', '请先登录后再操作'))
```

`ANONYMOUS` 白名单（62-82 行）共 14 条，**含 `/api/gw/tts/audio/*`，但不含 `GET /api/gw/health`**。

→ 结论：**未登录时这条请求根本不会发出去**，本地直接 reject → `settings.js` catch → 显示"未连接"。
而服务端其实是免登录的 —— **前后端匿名口径不一致**。

### 证据 4：即使登录了，解析也对不上（"假绿 + 假红"）

`settings.js:56-63` 期望的结构：

```js
{ gateway: { ok }, upstreams: { python_fastapi:{ok}, java_spring:{ok}, ollama:{ok} } }
```

网关实际返回的 `data`（见证据 1）：

```json
{ "status":"ok", "upstreams":[ {"name":"java","reachable":true}, {"name":"python","reachable":true} ] }
```

后果：
- `upstreams` 是**数组**，按对象取 `u.python_fastapi / u.java_spring / u.ollama` 全部 undefined → **3 个上游恒显示未连接**；
- `h.gateway` 不存在，`gwOk = !(undefined && ...)` = **true** → "统一网关"一旦请求成功就**恒绿**；
- 后端只上报 java / python 两个上游，**没有 ollama**，"大模型"永无数据源。

## 三、根因排序

| 级别 | 根因 | 触发条件 | 判别特征 |
|---|---|---|---|
| **主因 B** | 本地会话守卫拦截 `/api/gw/health`（不在匿名白名单） | 未登录 / 本地无 refresh token / refresh 超 7 天或刷新失败 | Network 面板**看不到** `/api/gw/health` 请求 |
| 次因 C | 响应契约漂移（数组 vs 对象、无 `gateway`、无 `ollama`） | 只要请求成功就会体现 | 有 200 响应，但 3 个上游仍红；"统一网关"反而恒绿 |
| 环境因 A | 域名校验被打开 | 开发者工具「不校验合法域名」未勾选 | 请求 failed，`errMsg` 含 `url not in domain list` |

### 关于环境因 A 的补充说明

- `miniprogram/project.config.json` 与 `miniprogram/project.private.config.json` 的 `urlCheck` **均为 false**（DEV_LOG:199 要求"开发者工具打开 `miniprogram/` 目录"）；
- 但**仓库根**的 `project.private.config.json` 是 `urlCheck: true`，而根目录没有 `app.json`（无法正常编译）。
- 因此：只要打开的是 `miniprogram/`、且没在"详情 → 本地设置"里手动勾上"校验合法域名"，A 不成立。
- 若你在界面上手动勾过，控制台会直接报 `url not in domain list` —— 一眼可辨。

## 四、三步自检（模拟器内即可确认，无需改码）

1. **Network 面板**过滤 `gw/health`
   - 无记录 → 根因 B（本地拦截，请求没发）
   - 有记录但 failed、`url not in domain list` → 根因 A
   - 有记录且 200 → 网关项应变绿；3 个上游仍红 → 根因 C
2. **Console 面板**：出现 `[global]` 前缀的日志 = 未处理 Promise 拒绝（`app.js` 的 `onUnhandledRejection` 兜底输出）。
3. **Storage 面板**：检查 `wb_*` 里是否存在 refresh token。不存在 → 处于未登录态 → 必然命中根因 B。
   可先做一次登录再回到设置页对照：若登录后网关项变绿，则 B 得到确认。
