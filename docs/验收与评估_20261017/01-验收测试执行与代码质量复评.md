## 三、问题分级与处置优先级

### D0（阻断验收，须先修）

| # | 问题 | 影响 | 定位 |
|---|---|---|---|
| D0-1 | 网关健康面板「统一网关·未连接」 | 用户可见误报；后端实测 200 | `services/request.js:62-82`（匿名白名单缺 `GET /api/gw/health`）+ `pages/profile/settings/settings.js:56-63`（响应结构漂移） |
| D0-2 | `test-nav-page` / `test-pages-paginate` 崩溃 | 两个运行时门禁失效 | 测试桩缺 `ensureSessionReady`、桩无会话 |
| D0-3 | `ProdWechatSessionProvider` 抛 `UnsupportedOperationException` | 生产登录不可用 | ai/business 生产微信会话未接入 |
| D0-4 | 隐私合规链缺失 | 微信平台审核风险 | `requirePrivacyAuthorize` / `__usePrivacyCheck__` 0 处 |

### D1（重要技术债）

1. **refresh 重放不撤销会话链**：`AuthSessionStore.rotate()` 每次 INSERT 新行、无 family 关联，与其注释「撤销该会话链」不符（实测重放后新 access 仍 200）。
2. **ai 单 worker 串行 + TaskStore 全量 JSON 重写**：并发与持久化性能瓶颈。
3. **信封三处重复实现**（网关 / business / ai）：契约变更需三处同步，是本次契约漂移的结构性诱因。
4. **VF-12 消息气泡组件未抽**：跨页重复实现，应与 03-F4 合并立项。
5. **前端 console 39 处**应按 BUILD_ENV 分档收敛。

### D2（改善项）

1. 空 `catch` 补一行注释说明「为何可忽略」，避免与"静默吞错"混淆。
2. 建立「测试桩 ↔ 产品代码导出」守卫（可复用 `check-exports` 思路），防止再次出现门禁失效窗口。

后端 328 用例与前端 4 项静态门全绿，工程底盘（分层、禁址、分包、适老化、动效纪律）保持得很好；
