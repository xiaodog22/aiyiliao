## 2. 首页

### 2.1 评分

| 维度 | 得分 | 评价 |
|---|---:|---|
| 视觉美感 | 20/25 | 蓝白体系清晰，医疗科技感较强；首屏蓝色面积稍重 |
| 信息层级 | 20/25 | 主入口明显，但「症状输入 / 四宫格 / 导诊 Banner」存在功能竞争 |
| 交互易用性 | 17/20 | 入口尺寸较大；横向症状词和部分图标语义仍不够清晰 |
| 屏幕适配 | 11/15 | 手机首屏正常；右侧 Chip 被截断，长文字及大字模式有风险 |
| 视觉一致性 | 12/15 | 圆角和蓝色基本统一，但 Hero、Banner、宫格的视觉语言略分散 |

### 2.2 改进项 1｜收敛首屏主任务，避免三个「导诊入口」同时竞争

**问题** `[截图]`
首屏同时出现三个同等级入口：Hero 内症状描述框、「AI问诊」等四宫格、「智能导诊·精准就医」Banner。症状输入框与导诊 Banner 都是强视觉元素，用户难以判断先点哪个；对老年用户直接抬高选择成本。

**修改方案**
- 将「请用一句话描述症状」确立为首页**唯一一级主入口**。
- 「智能导诊·精准就医」Banner 降为补充说明卡，取消同等级实心按钮，改为整卡点击 + 右箭头。
- 四宫格保留，但定位为快捷服务，不与主入口争视觉焦点。
- 首屏顺序统一为：问候与症状输入 → 四项快捷入口 → 导诊说明 → 常用服务。

**文件级改动**
- `pages/home/home.wxml`：保留 `hm-ask` 为主入口；`hm-banner-btn` 降级为文字 CTA 或右箭头，不改变 `goTriage`。
- `pages/home/home.wxss`：提高 `hm-ask` 的边框/阴影识别度，降低 `hm-banner` 饱和度与按钮视觉重量。
- **禁止**重新加入截图中的第二个强蓝实心导诊按钮。

### 2.3 改进项 2｜修复症状快捷词横向截断与「可滑动性不明显」

**问题** `[截图]`
最右侧快捷词被屏幕裁切，仅露出「头晕」部分文字。虽能暗示可横向滚动，但老年用户易理解为排版错误；Chip 也无明确滑动提示。

**修改方案**
- 首屏优先显示 3 个**完整** Chip，避免半个词露出。
- 横向列表末尾增加 24–32rpx 留白。
- 症状词仅 3–4 个时直接换行排列，不启用横向滚动。
- Chip 高度 ≥72rpx、字号 ≥26rpx。
- 按压态使用浅蓝底加深，不能只靠轻微缩放。

**文件级改动**
- `pages/home/home.wxml`：保留 `scroll-view`、`onQuickChip` 与数据结构。
- `pages/home/home.wxss`：`hm-quick-in` 增加右侧内边距；缩小水平 padding；`hm-chip:active` 增加明确背景态。
- 大字模式下允许 Chip 换行或减少默认展示数量，**不得压缩文字**。

### 2.4 改进项 3｜提升宫格图标辨识度与触控稳定性

**问题** `[截图]`
四个宫格标题清晰，但图标线条偏细、颜色相近，「AI问诊」与「AI养生」需依赖文字区分；卡片间隙偏窄，视觉上接近连续白色分栏。

**修改方案**
- 图标底板统一 80–88rpx，图标 40–44rpx。
- 统一线性图标体系，线宽一致。
- 仅用蓝、青、紫等低饱和辅助色；红橙装饰色不得用于普通功能。
- 点击区 ≥96rpx 高；标题 26–28rpx、600 字重。
- 卡片间距提升到 16rpx，消除边缘粘连。

**文件级改动**
- `pages/home/home.wxml`：保留 `quad` 循环、`data-key` 与 `onRoute`。
- `pages/home/home.wxss`：统一 `hm-tile`、`hm-quad-card`、`hm-quad-title` 尺寸；大字模式下隐藏或折行 `hm-quad-desc`，禁止撑破四列。
- `app.wxss`：继续使用全局 `tile-*` Token，不再造首页独立的第二套相近底色。

### 2.5 改进项 4｜降低蓝色大面积堆叠，强化卡片层级

**问题** `[截图]`
顶部导航、问候 Hero、主按钮连续使用高饱和蓝，科技感强，但医疗服务更需要稳定、可信、舒缓；连续深蓝压缩了下方白卡的呼吸感。

**修改方案**
- 顶部导航保留品牌蓝。
- Hero 改为「品牌蓝 → 浅蓝」轻微渐变，或缩小深蓝覆盖面积。
- 页面背景用 `#F4F7FC` 或当前 `#F1F8FD`。
- 普通卡片统一白底 + 极弱阴影或 1rpx 边框，避免同时叠加明显阴影与大圆角。
- 单页最多保留**一个**高饱和主按钮。

**文件级改动**
- `pages/home/home.wxss`：收敛 `hm-hero`、`hm-banner` 视觉重量，不新增发光或装饰渐变。
- `app.wxss`：全局卡片阴影维持 `0 2rpx 12rpx rgba(11,110,248,.06)` 级别，不得加重。
- 保留当前蓝白体系，**不改为绿色医疗主题**。

### 2.6 改进项 5｜控制首屏信息量，处理底部导航遮挡

**问题** `[截图]`
一个手机首屏内塞入 Hero、四宫格、导诊 Banner 和常用服务开头，密度偏高；TabBar 固定后常用服务下半部分被遮挡，用户易误判内容已结束。

**修改方案**
- 模块间距稳定在 20–24rpx，不靠压缩卡片高度塞内容。
- 页面底部预留 `TabBar 高度 + safe-area`。
- 常用服务保持 4 列，单项标题最多两行。
- 不要求首屏展示全部服务，允许自然滚动。
- 平板横屏沿用双栏策略，手机端保持单列。

**文件级改动**
- `pages/home/home.wxss`：页尾增加安全区留白；核查 `home-wave` 与自定义 TabBar 是否叠加。
- `app.wxss`：底部安全区统一维护，禁止多页重复硬编码高度。
- 保留 `pages/home/home.wxml` 中预约、健康提示、导航、科普模块的数据与跳转。

### 2.7 首页推荐规范

| 项 | 规范 |
|---|---|
| 字体 | 系统字体，苹方/微软雅黑回退；主标题 36rpx，区块标题 30–32rpx，正文 28rpx，辅助 ≥24rpx |
| 主色 | `#0B6EF8`；按下 `#0A5AD8`；浅蓝底 `#EAF3FF`；页底 `#F1F8FD` |
| 正文色 | 建议接近 `#17223B`；`#00024E` 用于标题，不宜全文偏蓝 |
| 圆角 | 主卡 24rpx；输入框 20rpx；普通按钮 16–20rpx；Chip 胶囊圆角 |
| 间距 | 页边距 28–32rpx；卡内 24–32rpx；模块间 20–24rpx |
| 触控 | 最低 88rpx × 88rpx |

### 2.8 首页必须保持不变

- 症状输入、快捷症状、四宫格、导诊 Banner 均继续进入真实导诊流程。
- `onRoute`、`goTriage`、`onQuickChip` 等事件与数据键不变。
- 不删除预约、健康提示、院内导航、健康科普功能。
- 不改变真实数据、空态与不可用状态的判断逻辑。
- 保留适老、大字、高对比能力。

## 3. 智能导诊页

### 3.1 评分

| 维度 | 得分 | 评价 |
|---|---:|---|
| 视觉美感 | 19/25 | 蓝白卡片体系稳定，但顶部蓝色偏重、内容略模板化 |
| 信息层级 | 21/25 | 就医人、症状描述、安全筛查顺序合理 |
| 交互易用性 | 17/20 | 表单问题直接；「切换」与安全筛查状态需更强可点击提示 |
| 屏幕适配 | 10/15 | 文本域占屏较高，下方问题易被截断；大字模式风险高 |
| 视觉一致性 | 10/15 | 截图表单式、代码对话式，两套交互架构不一致 |

### 3.2 改进项 1｜先解决「表单式截图 vs 对话式代码」的架构冲突

**问题** `[截图+代码]`
截图是结构化表单流程（就医人 → 症状描述 → 安全筛查 → 逐段填写）；当前 `pages/triage/triage.wxml` 是完整对话流（消息气泡、多轮补问、快捷服务、底部输入栏、实时结果卡）。这不是样式差异，而是核心交互模式不同。

**修改方案**
建议**保留当前对话式导诊**（更契合「一句话描述症状」与语音输入方向），吸收表单式的优点：
- 就医人固定展示在对话开头；
- 安全筛查设计为一题一卡的多轮补问；
- 固定采集栏显示已理解症状，可点击修改，而不是重复回答全部问题；
- 不再额外维护一套完整表单页面。

**文件级改动**
- `pages/triage/triage.wxml`：保留现有 `messages`、`ask`、`slots`、`triage` 类型与底部输入逻辑；**不要**照截图另建并列静态表单。
- `pages/triage/triage.wxss`：以 `ask-card`、`slots-card` 作为结构化采集的视觉承载。
- 若产品明确要求回到表单式，须**单独重构交互状态机**，不得只改 WXSS 模拟截图。

### 3.3 改进项 2｜缩减顶部占用，进页即可见可操作区

**问题** `[截图+代码]`
截图中导航 + 蓝色 Hero 约占屏幕 1/4，之后还有就医人卡，真正要填的「症状描述」出现在页面中段。当前代码还额外含 Hero、就医进度卡、用户信息条，首屏占用可能更高。

**修改方案**
- Hero 高度控制在 160–200rpx。
- 用户开始输入或发送首条消息后，Hero 折叠为紧凑标题栏。
- 「就医进度」若非本次导诊必需，折叠或移至「我的」；不长期占据首屏。
- 用户信息条保持一行，不展示不必要的完整证件掩码说明。
- 首屏必须露出第一条提问或输入框。

**文件级改动**
- `pages/triage/triage.wxml`：可按 `messages.length` 或流程状态切换紧凑 Hero，不改变消息与结果数据。
- `pages/triage/triage.wxss`：压缩 `tg-hero` 高度与上下间距，为紧凑态增加独立类。
- `flow-card` 若保留应默认折叠，继续沿用 `app.wxss` 的唯一实现。

### 3.4 改进项 3｜强化「就医人切换」的可点击性与隐私表达

**问题** `[截图]`
「切换」只有文字，无边界与箭头，易被当作状态文字；姓名、性别、年龄、证件掩码同时展示，信息密度偏高。

**修改方案**
- 文案改为「切换就医人 ›」，而非单独「切换」。
- 点击区 ≥88rpx，整行右侧均可点。
- 默认只展示「姓名 · 性别 · 年龄」；证件掩码作为次级信息按业务需要隐藏。
- 切换后给出明确反馈，并同步重置或提示已有症状是否保留。
- 不单靠蓝色表达可点击，须同时保留箭头与按压态。

**文件级改动**
- `pages/triage/triage.wxml`：保留 `onSwitchUser`，改可见文案并扩大绑定区域。
- `pages/triage/triage.wxss`：`user-switch` 设最小高度、水平内边距、圆角与按压背景。
- 不改变脱敏数据来源与身份切换逻辑。

### 3.5 改进项 4｜安全筛查突出「问题 / 解释 / 答案」三层关系

**问题** `[截图]`
「是否出现呕血或黑便？」与解释文字、右侧「否」距离过大，答案更像普通文字而非控件；连续问题仅靠细线区分，老年模式辨识度不足。

**修改方案**
- 每题独立行或独立卡片。
- 主问题 28–30rpx、600 字重。
- 解释文字 24rpx，颜色不浅于 `#5064A0`。
- 「是/否/不确定」用明确分段按钮或大号 Chip，选中态同时使用图标 + 边框 + 底色。
- 红旗问题选中「是」后立即显示红色警告与拨打 120 入口；普通未选态不得使用红色装饰。

**文件级改动**
- `pages/triage/triage.wxml`：继续复用 `ask-card` 与 `ask-opt`，后端选项不变。
- `pages/triage/triage.wxss`：`ask-opt` 最小高度由 64rpx 提升到 ≥80–88rpx，补充选中态与焦点态。
- 保留现有 `emergency` 常驻条、`onCall120` 与红旗结果逻辑。

### 3.6 改进项 5｜固定输入区减负，兼容键盘与安全区

**问题** `[代码]`
底部同时存在合规说明、症状采集栏、四个快捷服务、输入栏。固定区叠加后可能占用较大屏幕高度，在键盘弹出、大字模式或小屏设备上会明显压缩对话区。

**修改方案**
- 导诊主任务期间只固定输入栏与必要急诊提示。
- 快捷服务默认折叠为「更多服务」。
- 合规说明放在对话首条提示或输入栏上方一行，不重复长期占高。
- `collect-bar` 仅有内容时显示，并允许点击展开，不展示完整长文本。
- 输入栏适配 `safe-area-inset-bottom` 与键盘高度。

**文件级改动**
- `pages/triage/triage.wxml`：四个快捷服务收为单个「服务」入口，保留原事件；`collect-bar` 维持条件渲染。
- `pages/triage/triage.wxss`：限制固定栏总高度，`collect-text` 单行省略；输入框与语音按钮保持 ≥80–88rpx。
- 不删除语音输入、文字输入、快捷服务与生成结果能力。

### 3.7 导诊页推荐规范

| 项 | 规范 |
|---|---|
| 字号 | Hero 标题 40–44rpx；页面标题 34–36rpx；问题正文 28–30rpx；说明 ≥24rpx |
| 主色 | `#0B6EF8`；内容背景白 + 极淡蓝 |
| 急诊色 | `#F53F3F`，仅用于真实紧急状态 |
| 圆角 | 卡片 20–24rpx；输入框与快捷选项可用胶囊形 |
| 间距 | 页边距 24–28rpx；问题卡间 20–24rpx；卡内 24rpx |
| 输入区 | 多行输入最小高度约 180rpx（避免截图中近 230rpx 过高文本框挤压后续问题） |

### 3.8 导诊页必须保持不变

- 真实语音识别、文本输入、多轮补问、结构化症状采集与导诊分析。
- 急诊红旗检测、拨打 120、前往急诊区。
- 切换就医人、生成结果、挂号、院内路线、完整报告入口。
- AI 医疗免责声明。
- 后端接口字段、状态机、错误/本地规则降级逻辑。

### 4.1 评分

|---|---:|---|
| 视觉美感 | 21/25 | 报告 Hero 与白卡组合成熟，专业感较强 |
| 信息层级 | 22/25 | 推荐科室、判断依据、症状回顾顺序清楚 |
| 交互易用性 | 17/20 | 挂号与路线入口明显；风险时限不够突出 |
| 屏幕适配 | 11/15 | 长报告依赖滚动；长科室名、大字、按钮并排存在风险 |
| 视觉一致性 | 12/15 | 截图结构统一，但与当前 WXML 首屏结构不一致 |

### 4.2 改进项 1｜首屏先回答「紧不紧急、多久就医」

**问题** `[截图+代码]`
截图最醒目的是「建议就诊：消化内科」，而风险等级与建议时限只是小字「建议 2 天内就诊」。医疗导诊报告的第一任务不是报科室，而是先说明是否需要立即处理。当前代码已有独立 `rk-card`，但截图未体现该层级。

**修改方案**
首屏顺序统一为：
1. 风险等级
2. 建议就医时限
3. 一句话行动建议
4. 推荐科室
5. 挂号与路线

普通情况可用蓝/橙状态；紧急情况必须在推荐科室**之前**展示红色预警。

**文件级改动**
- `pages/triage/result/result.wxml`：保留现有 `rk-card` 置顶，不得为复刻截图而删除。
- `pages/triage/result/result.wxss`：提高 `rk-window` 与 `rk-advice` 可见性，使建议时限成为首屏主要信息。
- 若增加报告 Hero，风险等级与时限应放入 Hero，而不是再加一个纯装饰蓝色标题卡。

### 4.3 改进项 2｜删除重复结论，避免头部与推荐卡重复表达

**问题** `[截图]`
Hero 已显示「建议就诊：消化内科」，紧随其后的「推荐科室」卡再次显示「消化内科」。重复占用首屏空间，也易让用户误认为两个不同结论。

**修改方案（二选一）**
- **推荐**：Hero 只显示「导诊报告 + 风险时限」，科室详情交回推荐科室卡；
- 或：Hero 显示科室结论，下方卡片改名为「挂号与院内路线」，不再重复科室标题。

**文件级改动**
- `pages/triage/result/result.wxml`：如新增 Hero，不得重复渲染 `r.dept`；`dept-card` 为唯一科室详情源。
- `pages/triage/result/result.wxss`：不增加与 `rk-card`、`dept-card` 重叠的第二套卡片样式。
- 推荐科室、楼层、匹配度、相关科室等字段保持条件渲染。

### 4.4 改进项 3｜「判断依据」改为结构化证据，而非普通项目符号

**问题** `[截图]`
依据使用黑色圆点列表，虽清晰，但「症状持续时间 / 夜间加重 / 无急诊信号」属不同类型信息，同一文本样式降低扫描效率。

**修改方案**
- 依据拆为短标签或图标文本：主要症状 / 持续时间 / 加重因素 / 急诊信号。
- 每项一行，左侧使用检查或信息图标。
- 「未发现急诊信号」必须注明「基于当前描述」，避免过度确定。
- 长文本左对齐，行高 1.6–1.7。
- **不增加**百分比、评分等后端未返回的虚构指标。

**文件级改动**
- `pages/triage/result/result.wxml`：保留 `r.reasons` 循环，可增加统一图标或序号，不改变数据内容。
- `pages/triage/result/result.wxss`：增强 `dept-basis-item` 行间距与项目间距，使用 `flex` 对齐图标与文字。
- 不得依据前端猜测把依据改写成新的医学结论。

### 4.5 改进项 4｜主次按钮层级正确，但需处理长文案与单按钮场景

**问题** `[截图+代码]`
「预约挂号」实心主按钮 + 「查看路线」描边按钮层级正确。但当前代码只有 `r.navigable` 为真才显示路线；单按钮时若仍占半宽会显得不完整，大字模式下并排文字也可能拥挤。

**修改方案**
- 双按钮并存：各占一半。
- 仅挂号按钮：自动占满整行。
- 大字/超大字模式：允许上下排列。
- 按钮高度 ≥88rpx，间距 16rpx。
- 「去挂号」统一为更明确的「预约挂号」。

**文件级改动**
- `pages/triage/result/result.wxml`：保持 `onDeptBook`、`onNav` 与条件判断，仅统一可见文案。
- `pages/triage/result/result.wxss`：`dept-ops` 增加单按钮满宽规则；大字主题切换纵向排列。
- 不改变路线不可用时的真实提示。

### 4.6 改进项 5｜长报告增加导航锚点与底部行动闭环

**问题** `[截图]`
截图仅展示到「建议下一步」开头，完整报告还含症状回顾、下一步、重新分析、隐私说明等。长页面滚动后用户会失去最重要的行动入口。

**修改方案**
- 顶部增加紧凑目录/状态摘要：「风险 / 科室 / 依据 / 下一步」。
- 底部再次提供主行动，但只保留一个主按钮，如「预约消化内科」。
- 「补充症状，重新分析」作为次级文字按钮。
- 隐私与免责说明保持弱视觉，但字号 ≥24rpx。
- 不使用悬浮发光按钮；若采用底部固定操作栏，必须处理安全区与内容遮挡。

**文件级改动**
- `pages/triage/result/result.wxml`：可在 `law-card` 前补底部行动区，保留 `onRetry`、`onDeptBook`。
- `pages/triage/result/result.wxss`：页尾增加安全区留白，确保操作区不遮盖隐私说明。
- 不删除语音播报、清除本机记录、隐私说明与空报告状态。

### 4.7 报告页推荐规范

| 项 | 规范 |
|---|---|
| 字号 | 主标题 36–40rpx；风险时限 30–34rpx/700；科室名 40–44rpx；正文 28rpx；辅助 ≥24rpx |
| 语义色 | 普通 `#0B6EF8`；提醒 `#FF7D00`；紧急 `#F53F3F` |
| 底色 | 页底 `#F1F8FD`；内容卡 `#FFFFFF`；分组浅底 `#F5F8FC` 或全局背景色 |
| 圆角 | 主卡 24rpx；次级内嵌块 12–16rpx |
| 间距 | 卡片间 20–24rpx；卡内 28–32rpx |
| 阴影 | 保持极弱；层级主要依赖间距、标题与背景分组 |

### 4.8 报告页必须保持不变

- 风险等级、建议时限、急诊红旗、拨打 120。
- 推荐科室、备选科室、挂号、院内路线。
- 症状结构化回顾与用户原始描述。
- 语音播报、重新分析、隐私说明、删除本机记录。
- 「导诊结果仅供参考，不构成诊疗意见」等合规语义。
- 不展示后端未返回的科室匹配度、诊断结果或治疗方案。

## 6. 交给代码 Agent 的执行边界

1. **先确认架构**：以当前代码的「对话式导诊」为最终形态，不得按截图直接改成另一套表单状态机。
2. **优先级**：信息层级 > 触控尺寸 > 首屏占用 > 大字适配 > 底部安全区。
3. **复用 Token**：沿用 `app.wxss` 现有颜色、字号、圆角、卡片变量，不新建第三套视觉系统。
4. **不动逻辑**：接口、数据字段、页面跳转、急诊逻辑、语音能力、医疗合规文案语义均不修改。
5. **验收前提**：改动完成后必须重新取得**当前代码版本**的真实截图，方可完成视觉验收。
