## 三、近期工作交接（2026-10 下旬）

### 3.1 2026-10-24：AI 问诊接真实后端模型（重要里程碑）

**用户反馈**：AI 问诊没接后端 AI，用的是关键词匹配；后端应先收集信息、信息达标后再输出科室 + 置信度。

**实测定位 5 个根因（全部实测确认）**：

1. 前端调的是**不存在的端点** `POST /api/v1/case/recommend-department` → 一直降级本地关键词引擎；
2. **CHAT 任务没有多轮上下文**（inputInline 只传当句，模型看不到前文）→ 7B 只回「全科医学科」；
3. **AI 回复从不落库**（assistant 消息缺失）→ 下轮上下文缺 AI 的话、重复追问；
4. **分诊结果落库时被丢弃**（`UpstreamTaskResult` 未建模 `recommendedDepartments`）→ 分诊卡永远出不来；
5. **citations 非空即 502**（`UpstreamCitation` 缺 `@JsonIgnoreProperties`，上游新字段导致严格反序列化失败）。

**修复内容**：
- 后端：`chatContext()` 拼最近 12 条（≤3000 字）作 CHAT 上下文；`materializeChatReply()` 把 SUCCEEDED 的 CHAT 结果物化为 assistant 消息（幂等，客户端无法伪造）；新增 `POST /api/v1/consultations/{id}/triage`（聚合患者发言 ≤1000 字建 TRIAGE 任务，60s 防抖）；`UpstreamTaskResult` 补 `recommendedDepartments`；ai-service 导诊白名单 6→16 科室、prompt 升级（triage-supplement-v2 / consultation-chat-v5）、`AI_TRIAGE_TIMEOUT_SECONDS=180`。
- 前端：`pages/consultation` 走真实会话（首条 `POST /consultations`，后续 `POST /messages`）→ 轮询任务 → 打字机；第 2 轮起触发 TRIAGE；置信度 ≥0.7 且非兜底科室才出分诊卡。

**实测（qwen2.5:7b / CPU）**：嗓子疼→耳鼻喉科 0.8；胃胀反酸→消化内科 0.9；胸闷心慌→心血管内科 0.8；膝疼→骨科 0.8。多轮对话不复读、消息流完整落库。

**验证**：business-service 新增 `AiConsultOrchestrationTest` + `UpstreamTaskParseTest` 全绿；ai-service pytest 207 passed；前端 check 全绿；端到端（8089 header 模式）实测打通后实例关闭。

### 3.2 2026-10-24：医生工作站「结束问诊」+ 输入法只顶输入栏

- 后端新增 `POST /api/v1/doctor/consultations/{id}/close`（Idempotency-Key 必填；非本人/不存在 404、已结束 409、缺键 400；条件写 `WHERE id=? AND doctor_id=? AND status='ACTIVE'` 防并发双结束）；`requireWritable()` 挂到 send/confirm/草稿/推荐（ACTIVE 才可写）；系统提示「医生已结束本次问诊…」+ 患者消息通知。
- 医生端「结束」按钮二次确认（红字 `#D93025`）；已结束态：导航灰字、患者卡 chip、输入栏换只读条；患者端同步终态 + 停轮询。
- 输入法适配：两页 `adjust-position=false` + `bindkeyboardheightchange` 取高度，医生端 padding-bottom / 患者端 translateY 占位，键盘态去 safe-area 内边距。
- 附带修复：`var(--danger)` 不存在 → `var(--danger-text)`；`findDoctorUserId` 对 `user_id IS NULL` 医生抛 NPE → 过滤。
- 验证：14/14 测试通过；8089 真实 MySQL 实测（close 200 / 患者再发 409 / 未绑定医生 404 不再 500）。
