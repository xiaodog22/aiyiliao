## 3. `videoSrc` 解析逻辑

```js
// 首屏（onLoad）：先用包内源，保证秒开
videoSrc  = it.video || ''      // /packageContent/videos/wash-hands.mp4
posterSrc = it.cover || ''

// 异步拿到服务端详情后（仅 type === 'video' 才请求）
const src = userService.resolveAttachmentUrl(a.videoUrl)
//  ├─ a.videoUrl 为 undefined → String(undefined || '') = '' → 函数返回 '' → 不改 src（保持包内）
//  ├─ 为 '/api/v1/attachments/xxx.mp4?...' → ENV.gateway + 该路径 → 绝对 HTTPS
//  └─ 已是 http(s):// → 原样返回
if (src) setData({ 'item.videoSrc': src, videoUrl: a.videoUrl })

// poster 同一条规则
posterSrc = userService.resolveAttachmentUrl(a.coverUrl) || localCover
```

**为什么复用 `resolveAttachmentUrl`**：它的规则正是「空→`''`、绝对→原样、站内相对→拼网关」，
与视频需求完全一致；新造 `resolveRemote` 只会多一份需要同步维护的解析逻辑。
`String(undefined || '')` 保证了 `undefined` 走空值分支，**不会拼出 `ENV.gateway + undefined`**。

## 4. `onVideoError` 重试 / 回退流程

```
播放失败
  │
  ├─ videoRetried == false 且 有远端 videoUrl
  │     → videoRetried = true
  │     → 重新 GET /health-articles/{id} 拿新 videoUrl
  │         ├─ 新 URL 与旧**相同**  → _fallbackLocal()（再试也没意义）
  │         ├─ 拿到新 URL（不同）  → setData(src=新)
  │         │      └─ 若再失败 → videoRetried 已 true → _fallbackLocal()
  │         └─ 请求失败/404        → _fallbackLocal()
  │
  └─ 其它情况（已重试过 / 本来就没有远端 URL）
        → _fallbackLocal()
              ├─ 当前 src 不是本地 → setData(src=localVideo)（重新加载）
              └─ 当前 src 已是本地 → setData({videoErr:true})  ← **不再改 src**
```

**为什么不会死循环**：`_fallbackLocal()` 的第二分支只置 `videoErr`、不动 `src`，
不会再触发一次 `binderror`。而第一次回退时 `videoRetried` 已被置 true，
即使本地源再失败也只会走到"置文案"这一支。

### 5.4 「过期换新」怎么验（不用等 2 小时）

临时把视频 TTL 调短，制造"拖动时已过期"：

```bash
# 1) 停服务，用 5 秒 TTL 启动（仅验证用，验完改回）
export APP_ATTACHMENT_VIDEO_TTL_SECONDS=5
# 2) 重进 wash-hands 详情 → 播放 → 等 6 秒 → 拖动进度条
# 3) 期望：拖动触发 403 → onVideoError → 重拉详情换新 URL → 继续可播
# 4) 验完恢复默认（7200），重启
```
