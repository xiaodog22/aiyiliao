## 四、医生-患者挂号数据互通设计（本轮核心）

```text
患者端（dev-user-1）                      business-service                     医生端（dev-user-2）
─────────────────────                  ─────────────────                    ─────────────────
选科室/医生/号源
POST /api/v1/appointments ───────────▶ appointments 行（doctor_id=doc-gastro-1）
  （Idempotency-Key，原子扣号）          · status=PENDING                      GET /api/v1/doctor/appointments
                                         · messages+1「挂号成功」────────────▶  （列表见该医生全部挂号）
                                                                              POST .../status
                                                                                CONFIRMED/CHECKED_IN ──▶ status 流转 + version+1
                                                                                （乐观锁+幂等键+事件落表）   · messages+1「医生已叫号」
患者看状态：
GET /api/v1/appointments/me ───────────▶ status=CHECKED_IN（就诊中）
GET /api/v1/messages ─────────────────▶ 叫号通知（未读→已读）
```

**互通要点**：
1. **同一张 appointments 表**：患者下单带 slotId → 服务端解析 doctor_id；医生列表按 `doctor_id` 范围裁剪（SQL 条件内，不接受客户端传范围）——两端天然同一份数据；
2. **医生回应 = 状态流转**：`POST /api/v1/doctor/appointments/{id}/status`（CONFIRMED 接诊 / CHECKED_IN 叫号 / COMPLETED 完成），状态机 409 保护 + expectedVersion 乐观锁 + 幂等键重放 + 事件表审计；
3. **患者感知医生回应**：状态经 `/appointments/me` 实时可见；每次流转给患者写一条 messages 通知（消息中心 + 未读红点数据源）；
4. **号源闭环**：患者取消 → 号源原子回补（B3），避免"取消后号源被永久占用"的互通缺陷；
5. **脱敏边界**：医生端可见患者脱敏手机号（`patientPhoneMasked`）与头像；患者 symptomSummary 仅本人/授权人可见（既有契约约束不变）。
