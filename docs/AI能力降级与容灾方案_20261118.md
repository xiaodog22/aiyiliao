# AI 能力降级与容灾方案（2026-11-18）

> 范围：LLM（Ollama / DeepSeek）、ASR（FunASR）、TTS（edge-tts）、RAG（Redis/Qdrant）、知识库注入、AI 任务编排与前端语音链路。
> 目标：任何一级依赖失效时，**核心就医路径（导诊 → 科室 → 挂号 → 导航）不中断**；语音能力可降级；医疗安全结论**不降级生成**。
> 本文只做设计与事实盘点，**未改任何代码**。

---

## 0. 结论摘要

1. **LLM 不是单点**：已有 `Ollama → DeepSeek → 业务规则/前端本地规则` 链，TRIAGE 最完整；但 **CHAT / CARE_PLAN / INTERPRET 没有第三级内容兜底**，两级都失败时只剩错误码。
2. **ASR 是单点**：只有本地 FunASR 一级，且 `locale` 传到 ai-service 后被忽略；权重缺失/异常/超时 → 直接 503，语音输入全失。**按确认不接本地方言模型、不接云端 ASR，降级只做 `L1 本地 FunASR → L4 微信同声传译 → L5 文字/人工`。**
3. **TTS 是单点且本地引擎未接回**：现网只有 edge-tts 一级；**Qwen3-TTS 只剩历史实现，适配器已移除**（env/README 明确写「需另接适配器」）。edge 虽支持 3 个 zh-HK 音色，但业务目录只有 2 个普通话音色、`resolve_voice()` 不看 `locale`，粤语实际未接线。
4. **预算串行叠加会击穿上层超时**：TRIAGE `180+15=195 > 前端 180`、CARE_PLAN `150+45=195 > await 165`、INTERPRET `45+35=80 > await 60`。加降级级之前必须先改「共享截止时间」，否则降级越全、超时越多。
5. **当前实测（2026-11-18 10:30）**：Ollama 在线且 3 个模型在位，但 ai-service / business / gateway **三端口全部连接被拒**——此刻系统正处于「AI 全不可用」状态，正好说明降级不是纸面设计。
6. **P0 先做四件事**：① 总开关框架（`AI_DEGRADE_ENABLED`：全链路/仅本地，外部供应商全部否决）；② TTS 链改造 + 粤语音色接线 + `locale` 路由；③ 预算共享截止；④ CHAT 兜底话术。Qwen3-TTS 适配器接回单列 P0-b。

## 2. 降级设计原则（硬规则）

1. **能力级降级，不是服务级宕机**：依赖不可用 → 能力 `unavailable/degraded`，服务继续接收请求。
2. **安全不降级**：急症红旗、药物剂量、报告结论、诊断断言，**只能由规则或医生给**；降级路径只能「少说/不说/转人工」。
3. **不撒谎**：`engine / degraded / modelId / cached` 如实返回；不播占位音、不伪造转写、不编造引用、不空 200。
4. **总预算内降级**：给链传「共享截止时间（deadline）」，每级用 `min(本级预算, 剩余时间)`；剩余 ≤ 0 直接进下一级或兜底。
5. **总开关 + 分级开关**：`AI_DEGRADE_ENABLED` 控制「全链路 / 仅本地」；其下再分能力、分供应商；任一层关闭即跳过，**不得暗中回退**。
6. **用户可见一句人话**：降级必须让用户知道（「本次为本地规则结果」「语音识别暂不可用，请改用文字」），文案走 `err-text.js` 口径。
7. **隐私先于便利**：不引入第三方云 ASR；WechatSI 属微信平台能力，仍需告知；edge/WechatSI TTS 开启前必须完成告知与开关，且只走境内节点。

## 2.5 统一降级开关（总开关 + 分能力 + 分供应商）

### 2.5.1 语义

| 总开关 | 模式 | 允许 | 否决 |
|---|---|---|---|
| `AI_DEGRADE_ENABLED=true` | **全链路（full）** | 本地组件 + 已开启的云端/端侧供应商，按各链顺序降级 | 被能力级/供应商级开关显式关闭的项 |
| `AI_DEGRADE_ENABLED=false` | **仅本地（local）** | Ollama、FunASR、Qwen3-TTS（本地）、预生成产物、本机缓存、本地知识库、规则/模板 | **所有外部供应商一律硬否决**：DeepSeek、edge-tts、Azure、腾讯/讯飞/火山、WechatSI、外部 embedding 等 |

> **默认 false（仅本地）** 是合规优先：没有任何外部请求。需要云兜底时显式置 `AI_DEGRADE_ENABLED=true`；互联网演示环境可在 `env.local` 打开，院内内网保持 false。
> 总开关只控制「外部供应商是否允许」，本地 Ollama / FunASR / Qwen3-TTS 不受它否决。

### 2.5.2 开关表

| 开关 | 默认 | 作用域 | 说明 |
|---|---|---|---|
| `AI_DEGRADE_ENABLED` | `false` | 全局 | 总开关；false = 仅本地，true = 全链路 |
| `AI_DEGRADE_LLM_ENABLED` | 跟随总开关 | 能力 | LLM 是否允许降级到云端 |
| `AI_DEGRADE_ASR_ENABLED` | 跟随总开关 | 能力 | ASR 是否允许端侧 WechatSI |
| `AI_DEGRADE_TTS_ENABLED` | 跟随总开关 | 能力 | TTS 是否允许 edge / WechatSI |
| `AI_DEGRADE_RAG_ENABLED` | 跟随总开关 | 能力 | RAG 是否允许云端 embedding/检索 |
| `AI_PROVIDER_DEEPSEEK_ENABLED` | `true` | 供应商 | DeepSeek 云端 LLM |
| `AI_TTS_QWEN3_ENABLED` | `true` | 供应商（本地） | 本地 Qwen3-TTS |
| `AI_TTS_EDGE_ENABLED` | `true` | 供应商（外部） | edge-tts（微软朗读） |
| `AI_WECHAT_SI_ENABLED` | `true` | 供应商（外部） | 微信同声传译 ASR/TTS |
| `AI_ASR_CLOUD_ENABLED` | `false` | 供应商（外部） | 云端 ASR；本方案**不启用**，保留位 |

### 2.5.3 生效规则（硬编码，不靠调用方自觉）

```text
effective(provider) =
    AI_DEGRADE_ENABLED
    AND capability_switch(provider.capability)
    AND provider_switch(provider)

local_only 模式下，provider.location == "external" → 一律 false
```

- 配置加载时做一次「否决预计算」：被总开关否决的外部供应商，**直接标记 `denied_by_switch`**，不建连、不重试、不探测。
- 启动日志各打一行：`provider=deepseek location=external enabled=false reason=master_off`；禁止把密钥打出来。
- 请求级响应只暴露 `degradeMode=full|local` 与 `degraded=true|false`，不暴露供应商清单与开关细节。
- readiness 必须区分：`local_ok` 与 `fallback_ok`；总开关关时 `fallback_ok=false`，但核心流程仍可走本地。

### 2.5.4 关闭总开关后的实际形态

| 能力 | full（全链路） | local（仅本地） |
|---|---|---|
| LLM | Ollama → DeepSeek → 规则/模板 | Ollama → 规则/模板（DeepSeek 否决） |
| ASR | FunASR → WechatSI → 文字 | FunASR → 文字（WechatSI 否决） |
| TTS | 预生成 → Qwen3-TTS → edge → WechatSI → 文字 | 预生成 → Qwen3-TTS → 文字（edge/WechatSI 否决） |
| RAG | 本地/云端 embedding → 关键词 → 空引用 | 本地 embedding → 关键词 → 空引用 |
| 缓存/知识库/规则 | 保留 | 保留 |

> **操作提醒**：现网 `AI_TTS_ENGINE=edge`。若把总开关设为 false 且本地 Qwen3-TTS 未部署，TTS 只剩「预生成固定话术 + 文字」，这是预期行为，不是故障。

### 2.5.5 开关 ↔ 降级级对照

| 能力 | 降级级 | 开关 | 关闭后行为 |
|---|---|---|---|
| LLM | DeepSeek | `AI_PROVIDER_DEEPSEEK_ENABLED` | 跳过 L2，直接规则/模板 |
| LLM | CHAT 模板 | `AI_DEGRADE_CHAT_TEMPLATE` | 不回模板，返回稳定错误码 + 转人工 |
| LLM | CARE_PLAN 模板 | `AI_DEGRADE_CAREPLAN_TEMPLATE` | 同上 |
| ASR | WechatSI | `AI_WECHAT_SI_ENABLED` | 失败直接文字 |
| TTS | 本地 Qwen3-TTS | `AI_TTS_QWEN3_ENABLED` | 跳过 L1 |
| TTS | edge-tts | `AI_TTS_EDGE_ENABLED` | 跳过 L2 |
| TTS | WechatSI | `AI_WECHAT_SI_ENABLED` | 跳过 L4 |
| RAG | 关键词检索 | `AI_RAG_KEYWORD_FALLBACK` | 检索失败直接空引用 |
| 全部 | 预生成 / 文字 / 本地规则 | **无开关（常开）** | 不允许关：这是安全兜底 |

## 3. 统一预算设计（替代现网叠加）

| 任务 | 总预算 | L1 | L2 | L3 | 余量 |
|---|---|---|---|---|---|
| TRIAGE | 180s（前端轮询） | Ollama 150s | DeepSeek 20s | 规则（0s） | 10s |
| CHAT | 90s（前端） | Ollama 30s | DeepSeek 20s | 模板（0s） | 40s |
| CARE_PLAN | 165s（business await） | Ollama 105s | DeepSeek 45s | 模板（0s） | 15s |
| INTERPRET | 60s（business await） | Ollama 30s | DeepSeek 25s | 安全停答（0s） | 5s |
| ASR | 60s（business await） | 本地 FunASR 20s（失败即返回） | WechatSI 端侧（客户端） | 人工（0s） | 40s |
| TTS | 60s（business/ai 同口径） | 本地 Qwen3-TTS 35s（L0 预生成 0s） | edge 12s | WechatSI 端侧 5s | 8s |

实现要点：

- `providers/chain.py#generate` 增加 `total_budget_s` 或 `deadline_at`，每级 `timeout = min(level_budget, remaining)`；**不要只改各 `AI_*_TIMEOUT` 数值**，那仍然会叠加。
- business 侧 `AiTaskService.await` 的预算不变；ai-service 总预算 ≤ await − 5s 余量。
- `AI_ASR_TIMEOUT_SECONDS` 由 60 调到 **25**（本地 20s 失败即返回，给客户端留 35s 切 WechatSI）。
- TTS 建议：business `voice.tts.task-budget-seconds` 30 → 60；ai-service `AI_TTS_TIMEOUT_SECONDS` 30 → 55；前端 `ttsTimeout` 已 120s，不动。

## 4. LLM（AI 分析）降级链

### 4.1 链路图

```text
TRIAGE      : 前端本地规则(红旗,0ms) → 缓存 → Ollama 7B → DeepSeek(仅 full) → 业务规则/前端本地 → 结果卡
CHAT        : 缓存 → Ollama(profile) → DeepSeek(仅 full) → 固定安全话术 → 转人工/留言
CARE_PLAN   : 缓存 → Ollama 7B → DeepSeek(仅 full) → 结构化模板 → 医生随访
INTERPRET   : 缓存 → Ollama → DeepSeek(仅 full) → 安全停答(原文+参考区间) → 人工
```

> `local` 模式下 DeepSeek **一票否决**：Ollama 之后直接进 L3 规则/模板/安全停答，不建连、不重试。

### 4.2 分任务策略

| 任务 | L1 | L2 | L3 | L4 | 安全边界 |
|---|---|---|---|---|---|
| TRIAGE | 前端本地规则（红旗优先） | Ollama 7B | DeepSeek（仅 full） | business `TriageRuleEngine` + 前端本地 | 红旗只认本地；AI 只补科室；`aiFallback=true` 必须上卡 |
| CHAT | Ollama（按 profile） | DeepSeek（仅 full） | **模板话术（新增）** | 医生留言 | 模板不含诊断、剂量、处方；不假装是 AI 回答 |
| CARE_PLAN | Ollama 7B | DeepSeek（仅 full） | **结构化模板（新增）** | 医生随访 | 模板只写饮食/运动/监测/复诊；**不写药名剂量** |
| INTERPRET | Ollama | DeepSeek | **安全停答（新增）** | 人工 | **绝不推断指标含义**；只展示原文与参考区间 |
| RAG | Redis/Qdrant + embedding | 关键词检索（新增） | 空引用 | — | 不编造引用 |

### 4.3 本机 Ollama 专项降级

| 场景 | 现象 | 处理 |
|---|---|---|
| 冷启动未驻留 | `/api/ps` 空，7B 首 token 10~30s | `keep_alive=30m` 已有；启动后台预热（0.5b 必做，7B 可选）；首 token 8s 仍超时 → DeepSeek |
| 内存不足 | 7B 驻留约 5GB，空闲 <6GB | 启动 preflight 读可用内存；不足 → TRIAGE 直接 DeepSeek（**禁止 0.5b 做导诊**：实测把兜底科室排第一、置信度全 0.9） |
| 模型缺失 | `/api/tags` 无对应模型 | readiness `degraded`，该级跳过；日志给缺失模型名 |
| CPU 排队 | worker pool 3，Ollama 实际串行 | 队列上限背压；任务超时进云；不无限排队 |
| 熔断 | 连续 3 次失败 | 60s 冷却已有；冷却后半开一次；多副本各自独立 |
| 输出非法 | JSON 解析失败 | `MODEL_OUTPUT_INVALID`；同 provider 重试 1 次后降级 |

### 4.4 兜底内容规范（新增，必须评审后入库）

- **CHAT 模板**（2 句以内，不含医学结论）：
  > 「智能助手当前繁忙，暂时无法回答。你的问题已保留。可以先用『智能导诊』判断科室或直接挂号；如症状加重请立即就医。」
- **CARE_PLAN 模板**（四段固定：饮食 / 运动 / 监测 / 复诊），只允许来自人工审校的静态模板库，标注「模板建议，非 AI 生成」。
- **INTERPRET 安全停答**：
  > 「报告解读服务暂不可用。为避免误读，请携带纸质报告咨询开单医生。」
  > 若报告是结构化字段（有参考区间），**原样展示数值与区间**，不加解释。
- **禁止**：把模板包装成 AI 生成；在降级文案里给诊断/用药建议。

### 4.5 可选：第三家云端

`deepseek.py` 已是 OpenAI 兼容实现；P2 可抽象为 `openai_compatible` provider（豆包/通义/智谱任选），`AI_PROVIDER_ORDER=ollama,deepseek,vendor3`，配置即接入。**P1 不做**，避免多云合规与成本同时展开；且**受 `AI_DEGRADE_ENABLED` 总开关约束**，local 模式一律否决。

## 5. ASR 降级链（重点）

### 5.1 现状问题

- `executors/asr.py` 只认 `asr_status()==available` + `resolve_audio_path()`，失败即 `CAPABILITY_UNAVAILABLE`。
- `voice.py#transcribe()` **完全忽略 `locale`**：粤语/潮汕话录音也走普通话 paraformer。
- 端侧未接（按确认不接云端）；`AsrResultData` 无 `engine/degraded` 字段，降级不可见。
- `AI_ASR_TIMEOUT_SECONDS=60` 与 business await 60s 同界，一旦慢就双双超时。

### 5.2 三级链（按确认：无本地方言模型，不接云端 ASR）

```text
L1 本地 FunASR（普通话，现网）
L4 微信同声传译 WechatSI（端侧；普通话 / 粤语 / 四川话，随插件版本）
L5 人工兜底（重录 / 文字输入 / 医生听原始录音）
```

> 编号沿用原表 `L1/L4/L5`，便于与历史方案对照；实际只有三级。
> 原 `L2`（本地粤语/潮汕模型）因本机无此资产删除；原 `L3`（云端 ASR）按当前决策删除，不引入第三方云。
> **开关语义**：`local` 模式（`AI_DEGRADE_ENABLED=false`）下 WechatSI 被一票否决 → 只剩 FunASR，失败即文字；`AI_WECHAT_SI_ENABLED=false` 同理。

### 5.3 路由表（按 locale / 语言判定）

| 场景 | 首选 | 次选 | 末选 |
|---|---|---|---|
| `zh-CN` / 未指定 | 本地 FunASR | WechatSI `zh_CN` | 文字输入 |
| `zh-HK` / `yue` / 粤语特征词 | **直接 WechatSI `yue`**（本地 FunASR 不处理粤语） | 提示改用普通话 | 文字输入 |
| 潮汕话（建议 `zh-NAN`） | 无可用引擎 | 提示「请用普通话再说一遍」 | 文字 / 医生听原始录音 |
| `en-US` | WechatSI `en_US` | 本地 FunASR（仅少量英文，近似） | 文字输入 |

> 潮汕话没有标准小程序 locale；建议自定义 `zh-NAN`（ISO 639-3 `nan`）并在契约里固定，不要复用 `zh-TW`。
> **关键路由**：`zh-HK` 不再进本地 FunASR，避免把粤语硬转成错乱的普通话文本；直接走端侧插件，失败即提示普通话。

### 5.4 能力边界（只用现有两级，需实测验收）

| 引擎 | 支持 | 约束 | 用途 |
|---|---|---|---|
| 本地 FunASR paraformer-zh | 普通话（少量英文） | 16k 单声道；权重 881MB；首次加载约 27s | L1 默认 |
| 微信同声传译 WechatSI | `zh_CN`、`en_US`、粤语、四川话（随插件版本） | 端侧、≤60s、免费、依赖插件与基础库；**TTS 仅普通话** | L4 端侧 |
| 潮汕话 | **无** | 需自研模型或定制云服务 | 当前不做，提示普通话/文字 |

参考：
- WechatSI 官方文档：https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/extended/translator.html
- WechatSI 版本更新（新增粤语、移除 zh_HK）：https://developers.weixin.qq.com/community/develop/doc/0006a0dd25cfe0341941934e066c00

> 说明：本文不再列腾讯云/讯飞等云端 ASR。若后续要接，须单独立项（合规、费用、音频出境评估、异步回调），不在本次降级链内。

### 5.5 触发条件与预算

| 触发 | 动作 |
|---|---|
| 权重路径不存在 / 加载失败 | 服务端**快速返回** `ASR_UNAVAILABLE`，客户端直接 L4 |
| 本地超预算（20s） | 服务端返回 `ASR_TIMEOUT`，客户端 L4（**不在服务端串云端**） |
| 转写为空 | 客户端用同一段录音进 L4 |
| `ASR_BUSY` / 队列满 | 客户端 L4 |
| 连续 2 次异常 | 本地熔断 60s，期间客户端直接 L4 |
| 音频 >60s 或 >3MB | 提示缩短/改文字（WechatSI 同样 ≤60s） |

> 服务端职责只有一件事：**在 20~25s 内给出确定结果或确定失败**，让客户端有机会切 WechatSI；否则用户干等 60s，降级就失去意义。

### 5.6 结果契约扩展

`AsrResultData` 建议追加两个可选字段（向后兼容，前端可忽略）：

- `engine`：`funasr` / `manual`（WechatSI 走文字通道落库，草稿标 `source=wechat_si`，不改 ASR 契约）
- `degraded`：是否走了非默认级

同时约定：
- `requiresConfirmation` 恒 `true`（已有）；
- **WechatSI 结果必须标注「端侧识别（草稿）」**，不得直接进入诊疗结论；
- `language` 仍只透传引擎真实给出的值，不猜。

### 5.7 热词与医学词纠错

所有层级输出后统一过一层**保守纠错**（新增 `asr-hotwords`）：

- 词表：科室名（呼吸内科/消化内科/心血管内科/骨科）、常见症状（心绞痛/胸闷/反酸/眩晕）、常见药名（仅纠正字形，不改剂量）。
- 方法：拼音近邻 + 编辑距离 ≤1（如「心胶痛→心绞痛」「呼吸内壳→呼吸内科」）；**否定词、数字、单位一律不动**。
- 目的：把「端侧 WechatSI」的准确率损失补回来一部分；不做语义改写。

### 5.8 隐私与合规

- **不接第三方云 ASR**：不存在音频出境/第三方留存问题；`AI_ASR_CLOUD_ENABLED` 保留为 false，仅作未来扩展位。
- WechatSI 属微信平台能力，仍需在隐私指引中写明「语音可能由微信同声传译能力转写」，并提供「不用语音、改文字」的选项。
- 音频生命周期：business 在任务收口后删除（已有）；WechatSI 录音由客户端管理，转写成功后不留存。
- 日志不落音频、不落转写原文。

### 5.9 实施落点

| 文件 | 改动 |
|---|---|
| `backend/ai-service/app/config.py` | ASR 超时 60→25、本地预算 20；不新增云端凭据 |
| `backend/ai-service/app/voice.py` | `transcribe()` 按 `locale` 拒绝 `zh-HK/zh-NAN`（避免错误转写），快速失败 |
| `backend/ai-service/app/executors/asr.py` | `engine=funasr`、`degraded=false`、失败分类可区分 |
| `backend/ai-service/app/capabilities.py` | readiness 如实反映本地 ASR |

| `miniprogram/services/speech.js` | 后端失败 → 同一段录音进 WechatSI；`zh-HK` 直接走插件；`zh-NAN` 提示普通话/文字 |

### 5.10 验收指标

- 普通话：本地 FunASR 为基线；WechatSI 兜底的字准相对基线下降 ≤8 个百分点；端到端 P95 ≤8s（本地热态）。

- 潮汕话：**不宣称支持**；必须 100% 给出「请用普通话/改文字」的明确出路，不能空转。
- 降级成功率：服务端 503/504 后，WechatSI 接管成功率 ≥95%（插件可用前提下）；其余 100% 落到文字输入。

## 6. TTS 降级链（重点）

### 6.1 现状问题

- `tts_status()` 只认 `edge`；`AI_TTS_ENGINE` 其他值一律 `unavailable`，没有本地引擎。
- **本地 Qwen3-TTS 只剩历史实现**：`env.example` / README 明确写「Qwen3-TTS 需另接适配器」；当前 `voice.py` 没有 sidecar/adapter，**不能把 L1 当成已可用**。
- 业务音色目录只有 `qwen3-female-1` / `qwen3-male-1`（zh-CN），没有粤语音色。
- `resolve_voice(settings, voice_id)` 不看 `locale`：传 `zh-HK` 仍落到普通话默认音色。
- 缓存摘要 `sha256(text|engine_voice|locale)` **不含引擎名**：切引擎后可能复用旧引擎产物，`engine` 标识不实。
- `AI_TTS_TIMEOUT_SECONDS=30` 与 business `task-budget-seconds=30` 同界；Qwen3-TTS 冷启动 20~30s，必超。

### 6.2 降级链（按确认：不接 Azure / 境内厂商）

```text
L0 固定话术预生成（盘缓存；任何模式都保留）
L1 本地 Qwen3-TTS（本地 sidecar/adapter；WAV/MP3）
L2 edge-tts（微软 Edge 朗读；zh-CN / zh-HK / zh-TW）
L4 微信同声传译 TTS（端侧，仅普通话）
L5 纯文字 + 视觉提示（始终保留）
```

> 编号沿用 `L0/L1/L2/L4/L5`；`L3` 有意跳过：Azure Speech 与境内厂商 TTS 不在本次链路，若未来需要商业 SLA 再单独立项。

### 6.3 L1 本地 Qwen3-TTS（前提，不是现状）

| 项目 | 要求 |
|---|---|
| 形态 | 本地 sidecar（HTTP）或进程内 adapter；**当前仓库未接** |
| 健康检查 | `GET /health` 或进程内 ready；失败 → 该级 `unavailable` |
| 预热 | 启动后台预热，首次 20~30s；常驻不卸载 |
| 输出 | WAV（优先）或 MP3；校验非 0 字节、可解析 |
| 预算 | 首字节 ≤5s（热态）、整体 ≤35s（冷启动） |
| 音色 | `qwen3-female-1` / `qwen3-male-1` 映射本地 speaker；粤语/潮汕话能力**未验证前不宣称** |
| 标识 | `engine=qwen3-tts`、`degraded=false` 如实返回 |

> 若 L1 未部署：full 模式直接进 L2；local 模式直接 L0/L5。**不得把 edge 的音频冒充 Qwen3-TTS。**

### 6.4 L2 edge-tts（微软朗读）

| 性质 | 音色 | 约束 |
|---|---|---|
| 免费、无 SLA、可能限流 | zh-CN 6、zh-HK 3、zh-TW 3、辽宁/陕西 2 | 需联网；总开关 `local` 时**硬否决** |

粤语映射（新增内置音色）：

| 业务音色 | 名称 | locale | edge 音色 |
|---|---|---|---|
| `yue-female-1` | 温柔女声（粤） | zh-HK | `zh-HK-HiuMaanNeural` |
| `yue-male-1` | 沉稳男声（粤） | zh-HK | `zh-HK-WanLungNeural` |

> `zh-HK` 是**粤语朗读书面中文**，不是「粤语口语改写」。医疗文本不要机器转写成口语（语义风险），只允许人工审校过的固定话术做口语化版本。

### 6.5 L4 微信同声传译 TTS

| 能力 | 支持 | 约束 |
|---|---|---|
| WechatSI `textToSpeech` | **仅普通话** | 端侧、短文本、依赖插件；粤语 TTS 不可用 |

> 粤语在 full 模式只用 L2 edge；local 模式只用 L1（若已验证粤语）或 L0 预生成/文字。**不允许把普通话 TTS 当粤语兜底。**

### 6.6 音色目录与 locale 路由改造

1. business `application.yml#voice.builtin` 增加粤语两项（后端是音色唯一数据源）。
2. `resolve_voice(settings, voice_id, locale, engine)`：
   - 显式 `voiceId` 且该引擎可用 → 用它；
   - 否则按 `locale` 选默认（`zh-HK`→粤语默认，`zh-CN`→普通话默认）；
   - 再否则全局默认。
3. `AI_TTS_VOICE_MAP` 升级为**分引擎映射**：`voiceId=qwenSpeaker|edgeVoice`，避免换引擎时音色漂移。
4. 缓存摘要加入引擎名：`sha256(engine|text|engine_voice|locale)`。
5. 同一 `voiceId` 在不同引擎音色不同时，UI 不得显示原音色名，只显示「备用语音」。

### 6.7 预生成与缓存门禁

- 预生成清单从 23 条扩到「导诊首句 / 问诊首句 / 养生首句 / 错误提示 / 导航提示」；**每个启用音色 × 每条话术都必须有产物**。
- 预生成产物是**本地资产**：local 模式可直接播放（播放不联网）；但**重新生成时只能用当前允许的引擎**，local 模式不得调 edge 补跑。
- TTS 缓存命中以「文件存在且非空」为准；0 字节残留先删再合成（已有，保持）。
- 磁盘守护：`runtime/tts` 低于 200MB 可用空间时拒绝新合成并清理过期产物。
- 启动校验覆盖率：缺一条 → WARN + 后台补跑；发布门禁要求 **100% 覆盖**。

### 6.8 触发条件与预算

| 触发 | full 模式 | local 模式 |
|---|---|---|
| L1 未部署 / 健康失败 / 35s 未出首字节 | 进 L2 edge（12s） | 直接 L0 / L5 |
| L1 返回 0 字节 / 不可解析 | 清残片，进 L2 | L0 / L5 |
| edge 429/403/连接失败/12s 未出首字节 | 普通话 → L4 WechatSI；粤语 → L0/L5（不得用普通话顶替） | edge 已否决，不适用 |
| WechatSI 失败 | 固定话术回 L0；动态文本 → L5 | WechatSI 已否决，不适用 |
| 全部失败 | `TTS_UNAVAILABLE`，页面保留文字 | 同左 |

> 预算：business 60s、ai-service 55s；L1 35s + L2 12s + L4 端侧 5s，余量 8s。
> **绝不**：用另一句的音频顶替当前文本；用占位音冒充合成成功。

### 6.9 TTS 开关语义（落到代码）

- `effective(tts_provider) = AI_DEGRADE_ENABLED && AI_DEGRADE_TTS_ENABLED && AI_TTS_<PROVIDER>_ENABLED`。
- `AI_DEGRADE_ENABLED=false`：只允许 Qwen3-TTS（本地）；若 L1 未部署则 L0/L5。edge / WechatSI **一票否决**，不建连、不重试。
- `AI_DEGRADE_ENABLED=true` 但 `AI_TTS_EDGE_ENABLED=false`：跳过 L2；普通话 → L4（若 `AI_WECHAT_SI_ENABLED=true`），粤语 → L1（若已验证）或 L0/L5。
- 每次否决打日志：`provider=edge reason=denied_by_switch`；不得静默尝试。
- readiness 返回 `degradeMode=full|local`、`tts.engines=[qwen3|edge]`、`fallbackOk`。

### 6.11 验收指标

| D2 | kill Ollama | full：TRIAGE 进 DeepSeek；local：TRIAGE 进规则；readiness `degraded` |

| D4 | 限制内存 <6GB | preflight 检测；full 直接 DeepSeek；local 直接规则；不 OOM |
| D5 | edge 返回 403/429 | 普通话 → WechatSI 接手；粤语 → L1 或 L0/文字；无 0 字节产物 |
| D6 | WechatSI 不可用（插件/网络） | 普通话 → L0/L5；粤语 → L1 或文字；不得用普通话顶替 |
| D6b | 总开关置 false | 所有外部供应商零请求；LLM 只用 Ollama+规则；TTS 只用 Qwen3/预生成/文字；ASR 只用 FunASR |
| D6c | 总开关 true 但 edge 开关 false | 跳过 L2；普通话走 L4；粤语走 L1/文字 |
| D7 | 删 ASR 权重 | full：客户端 WechatSI 接管（普通话/粤语）；local：文字；潮汕话提示普通话/文字 |
| D8 | 停 Redis | RAG 空引用或关键词；回答仍生成；不编造 |
| D9 | kill ai-service | TRIAGE 本地；CHAT 模板；INTERPRET 安全停答 |
| D10 | 三服务 + 外网全断 | 前端本地导诊、本地挂号、导航仍可用；语音全转文字 |

**通过标准**：每级降级后核心路径仍可达；无 5xx 暴露给用户；无伪造数据；用户提示为中文且 ≤20 字；P95 不超总预算。

### 9.3 巡检脚本（建议 P0 一并落地）

`tools/ai-degrade-probe.py`（只读，不改状态）：
- 探 Ollama `/api/tags`、`/api/ps`；
- 探 Qwen3-TTS sidecar `/health`（未部署 → `unavailable`）；

## 12. 明确不做 / 风险

**不做**：

- 不把 edge-tts 当 SLA，也不让它成为唯一通道；`local` 模式必须一票否决。
- 不接 Azure Speech / 境内厂商 TTS；本次链路只到 `Qwen3-TTS → edge → WechatSI`，需要商业 SLA 再单独立项。
- 不把普通话文本机器转写成粤语口语（医疗语义风险）；粤语只做「书面朗读」或人工审校的固定话术。
- 不接第三方云 ASR：当前只用本地 FunASR + WechatSI；如未来接入须单独立项。
- 不用 0.5B 做导诊（已有质量事故记录）。
- 不为降级伪造转写、音频、引用、AI 生成标识。

**风险**：

- **Qwen3-TTS 当前未接线**：L1 可能直接 unavailable；`local` 模式下 TTS 只剩 L0/L5。上线前必须先完成 sidecar/adapter 与 35s 冷启动验收。
- **外部供应商否决必须彻底**：`local` 模式不得因「缓存未命中」偷偷调 edge/WechatSI；要用出口抓包/日志证明零外部请求。
- 方言能力：粤语 full 模式仅 edge；local 模式仅 Qwen3（若已验证粤语），否则 L0/文字；潮汕话无引擎，**不能承诺识别或合成**。
- 多引擎音色不一致：Qwen3 与 edge 音色不同，同 `voiceId` 听感会变；UI 必须显示「备用语音」，不得冒充原音色。
- 预算收紧可能让 7B 在 CPU 上更容易超时：需按真实流量重新标定，不要只看单机空载。
