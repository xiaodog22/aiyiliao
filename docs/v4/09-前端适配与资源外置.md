## 0. 目标与原则

前端「完美适配 V4 后端」= 三条硬线：

1. **单一入口**：前端只维护一个后端地址（`config/env.js#gateway`），上游分流由网关路由表负责；
2. **契约照做**：请求头、幂等、错误码、超时，以 `backend/contracts/**` 为唯一事实源；
3. **素材不挤包**：图片等非关键素材经后端下发 + 本地缓存 + 内置回退；**A 级**（TabBar 图标等）必须随包。

原则：**不伪造**——本文把「已就位 / 待接线 / 待 M 侧」逐项标注，测试只测真实存在的能力。

## 2. 请求层适配（✅ 已就位：`services/request.js` V1.7）

- **唯一出口**：页面 → `services/` → `request.js`；三层 base（gateway/python/java）在**同一地址**解析，由网关路由表分流（对照 V4 网关：`/api/gw/**` 网关自身，其余 `/api/**` 全量代理 business）。
- **统一注入头**：`Authorization: Bearer`（`session.js` 自动）、`X-Request-Id`；非生产附带 `ngrok-skip-browser-warning`（隧道兼容）。
- **401 语义**：自动**单飞刷新**（`POST /api/v1/auth/refresh`，一次一换；并发复用同一 Promise），刷新失败 → `AUTH_EXPIRED` 清会话；页面引导重登。
- **错误分类**（不弹 Toast、不吞错，统一 reject `{code,message}`）：`NO_BASE_URL / NETWORK_ERROR / TIMEOUT / HTTP_ERROR / BIZ_ERROR / PARSE_ERROR / AUTH_EXPIRED` → 页面统一走 `utils/err-text.js#errText()`（保证界面零英文、零 HTTP 码）。
- **超时三档**（`env.js`）：`aiTimeout 90s / ttsTimeout 120s / carePlanTimeout 180s`（生产档 45/60/90s）；网关代理读超时 220s 兜底（`deploy/config.json`）。

> ⚠️ **契约必填头尚未携带（P0，见 §3.3-①）**：`X-Client-Version`、`X-Platform` 是契约 `required: true` 参数，
> business 侧 `@RequestHeader(required = true)` 强校验；缺失 → `400 BAD_REQUEST`（"缺少必需请求头 X-Client-Version"）。
> 影响登录类接口（患者/医生）。本文配套自测脚本**已按契约携带**这两个头——脚本通过 ≠ 前端已带。

## 3. 适配矩阵（前端 ↔ V4 后端）

### 3.1 鉴权与登录（V4 会话机制）

- 机制：`POST /api/v1/auth/wechat/login`（`X-Client-Version`/`X-Platform`/`consentVersion` 必填）
  → `OkSession{accessToken, refreshToken, expiresIn, tokenType:"Bearer", user}`；
  `POST /api/v1/auth/refresh` 轮换（**一次一换**；重放视为撤销信号 → 401）；`POST /api/v1/auth/logout`。
- 401 双码：`UNAUTHORIZED`（未携带凭证）/ `SESSION_REVOKED`（携带但过期/撤销/伪造）→ 刷新或重登引导。
- 现状（已逐文件审计）：
  - ✅ `session.js`：access token 仅驻内存（不落盘），refresh token 落盘 + 到期窗口；`request.js` 已接入 401 单飞刷新链；
  - ⬜ **登录成功回调未调用 `session.setTokens(...)`**（全仓仅 `request.js` 刷新成功时写入）→ 登录后业务请求仍匿名，strict 档下会被 401；
  - ⬜ `user.js#loginByWxCode` / `doctor.js#loginByWxCode` 仍按**旧响应形状**解析（`data.userId/name/phone`；V4 为 `data.user`），且未传 `consentVersion`；两处 stale 注释（"后端当前无此接口"）需一并清理；
  - ⬜ 患者手输登录 `USER_LOGIN = /api/user/login` 属 legacy 兼容条目（dev 替身，**生产禁用**）——生产前须迁 V4 路径（登记：U-02 联调轮）。

### 3.2 写操作与幂等（契约不变量）

- 契约：写操作携带 `Idempotency-Key`（缺失 → `400 MISSING_IDEMPOTENCY_KEY`；同键异载荷 → `409 IDEMPOTENCY_KEY_REUSE`；重放成功带 `Idempotency-Replayed` 响应头）。
- 现状：**前端 0 处携带**（全仓仅 `api.js` 有按幂等键**查询**路径 `APPOINT_BY_KEY`）→ ⬜ 待接线（§3.3-④；M4 门遗留登记：TTS 任务提交、预约提交、床位、删除申请等写端点）。
- 乐观锁：更新类接口回传 `expectedVersion`；`409 VERSION_CONFLICT` → 刷新重取再改（交互口径见 02 文档）。

### 3.3 前端待接线清单（可直接照做）

| # | 级别 | 项 | 位置 | 改动要点 |

### 3.4 后端错误码速查（前端兜底对照）

统一信封 `{code, message, requestId, retryable, serverTime}`；`message` 为中文可直接展示，兜底一律走 `errText()`：

| code | HTTP | 触发 | 前端应做 |
|---|---|---|---|
| `BAD_REQUEST` | 400 | 缺必填头（X-Client-Version 等）/ 体格式错 | 检查 §3.3-① |
| `MISSING_IDEMPOTENCY_KEY` | 400 | 写操作未带幂等键 | 补 §3.3-④ |
| `UNAUTHORIZED` / `SESSION_REVOKED` | 401 | 无凭证 / 会话失效 | 刷新或重登引导 |
| `FORBIDDEN` | 403 | 无权限/非医生 | 权限文案 |
| `NOT_FOUND` | 404 | 资源不存在 | 兜底文案 |
| `VERSION_CONFLICT` / `IDEMPOTENCY_KEY_REUSE` / `BED_STATE_CONFLICT` | 409 | 乐观锁/幂等/状态冲突 | 刷新重取再改 |
| `VALIDATION_FAILED` | 422 | 参数不合法 | 定位参数提示 |
| `RATE_LIMITED`（+`Retry-After`） | 429 | 网关限流（生产可开） | 稍后重试 |
| `COMPAT_PENDING` | 501 | 旧路径未迁移（含 blockers） | **不得依赖**，按 §3.3-⑤ 迁移 |
| `UPSTREAM_UNAVAILABLE` / `AI_UNAVAILABLE` / `CAPABILITY_UNAVAILABLE` | 503 | 上游宕/能力未配（快降级） | "服务暂不可用"降级，**不伪造**结果 |

### 4.2 分发通道（本次新增 · 已测试）

**`GET /api/gw/assets/{filename}`**（网关自身域；公开只读——图片元素无法携带 Authorization 头）

- **白名单四道**：文件名 `^[a-z0-9][a-z0-9._-]{0,79}$`（禁斜杠与 `..`）＋扩展名 `.png/.jpg/.jpeg/.webp` ＋目录穿越双保险（resolve 后父目录必须等于素材根）＋单文件 ≤ 4 MiB；任一不满足 → 统一信封 404。
- **缓存与校验**：`ETag`（内容 sha256 前 32 位）→ 支持 `If-None-Match` 304 复用；`Cache-Control: public, max-age=86400`；`X-Resource-Sha256` / `X-Resource-Size`（下载端校验权威值）；HEAD 可用（先探后下）。
- **配置**：`backend/deploy/config.json#assets.dir`（默认 `backend/deploy/resources`，相对路径以仓库根为基准）或环境变量 `GW_ASSETS_DIR`。
- **种子**：从包内真实素材复制 13 张（共 131.6 KB）至 `backend/deploy/resources/`（保留原文件名，便于迁移）；新增素材直接放目录即可生效（无需改配置）。
- **证据**：`backend/edge-gateway/tests/test_assets.py`（10 例：白名单/穿越/超限/304/HEAD/信封 404）+ §6 链接自测实测通过（网关 pytest 累计 **104**）。
- ⚠️ 新路由需**重启网关**生效：`backend/deploy/restart.bat`（或 stop-all+start-all）。

### 4.3 资产分布规划（该随包的随包、该远侧的远侧）

### 4.4 前端接入设计（`resource.js` 下载层——待接线）

1. **启动**：`app.js onLaunch` 后台调 `resource.refreshManifest()`（**不阻断启动**；失败静默回退内置——模块本来就是"绝不阻断"设计）。
2. **取图**：`resource.resolveResource(key, builtinPath)` → 远端 `url` 存在且已缓存 → 本地文件路径；否则**内置回退**；首屏关键图一律先用内置、远端就绪后替换。
3. **下载缓存**：`wx.downloadFile` → `saveFile` 到 `wx.env.USER_DATA_PATH` 下自有目录 → 校验 → 以 `key+version` 命名复用；失败丢弃并回退（**不做重试风暴**）。
4. **sha256 校验口径（U-25 定策）**：`wx.getFileInfo` 仅支持 md5/sha1 → 图片类小文件（≤2 MB）用 `wx.request {responseType:'arraybuffer'}` + 纯 JS sha256（约 2 KB 代码）本地计算，与清单条目 / 响应头 `X-Resource-Sha256` 比对；失败回退。视频等大文件暂不向客户端校验（维持分包内）。
5. **url 口径建议（待 M 侧采纳）**：清单 `url` 用**相对路径**（`/api/gw/assets/<name>`），前端拼接 `ENV.gateway`——local/隧道/生产三档零改动。

### 4.5 M 侧待办（登记，不越权代做）

### 6.4 排障

| 现象 | 先查 |
|---|---|
| 素材 404 | ① 网关是否已**重启**（新路由需重启生效）② 文件名是否符白名单（全小写、无子目录）③ 文件是否在 `backend/deploy/resources/` |
| 清单 401 | 当前档位需要有效会话（dev `header` 档也要求身份）→ 先登录再测 |
| 全部连接失败 | 网关未启动 → `backend/deploy/start-all.bat`；确认 `env.js` 档位与端口 |
| 脚本登录 FAIL 但素材全过 | 素材通道=公开，登录问题独立看（§3.1 现状） |
