# 页面数据与交互契约（V4）

> 本文是拟实施契约，不表示相关接口已存在。页面全集以 `miniprogram/app.json` 为唯一范围依据；具体 24 页映射见根目录 V4 说明书。若本文与已部署服务冲突，应先版本化契约并完成迁移，不得由客户端静默猜测。

## 1. 契约总原则

1. **后端权威**：身份、档案、同意、问卷、评估、对话、报告、任务、资源元数据、会员/权益状态、内容版本和功能开关均由后端裁决。前端静态配置只能控制表现，不能充当业务事实。
2. **最少数据**：页面只请求当前功能必需字段；健康、语音、图片和会话数据默认不进入埋点。
3. **可恢复交互**：加载、空、错、离线、超时、无权限、拒绝授权均是契约状态，不由页面自由拼接假数据。
4. **AI 可辨识**：AI 输出携带生成状态、模型策略版本、知识引用和边界提示；不能冒充医生意见。
5. **资源软依赖**：插图、头像、音效、数字人素材或非核心模型资源失败时显示占位并继续启动。

## 2. 通用请求与响应

### 2.1 请求头

```http
Authorization: Bearer <短期访问令牌>
X-Request-Id: <UUID>
X-Client-Version: <小程序版本>
X-Platform: wechat-miniprogram
Idempotency-Key: <写请求必需，按操作生成>
```

令牌不得放入 URL。日志仅记录令牌指纹，不记录原值。客户端时间仅供展示，服务端时间决定审计与冲突。

### 2.2 成功响应

```json
{
  "code": "OK",
  "message": "成功",
  "requestId": "...",
  "serverTime": "2026-10-14T10:30:00+08:00",
  "data": {},
  "meta": { "version": "...", "nextCursor": null }
}
```

### 2.3 失败响应

```json
{
  "code": "VALIDATION_FAILED",
  "message": "请检查标注字段",
  "requestId": "...",
  "details": [{ "field": "...", "reason": "..." }],
  "retryable": false
}
```

统一语义：`400` 参数错误，`401` 未登录，`403` 已识别但无权限，`404` 不泄漏对象归属，`409` 版本冲突/重复状态，`413` 文件过大，`422` 业务校验失败，`429` 限流，`503` 依赖不可用，`504` 网关超时。

## 3. 页面状态机

所有页面/组件采用以下状态，不允许把失败折叠为空态：

| 状态 | 进入条件 | 页面行为 | 可用操作 |
|---|---|---|---|
| `idle` | 初始、无自动请求 | 显示默认内容 | 开始、输入、导航 |
| `loading` | 首次加载 | 骨架屏，保留导航 | 取消（长任务） |
| `refreshing` | 已有内容刷新 | 保留旧内容并标注刷新 | 取消/继续查看 |
| `empty` | 请求成功且合法空集合 | 解释为空原因 | 创建/调整条件 |
| `error` | 明确业务或系统失败 | 原因、请求 ID | 重试/反馈 |
| `offline` | 无网络或网络不可达 | 显示缓存时间，不假成功 | 重连/查看安全缓存 |
| `timeout` | 达到客户端时限 | 与“失败”区分 | 查询任务状态/重试 |
| `forbidden` | 账户或对象权限不足 | 不泄漏他人资源 | 返回/申请权限（如适用） |
| `permissionDenied` | 系统权限被拒 | 解释用途与替代路径 | 去设置/手动输入/稍后 |
| `ready` | 有效数据完成 | 显示内容 | 页面主操作 |
| `submitting` | 写入进行中 | 禁止重复提交 | 取消（若安全） |
| `conflict` | ETag/版本冲突 | 展示冲突说明 | 刷新后重新确认 |

客户端超时建议是体验预算而非服务承诺：普通读请求 8 秒、普通写请求 12 秒；上传和 AI 使用异步任务，不持有无限连接。重试仅适用于幂等请求，指数退避并限制次数。

## 4. 权限与授权契约

| 能力 | 申请时机 | 拒绝后的替代 | 敏感数据 |
|---|---|---|---|
| 麦克风 | 用户点击录音/语音对话 | 文本输入 | 原始录音、转写文本 |
| 相机 | 用户点击拍摄 | 相册选择/手动录入 | 健康图片及元数据 |
| 相册 | 用户点击选择图片 | 拍摄/跳过 | 图片及 EXIF（应清理非必要项） |
| 通知 | 用户开启特定提醒 | 页面内消息中心 | 订阅标识、提醒内容 |
| 剪贴板 | 用户明确点击粘贴 | 手动输入 | 粘贴内容（不自动读取） |

系统权限同意不等于敏感个人信息单独同意。后端保存同意版本、目的、范围、时间、渠道和撤回记录。

## 5. 领域对象

### 5.1 用户与档案

`UserProfile` 最少包含：`id`、展示名、头像对象键（可空）、档案完整度、同意版本、创建/更新时间。年龄、性别、病史等只有功能确需时收集，并由医疗与法律分别确认字段必要性。

### 5.2 问卷与评估

- `QuestionnaireDefinition`：版本、题目、选项、校验、适用范围、生效时间、医疗审核状态。
- `AssessmentSubmission`：定义版本、答案、提交时间、幂等键。
- `AssessmentResult`：规则/模型版本、输入摘要、风险等级（若真实业务确认需要）、说明、来源、限制、生成时间。

客户端不得保存计分阈值作为权威规则；离线可暂存草稿，但上线提交必须由服务端按对应版本验证和计算。

### 5.3 AI 会话

- `Conversation`：所有者、标题、状态、创建/更新时间。
- `Message`：`user/assistant/system_notice` 角色、内容类型、引用、风险标签、生成状态。
- `AITask`：排队、运行、完成、失败、取消、过期；包含 `progressPhase`，不伪造百分比。

高风险输入先显示即时安全提示，再进入生成队列；生成结果必须允许复制前核对，语音转写先让用户确认文本。

### 5.4 文件与媒体

上传流程：创建上传意图 → 短期签名上传 → 服务端校验/扫描 → 状态可用。元数据包括对象键、SHA-256、大小、MIME、所有者、用途、保留类别、扫描状态；不得直接信任扩展名。下载使用短期授权 URL。

## 6. 页面级数据契约模板

每个 24 页页面在开发时建立一行契约，字段必须完整：

| 字段 | 要求 |
|---|---|
| 路由 | 与 `app.json` 完全一致 |
| 页面目的 | 单一主要用户任务 |
| 权威读模型 | 服务端资源、字段与版本 |
| 写操作 | 方法、幂等键、权限、冲突策略 |
| 缓存 | 是否允许、TTL、失效与敏感级别 |
| 状态 | 默认/加载/空/错/离线/超时/无权限/拒绝授权 |
| 埋点 | 仅事件与非敏感枚举，不含原始内容 |
| AI 边界 | 是否生成、引用、风险提示、失败降级 |
| 无障碍 | 标题、焦点、语义、播报 |
| 响应式 | 手机/平板布局变化 |

### 6.1 页面类别与建议资源

> 路由与页面名称以根目录 V4 的 24 页清单为准，下表只定义类别接口，不声称现有服务已实现。

| 页面类别 | 建议资源 | 写操作 | 安全要点 |
|---|---|---|---|
| 首页/聚合页 | `/v1/home` | 无或轻量偏好 | 聚合接口不返回不必要健康明细 |
| 登录/授权 | `/v1/auth/*`、`/v1/consents` | 登录、同意、撤回 | 防重放、最少权限 |
| 个人中心/设置 | `/v1/me`、`/v1/preferences` | 更新档案/偏好 | 字段级校验、版本冲突 |
| 问卷/评估 | `/v1/questionnaires`、`/v1/assessments` | 草稿、提交 | 题目版本锁定、服务端计分 |
| 报告/记录 | `/v1/reports`、`/v1/records` | 删除/导出申请 | 对象级授权、水印/短链 |
| AI 文本对话 | `/v1/conversations`、`/v1/ai-tasks` | 发消息、取消 | 安全分类、引用、拒答 |
| 语音交互 | `/v1/asr-tasks`、`/v1/tts-tasks` | 上传、转写确认 | 明示录音、第三方 TTS 披露 |
| 图片/检测 | `/v1/uploads`、业务分析任务 | 上传、确认 | 格式扫描、结果非诊断 |
| 内容/知识 | `/v1/content` | 收藏/反馈 | 来源、版本、有效期 |
| 消息/提醒 | `/v1/notifications` | 已读/偏好 | 避免通知正文泄露健康信息 |

## 7. AI 服务契约

Spring Boot 对客户端提供稳定业务 API，FastAPI 作为受控内部 AI 服务；客户端不直接访问 Ollama、Qdrant、Redis 或 `edge-tts`。

### 7.1 内部任务提交

```json
{
  "tenantId": "...",
  "userId": "...",
  "taskType": "chat|rag|asr|tts",
  "inputRef": "受控对象引用或最小文本",
  "policyVersion": "...",
  "requestedProfile": "small-default|large-upgrade",
  "traceId": "..."
}
```

默认 `small-default` 对应经部署验证的 0.5B 资源档；`large-upgrade` 对应 7B，仅由服务端配置和容量策略选择。模型具体标签属于部署配置，不能由客户端指定。

### 7.2 ASR

目标为本地 `qwen3-asr-0.6b`。响应须含转写文本、语言/方言标记（若模型真实提供）、时间戳能力标记、模型版本和“需用户核对”。任何准确率或实时性能须来自实际基准测试。

### 7.3 TTS

`edge-tts` 作为联网第三方适配器：

- 不得称为 Azure 正式商业 API，不承诺可用性、配额、地域或数据处理保证；
- 默认只发送合成所需文本，先移除不必要标识符；
- 失败返回文本内容与可重试状态，不阻断对话；
- 正式商用前由法律、隐私与采购评估是否更换为有合同/SLA 的服务。

## 8. 内容寻址缓存

缓存键禁止使用原始敏感文本，使用 HMAC 或哈希派生：

```text
inputDigest = SHA-256(canonicalBytes)
cacheKey = HMAC-SHA256(
  tenantSecret,
  taskType | inputDigest | modelId | modelVersion | quantization |
  promptTemplateVersion | policyVersion | knowledgeSnapshot |
  voice | locale | generationParameters
)
```

**字段集为权威版本**（`docs/v4/04` 第 9.2 节与此一致）：早期草稿中的 `tenant-salt` 与 `tenantSecret` 是同一概念，契约中**统一使用 `tenantSecret`**；本文此前省略的 `quantization`、`knowledgeSnapshot` 为必填字段。

规范化不能改变医疗含义（必须保留有医学意义的数字、单位、否定词与时间）。缓存值包含创建时间、来源版本、保留类别和完整性哈希。授权先于命中；不同租户/用户隔离。删除、撤回同意、模型/模板/安全策略升级时应失效或使缓存不可达。

## 9. 离线、同步与冲突

- 可离线：非敏感静态说明、已脱敏且用户明确允许的最近内容、表单草稿（加密且短期）。
- 不可离线假提交：问卷结果、健康结论、AI 消息、授权同意、删除申请。
- 恢复网络后展示待同步项，让用户确认；使用原幂等键避免重复。
- 更新档案使用 `If-Match`/版本号。发生 `409` 时展示服务端新版本和用户待提交内容，不静默覆盖。

## 10. 埋点与可观测性

允许：页面路由、功能按钮枚举、成功/失败代码、耗时分桶、客户端版本、匿名会话标识。禁止：对话正文、问卷答案、录音转写、图片 URL、报告内容、身份证明、手机号、令牌。请求 ID 贯穿小程序 → Spring Boot → FastAPI → 模型适配器，但不得成为可枚举资源凭证。

## 11. 无障碍与响应式契约

- 动态加载完成、错误和 AI 生成状态使用可读文本并触发适度播报，不连续打断读屏。
- 输入错误绑定字段，焦点移至首个错误；图标按钮有中文可访问名称。
- 最小触控区建议 44×44 CSS px；正文支持系统字体放大至 200% 后仍可完成主要操作。
- 手机采用单列；平板可双栏（列表/详情、表单/说明），但阅读与焦点顺序保持一致。
- 横竖屏切换不丢未提交输入；底部操作栏避开安全区和虚拟键盘。

## 12. 契约变更治理

1. OpenAPI/JSON Schema 为机器可读事实源，本文是解释层。
2. 破坏性变更必须新版本；新增字段默认可忽略，枚举新增需客户端具备未知值兜底。
3. 契约测试覆盖正常、空、错、离线模拟、超时、无权限、拒绝授权与重复提交。
4. 下线字段先度量旧客户端使用率，再经历公告与兼容期。
5. 任何“已实现”结论必须由代码、测试和运行结果共同证明。
