# 上线审查与整改清单（V4）

> 文档性质：上线前设计与工程审查基线，不代表当前项目已经实现、测试通过、取得医疗资质或完成法律合规审查。  
> 适用范围：`miniprogram/app.json` 声明的 24 个页面及其拟接入的业务后端、AI 后端与资源服务。  
> 判定原则：任何 **No-Go** 未关闭，不得发布正式环境；“人工确认”必须留下确认人、日期、依据与适用版本，不能以开发自测替代。

## 1. 审查结论分级

| 级别 | 定义 | 发布处理 |
|---|---|---|
| No-Go | 可能导致违法违规、医疗伤害、隐私泄露、核心业务不可用或无法追责 | 阻断上线，必须整改并复验 |
| High | 主要流程有明显风险，但存在安全降级路径 | 原则上阻断；确需灰度须由产品、技术、安全共同签字 |
| Medium | 不影响核心安全，可在明确期限内修复 | 建立缺陷单、责任人和期限 |
| Low | 文案、一致性或体验优化 | 可进入后续迭代 |

状态统一使用：`未核验 / 不通过 / 整改中 / 待人工确认 / 已通过 / 不适用（附理由）`。

## 2. 上线 No-Go 阻断项

### 2.1 法律、隐私与平台合规

- [ ] **No-Go-L01** 未展示或无法访问隐私政策、用户协议、第三方信息共享清单、个人信息收集清单。
- [ ] **No-Go-L02** 实际收集目的、字段、调用时机、接收方或保留期与告知内容不一致。
- [ ] **No-Go-L03** 首次进入即申请相机、麦克风、相册、位置等权限，未做到“使用时申请”和拒绝后可继续使用无关功能。
- [ ] **No-Go-L04** 健康信息、症状描述、问诊对话、录音、图片、体检资料、身份标识等敏感个人信息未取得单独同意，或撤回同意后仍继续采集。
- [ ] **No-Go-L05** 未成年人可独立提交敏感健康数据，但没有年龄识别、监护人同意或适当限制方案。
- [ ] **No-Go-L06** 日志、埋点、错误上报、模型提示词或缓存中出现明文手机号、身份证件、原始录音、完整病历或访问令牌。
- [ ] **No-Go-L07** 无账号注销/数据删除申请入口，或请求无法追踪、无法执行、没有处理时限。
- [ ] **No-Go-L08** 将用户健康数据、语音或图片发送给未披露的联网第三方；`edge-tts` 被错误描述为本地能力、Azure 正式商业 API 或已获服务保障。
- [ ] **No-Go-L09** 小程序平台隐私接口、类目、备案、域名、TLS、用户协议配置未按计划发布地区和当日平台规则核验。
- [ ] **No-Go-L10** 生产密钥、数据库口令、MinIO 凭据、模型服务管理接口或调试端点暴露于客户端包或公网。

### 2.2 医疗安全与 AI 边界

- [ ] **No-Go-M01** 页面或 AI 输出把系统描述为医生、医院、诊断工具或治疗方案提供者，但没有相应真实资质和审核依据。
- [ ] **No-Go-M02** AI 输出可能给出确诊、处方、停药/换药、剂量调整或替代线下就医指令，且没有规则拦截和人工升级路径。
- [ ] **No-Go-M03** 胸痛、呼吸困难、意识障碍、严重过敏、自伤他伤、孕产急症、婴幼儿高危等紧急信号未触发显著急救提示。
- [ ] **No-Go-M04** 风险评估、健康报告或检测数值没有来源、时间、单位、适用范围、局限性与“仅供健康管理参考”提示。
- [ ] **No-Go-M05** 用户无法区分 AI 生成内容、规则计算结果、用户原始数据和人工意见。
- [ ] **No-Go-M06** AI 失败时用臆测结果、旧结果或占位值冒充本次结果；无法回溯模型版本、提示模板版本和安全策略版本。
- [ ] **No-Go-M07** 医疗知识库无来源与版本控制，过期或冲突内容可直接进入面向用户的高风险回答。
- [ ] **No-Go-M08** 语音识别误差未明确提示用户核对，高风险症状或药品名称未经文本确认即进入后续建议。

### 2.3 技术、安全与可用性

- [ ] **No-Go-T01** 24 页中任一核心入口依赖前端硬编码“权威数据”（健康指标、问卷结论、会员权益、服务状态、知识内容、设备/用户状态），导致不同终端口径不一致。
- [ ] **No-Go-T02** 鉴权仅靠前端标记；对象 ID 可枚举访问他人报告、对话、文件或任务。
- [ ] **No-Go-T03** 上传文件未校验大小、扩展名、MIME、魔数与恶意内容；对象存储桶公开或永久 URL 泄漏。
- [ ] **No-Go-T04** 资源文件、头像、插图、数字人素材或非关键模型资源缺失会导致小程序、Spring Boot 或 FastAPI 无法启动。
- [ ] **No-Go-T05** API 无统一超时、重试上限、幂等键、错误码与请求追踪 ID；重复点击可能造成重复写入或重复任务。
- [ ] **No-Go-T06** 生产环境没有备份恢复验证、最小权限、审计日志、容量告警和可执行回滚方案。
- [ ] **No-Go-T07** AI 服务不可用时没有安全降级，0.5B/7B 切换会丢会话、改变接口契约或越过资源保护阈值。
- [ ] **No-Go-T08** 线上仍使用演示数据冒充真实用户数据，或以“已完成/正常/低风险”等结论掩盖接口失败。

## 3. 必须人工确认的事项

### 3.1 法律人工确认（法律/合规负责人）

以下内容不能由开发团队或本文自动作出结论：

1. 产品运营主体、个人信息处理者身份及联系方式是否准确。
2. 产品实际功能对应的小程序类目、备案、许可、资质及发布地区要求。
3. 是否构成互联网诊疗、医疗器械软件、健康咨询、健康管理或其他受监管活动。
4. 隐私政策、用户协议、儿童/未成年人条款、敏感信息单独同意的有效性。
5. 微信平台、地图/短信/语音合成/云服务等第三方条款与跨境传输安排。
6. 数据保留期限、删除例外、法定义务和争议留存策略。
7. 开源模型、字体、图标、图片、音视频、知识库和依赖的许可证及商用权利。
8. `edge-tts` 的使用方式是否符合第三方服务条款；它不是本项目可承诺 SLA 的 Azure 正式商业 API。

**留痕要求**：确认人、角色、确认日期、适用版本、依据链接/文件、保留意见、复核日期。

### 3.2 医疗人工确认（具备相应职责的医疗专业人员）

1. 所有急症触发词、风险分级、转诊/急救文案及漏报处理。
2. 问卷题目、计分规则、阈值、单位、参考范围和适用/禁用人群。
3. AI 回答允许范围、禁止范围、免责声明位置与强度。
4. 药品、疾病、检验指标、孕产、儿科、心理危机等高风险内容策略。
5. 知识内容来源、发布日期、更新频率、冲突解决和撤回机制。
6. 语音识别错误对医疗含义的影响与强制复核点。
7. 健康报告结论是否可能被误解为诊断或治疗依据。

**不得替代**：医疗人工确认不能替代法律确认；法律确认也不能证明医学内容正确。

## 4. 24 页通用 UI/UX 审查

每页均须逐项验证，不得只抽查首页：

- [ ] 默认态明确当前任务、主要操作和返回路径。
- [ ] 加载态使用骨架屏/局部进度，不用无期限全屏转圈；超过 2 秒给出说明。
- [ ] 空态说明“为什么为空”和下一步；不能把接口失败显示成“暂无数据”。
- [ ] 错误态包含可理解原因、重试、反馈入口和请求 ID（如适用）。
- [ ] 离线态保留可安全查看的本地内容，禁止写操作假成功；恢复网络后由用户确认重试。
- [ ] 超时态与业务失败区分，不自动无限重试；AI 长任务可查询状态和取消。
- [ ] 无权限态区分“系统未授权、账户无权限、资源不存在”；不泄漏资源是否属于他人。
- [ ] 拒绝授权后解释用途并提供替代输入，非相关功能可继续使用。
- [ ] 破坏性操作二次确认，可撤销时优先撤销；重复提交受幂等保护。
- [ ] 页面不以颜色作为唯一信息通道；文字对比度、字号、触控区域符合无障碍基线。
- [ ] 手机 320–430 CSS px 和常见平板横/竖屏无横向溢出，安全区、键盘顶起、分栏变化正确。
- [ ] 读屏顺序、控件语义、焦点、错误提示关联和动态内容播报可理解。

## 5. API 与数据整改清单

- [ ] 以服务端为权威：用户档案、同意记录、问卷版本与答案、评估结论、会话、报告、任务、资源元数据、功能开关、内容版本均后端化。
- [ ] 客户端仅缓存可失效副本，响应携带 `version/updatedAt` 或 ETag；冲突由明确策略处理。
- [ ] 契约统一：`requestId`、业务 `code`、用户可读 `message`、可选 `details`，HTTP 状态码语义正确。
- [ ] 所有写请求支持鉴权、授权、参数校验、速率限制；关键写操作支持 `Idempotency-Key`。
- [ ] 列表采用游标或稳定分页，明确排序；时间统一 ISO 8601 与时区，数值带单位。
- [ ] 文件采用短期签名 URL；数据库只保存对象键、哈希、大小、MIME、所有者和状态。
- [ ] AI 任务返回任务 ID，支持排队、运行、完成、失败、取消、过期；不得让网关连接无限等待。
- [ ] 敏感字段最小返回；禁止在 URL 查询参数传递健康信息和令牌。

## 6. AI 与模型审查

- [ ] 默认资源档为 0.5B；7B 仅在容量、延迟、内存和质量验证通过后按配置升级，接口不变。
- [ ] 本地 ASR 明确为 `qwen3-asr-0.6b` 目标组件；未实测前不得宣称准确率、实时率或方言医疗术语能力。
- [ ] Ollama、Qdrant、Redis 不可用时分别有超时、熔断、降级和可观测状态。
- [ ] RAG 引用可追踪到知识条目版本；检索为空或置信不足时明确“不足以回答”。
- [ ] 输入输出经过安全分类；提示注入不能访问其他用户数据、系统提示词或管理工具。
- [ ] `edge-tts` 标记为联网第三方、非 Azure 正式商业 API；失败不阻断文本答复，隐私政策披露发送内容。
- [ ] 内容寻址缓存键至少包含规范化输入哈希、模型/声音/参数/模板版本、租户隔离信息；禁止仅按文件名命中。
- [ ] 缓存命中仍执行授权；删除源数据时同步处理关联缓存或使其不可达。

## 7. 发布前证据包

至少保留以下证据，不要求提交给终端用户：

- 24 页状态矩阵及手机/平板截图；关键读屏和键盘操作记录。
- API 契约测试、越权测试、错误码与超时/离线演练结果。
- 紧急医疗信号、拒答、转人工/线下就医提示测试集及医疗人工确认记录。
- 隐私告知与同意版本、权限调用清单、第三方数据流核对记录。
- 依赖与素材许可证清单、漏洞扫描和密钥扫描结果。
- 备份恢复、限流熔断、资源缺失启动、0.5B/7B 切换、AI 服务不可用演练。
- 版本号、构建哈希、配置摘要、数据库迁移版本、回滚包与负责人。
