### 11.2 补跑中新发现并修复：N-5（D 侧）

**现象**：E2E-B1 首轮（22:10）经网关恒定 `503 TTS_UNAVAILABLE`，而 ai-service `readiness.tts_provider=available` —— 矛盾指向执行器内部。

**根因（已坐实）**：现场留有一枚 **0 字节产物** `runtime/tts/dbca9ad2e4328a8c.mp3`，其名 = `sha256("请按时服药，注意休息。如有不适请及时就医。|zh-CN-XiaoxiaoNeural|zh-CN")[:16]` —— 正是 E2E 文本。执行器把「文件存在」当缓存命中 → 跳过合成 → 再判「产物为空」失败 → **该文本被永久毒化（永不再合成）**。

**修复**（`app/voice.py` + `app/executors/tts.py`）：
1. **命中契约**：命中 = 产物**存在且非空**；0 字节残留先删再重合成；
2. **原子落盘**：`synthesize` 先写 `{name}.part`，成功且非空才 `replace()` 到目标名；失败/空产出删临时文件——半成品永不成为缓存产物；
3. **纵深防御**：执行器在合成异常路径**主动清理** `out_path`（不依赖合成器实现）；
4. **可诊断性**：失败时记录引擎异常原因（`err=RuntimeError: ...`），不再只记类名。

**自愈证明（同一任务内）**：换装前 `dbca9ad2e4328a8c.mp3 = 0B` → 修复后同文本请求 → **31680B**、`cached=false`；再请求 → `cached=true` 同 URL。
