# Spring Boot 业务后端开发指南（V4）

> 目标架构：Spring Boot + MySQL + MinIO，向小程序提供权威业务 API，并编排 FastAPI AI 服务。本文是实施指南，不代表仓库当前已完整实现这些组件或已达到生产标准。

## 1. 职责边界

Spring Boot 负责：登录与会话、用户与档案、同意记录、问卷定义/答案/规则结果、对话与消息元数据、报告、任务、文件元数据、内容版本、通知、审计、对象级授权、幂等和 AI 服务编排。

Spring Boot 不负责直接加载大模型，也不允许客户端绕过它访问 FastAPI、Ollama、Qdrant、Redis 或 TTS 第三方。FastAPI 返回的是候选生成结果；是否可交付用户仍由业务安全策略决定。

## 2. 推荐模块

```text
backend/
  app-api            # Controller、DTO、统一错误
  app-application    # 用例、事务、幂等、编排
  app-domain         # 聚合、策略、领域事件
  app-infrastructure # MySQL、MinIO、FastAPI 客户端、审计
  app-security       # 认证、授权、限流、脱敏
```

若保留单模块工程，也应按包维持相同依赖方向：接口层不得直接访问 Repository；领域层不得依赖 HTTP 或对象存储 SDK。

## 3. 核心数据模型

建议以真实需求裁剪，禁止因本文出现即机械建表：

- `users`：账号主体、状态、版本号、创建/更新时间。
- `user_profiles`：最少档案字段，与身份认证信息分离。
- `consent_records`：政策版本、目的、范围、同意/撤回、渠道和证据摘要；记录不可原地覆盖。
- `questionnaire_definitions` / `questionnaire_items`：版本化定义与医疗审核状态。
- `assessment_submissions` / `assessment_answers`：提交快照与答案。
- `assessment_results`：规则/模型版本、解释与边界提示。
- `conversations` / `messages`：对话和消息状态；大媒体仅存对象引用。
- `ai_tasks`：任务类型、状态、输入引用、结果引用、策略/模型版本、重试与过期时间。
- `file_objects`：MinIO 对象键、哈希、MIME、大小、所有者、扫描状态、保留类别。
- `content_items` / `content_versions`：知识内容、来源、审核、生效与撤回。
- `deletion_requests`：删除/注销范围、状态、法定保留例外和执行证据。
- `audit_events`：不可含原始健康内容；保存谁在何时对哪类对象执行何动作。

所有含用户数据的表都应有不可由客户端指定的所有者/租户字段，并建立对象级授权测试。金额、计量值、风险等级等不可用模糊字符串替代结构化字段。

## 4. API 实现规范

### 4.1 控制器

- 只处理协议转换、Bean Validation、认证上下文和 HTTP 状态。
- DTO 与持久化实体分离，禁止把实体直接序列化。
- 未知 JSON 字段策略明确；敏感写接口建议拒绝拼写错误字段。
- 统一返回 `code/message/requestId/serverTime/data/meta`。

### 4.2 鉴权与授权

- 微信登录凭证仅在后端换取；客户端不保存第三方密钥。
- 访问令牌短期有效，刷新令牌轮换并支持撤销。
- 每次对象读取/写入按当前主体校验所有权和作用域，不能只在列表入口过滤。
- `404` 与 `403` 策略避免暴露他人对象存在性。
- 管理操作采用独立角色、强认证、审计和网络边界。

### 4.3 幂等与并发

关键写请求要求 `Idempotency-Key`，以用户、操作类型、键组成唯一约束，保存请求摘要与最终响应。相同键不同载荷返回冲突。档案、问卷草稿等使用乐观锁 `version`；禁止最后写入无提示覆盖。

### 4.4 事务与事件

MySQL 事务只包围本地一致性操作，不把调用 FastAPI/MinIO 放入长事务。采用 Outbox：事务内写业务状态和事件，异步工作器投递 AI 任务、通知或清理对象。消费者按事件 ID 幂等。

## 5. MySQL 基线

- 字符集 `utf8mb4`；时间以带明确时区的应用语义存储，数据库统一 UTC 或明确约定。
- 迁移使用 Flyway/Liquibase，生产禁止自动破坏性建表更新。
- 索引根据真实查询验证：所有者+状态+时间、任务状态+更新时间、对象哈希等。
- 健康数据字段最少化；特别敏感字段按威胁模型做列级/应用层加密，密钥与数据库分离。
- 备份加密、限制访问，定期做恢复演练；“有备份文件”不等于可恢复。
- 删除采用可审计工作流：软删除只用于恢复窗口，期满后清理主库、对象存储、缓存和派生数据；法定保留须记录依据。

## 6. MinIO 文件服务

### 6.1 上传流程

1. 客户端向 Spring Boot 请求上传意图，声明用途、预计 MIME 和大小。
2. 后端校验权限、配额和用途，生成短期预签名上传地址及对象键。
3. 客户端直传 MinIO；完成后通知后端。
4. 后端核验对象存在、大小、MIME、文件魔数和 SHA-256，执行安全扫描。
5. 只有状态为 `AVAILABLE` 的对象才能进入业务流程。

桶默认私有；客户端永不获得 MinIO 管理凭据。对象键使用随机 ID/哈希分片，不包含姓名、手机号、病种或原文件路径。下载使用短期预签名 URL，并在签发时再次鉴权。

**关于"直传"与"不公网暴露"的口径**（与 `docs/v4/05` 第 1 节不矛盾）：

- **不公网暴露**指的是 MinIO 的**管理控制台、S3 管理 API 与内部网络面**，这些绝不对外开放。
- **客户端直传**指的是经由**反向代理暴露的受控对象数据端点**（仅放行签名 URL 的 GET/PUT，限定路径与有效期），或退化为**经业务网关代理上传**。
- 两种模式二选一，由架构与安全共同定稿，**并在 `docs/v4/06` 的 SEC-09 用例中验证**：匿名访问对象必须失败，签名过期后必须失败。
- **当前状态**：口径未最终敲定，列为 `docs/v4` 待决事项 O-01，实施前必须闭环。

### 6.2 内容寻址与去重

可按 `sha256/前2位/完整哈希` 保存不可变内容，但业务授权不能由“知道哈希”获得。`file_objects` 维护逻辑所有者和引用。跨用户物理去重需先完成隐私侧信道评估；默认仅在同一安全域内去重。

### 6.3 资源故障不阻断启动

应用启动时不得同步要求所有默认头像、插图、数字人资源或示例文件存在。资源读取返回显式占位元数据；后台巡检报告缺失。只有数据库迁移失败、关键密钥缺失等真正不可安全运行的条件才应阻断启动。

## 7. FastAPI 编排

使用受控内部服务身份和 mTLS/私网（按部署条件选择）。调用包含 `traceId`、任务 ID、最小必要输入引用、策略版本和资源档，不传客户端任意模型名。

- 提交成功后业务状态为 `QUEUED`；通过回调或轮询更新。
- 设置连接、读取、总任务期限；重试仅针对安全可重试错误。
- 断路器开启时立即返回可理解的 AI 暂不可用状态。
- 回调必须签名、校验时间窗并幂等；未知任务不得落库。
- AI 原始输出先进入隔离结果，经过安全策略后生成面向用户的消息。

## 8. 医疗与 AI 安全

- 服务端在模型前后执行规则：急症提示优先于生成；处方、确诊、停药/剂量等内容按确认策略拒绝或转介。
- 保存模型档、模型版本、提示模板版本、知识库版本和策略版本，不默认保存完整提示词/敏感正文到通用日志。
- 报告、评估和消息明确类型：`USER_INPUT`、`RULE_RESULT`、`AI_GENERATED`、`HUMAN_REVIEWED`。
- 医疗免责声明不能只藏在协议；应在高风险输出附近显示，但不能用免责声明替代产品限制。

任何风险规则与医疗阈值需医疗专业人员确认；是否需要资质由法律/合规人员确认。

## 9. 缓存策略

业务缓存可使用本地短 TTL 或 Redis（若由总体架构提供），但 MySQL 是权威源。缓存键包含租户/用户和版本；敏感对象不使用可猜测键。权限在返回缓存前校验。更新采用删缓存/版本化，不实施无界 TTL。

AI 内容寻址缓存由 FastAPI 管理时，Spring Boot 保存任务与结果引用；撤回同意、删除请求或对象失效通过事件通知缓存清理。

## 10. 错误、超时与降级

| 故障 | 服务端处理 | 客户端语义 |
|---|---|---|
| MySQL 不可用 | 就绪探针失败，停止接收业务流量 | 服务暂不可用，不显示空数据 |
| MinIO 不可用 | 非文件页面继续；上传/下载返回可重试错误 | 保留表单，稍后重试 |
| FastAPI 不可用 | 熔断；创建任务可失败或延迟入队 | AI 暂不可用，核心非 AI 功能继续 |
| 非关键资源缺失 | 占位资源、告警 | 页面可用 |
| 下游超时 | 终止等待、保留任务可查询状态 | 超时而非失败/空态 |

严禁捕获异常后返回 `200 + 空对象`。

## 11. 安全基线

- 配置来自环境变量/密钥管理，不提交真实密钥；生产关闭调试、堆栈和开放管理端点。
- Actuator 仅暴露最少健康指标，管理网络隔离。
- 限制请求体、分页大小、上传大小和并发；对登录、上传、AI 提交、导出单独限流。
- ORM 参数化查询；富文本白名单净化；防 SSRF 的 URL 白名单与 DNS/IP 复核。
- 审计日志防篡改并设访问权限；应用日志进行字段脱敏和保留期管理。
- 依赖漏洞、容器镜像、许可证和密钥扫描进入 CI。

## 12. 可观测性

指标至少覆盖：请求量/延迟/错误码、鉴权失败、幂等冲突、连接池、慢查询、MinIO 错误、AI 任务队列时长/成功率/超时、熔断状态、删除任务积压。日志使用请求 ID/任务 ID 串联，不记录敏感正文。告警必须对应值班动作，避免只收集不处置。

## 13. 测试策略

- 单元测试：权限策略、状态机、幂等、问卷版本、删除规则。
- Repository 集成：真实 MySQL 容器、迁移向前/回滚策略。
- MinIO 集成：签名上传、恶意类型、超限、孤儿清理。
- 契约测试：小程序 API 与 FastAPI 内部 API。
- 安全测试：跨用户 IDOR、批量赋值、重放、令牌撤销、日志泄漏。
- 故障测试：MinIO/FastAPI/非关键资源缺失不阻断核心启动；数据库故障正确拒绝就绪。

## 14. 发布步骤

1. 冻结 OpenAPI 和数据库迁移，备份并验证恢复点。
2. 在影子/预发环境执行迁移与兼容测试。
3. 先部署向后兼容后端，再发布小程序；破坏性清理延后。
4. 验证健康、核心读写、对象授权、文件上传、AI 降级和审计。
5. 灰度观察指标；触发阈值则回滚应用，数据库采用预先设计的向前修复或兼容回退。
6. 发布后再下线旧字段和任务消费者。
