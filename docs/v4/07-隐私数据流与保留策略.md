# 隐私数据流与保留策略（V4）

> **文档状态**：本文定义**目标隐私基线与拟实施的数据流**，不构成法律意见，也不表示相关机制已实现或已通过合规审查。
> 保留期限、法定例外与跨境安排**必须由法律/合规人员确认**；本文给出的时限为**建议值，标注"待确认"**，未确认前不得写入对外隐私政策。
> 页面范围以 `miniprogram/app.json` 为准，当前 24 页。

---

## 1. 基本原则

1. **最小必要**：只收集当前功能必需字段；能用聚合值就不收集明细。
2. **目的绑定**：一次收集只用于已告知的目的，不得二次利用。
3. **端侧最少**：健康、语音、图像、会话等敏感数据不留存于客户端。
4. **单独同意**：敏感个人信息与系统权限分别取得，分别留痕，分别可撤回。
5. **可删除**：用户可注销、可删除、可撤回；删除必须真实执行并可审计。
6. **默认不记录**：日志、埋点、错误上报默认不含健康内容与身份标识。
7. **第三方透明**：任何联网第三方（含语音合成）必须在第三方清单中披露。

## 2. 数据分类与敏感级别

| 级别 | 数据类别 | 示例 | 处理要求 |
|---|---|---|---|
| **S0 公开** | 科普内容、医院公开信息 | 文章标题、科室简介 | 无特殊限制，但需标注来源与版本 |
| **S1 内部** | 聚合统计、系统配置 | 号源总数、床位占用数 | 不含个人标识；按角色授权 |
| **S2 个人一般** | 账号标识、偏好 | 用户 ID、字号档位、音色偏好 | 最小化；可本地保存偏好 |
| **S3 个人敏感** | 身份与联系方式 | 手机号、姓名、出生日期、就诊人关系 | 加密存储、脱敏展示、严格最小化 |
| **S4 健康敏感** | 症状、病史、指标、影像、病历 | 症状描述、血压、检查报告 | 单独同意；访问审计；禁止进入埋点 |
| **S5 强敏感** | 语音原文、会话正文、证件号、生物特征 | 原始录音、问诊对话、身份证号 | 最高保护；默认最短保留；默认不落日志 |

**判定规则**：无法确定级别时，按更高一级处理。

## 3. 数据流全景

```text
┌─────────────┐
│ 微信小程序  │  端侧：仅存 refresh token、偏好、非敏感资源版本
└──────┬──────┘  ❌ 不存：健康数据、会话正文、预约记录、原始录音
       │ HTTPS（正式备案域名 + TLS）
┌──────▼──────────────────────────────┐
│ 反向代理 / WAF / 网关                │  仅暴露必要业务入口
└──────┬──────────────────────────────┘
       │
┌──────▼──────────────────────────────┐
│ Spring Boot（业务权威层）            │  身份、授权、同意、业务状态、审计
└──┬────────┬─────────┬───────────────┘
   │        │         │
┌──▼───┐ ┌──▼───┐ ┌───▼──────────────────┐
│MySQL │ │MinIO │ │FastAPI（内部 AI 服务）│
│权威源│ │私有桶│ └───┬──────┬──────┬─────┘
└──────┘ └──────┘     │      │      │
                 ┌────▼┐ ┌───▼──┐ ┌─▼──────────┐
                 │Redis│ │Qdrant│ │Ollama 本地  │
                 │临时 │ │知识  │ │ASR 本地     │
                 └─────┘ └──────┘ └────────────┘
                                     ┌─▼───────────────┐
                                     │edge-tts（联网第 │
                                     │三方，可关闭）   │
                                     └─────────────────┘
```

**关键约束**：客户端不得绕过 Spring Boot 直接访问 FastAPI、Ollama、Qdrant、Redis 或 TTS 第三方。

## 4. 逐环节数据流与要求

### 4.1 客户端（微信小程序）

| 数据 | 是否可存 | 要求 |
|---|---|---|
| refresh token | 是 | 仅存令牌与到期时间；access token 只驻留内存 |
| 角色提示 | 是 | **非权威**，仅用于界面提示，绝不用于鉴权 |
| 用户资料、档案、预约、会话 | **否** | 一律从服务端读取 |
| 健康表单草稿 | 有条件 | 需加密、短期、用户明确允许；提交前必须联网确认 |
| 原始录音 | **否** | 转写完成后立即释放；不上传前不落盘 |
| 偏好（字号/高对比/音色） | 是 | 非敏感，可本地保存 |
| 匿名质量计数 | 是 | 不含任何可识别信息 |

**禁止**：`sitemap.json` 允许索引私密页面（登录、患者、医生、预约、记录、档案）；以手机号在客户端过滤全量列表；以本地键伪造业务记录。

### 4.2 传输

- 全链路 HTTPS，正式备案域名，禁止临时隧道域名用于生产。
- 令牌放 `Authorization` 头，**禁止放入 URL 查询参数**。
- 健康信息禁止放入 URL 路径或查询串。
- 请求携带 `X-Request-Id` 用于追踪，但请求 ID 不得成为可枚举的资源凭证。

### 4.3 Spring Boot（业务权威层）

| 数据 | 存储 | 要求 |
|---|---|---|
| 账号与身份映射 | MySQL | openid 加密存储；手机号加密或受控存储 |
| 同意记录 | MySQL | **追加写，不原地覆盖**；含政策版本、目的、范围、时间、渠道、证据摘要、撤回记录 |
| 就诊人资料 | MySQL | 最小字段；与认证信息分离 |
| 预约与状态流转 | MySQL | 稳定 ID 关联，不以姓名/手机号关联 |
| 健康档案与文件元数据 | MySQL + MinIO | 文件存私有桶，库中只存对象键、哈希、大小、MIME、所有者、状态 |
| 问诊会话与消息 | MySQL | 权威记录；AI 原始输出先入隔离区，经安全策略后才成为用户可见消息 |
| 审计日志 | MySQL | 记录"谁在何时对哪类对象执行何动作"；**不含健康正文** |
| 删除申请 | MySQL | 范围、状态、法定保留例外、执行证据、处理时限 |

**对象级授权**：每次读取/写入都校验当前主体对目标对象的权限；禁止只在列表入口过滤。`404` 与 `403` 策略避免暴露他人对象存在性。

### 4.4 MinIO（对象存储）

- 桶默认**私有**；客户端永不获得管理凭据。
- 对象键使用随机 ID / 哈希分片，**不得包含**姓名、手机号、病种或原始路径。
- 上传流程：创建意图 → 短期预签名上传 → 服务端核验存在/大小/MIME/魔数/SHA-256 → 安全扫描 → 状态 `AVAILABLE`。
- 下载使用**短期**签名 URL，签发时再次鉴权。
- 跨用户物理去重需先完成隐私侧信道评估；默认仅同安全域内去重。
- **待决**：直传 MinIO 与"MinIO 不公网暴露"的表述冲突，需明确为"经反向代理的受控对象数据端点"或"经网关代理上传"（见 V4 第 9.1 节 O-01）。

### 4.5 Redis（临时层）

**允许存储**：任务状态、SSE 游标、限流计数、单飞锁、内容寻址缓存索引。
**禁止存储**：长期令牌、原始录音、完整病历、无期限提示内容、任何作为唯一副本的业务数据。

所有键**必须设置 TTL**。Redis 不可用时拒绝新重任务或切受限模式，不得无界接收。

**建议 TTL（待确认）**：

| 键类型 | 建议 TTL | 说明 |
|---|---|---|
| 任务状态 | 24 小时 | 最终状态回写 MySQL，Redis 仅作热缓存 |
| SSE 游标 | 1 小时 | 断线恢复窗口 |
| 单飞锁 | 短于任务总超时 | 租约 + 唯一令牌释放 |
| 限流计数 | 1 分钟–1 小时 | 按维度设置 |
| TTS 音频缓存 | 7 天 | 仅非敏感、通用文本；敏感内容不缓存 |
| ASR 结果缓存 | 1 小时 | 短保留；支持立即删除 |

### 4.6 Qdrant（向量检索）

- 只索引**已通过医学审核**的知识材料。
- **禁止**写入患者身份、聊天全文或任何可识别用户的原文。
- 每个知识块至少包含：`documentId`、`chunkId`、版本、来源、发布日期、有效期、审核状态、适用人群、主题、内容哈希。
- 内容撤回后先在检索层禁用，再异步清理。
- 向量相似度**不是**医学置信度，不得对外表述为置信度。

### 4.7 Ollama 与本地 ASR

- 仅绑定内网/回环，禁止公网无认证访问。
- 默认不记录输入原文与输出全文；调试采样须审批、短保留、访问受控。
- 限制最大输入、输出、上下文与并发，防止单任务耗尽资源。
- 模型文件缺失返回 `CAPABILITY_UNAVAILABLE`，**禁止启动时联网自动下载未锁定模型**。
- ASR 音频：统一转 16kHz 单声道；限制时长（建议 ≤60 秒）、文件大小与队列长度；使用受控临时目录，任务结束即清理。
- ASR 结果必须由用户核对，尤其是症状、药名、剂量、数字与时间。

### 4.8 edge-tts（联网第三方）

**必须如实披露**：

- 它是**联网第三方服务**，待合成文本会发送至外部服务。
- 它**不是**本项目购买并受 SLA 约束的 Azure 正式商业 API，也**不是**本地离线 TTS。
- 可用性、配额、声音列表、地区与数据处理方式可能变化，必须设置超时、熔断与功能开关。

**处理要求**：

- 调用前对姓名、手机号、证件号、病历号等脱敏。
- 高敏感内容**默认不自动朗读**。
- 用户拒绝后保持文字模式。
- 失败返回文本 + `TTS_UNAVAILABLE`，**不得播放伪造占位音频**。
- 出口网络收紧到必要目标；记录调用状态但**不记录文本**。
- 正式商用前由法律、隐私与采购评估是否更换为有合同与数据处理承诺的服务。

## 5. 同意管理

### 5.1 同意的三个层次

| 层次 | 对象 | 取得方式 |
|---|---|---|
| 平台协议 | 用户协议、隐私政策 | 首次使用前展示，明示同意 |
| 敏感个人信息单独同意 | 健康信息、语音、图像、就诊人资料 | **独立勾选**，不默认选中，不与登录捆绑 |
| 系统权限 | 麦克风、相机、相册、通知 | 用户触发相应功能时申请 |

**铁律**：系统权限同意 ≠ 敏感个人信息单独同意；登录 ≠ 同意全部条款。

### 5.2 同意记录字段

`政策版本`、`目的`、`范围`、`同意/撤回时间`、`渠道`、`客户端版本`、`证据摘要`、`撤回原因（可选）`。

记录**追加写**，不原地覆盖；撤回后相关采集入口立即关闭。

### 5.3 撤回后的行为

| 能力 | 撤回后 |
|---|---|
| 症状上传（导诊/问诊） | 仅使用本地规则，不上传 |
| 语音输入 | 麦克风入口关闭，仅文本 |
| 图像上传 | 相册/相机入口关闭 |
| 健康档案同步 | 停止同步，已存数据按删除流程处理 |
| 个性化推荐 | 退化为通用内容 |

## 6. 缓存与内容寻址

### 6.1 键设计

```text
inputDigest = SHA-256(canonicalBytes)
cacheKey = HMAC-SHA256(
  tenantSecret,
  taskType | inputDigest | modelId | modelVersion | quantization |
  promptTemplateVersion | policyVersion | knowledgeSnapshot |
  voice | locale | generationParameters
)
```

- 敏感原文**不得**出现在键或日志中。
- 规范化必须保留有医学意义的数字、单位、否定词与时间，**不得**为提高命中率而合并不同含义。
- 命名统一：早期文档中的 `tenant-salt` 与 `tenantSecret` 是同一概念，**契约中统一为 `tenantSecret`**（见 V4 第 9.1 节 O-03）。

### 6.2 隔离与授权

- 不同租户/用户**必须隔离**；患者内容加入作用域，防止跨用户命中形成隐私侧信道。
- **授权先于命中**：命中缓存也必须先校验调用方对目标对象的授权与任务用途。
- 高风险生成默认**不跨用户共享**；跨用户去重须经隐私评估。

### 6.3 失效事件

以下任一发生即失效或使缓存不可达：源对象删除、用户撤回同意、安全策略升级、知识撤回、模型/模板版本变更、权限变化。

## 7. 日志、埋点与可观测性

### 7.1 允许记录

时间、级别、服务、环境、请求/任务 ID、路由、状态码、错误码、耗时分桶、客户端版本、匿名会话标识、模型/模板/策略版本。

### 7.2 禁止记录

令牌、密码、手机号、身份证件、问卷答案、原始录音、完整对话、转写全文、生成全文、报告正文、图片签名 URL、知识全文。

### 7.3 脱敏要求

- 手机号：展示层脱敏为 `138****8888`；存储层加密或受控。
- 姓名：按服务端策略展示（如 `张*`）。
- 证件号、住院号：仅展示末位或全脱敏。
- 堆栈仅进受控日志，不返回客户端。

### 7.4 埋点约束

禁止：对话正文、问卷答案、录音转写、图片地址、报告内容、身份证明、手机号、令牌。
允许：页面路由、功能按钮枚举、成功/失败代码、耗时分桶、客户端版本、匿名标识。

## 9. 用户权利与执行流程

### 9.1 权利清单

查询、复制、更正、删除、撤回同意、注销账号、投诉。

### 9.2 注销流程

1. 用户在"设置"页发起，页面列出：将删除的数据类别、法定保留例外、处理时限、是否可撤销。
2. 需输入确认文字防误触。
3. 服务端创建删除申请并返回受理编号与预计完成时间。
4. 执行覆盖：主库、对象存储、缓存（Redis/Qdrant 派生数据）、备份中的再删除机制。
5. 完成后通知用户；保留执行证据。
6. 法定保留项单独列出并说明依据。

**禁止**：设置不合理障碍（如仅支持联系客服注销）、注销后继续采集、以"已提交"代替"已删除"。

### 9.3 撤回同意流程

与注销分离：撤回只关闭对应能力，不删除账号。撤回后立即停止相关采集与处理；已收集数据的处理方式须明确告知。

## 10. 未成年人保护

- 未满 14 周岁的用户需监护人同意。
- 为儿童添加家庭成员时，必须由监护人确认处理其健康信息。
- 涉及儿童健康数据的功能需单独评估必要性。
- 不得向未成年人推送与其健康数据关联的营销内容。
- 年龄识别方案与限制策略**待法务与产品共同确认**。

## 12. 安全基线

- 密钥由环境变量或密钥服务注入，不提交仓库，生产无默认值。
- 敏感字段按威胁模型做列级或应用层加密，密钥与数据库分离。
- 数据库、对象存储、队列凭据分别授权并定期轮换。
- 出口网络默认收紧，仅放行必要目标。
- 备份加密、最小访问、到期销毁，并定期恢复演练。
- 所有写操作支持鉴权、授权、参数校验与速率限制；关键写操作支持 `Idempotency-Key`。
- 上传校验大小、扩展名、MIME、魔数与恶意内容。
- ORM 参数化查询；富文本白名单净化；防 SSRF 的 URL 白名单与 DNS/IP 复核。
