# FastAPI AI 后端开发指南（V4）

> 目标技术栈：FastAPI + Redis + Qdrant + Ollama；默认 0.5B 资源档，可配置升级 7B；本地语音识别目标为 `qwen3-asr-0.6b`；语音合成可通过 `edge-tts` 适配。本文是目标方案，不代表组件均已落地、模型效果已验证或第三方服务可正式商用。

## 1. 服务定位

FastAPI 是内部 AI 编排与推理服务，不是小程序直接后端。它接受 Spring Boot 创建的受控任务，完成安全预检、检索、模型调用、ASR/TTS、内容寻址缓存和结果封装。

边界：

- Spring Boot：用户身份、对象授权、同意记录、业务状态、审计主账和最终交付决策。
- FastAPI：AI 任务执行、模型适配、检索、生成安全、推理元数据和缓存。
- Redis：短期队列/状态/锁/限流/缓存索引，不作为医疗业务永久事实源。
- Qdrant：版本化知识向量与最小元数据，不存无必要的可识别用户原文。
- Ollama：本地模型运行适配层，仅内网暴露。

## 2. 推荐目录与依赖方向

```text
ai-service/
  api/            # 内部路由、DTO、鉴权
  application/    # 任务编排、状态机、策略
  domain/         # 任务、引用、安全判定
  adapters/
    ollama/
    qdrant/
    redis/
    asr/
    tts/
    object_store/
  workers/        # 异步执行器
  observability/
```

路由层不直接拼提示词或调用模型；适配器不决定医疗业务规则。提示模板、安全策略、知识库清单均版本化。

## 3. 内部 API

建议最小端点：

- `POST /internal/v1/tasks`：创建任务，要求服务身份、时间戳、签名/令牌、幂等键。
- `GET /internal/v1/tasks/{id}`：查询状态和可交付结果引用。
- `POST /internal/v1/tasks/{id}/cancel`：尽力取消，状态转换幂等。
- `POST /internal/v1/callbacks/task-events`：**向 Spring Boot 回传终态**（成功后、失败后、取消后各一次）。
  要求：HMAC 签名 + 时间窗（建议 ±5 分钟）+ 幂等（同一 `eventId` 重复投递只生效一次）+ 未知任务不落库。
  载荷最小字段：`eventId`、`taskId`、`tenantId`、`status`、`resultRef`、`errorCode`、`policyVersion`、`occurredAt`、`traceId`。
  **当前状态**：回调端点在 `docs/v4/03` 第 7 节仅表述为"回调或轮询"，具体路径与载荷字段**未定稿**，列为待决事项 O-02；在定稿前，Spring Boot 侧以**轮询 `GET /internal/v1/tasks/{id}`** 为唯一权威路径。
- `GET /internal/health/live`：进程存活，不检查所有外部资源。
- `GET /internal/health/ready`：按服务档判断是否可接受目标任务。

任务状态：`QUEUED → RUNNING → SUCCEEDED | FAILED | CANCELLED | EXPIRED`。阶段可为安全检查、检索、生成、后处理、合成等，禁止伪造模型不提供的精确进度百分比。

## 4. 模型档位

### 4.1 默认 0.5B

0.5B 是低配默认资源档，不等于质量已满足医疗场景。适用于意图整理、格式转换、低风险摘要等经测试任务。必须通过具体任务集评估后才能开放；置信不足、检索不足或风险过高时应拒答/转人工，而非靠小模型猜测。

### 4.2 7B 升级

7B 作为配置升级档，要求：

- 显存/内存、冷启动、并发和延迟压测通过；
- 同一 API/结果 Schema，不让前端感知模型切换；
- 针对医疗安全、幻觉、引用正确性进行回归；
- 有资源保护：队列上限、并发信号量、超时、熔断和回退；
- 回退至 0.5B 时不能把高风险 7B 任务强行交给能力不足的小模型，可返回能力暂不可用。

不得在文档中虚构具体 Ollama 标签；实际标签、量化和上下文长度记录在部署配置与模型清单中。

## 5. RAG 与 Qdrant

### 5.1 索引治理

每个知识块至少包含：`documentId`、`chunkId`、版本、来源、发布日期/有效期、审核状态、适用人群、主题和内容哈希。向量与正文访问受集合/载荷过滤限制。撤回内容后从检索层禁用，再异步清理。

### 5.2 查询流程

1. 最小化并净化查询，先做紧急医疗信号与注入检测。
2. 根据业务、语言、内容版本和适用范围过滤集合。
3. 检索并执行阈值/重排；无足够证据时返回“知识依据不足”。
4. 提示模型只基于候选证据生成，并输出引用 ID。
5. 后处理验证引用确实存在、版本有效且内容支持相应陈述。
6. 执行医疗与隐私安全策略，生成用户可见说明和局限。

向量相似度不能被表述为医学置信度。知识内容及阈值需医疗专业人员审核。

## 6. Ollama 适配

- 仅绑定内网/回环地址，禁止公网无认证访问。
- 连接、首字节、生成总时限分别配置；客户端取消传递到下游。
- 限制最大输入、最大输出、上下文和并发，防止单任务耗尽资源。
- 流式事件仅向 Spring Boot 内部发送；持久化最终安全结果，而不是不完整 token。
- 模型热身失败不应导致整个 FastAPI 进程无法提供健康检查、任务查询或非该模型能力；就绪状态按能力细分。
- 模型文件缺失返回 `CAPABILITY_UNAVAILABLE` 并告警，不下载未知资源后静默启动。

## 7. 本地 ASR：qwen3-asr-0.6b

目标组件为本地 `qwen3-asr-0.6b`，上线前必须用实际设备和真实授权测试集验证：普通话/目标方言、医疗术语、药名、数字、噪声、老年语音、长音频、实时率、内存和失败恢复。未经测试不得宣称准确率或方言医疗识别能力。

处理建议：

1. Spring Boot 提供受控音频引用，而非任意 URL。
2. 校验音频格式、时长、采样率、大小和恶意内容；转为受支持规范格式。
3. 执行 ASR，输出文本、模型版本和可用的时间戳/语言信息。
4. 删除临时音频，保留按政策允许的对象引用与任务证据。
5. 小程序必须让用户确认转写文本，尤其是症状、药品、剂量和时间。

模型加载失败只使 ASR 能力不可用，不阻断文本对话、任务查询和健康检查。

## 8. TTS：edge-tts 边界

`edge-tts` 应视为**联网第三方适配器**：

- 它不是本项目购买并受 SLA 约束的 Azure 正式商业 API；不得使用“Azure 官方商用接口”“本地离线 TTS”等表述。
- 可用性、配额、声音列表、地区和数据处理方式可能变化，必须设置超时、熔断和功能开关。
- 只发送合成所需文本，去除不必要的姓名、联系方式、身份标识；高敏感内容默认不自动朗读。
- 隐私政策和第三方清单披露其联网数据流；商用前由法律/隐私/采购人工评估。
- 失败时返回文字结果与 `TTS_UNAVAILABLE`，不让页面、对话或服务启动失败。
- 如需强 SLA、合同和数据处理承诺，应更换/新增经评估的正式商业服务适配器。

## 9. 内容寻址缓存

### 9.1 目标

相同规范输入、模型、模板、安全策略和参数可以复用安全结果，降低低配环境开销；缓存不是权威业务数据，不能绕过授权或删除。

### 9.2 键设计

```text
inputDigest = SHA-256(canonicalBytes)
cacheKey = HMAC-SHA256(
  tenantSecret,
  taskType | inputDigest | modelId | modelVersion | quantization |
  promptTemplateVersion | policyVersion | knowledgeSnapshot |
  voice | locale | generationParameters
)
```

敏感原文不出现在 Redis 键或日志。规范化必须保留有医学意义的数字、单位、否定词和时间，不能为了提高命中率而合并不同含义。

### 9.3 值与生命周期

值包含结果对象引用、完整性哈希、创建/过期时间、模型/模板/策略/知识版本、敏感级别。大结果存对象存储，Redis 仅存索引。命中流程必须先认证 Spring Boot 服务、校验租户/用户授权和任务用途，再返回引用。

以下事件失效：源对象删除、用户撤回同意、策略升级、知识撤回、模型/模板改变、权限变化。高风险生成默认不跨用户共享；跨用户去重须经隐私评估。

## 10. Redis 使用规则

- 队列/任务状态：设置 TTL 和最大长度；永久任务记录回写 Spring Boot。
- 分布式锁：短租约、唯一令牌释放，任务本身仍须幂等。
- 限流：按服务主体、租户、用户与任务类型分层。
- 故障策略：Redis 不可用时拒绝新重任务或切到受限同步/本地模式（仅经设计的低风险能力）；不得无界接收。
- 禁止缓存长期令牌、原始录音、完整病历和无期限提示内容。

## 11. 安全与医疗边界

### 11.1 输入安全

检查超长、编码异常、提示注入、越权引用和紧急医疗信号。用户文本始终作为数据，不作为系统指令。模型工具白名单、参数 Schema 和服务身份固定，禁止模型构造任意 URL/SQL/对象键。

### 11.2 输出安全

- 禁止模型冒充医生或声称确诊。
- 对处方、停换药、剂量、紧急症状、自伤他伤等执行专门规则。
- 显示 AI 标识、生成时间、依据引用、局限和就医升级建议。
- 规则命中或证据不足时返回结构化拒答，不用空字符串或“系统正常”掩盖。
- 不向用户展示隐藏思维链；仅给出可核验的依据摘要和引用。

医疗规则须由医疗专业人员确认，产品资质与文案由法律/合规人员确认。

## 12. 资源故障与启动策略

进程启动仅校验配置语法和最基本安全条件。Qdrant 集合、Ollama 某模型、ASR 权重、声音列表、默认素材或缓存预热失败时：

- 服务进程仍可启动并提供存活、任务查询和可用能力；
- 就绪接口按能力返回 `available/degraded/unavailable`；
- 新任务依据所需能力快速失败或排队，不无限等待；
- 后台重试有退避和上限；禁止启动时联网自动下载未锁定模型；
- 资源缺失产生可操作告警，不打印敏感路径/令牌。

只有服务身份密钥缺失、配置无法安全解析等条件才应整体拒绝接收流量。

## 13. 可观测性

指标：队列深度/等待时间、各任务成功/失败/取消、模型冷/热延迟、首 token/总生成时长、输入输出 token（如可得）、Qdrant 检索耗时和空结果率、缓存命中、ASR 音频时长与实时率、TTS 失败、GPU/CPU/内存、Ollama 熔断。

日志只含任务 ID、追踪 ID、版本和错误码；默认不记录用户原文、知识全文、转写全文或生成全文。调试采样必须有审批、短保留与访问控制。

## 14. 测试门槛

- 契约：任务创建/查询/取消/幂等/回调签名。
- 模型：0.5B 与 7B 分别测试质量、拒答、安全、延迟和资源，不以一个模型结果替代另一个。
- RAG：召回、引用一致、过期内容撤回、无结果和注入。
- ASR：目标方言、医疗术语、数字否定、噪声、长音频、坏文件和用户核对。
- TTS：断网、超时、限流、声音失效、敏感文本策略；验证失败不阻断文本。
- 缓存：版本隔离、租户隔离、权限先于命中、删除失效、哈希碰撞防护假设。
- 故障：Redis/Qdrant/Ollama/ASR 权重/TTS/非关键资源逐一中断，确认服务安全降级。
- 安全：SSRF、路径穿越、反序列化、提示注入、跨用户引用、日志泄漏和资源耗尽。

## 15. 部署检查

1. 锁定模型、依赖、提示模板、策略与知识快照版本及哈希。
2. 默认启用 0.5B 资源档；只有 7B 容量和回归通过后开放升级配置。
3. Ollama/Qdrant/Redis 仅内网访问，凭据最小权限。
4. 预热是优化，不是启动硬依赖；配置内存/磁盘/队列水位。
5. 先验证文本任务，再验证 RAG、ASR、TTS；每项有独立开关和回滚。
6. 发布后观察安全拒答、空检索、超时、资源和缓存指标；异常即关闭相应能力而非全站停服。

## 16. 不作出的承诺

本文不证明模型适合诊疗、不证明 `qwen3-asr-0.6b` 对目标方言达到特定准确率、不证明 `edge-tts` 具有商业 SLA，也不证明 0.5B/7B 已部署。正式结论必须来自真实运行、基准测试、许可证核验以及法律和医疗人工确认。
