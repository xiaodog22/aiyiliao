## 1. 与任务书的偏差声明（必读）

任务书假设的是「Spring Boot 8080 + FastAPI 其他端口 + Nginx 分流」。本项目实际拓扑不同，
**按现状落地等价方案，没有为了对齐文字而搬动服务端口**：

| 任务书 | 本项目实际 | 本轮处理 |
|---|---|---|
| Spring Boot 监听 8080 | Spring Boot `:8088` | **保持 8088**（改动会牵动 orchestrator、冒烟脚本、既有 228 例测试与部署卷）；对外不暴露 |
| FastAPI 在其他端口 | ai-service `:8001`，全部端点在 `/internal/**` | **保持内网**，仅通过 `/ai/health` 暴露一条探针 |
| Nginx 做 8080 统一入口 | 已有 `edge-gateway`（FastAPI）`:8000` | **端口从 8000 迁到 8080**，继续由网关分流；不引入 Nginx |
| `/api/` → Java，`/ai/` → Python | `/api/**` → Java（全量）；ai 仅内网 | 新增 `/ai/health` 白名单分流 |

**为什么不用 Nginx**：项目网关已经承担了 `/api/gw/**` 自身域、全量代理、legacy 兼容层（路径翻译 +
501 语义）、限流、统一错误信封、素材白名单通道。换成 Nginx 这些都要重做一遍，且多一跳。
任务书自己也写了「没有现成网关时，优先 Nginx」—— 这里有现成网关。

**为什么 `/ai/**` 不做通配代理**：ai-service 的全部业务端点都在 `/internal/**`（设计上仅供网关内网调用）。
通配转发等于把内部契约与鉴权边界一起暴露到公网。所以只开放一条只读探针 `/ai/health`，
新增 AI 对外能力必须先有契约端点，再在 `main.py` 显式登记一条。

## 2. 阶段一：统一入口 8080 与分流

### 2.1 实际路由表

| 前缀 | 去向 | 鉴权 | 说明 |
|---|---|---|---|
| `/api/gw/**` | 网关自身 | 部分（`/routes`、`/cast/**` 要 Authorization） | health / routes / voices 别名 / assets / tts audio |
| `/api/**`（除 gw） | Spring Boot `127.0.0.1:8088` | 由 Java `AuthInterceptor` 决定 | 路径**原样**转发，不做 StripPrefix |
| `/ai/health` | ai-service `127.0.0.1:8001/internal/health/live` | 公开只读 | 分流可用性探针 |
| `/health` | 网关自身健康 | 公开 | 旧探针兼容 |

**路径对齐**：`proxy_pass` 语义等价 `target_path = request.url.path`，**保留完整前缀**。
所以 Java 侧看到的仍是 `/api/v1/...`，与直连一致 —— 这是契约路径不做二次映射的前提。

### 2.2 关键配置

| 项 | 值 | 位置 |
|---|---|---|
| 统一入口端口 | `8080` | `backend/deploy/config.json` → `ports.gateway`；`edge-gateway/app/config.py` 默认值 |
| 上游 | business `http://127.0.0.1:8088`、ai `http://127.0.0.1:8001` | 同上 `upstreams` |
| 代理读超时 | `220s` | `config.json.proxyTimeoutSeconds` |
| query 透传 | 原样 `str(request.url.query)` 拼接 | `proxy.py` |

**超时取值说明**：任务书建议 300s。本项目最长链路是 care-plan（前端 180s → 网关 220s），
220s 已在 180s 上留 40s 余量；调到 300s 只会让「上游真挂了」的请求多占 80s 连接。
要改：`config.json` 的 `proxyTimeoutSeconds`，或环境变量（见 `config.py` 的 `GW_*` 覆盖链）。

### 2.3 本轮修正的两个网关缺陷（实测发现，非本次引入）

**① `Content-Length` 被代理丢弃**
`proxy.py` 原先把 `content-length` 与 `content-encoding` 一起从响应头剔除，
`StreamingResponse` 于是退化为 `Transfer-Encoding: chunked`。
后果：`<image>` 无法预判大小、下载无进度、`curl -I` 拿不到长度（任务书验收项直接失败）。
修复：只剔除 `content-encoding`，**保留 `content-length`**；
仅兼容适配分支（body 可能被改写）才剔除并按实际字节重算。

**② 路径穿越被规范化成「别的接口」**
请求 `GET /api/v1/resources/../..%2Fetc%2Fpasswd` 时，uvicorn 先把 `%2F` 解码进 `scope["path"]`，
httpx 再对 URL 规范化，**实际打到上游的是 `GET /etc/passwd`**，返回 501「该接口尚未实现」。
这不是"读到了文件"（Java 侧 `add-mappings: false`，无静态资源服务），但属于路径混淆，
语义完全错位。修复：`proxy.py` 在发上游请求前拒绝含 `..` 段的路径 → 400 `VALIDATION_FAILED`。

### 2.4 阶段一实测

curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/api/v1/departments
# 200
curl -s --noproxy '*' http://127.0.0.1:8080/ai/health
# {"status":"ok","uptimeSeconds":1741.9,"version":"0.1.0-m3"}   ← ai-service 的 /internal/health/live

> ⚠️ 本机环境有两个坑，验收脚本已处理，人工测时注意：
> - `HTTP_PROXY/HTTPS_PROXY` 指向本机代理，`curl` 打 `127.0.0.1` 也会被劫持（表现为 502），必须 `--noproxy '*'`；

## 3. 阶段二：资源库与流式返回

### 3.1 表结构（DDL）

文件：`backend/business-service/src/main/resources/db/migration/V14__resource_asset.sql`
（Flyway 已按序执行：`Successfully applied 6 migrations ... now at version v14`）

```sql
CREATE TABLE resource_asset (
    id           BIGINT       NOT NULL AUTO_INCREMENT,
    resource_key VARCHAR(128) NOT NULL COMMENT '业务唯一 key，如 home.svc-triage',
    category     VARCHAR(32)  NOT NULL COMMENT 'icon / image / cover / avatar / video',
    file_path    VARCHAR(512) NOT NULL COMMENT '相对 app.resources.dir 的路径（禁止绝对路径与 ..）',
    mime_type    VARCHAR(128) NOT NULL,
    file_size    BIGINT       NULL,
    sha256       CHAR(64)     NULL,
    status       TINYINT      NOT NULL DEFAULT 1 COMMENT '1 启用 / 0 停用（停用对外 404）',
    level        VARCHAR(1)   NOT NULL DEFAULT 'B' COMMENT '契约 ResourceItem.level：A | B',
    bundle_path  VARCHAR(255) NULL COMMENT '小程序包内兜底路径（清单 fallbackKey）',
    sort_order   INT          NOT NULL DEFAULT 100,
    created_at   DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at   DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    PRIMARY KEY (id),
    UNIQUE KEY uq_resource_asset_key (resource_key),
    KEY idx_resource_asset_status (status, sort_order)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci;
```

**只存路径与元数据，不存 BLOB**：`file_path` 是相对 `app.resources.dir` 的路径，
二进制永远在文件系统，由 `FileSystemResource` 零拷贝输出。

**key 为什么是单段点分（`home.svc-triage`）而不是斜杠分级**：
`AuthInterceptor` 的匿名白名单是**单段通配** `/api/v1/resources/*`，
多段 key 会匹配失败并被打成 401。所以分级语义统一用点号（与任务书示例 `icons.home` 一致）。

### 3.3 接口行为

`GET /api/v1/resources/{key}` → `ResourceController` → `ResourceAssetService`

| 情况 | 结果 |
|---|---|
| 正常（status=1，文件在，mime 白名单内） | `200` + 文件字节流 |
| key 形状非法（含 `..`、`/`、空白、超 128） | `400 VALIDATION_FAILED` |
| 无记录 / `status=0` / 文件缺失 / 路径越界 | `404 NOT_FOUND`（统一话术，不泄露存在性） |
| `If-None-Match` 命中 sha256 | `304`，无 body |

**安全模型（五层，任一层单独失效都不至于越界）**：
1. key 只做数据库查询，**绝不参与路径拼接**（路径 100% 来自 `file_path`）；
2. key 形状正则 `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`，且显式拒绝 `..`；
3. `Paths.get(file_path)` 必须非绝对，`resolve().normalize()` 后必须 `startsWith(root)`；
4. mime 白名单（png/jpeg/webp/gif/mp4/pdf），库内登记其它类型按不存在处理；
5. 只返回 `status=1`；文件不可读也按 404。

**响应头**：

| 头 | 值 |
|---|---|
| `Content-Type` | 取库内 `mime_type`（不写死 `application/octet-stream`） |
| `Content-Length` | `Files.size()`，显式设置 |
| `Cache-Control` | 图片 `max-age=604800, public` / 视频 `max-age=86400, public` / 其它 `max-age=3600, public` |
| `ETag` | `"<sha256>"`，支持 `If-None-Match` → 304 |
| `Content-Disposition` | `inline; filename="ai-doctor.png"` |
| `Accept-Ranges` | `bytes`（Spring 自动，视频可拖动） |

> **`Content-Disposition` 为什么必须显式写**：Spring 6.1 的 `ResourceHttpMessageConverter` 在未显式设置时
> 会兜底成 `inline;filename=f.txt`，下载图片/PDF 会全被存成 `f.txt`（实测踩到）。
> 纯 ASCII 名走简洁引号形式，含中文才走 RFC 5987 编码。

### 3.4 资源清单改造

配置（`application.yml`）：

```yaml
app:
  resources:
    public-base-url: ${APP_RESOURCES_PUBLIC_BASE_URL:}   # 空 → url=null（回到改造前行为）
    dir: ${APP_RESOURCES_DIR:../deploy/resources}        # 路径穿越防护的根
```

`ResourceManifestService` 改为**表驱动**：
- 取 `status=1` 且 mime ∈ {png, jpeg, webp}，按 `sort_order ASC, id ASC` 稳定排序；
- `url = {public-base-url}/api/v1/resources/{key}`，`public-base-url` 为空则 `null`；
- `fallbackKey = bundle_path`（小程序包内路径），远端失败时前端回退；
- **表为空时回退原内置 7 条**（迁移未执行/库被清空时不至于清单为空）；
- 逐条硬校验保留（禁可执行后缀、禁未签名规则词表、sha256 必须 64 位小写）。

视频不进清单：契约 `ResourceItem.mime` 只允许图片，`video/*` 会被红线校验拒绝。
视频仍可通过 `GET /api/v1/resources/video.wash-hands` 取流（`Content-Type: video/mp4`）。

## 4. 阶段三：穿透与小程序合法域名 — ⛔ BLOCKED

### 4.1 穿透实测与根因

```bash
nslookup qv56gv32944.vicp.fun
# Address: 115.236.153.177

curl -sS --noproxy '*' -m 12 -o /dev/null -w "code=%{http_code} connect=%{time_connect} tls=%{time_appconnect}\n" \
  https://qv56gv32944.vicp.fun/
# curl: (52) Empty reply from server
# code=000 connect=0.126946 tls=0.215518
```

判读：
- **DNS 正常**（解析到 `115.236.153.177`）；
- **TCP 建连正常**（0.127s）；
- **TLS 握手成功**（0.216s，无证书告警）→ 证书链受信，不是自签名/HTTP 问题；
- **HTTP 层空响应** → 服务端接受 TLS 后直接关闭，没有把请求投递给任何本地服务。

**已确认根因（22:15 补齐）**：读花生壳客户端日志
`<home>\AppData\Local\HskDDNS\log\phtunnel.log`，拿到映射定义原文：

```
[2026-10-19 21:56:08.589][INFO] [maps] 网站, via: phfwba-std-g4.oray.net(tcp,udp),
                                        qv56gv32944.vicp.fun:443(10.103.103.101:8080)
```

内网主机写的是 **`10.103.103.101`**，本机以太网是 **`172.29.188.115`** —— 请求被投递到一个
不在线、也不属于本机的地址，所以 `forward stats ... up:0 down:0`、网关 access log 零新增。
**不是端口指错，也不是监听地址或防火墙问题**：已把网关改绑 `0.0.0.0`（`127.0.0.1` 与
`172.29.188.115` 均 200），并在 11 个候选端口同时挂探针，零命中；防火墙三个 profile 全关。

修复只需把映射的**内网主机**从 `10.103.103.101` 改为 `172.29.188.115`（或 `127.0.0.1`），
端口保持 `8080`。证据、操作步骤与自检命令见 **`docs/穿透链路验证记录_20261019.md`**。

## 7. 残余风险 / 未做的事

1. **穿透与真机未验证**（§4/§5）—— 这是唯一的硬阻塞，且只能由你操作。
2. **`/ai/**` 只开了 `/ai/health`**：任务书要的是"`/ai/...` 能到 FastAPI"，机制已通，
   但业务能力仍按原设计留在内网。若确要对外，需要先有契约端点再逐条登记，不能开通配。
3. **`GET /api/v1/attachments/{key}` 无签名参数时返回 500**（实测，既有行为）。
   正确语义应是 400/403。本轮未改（超出资源库范围），已记录待办。
4. **资源清单与包内旧 key 不兼容**：改造前 7 条内置 key（`tab-home`、`icon-alert`…）在表驱动后不再出现；
   这些 key 目前**无页面消费**（前端只用 `refreshManifest` + `resolveResource`，未按 key 引用），
   故无回归。若后续有页面按旧 key 取值，需在 V14 种子里补对应行。
5. **`APP_RESOURCES_DIR` 依赖工作目录**：默认 `../deploy/resources` 相对 `backend/business-service`。
   用 orchestrator 启动时正确；若从仓库根直接 `java -jar`，必须显式传绝对路径，否则全部 404。
6. **生产必须配置 `app.attachment.sign-secret`**（既有风险，与资源库无关）：缺省为进程内随机，
   多实例/重启后旧签名 URL 立即失效。
