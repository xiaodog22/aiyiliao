## 1. 测试目标

### 1.1 总体目标

以契约为唯一权威，验证 business-service（含其编排的 ai-service、edge-gateway 边界）在**功能正确性、
契约一致性、数据与状态正确性、安全与越权、幂等与并发、医疗合规红线**六个维度上满足上线要求，
并把结论固化为可重复执行的自动化测试，防止后续改动回归。

### 1.2 分项目标

| # | 目标 | 判定方式 |
|---|---|---|
| G1 | **契约一致性**：每个操作的实测状态码落在契约声明集合内；响应信封字段、错误码、`retryable` 语义与契约一致 | 契约探针测试（逐路径） |
| G2 | **功能正确性**：挂号、叫号、床位、档案、问诊、语音、养生计划等主流程按业务规则正确流转 | 集成测试 + 用例断言 |
| G3 | **幂等与并发正确性**：写操作同键同体重放、同键异体 409；并发下原子扣减/乐观锁/状态机恰一次生效 | 并发专项测试（多线程真实 Tomcat） |
| G4 | **安全与越权**：无身份 401；伪造/撤销会话 401；他人资源一律 404（不泄露存在性）；非医生 403；匿名白名单无旁路 | 鉴权全矩阵 + IDOR 抽查 |
| G5 | **数据完整性**：唯一约束、乐观锁、级联删除、脱敏列（手机号/姓名/证件号）不落明文、时间戳 UTC | 数据层断言 + H2 迁移演练 |
| G6 | **合规红线**：不 `200 + 空对象`、不伪造数据、`disclaimer` 原样、拒答结构化、AI 不得降级急症等级、隐私撤回生效 | 专项用例 |
| G7 | **性能与容量**：接口时延在预算链内（care-plan 服务端等待预算 75s < ai 上游 60s+余量 < 网关代理 220s < 前端 180s；ASR/TTS 上游超时各自配置化），限流按契约 429 生效 | 性能用例 + 限流测试 |
| G8 | **可回归**：每次改动全量测试 + 门禁脚本可一键执行，失败可定位到契约条目 | CI 化执行 + 报告 |

**契约通用约定（测试断言基线）**：
统一信封 `{code, message, requestId, serverTime, meta?}`；错误信封 `ApiError{code, message, requestId, details?, retryable, serverTime}`；
`404` 不区分"不存在/不属于你"；写操作要求 `Idempotency-Key`（8~128 字符），同键异载荷 `409`；
严禁 `200 + 空对象`；`Idempotency-Replayed: true` 响应头标识重放。

### 2.3 核心业务逻辑（测试视角）

| 模块 | 关键规则（测试必须覆盖的点） |
|---|---|
| **认证/令牌** | 微信 code→openid 换会话；access/refresh 随机令牌库内只存 SHA-256；`expiresIn≥60`；refresh **一次一换**，旧 token 重放→401 `SESSION_REVOKED`；logout 撤销整链且重复调用幂等 200；注销冷静期（30 天）账号不可再登录（403 `ACCOUNT_DELETION_PENDING`）；微信上游失败分类（配置类/无效 code/繁忙/未知 errcode）分别映射 422/503 且 `retryable` 语义不同；任何失败不签发会话、不记 session_key |
| **短信挑战（N9）** | 6 位码 SecureRandom、库存 SHA-256；TTL 300s；一次性（consume 原子置位）；同手机号 60s 冷却→429；连续错 5 次作废；scene 隔离（DOCTOR_LOGIN/ACCOUNT_DELETION）；所有失败统一 401 同文案（防枚举 oracle） |
| **医生登录（N8）** | 工号/手机号 + 验证码；顺序：参数齐全(400)→挑战校验(401)→定位账号(401)→任职校验(403)→一次性消费(401)→签发(200)；角色**只能由服务端按任职关系判定**；验证码手机号须与账号绑定手机号一致（工号同样校验） |
| **挂号** | 幂等三态（同键同体 200 重放 / 同键异体 409 `IDEMPOTENCY_KEY_REUSE` / 缺键 400）；号源原子扣减 `UPDATE remaining-1 WHERE remaining>0`，0 行→409 `SLOT_FULL`；过去时段→422 `SLOT_IN_PAST`；`slot.status≠OPEN`→409 `SLOT_CLOSED`；就诊地点快照（location/hospital_name 冗余自科室）；并发同键撞唯一键 `uk_appointments_idem` 由兜底路径转重放/409；状态机 PENDING→{CONFIRMED,CHECKED_IN,CANCELLED,NO_SHOW,EXPIRED}、CONFIRMED→{CHECKED_IN,CANCELLED,NO_SHOW,EXPIRED}、CHECKED_IN→{COMPLETED,CANCELLED}，其余终态（含流转到自身→409 `APPOINTMENT_STATUS_INVALID`） |
| **医生端** | workbench 范围=任职科室+ACTIVE 病区，计数 UTC 日窗口，**子块独立降级**（异常→该块 unavailable 且省略计数，不用 0 冒充）；叫号 `expectedVersion` 乐观锁 + 每次流转追加 `appointment_status_events`；幂等摘要**含 appointmentId**（防同键跨预约静默命中重放）；他人/他科挂号→404 |
| **床位** | 五动作状态机（AVAILABLE/RESERVED/OCCUPIED/CLEANING/OUT_OF_SERVICE × ASSIGN/RELEASE/RESERVE/SET_CLEANING/SET_OUT_OF_SERVICE，非法→409 `BED_STATE_CONFLICT`）；`expectedVersion` 乐观锁；ASSIGN 只接受内部患者 ID（手机号/姓名→422，不存在→404）；**占用者脱敏落库**（首字+*）；越权病区→404（assign）/403（list 显式指定） |
| **健康档案/附件** | category 6 值枚举（非法→422）；`recordedAt` 必填；代理授权：带 `familyMemberId` 仅 `proxy_status=GRANTED` 放行否则 404（**添加≠授权**）；两段式上传（先 `POST /attachments` 拿 objectKey，建档 `attachmentKeys` 挂载）；附件 32hex 文件名 + 白名单 jpg/jpeg/png/webp/pdf(+mp4) + 限额 10MB(视频 50MB)；读取匿名 + HMAC 签名（缺 expires/sig→400、过期 410、错签 403、不存在 404）；删除档案级联清理附件文件与行 |
| **问诊/AI 任务** | **急症优先**：本地红旗规则先跑，命中即 `safety.emergency=true` 随响应返回（不等模型）；**用户消息先落库（REQUIRES_NEW 独立提交）再建 AI 任务**，上游 503 不影响消息持久化；同键重试补建任务；确认语义：DRAFT→CONFIRMED 先行提交，终止源任务失败不回滚确认；任务查询 `result` 仅 SUCCEEDED 出现、`error` 仅 FAILED 出现（NON_NULL 序列化）；SSE `Cache-Control: no-store` + `X-Accel-Buffering: no`；取消终态幂等 |
| **导诊** | 红旗词表 7 组（胸痛/呼吸困难/意识/咯血/昏迷/严重出血/卒中体征）；**先归一后匹配**；客户端 `localRuleHits` 非空即 EMERGENCY（不得降级）；`provenance=RULE_RESULT` 恒真；科室映射只落到真实 departments 数据 |
| **语音** | ASR 时长 1~60000ms（超→400）；空音频→400；缺 Idempotency-Key→400；识别成功落 DRAFT 草稿、`requiresConfirmation` 恒 true、不回显 inputRef；TTS 同文本缓存重放 `cached=true`；上游失败→503 `TTS_UNAVAILABLE` 降级提示；音色删除幂等（不存在/内置也 200）；`voice/models` 探针不可达→各项 `status=unavailable` 且 detail 非空（不 200+空对象） |
| **养生计划** | 定位生活方式建议（limitations 固定含"不构成处方"）；证据不足→结构化拒答（`refused=true` + `refusalReason`，不用通用话术填充）；上游失败→503 且同事务回滚不落 PENDING 残行；同键同体重放、异体 409 |
| **横切** | 三层拦截器 `Audit(0)→Auth(1)→RateLimit(2)` 仅拦 `/api/v1/**`；auth 三档（strict 生产/header itest/off 回滚阀）；限流只拦契约声明 429 的 12 条路径（登录类键=IP、提交类键=认证主体，429 信封 `RATE_LIMITED`+`Retry-After`+`retryable=true`）；审计只追加 `audit_events`（action=路径模板、不含正文）；严格反序列化（契约 DTO 未知字段→400）；未实现路径统一 501 `NOT_IMPLEMENTED` |

## 4. 测试策略

### 4.1 测试分层（金字塔）

```
        ┌─────────────────────┐
   L4   │ E2E / 真机联调      │  少量、关键链路（登录→挂号→叫号→档案）
        ├─────────────────────┤
   L3   │ 契约测试（80 业务操作） │  逐路径探针，状态码 ∈ 契约集合（当前 60/80 + 占位 7/7，映射见 §7.2）
        ├─────────────────────┤
   L2   │ 集成测试（MockMvc） │  业务流 + 种子数据 + 横切拦截器
        ├─────────────────────┤
   L1   │ 切片测试（@JdbcTest）│  SQL 行为 + 约束 + 迁移
        ├─────────────────────┤
   L0   │ 单元测试            │  规则引擎/加解密/摘要/游标
        └─────────────────────┘
```

**分层原则**：规则与算法下沉 L0；SQL 与约束下沉 L1；跨模块业务流与横切在 L2；契约一致性在 L3 全量收口；
真机与环境相关在 L4 少量执行。**每一层禁止伪造下一层的真实行为**（如 L2 不 Mock 掉限流拦截器）。

### 4.4 通过/失败判据（断言规范）

1. **状态码判据**：实测状态码 ∈ 契约该操作声明集合（契约测试逐条断言；业务测试允许更精确的唯一值）。
2. **信封判据**：成功 `code=OK`（HTTP 200）且 `data` 形状符合 schema；失败 `code` 为稳定错误码、`message` 为中文、`retryable` 与语义一致、`requestId` 非空且贯穿响应头/体/审计表。
3. **语义判据**（项目红线，违反即失败）：
   - 禁止 `200 + 空对象` 冒充成功；能力不可用必须结构化降级（503 + 错误码）或显式状态（unavailable/GENERATING）；
   - 禁止伪造业务数据（不生成假号源/假待办/假 AI 结论）；
   - 越权一律 404（对象级）/403（能力级），不泄露存在性；
   - `disclaimer`/`limitations` 原样下发；AI 输出不得降低本地急症等级；`provenance` 不得伪装。
4. **数据判据**：脱敏列（手机号/身份证/医保号/患者展示名）不落明文；时间列 UTC；唯一约束冲突走结构化错误而非 500。

### 4.5 缺陷分级

| 级别 | 定义 | 示例 | 响应 |
|---|---|---|---|
| **P0 致命** | 数据错误/丢失、越权可读、鉴权绕过、`200+空对象` 伪造成功、急症漏判 | 他人档案可读；叫号幂等跨预约命中 | 当日修复，阻塞发布 |
| **P1 严重** | 主流程异常/500、幂等或乐观锁失效、限流/审计失效、契约状态码漂移 | 同键异体返回 200；并发双扣号源 | 当迭代修复 |
| **P2 一般** | 边界参数处理不当、错误文案不准确、降级路径不完整 | durationMs=0 返回 500 | 排期修复 |
| **P3 提示** | 文档/日志/可观测性缺陷 | 审计 action 不含路径模板 | 随手修复 |

### 4.6 进入 / 退出准则

**进入准则**：契约冻结版本已合入；代码编译通过；`mvnw test` 基线全绿；测试种子可用。
**退出准则**：
- 新增与改动代码行覆盖率 ≥ 80%（Service 层 ≥ 90%）；
- P0/P1 缺陷清零，P2 有规避方案或明确排期；
- 契约显式探针 67/87（60/80 个 `/api/v1/**` 业务操作 + 7/7 gw/internal 占位；剩余 20 个由集成/专项覆盖，映射见 §7.2）+ 门禁 `check-v4-contracts` 0 警告；
- 并发/迁移/限流/审计四专项全绿；
- 真机 E2E 关键链路（登录→挂号→取消→叫号→档案附件）通过并留证。

**TC-AUTH-005 · 医生账号登录顺序与防枚举（P1）**

### 6.4 PAT 健康档案与附件

**TC-PAT-001 · 附件签名 URL 四态（P0）**

**TC-PAT-003 · 附件上传白名单与限额（P1）**
