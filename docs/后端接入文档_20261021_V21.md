## 2. ① 语音识别：funasr（端点已实现，配环境即可用）

> 2026-10-22 修订：产品口径确定为 **funasr**（本地 FunASR 权重），不再规划 qwen_asr 适配器。
> ai-service 的 ASR 引擎白名单里**本来就有 funasr**（`app/voice.py:150`），缺的只是「装依赖 + 配权重」，不是缺代码。

### 2.1 客户端契约（**已实现，不要改**）

```http
POST /api/v1/voice/asr
Authorization: Bearer <token>
Idempotency-Key: <uuid>            # header，required
Content-Type: multipart/form-data

audio=<binary>                     # 必填（wav/mp3/m4a/pcm/ogg/webm）
durationMs=3200                    # 可选，1 ~ asr.maxDurationMs
locale=zh-CN                       # 可选
consultationId=<id>                # 可选：带上则识别成功后落 DRAFT 转写草稿
```

响应 `data`（`AsrResultData`）：

```json
{
  "text": "最近饭后胃胀三天",
  "language": null,
  "durationMs": null,
  "modelId": "funasr",
  "modelVersion": "<权重版本标记>",
  "hasTimestamps": false,
  "requiresConfirmation": true,
  "cached": false
}
```

- `requiresConfirmation` **恒为 true**：前端必须让用户核对/修改文本，再用 `POST /api/v1/consultations/{id}/confirmations`（`sourceTaskId` 见会话详情里的 DRAFT 消息）提交，确认后才允许进入问诊生成。
- `language`：FunASR 不提供语言标记 → 如实 `null`，**前端不得补成 `zh-CN`**（`app/voice.py:199`）。
- 服务端是**同步阻塞**语义：Java 侧 `VoiceService.recognize()` 内部建 `ASR` 任务并 `await` 到预算耗尽（默认 `asr.taskBudgetSeconds`），所以前端超时要 ≥ 60s（当前 `aiTimeout=90s`，够）。超预算 → `504 ASR_TIMEOUT`。
- 音频**不出服务器**：落临时文件 → 提交任务 → `finally` 立即清理；任务侧通过 `inputRef=asr:{id}` 从 `AI_ASR_AUDIO_DIR` 只读取用。

错误码（前端必须分档提示，不要笼统「识别失败」）：

| HTTP | code | 含义 | 前端动作 |
|---|---|---|---|
| 400 | `MISSING_IDEMPOTENCY_KEY` | 漏传 header | 客户端 bug，查 `speech.js` |
| 413 | `PAYLOAD_TOO_LARGE` | 超大小上限 | 提示缩短录音 |
| 422 | `ASR_EMPTY` | 没听到内容 | 提示重录 |
| 429 | `ASR_BUSY` | 识别队列满 | 稍后重试 |
| 503 | `CAPABILITY_UNAVAILABLE` | **引擎未配置**（当前默认态） | 引导改用文字输入 |
| 503 | `ASR_UNAVAILABLE` | 执行失败（含 funasr 依赖/权重问题） | 重录 |
| 504 | `ASR_TIMEOUT` | 超预算 | 重录 / 改文字 |

## 3. ② AI 问诊（真实 Ollama · 后端已就绪，前端待接线）

### 3.1 三步流（契约要求，禁止只用其中一步）

```http
# 1) 建会话（Idempotency-Key 必填）
POST /api/v1/consultations
{"initialMessage":"最近饭后胃胀，持续三天","inputMode":"TEXT","requestedProfile":"large-upgrade","locale":"zh-CN"}
→ data: { "consultation": {id,status,messageCount,...}, "task": {taskId,status} }

# 2) 继续对话
POST /api/v1/consultations/{consultationId}/messages
{"content":"没有发热，但晚上更明显","inputMode":"TEXT","requestedProfile":"large-upgrade"}
→ data: { "message": {...}, "task": {taskId,status} }

# 3) 轮询任务（终态才停）
GET /api/v1/ai/tasks/{taskId}
→ data: { status: QUEUED|RUNNING|SUCCEEDED|FAILED|CANCELLED|EXPIRED,
          result: { text, citations:[], provenance, refused, refusalReason, language },
          error:  { code, message } }
```

会话读取三件套（重进页面靠它们恢复，不要只存内存）：

| 用途 | 端点 | 说明 |
|---|---|---|
| 我的问诊列表 | `GET /api/v1/consultations?cursor&limit(≤50)` | 只给元数据 + 摘要，不含正文 |
| 详情 + 消息 | `GET /api/v1/consultations/{id}?cursor&limit` | 一次拿医生卡字段（`doctorName/doctorTitle/departmentName/accepting`）+ 消息 |
| 消息正文 | `GET /api/v1/consultations/{id}/messages` | 详情不可用时的回退通道 |
| 确认转写 | `POST /api/v1/consultations/{id}/confirmations` | 语音转写必须经确认才生成 |

## 9. ⑧ 排班设置 / 在线问诊状态（**2026-10-22 已实现，V22**）

> 变更前：契约无路径、Java 零实现，前端 `personal.wxml:46` 只能 `onPlaceholder` 弹「功能建设中」。
> 变更后：两张表 + 4 个端点，医生可维护周模板、开关在线接诊；患者侧可判断「该医生现在能不能发起在线问诊」。

### 9.1 端点一览

| 方法 | 路径 | 身份 | 说明 |
|---|---|---|---|
| GET | `/api/v1/doctor/schedule` | 医生本人（403 非医生） | 周模板 + 在线状态；无排班 → `version=0`、`weekdays=[]` |
| PUT | `/api/v1/doctor/schedule` | 医生本人 | **整体替换**周模板；`Idempotency-Key` 必填；乐观锁 409 |
| POST | `/api/v1/doctor/online-status` | 医生本人 | 开关在线接诊；`Idempotency-Key` 必填；下线前校验待回复 |
| GET | `/api/v1/doctors/{doctorId}/availability` | **公开**（`security: []`） | 患者侧只读：`online/accepting/nextSlotAt` |

### 9.2 契约细节

```http
PUT /api/v1/doctor/schedule
Authorization: Bearer <token>
Idempotency-Key: <uuid>
Content-Type: application/json

{
  "expectedVersion": 1,
  "weekdays": [
    {"weekday": 2, "slots": [
       {"startTime":"08:30","endTime":"11:30","slotMinutes":30,"capacity":4}
    ]},
    {"weekday": 4, "slots": [
       {"startTime":"13:30","endTime":"16:30","slotMinutes":60,"capacity":2,"onlineOnly":true}
    ]}
  ]
}
```

```json
{ "code":"OK", "data": {
   "version": 2,
   "weekdays": [
     {"weekday":2,"slots":[{"startTime":"08:30","endTime":"11:30","slotMinutes":30,"capacity":4,"onlineOnly":false}]},
     {"weekday":4,"slots":[{"startTime":"13:30","endTime":"16:30","slotMinutes":60,"capacity":2,"onlineOnly":true}]}
   ],
   "online": {"online":true,"accepting":true,"version":1,"updatedAt":"2026-10-22T02:48:29.408Z"}
}}
```

字段口径：

| 字段 | 口径 |
|---|---|
| `weekday` | `1=周一 … 7=周日`（ISO-8601），不重复；每天最多 **8** 段 |
| `startTime`/`endTime` | `HH:mm` **本地墙上时间**（不含时区），`start<end` |
| `slotMinutes` | 仅 `10/15/20/30/60`（号源粒度） |
| `capacity` | 每号源可约人数，`1~50` |
| `onlineOnly` | 该时段仅接在线问诊（不生成线下号源），缺省 false |
| `version` | **医生级**排班版本（所有时段共享）；无排班为 `0`，首次保存 `expectedVersion=0` |
| `accepting` | 服务端不变式：`online=false` 时恒 `false`（客户端不能单独改 accepting） |

### 9.3 错误码

| HTTP | code | 触发场景 | 前端动作 |
|---|---|---|---|
| 400 | `MISSING_IDEMPOTENCY_KEY` | 写操作漏传幂等键 | 客户端 bug |
| 403 | `FORBIDDEN` | 当前账号无 ACTIVE 医生任职 | 回工作台 |
| 409 | `VERSION_CONFLICT` | `expectedVersion` 与当前版本不符且内容不同 | 提示「排班已在别处修改，请刷新」 |
| 409 | `ONLINE_BUSY` | 下线时仍有待回复的在线问诊 | 提示先处理完 `N` 条问诊 |
| 422 | `VALIDATION_FAILED` | weekday 越界/重复、start≥end、slotMinutes 非法、capacity 越界 | 表单就地提示 |
| 422 | `SCHEDULE_OVERLAP` | 同一天时段重叠 | 高亮冲突时段 |

**幂等语义（重点）**：整体替换天然"重发即覆盖"，但乐观锁会让重发变成 409。因此服务端做了**同内容回放**：
`current == expectedVersion + 1` 且内容与库里完全一致 → 200，并回 `Idempotency-Replayed: true`。
客户端超时重试不会误报冲突，只有内容真的变了才 409。

### 9.4 患者侧 availability

```json
{ "code":"OK", "data": {
    "doctorId":"doc-gastro-1",
    "online":true,
    "accepting":true,
    "nextSlotAt":"2026-10-22T05:30:00Z"
}}
```

- 未开局 → `online=accepting=false`（不臆造在线）；

## 10. ⑨ 首页数值（现成端点就能拼，不必等后端）

`GET /api/v1/home/summary` 当前只返回：

```json
{ "greeting": "上午好，李先生", 
  "blocks": [
    {"kind":"NEXT_APPOINTMENT","status":"ok","nextAppointment":{...}},
    {"kind":"QUICK_SERVICES","status":"ok","services":[...]},
    {"kind":"CONTENT_FEED","status":"ok","contents":[...]}
  ]}
```

`kind` 枚举：`NEXT_APPOINTMENT / HEALTH_TIPS / QUICK_SERVICES / CONTENT_FEED / CARE_PLAN`；`status ∈ ok/degraded/unavailable`，**`unavailable` 时整块隐藏，不显示空数据**。**summary 里没有任何计数**。

数字的真实来源（都已实现）：

| 数字 | 端点 | 字段 |
|---|---|---|
| 未读消息 | `GET /api/v1/messages/unread-count` | `data`（number） |
| 待就诊 / 已完成 / 已取消 | `GET /api/v1/appointments/stats` | `{upcoming, completed, cancelled}` ⚠️ **契约外补充端点**（控制器注释已标注，`api.js` 尚未登记） |
| 下次就诊时间/科室 | `GET /api/v1/home/summary` | `blocks[NEXT_APPOINTMENT].nextAppointment` |

**两种接法**

- **推荐（零后端改动）**：首页 `onShow` 并行发 `home/summary` + `unread-count` + `appointments/stats`，任一失败只隐藏对应数字（保留已有块），不阻塞首屏。
- 备选（一次往返）：`home/summary` 增 `stats` 子块。属于契约变更，要同步 `business-openapi.yaml` + `HomeBlockData`，并保证老客户端忽略未知字段 —— 收益有限，**本批不做**。

红线：数字不能用 `0` 冒充「确实是 0」与「没取到」——失败时不渲染该数字，或显示 `--` 并给出重试。
