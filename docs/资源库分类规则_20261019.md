## 2. 两个字段的分工

| 字段 | 取值 | 含义 | 谁读它 |
|---|---|---|---|
| `status` | 1 / 0 | 是否对外可见 | 端点（status=0 → 404）与清单（只取 1） |
| `delivery` | `local` / `remote` | **要不要走远端** | 清单（只对 remote 下发 url）；端点**不区分**（按 key 直取都能取到） |

> `delivery` 与 `level` 是两件事：`level` 是契约里的完整性等级（A=客户端必须保留本地兜底），
> `delivery` 是分发策略。当前所有图标 `level=A` 且 `delivery=local`——既不丢兜底，也不走网络。

**默认值 `local` 是安全默认**：新增资源漏填也不会误上云。

## 3. 分类规则（判定表）

| 类别 | 判定条件 | delivery | 理由 |
|---|---|---|---|
| 图标库 | key 前缀 `icons.` | **local** | 96×96 小图，页面里几十个同时渲染；每个一次网络往返是净亏（包内 0ms） |
| 默认头像 | `img.avatar-default` | **local** | 离线/弱网必须立刻显示，不能等网络；空头像不能留灰块 |
| 空态插画 | `img.empty-*` | **local** | 本来就是"加载失败/无数据"时给人看的，让它依赖网络是自相矛盾 |
| 画布底图 | `nav.floor1` | **local** | `canvas.drawImage` 需要可同步读取的本地路径，网络图有跨域与异步时序问题 |
| 首页常驻小图 | `home.ai-doctor`、`home.svc-*` | **local** | 首屏必现，等网络会闪白；`svc-*` 8 个同时出现 |
| 登录页主视觉 | `home.xiaoan-robot` | **remote**（2026-10-21 例外） | 唯一"会改错、又必须能独立纠错"的首屏大图：原图腰部 alpha 整块缺失，包内修不掉只能等发版。改远端后换图不必重新提审；**流程上要求先 `wx.getImageInfo` 预热成功再换 src**（见 `pages/auth/login/login.js#_preloadRobotArt`），所以不会闪白，失败静默留在包内同版图 |
| 插画/封面 | `category='cover'`（banner、kb-cover） | **remote** | 大图、低频、需要**不发版**就能换 |
| 科普图 | `health.*`（jpeg） | **remote** | 同上；内容运营会换图 |
| 视频 | `video.*`（mp4） | **local**（V17 收口） | 实际走分包内 `packageContent/videos/*.mp4`，前端从 `knowledge-kb.js` 直接引用；清单只下发图片 mime，标 remote 是**死标记**。远端化见 `docs/视频远端化需求.md`（本轮不实现） |

**判定函数**（`tools/resource-import.py#delivery_for`）：

```python
if key.startswith(("icons.", "img.", "nav.")): return "local"
if key == "home.xiaoan-robot":                  return "remote"   # 2026-10-21 例外，见上表
if category in ("cover", "video"):             return "remote"
return "local"                                  # 其余一律 local
```

### 4.1 清单 url 为 null 时怎么取图（2026-10-21）

清单 `items[].url` 由 `app.resources.public-base-url` 拼出（`{base}/api/v1/resources/{key}`），
**该配置为空时 url 恒为 null**——本地 dev 与当前 env.local 都是这个状态。

此时前端不能死等 url，否则"远端优先"等于永远不生效。约定：

| 情形 | 前端行为（`services/resource.js#resourceUrl`） |
|---|---|
| `items[].url` 非空 | 直接用（服务端配了公网基址，最标准） |
| `items[].url` 为空但 key 在清单里 | 按自身网关拼 `{ENV.gateway}/api/v1/resources/{key}?v={sha256前12位}` |
| key 不在清单 | 返回包内兜底路径 |

`?v=` 是**客户端缓存击穿**：微信按 URL 缓存图片，服务端 `Cache-Control` 是 7 天，
不带指纹时换图后旧图最长残留一周。服务端忽略未知 query，不影响 ETag/304。

## 5. 性能账（为什么不全量上云）

| 方案 | 首屏图片请求数 | 最坏情况 |
|---|---|---|
| 全量 remote（219 图标 + 其余） | 20~40 次/页 | 弱网下图标逐个"跳出来"，首屏抖动 |
| **本方案（local 为主）** | **0~2 次/页** | 只有 banner 可能走网络，失败自动回退包内 |

包内 219 个图标合计约 **1.3MB**，早已计入主包体积（main 1.4MB / 上限 2MB），
走远端既省不了包体（`bundle_path` 兜底必须留着），又多一次往返——所以不做。

## 6. key 命名规范

| 来源 | 规则 | 示例 |
|---|---|---|
| 图标 | `icons.<icons.js 的键>` | `icons.home`、`icons.homeGray` |
| home 素材 | `home.<文件名去扩展名>` | `home.banner-hospital`、`home.svc-triage` |
| img | `img.<文件名去扩展名>` | `img.avatar-default` |
| 导航 | `nav.<文件名去扩展名>` | `nav.floor1` |
| 科普图 | `health.<文件名>`（V14 既有） | `health.wash-hands` |
| 视频 | `video.<文件名>`（V14 既有） | `video.wash-hands` |

**硬约束**：key 必须**单段点分**，只能用 `[A-Za-z0-9._-]`。
带 `/` 的多段 key 会被匿名白名单的单段通配 `/api/v1/resources/*` 打成 401。

## 7. 服务端副本从哪来

`resource_asset.file_path` 相对 `app.resources.dir`（= `backend/deploy/resources`），
而源文件在小程序包内。导入脚本负责复制：

```
miniprogram/assets/icons/home.png      → backend/deploy/resources/icons/home.png
miniprogram/assets/home/xiaoan-robot.png → backend/deploy/resources/xiaoan-robot.png
miniprogram/assets/img/avatar-default.png → backend/deploy/resources/img/avatar-default.png
miniprogram/packageNav/assets/floor1.png  → backend/deploy/resources/nav/floor1.png
miniprogram/packageContent/assets/covers/*.png → backend/deploy/resources/content/*.png
```

**副本目录是构建产物**（已加 `.gitignore`）：部署前必须跑 `resource-import.py --write` 生成，
否则资源端点全 404、应用启动时 `app.resources.dir` 校验也会失败。

**包内原件不移动、不删除**——前端 `bundlePath` 兜底依赖它（这也是"不得删除本地兜底资源"的落点）。
复制是"分发副本"，校验脚本会比对两边 **sha256 必须相同**。

## 8. 新增资源的标准流程

```bash
# 1) 先把文件放进 miniprogram 对应目录（图标要同时在 icons.js 登记键名）
# 2) 盘点（不写文件），看报告有没有缺失/重复/非法 mime
python tools/resource-import.py --check

# 3) 落库：复制副本 + 生成 V<N>__resource_asset_catalog.sql
python tools/resource-import.py --write --version 17

# 4) 重启后端触发 Flyway
backend/deploy/start-all.bat restart

# 5) 四方对账
python tools/check-resource-consistency.py
```

**注意**：`--write` 会生成**新版本号**的迁移（Flyway 只能版本递增）。
若同一批资源要重来，先手动删掉上次生成的 V<N> 文件（**未执行过**的前提下）。

## 10. 边界

- **不保证"远端可用"**：`delivery=remote` 只表示"清单下发了 url"，
  真正能否取到还取决于 `app.resources.public-base-url` 与穿透链路。
- **不删除任何包内资源**：即使全部走 remote，`bundlePath` 兜底仍留在包里。
- **`status=0` 不出现在清单**：查询条件里有 `status=1`，
  校验脚本的"清单出现停用资源"一项专门守这条。
