### 1.5 一键启动 start.bat 修复（2026-11-20）

- **问题**：`start.bat` 以 UTF-8 保存，但 `chcp 65001` 之前已有中文 `rem`；cmd 在默认代码页下按 GBK 解析，出现 `'-------' 不是内部或外部命令`、`'LINIC_PORT（默认'` 等报错。服务有时能启动，但窗口大量红字，端口被占用时还会重复起进程。
- **修复**：批处理改为全 ASCII + UTF-8 无 BOM + CRLF；中文启动横幅由 Python 输出。启动前探测端口：已在运行 → 打开浏览器并退出 0；被其他程序占用 → 提示改 `CLINIC_PORT=8311` 并退出 1。Python 按 `py -3` → `python` → 本机 Anaconda/常见路径逐个做 3.10+ 校验。新增 `scripts/ensure-secret.ps1`，首次生成 64 位 hex 密钥到 `data/.doc_secret` 并注入 `CLINIC_DOC_SECRET`，重启后旧 PDF 签名链接仍有效。
- **验证**：8310 已运行 exit 0 且不重复起进程；8312 空闲启动 `/openapi/v1/ping` 200，stderr 0 行；8313 被 TcpListener 占用 exit 1；`start.bat` 非 ASCII 字节 0、CRLF 110 行。

## 3. 启动与使用

### 3.1 clinic-his

```powershell
cd D:\asr_chaoshanhua\asr_chaoshanhua_V01\_V01\wechar\clinic-his
$env:CLINIC_PORT = "8310"
$env:CLINIC_DOC_SECRET = "<32 字节以上固定随机串>"
python -m app.main
```

> `CLINIC_DOC_SECRET` 不设置时每次重启随机生成，旧签名链接会失效；生产必须固定注入。

### 3.2 护士站

```powershell
cd D:\asr_chaoshanhua\asr_chaoshanhua_V01\_V01\wechar\backend\business-service
$env:NURSE_STATION_TOKEN = "<至少 16 位随机串>"
.\mvnw.cmd spring-boot:run
```

打开 `http://127.0.0.1:8088/nurse-station/index.html`，填写令牌与病区 ID，即可看到 `PENDING` 申请和本病区空闲床位；点“通过”时填床位 ID（申请已有床则直接确定），系统校验床位属于本病区且空闲后落床。

> 终端令牌是共享模式，适合病区护士站终端；生产应替换为护士个人账号 + RBAC（`nurses` 表、工号登录、`bed.review` 权限）。

## 5. 风险与注意

1. `NURSE_STATION_TOKEN` 是共享令牌：泄露后可审全院床位（不含病历）。必须定期轮换、只放病区终端、不要写进代码/群聊。
2. `CLINIC_DOC_SECRET` 未固定时，重启会使所有未过期打印链接失效；生产必须固定并纳入密钥管理。
3. PDF 依赖本机 Edge/Chrome；Linux 需安装 Chromium 并设置 `CLINIC_PDF_BROWSER`。
4. 护士读取任意病历仍是 `200`（`visit.read` 未区分 own/all），需业务/合规拍板后收口。
5. 8310 的 `data/openapi-credentials.txt` 是演示密钥，勿提交、勿外传。
