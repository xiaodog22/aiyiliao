# 后端迁移适配文档（2026-10-25）

> 目标读者：把本项目迁移到新机器/新环境的**开发人员或 AI Agent**。
> 本文只讲一件事：**如何在一台新机器上把后端跑起来**（含环境配置、启动命令、验证与排障），并附「AI 快速启动向导」。
> 配套文档：`docs/项目介绍文档_医疗健康AI微信小程序_20261025.md`（项目功能总览）、`docs/交接文档_20261025.md`（工作交接）。

---

## 一、文档目的与适用场景

- **场景 A（换机迁移）**：整个仓库换到新电脑，从零准备环境并启动三服务。
- **场景 B（AI 接管启动）**：交给另一个 AI Agent 快速把后端拉起并验证——直接看「七、AI 快速启动向导」。
- **场景 C（联调/部署）**：本机已就绪，日常重启、看状态、查日志。

**后端由三个服务组成，必须一起运行（网关是前端唯一入口）：**

| 服务 | 技术 | 端口 | 职责 |
|---|---|---|---|
| edge-gateway（统一网关） | Python FastAPI | **8080** | 前端唯一入口，反向代理 + 兼容层 + 素材/TTS 公开通道 |
| business-service（业务服务） | Java Spring Boot 3.5.x（JDK 17） | **8088** | 业务权威面：登录/用户/挂号/医生/档案/资源库/消息等 |
| ai-service（AI 服务） | Python FastAPI | **8001** | 仅内网可达：导诊/问诊/养生/TTS/ASR/RAG/知识库注入 |

> ⚠️ 前端代码**禁止出现** 8001/8088/127.0.0.1/localhost（唯一豁免是 `miniprogram/config/env.js` 的 `DEV_DIRECT` 行）；所有联调一律经 8080 网关。

## 二、总体架构速览

```text
微信小程序前端（miniprogram/，原生 WXML/WXSS/JS）
        │  只认 env.js 的 gateway（:8080）
        ▼
统一网关 edge-gateway :8080 ──/api/gw/** 自身；其余 /api/** 全量代理──► business-service :8088
        │                                                        │  编排 AI 任务 / 鉴权 / 落库
        │  白名单通道（TTS 产物 / 静态素材）
        ▼
   ai-service :8001（仅内网）──► Ollama :11434（qwen2.5:7b / 0.5b / nomic-embed-text）
        │                      ──► edge-tts（在线语音合成）
        │                      ──► FunASR（本地权重，ASR）
        └──► MySQL 8（wechar_dev，Flyway 自动迁移） / Redis :6379（RAG 演示）
```

依赖关系一句话：**MySQL 是 business-service 的硬依赖**（连不上启动即失败）；Ollama/Redis/FunASR/edge-tts 均是可降级依赖（缺失时对应 AI 能力如实报不可用，服务本身照常启动）。

## 三、迁移前置条件清单

### 3.1 软件依赖

| 依赖 | 版本要求 | 用途 | 缺失影响 |
|---|---|---|---|
| Windows | 10/11（脚本按 PowerShell 5.1 兼容编写） | 运行环境 | — |
| JDK | **17+** | business-service | 该服务起不来 |

## 四、环境配置（关键）

### 4.1 env.local —— 唯一生效的环境文件

**铁律**：`backend/deploy/env.local` 是唯一被 `orchestrator.ps1` 加载的环境变量文件（gitignore 已排除，**不入库**）。`env.example` 只是模板；`backend/deploy/.env.ai-service.example` **不被任何脚本加载、且未入库**，其默认值与代码相反，**禁止照抄**。

**迁移时二选一：**
- 最省事：从原机器**直接复制 `backend/deploy/env.local`**（文件很小，含全部口令与令牌）。
- 或者按 `env.example` 重建（见下表），**令牌类必须重新生成**（不要沿用旧值散落到文档/聊天记录）。

**重建指引（逐项说明）：**

| 变量 | 必填 | 说明 / 生成方法 |
|---|---|---|
| `MYSQL_URL` | ✅ | JDBC 连接串，指向 `wechar_dev` 库（模板里已给，改主机/库名即可） |
| `MYSQL_USER` | ✅ | 数据库账号（dev=`wechar_dev`；生产用最小权限账号，勿用 root） |
| `MYSQL_PASSWORD` | ✅ | 数据库口令。**从原机 env.local 复制**（dev 库口令为开发占位值）；生产必须换强口令。注意：**本文件不入库，不要把你的口令写进任何文档/聊天** |
| `PHONE_KEY_BASE64` | ✅ | 手机号 AES-GCM 密钥（Base64，32 字节）。缺省/非法**启动即失败**。dev 有占位值（见 business-service README）；生产必须覆盖 |
| `AI_AUTH_MODE` / `AI_SERVICE_TOKEN` | ✅ | AI 服务鉴权。生产形态 `static` + 强随机 64 位 hex 令牌（`openssl rand -hex 32` 生成）；`AI_SERVICE_TOKEN` 同时供 business-service 的 `ai.client.token` 使用，两端必须一致。弱/缺令牌 → ai-service **启动即失败（fail-fast）** |
| `AI_TENANT_SECRET` | 建议 | 缓存键 HMAC 密钥（32B hex）。**固定后多实例必须一致**，否则重启/多实例命中率归零 |
| `APP_ATTACHMENT_SIGN_SECRET` | 建议 | 健康档案附件签名密钥。**生产必须固定且多实例一致**（随机会在每次重启后使已签 URL 全部 403） |
| `AI_TTS_PUBLIC_BASE` / `AI_TTS_PUBLIC_PATH` | ✅ | TTS 产物对外可达基址。本机联调=`http://127.0.0.1:8080` + `/api/gw/tts/audio`；真机联调必须换成隧道对外域名 |
| `AI_ASR_ENGINE` / `AI_ASR_MODEL_PATH` / `AI_ASR_AUDIO_DIR` | 可选 | FunASR 权重路径（权重缺失则 ASR 如实不可用，不伪造转写）；`AI_ASR_AUDIO_DIR` 由 business 写入、ai 只读，**两端值必须一致** |
| `AI_RAG_ENABLED` / `AI_RAG_STORE` / `AI_REDIS_URL` | 可选 | 当前 demo 用 `redis` 存储 + 服务端余弦检索（`AI_REDIS_URL=redis://127.0.0.1:6379/0`）；**开启前先入库**：`ai-service/.venv/Scripts/python.exe tools/rag_redis_seed.py` |
| `AI_CACHE_ENABLED` / `AI_CACHE_TTL_SECONDS` | 可选 | 内容寻址缓存（默认关，生产建议开）。Redis 缺失时退化为本机 JSON 文件 |
| `AI_LLM_STREAM` / `AI_LLM_WORKER_POOL_SIZE` / `AI_LLM_HTTP_CLIENT_REUSE` | 可选 | LLM 并发/流式三开关（默认保守：stream=false、pool=1、reuse=true；各自独立可回滚） |
| `AI_TRIAGE_TIMEOUT_SECONDS` | 可选 | 导诊单次生成超时。**7B 在 CPU 上需 30~90s，当前配 180**；上 GPU 后调回 60 |
| `AI_ASR_PRELOAD` | 可选 | 启动时后台预热 FunASR（CPU 加载约 27s，不阻塞启动） |
| `GW_*` | 可选 | 网关覆盖项（`GW_LOG_LEVEL`、`GW_RATE_LIMIT_*` 默认关、`GW_ASSETS_DIR`） |
| `WECHAT_MINIPROGRAM_APP_ID/SECRET` | 生产 | 微信登录（code2session）。**不得写入本文件**；本地 dev 档用 `DevWechatSessionProvider` 假数据，无需这两项。生产缺省 → 登录 503 |

> ⚠️ 生产形态与 dev 的差异集中在：`APP_AUTH_MODE`（strict vs header）、微信凭证注入、正式 HTTPS 域名、`AI_TTS_PUBLIC_BASE` 指向正式域名、资源 `public-base-url`（见 env.example 注释）。

### 4.2 config.json —— 启动行为配置（一般不用改）

`backend/deploy/config.json` 是脚本唯一配置点：
- `ports`：8080 / 8008…（实际为 gateway 8080 / business 8088 / ai 8001）；
- `upstreams`：business/ai 本机地址；
- `healthTimeoutSeconds`（默认 90）、`proxyTimeoutSeconds`（220，须大于前端三档超时 90/120/180）；
- `pipIndexUrl`：清华镜像（首装依赖用，可换/留空用官方源）；
- `services[]`：每服务的启动命令、健康 URL、健康判定（business 判 `"UP"`、ai 判 `"status"`、网关接受 `200/503`）；
- `smoke[]`：冒烟打点（`/api/gw/health`、`/api/gw/routes`）。
- `mysql.host/port`：前置检查用（MySQL 可达性探测，也可用 `MYSQL_HOST/MYSQL_PORT` 覆盖）。

> `compat.legacyLoginEnabled` 默认 `false`（安全默认，生产严禁开启）。旧登录替身仅本地/联调需要时显式置 `true`。

### 4.3 静态资源副本（迁移后必做，否则资源端点全 404）

`backend/deploy/resources/` 是**构建产物**（gitignore），内含小程序包内图片的**服务端副本**。`resource_asset.file_path` 相对此目录，`GET /api/v1/resources/{key}` 从这里流式读文件——**目录缺失/为空 → 资源端点全 404；business 启动时还会因 `app.resources.dir` 校验失败直接起不来**。

```powershell
# ① 盘点（只读）：列出新增/变更/缺失
python tools/resource-import.py --check
# ② 生成：复制服务端副本 + 生成 Flyway 迁移（V<下一版本号>）
python tools/resource-import.py --write --version V21
# ③ 重启后端让 Flyway 执行
backend\deploy\restart.bat
# ④ 四方对账（DB / 副本 / 包内源 / 前端引用）
python tools/check-resource-consistency.py
```

> ⚠️ 从仓库根直接 `java -jar` 时，必须显式传 `APP_RESOURCES_DIR`（绝对路径），否则路径穿越防护的根会错、资源全 404。

### 4.4 MySQL 准备

1. 启动 MySQL 8（本地服务或容器），确认 3306 可达。
2. 建库建账号（与 env.local 对齐）：
   ```sql
   CREATE DATABASE IF NOT EXISTS wechar_dev DEFAULT CHARACTER SET utf8mb4;
   CREATE USER IF NOT EXISTS 'wechar_dev'@'%' IDENTIFIED BY '<与env.local一致>';
   GRANT ALL PRIVILEGES ON wechar_dev.* TO 'wechar_dev'@'%';
   FLUSH PRIVILEGES;
   ```
3. **表结构不用手动建**：business-service 启动时 Flyway 自动执行全部迁移（含 dev 种子 V9000~V9002：科室、医生账号、演示用户）。首次启动约需 30~60s 等待迁移完成。

## 五、一键启动 / 停止 / 状态（推荐）

所有入口在 `backend/deploy/`：

| 入口 | 作用 |
|---|---|
| `start-all.bat [-Setup] [-SkipAI] [-Smoke] [-Yes]` | 启动全套（顺序 business → ai → gateway） |
| `restart.bat` | 先停后启（改了 env.local / 代码后用它） |
| `stop-all.bat` | 停止（**仅回收本工具启动的进程**，不碰外部实例） |
| `status.bat` | 状态矩阵：PID / 端口 / 健康 / 日志路径 |
| `start-gui.bat` | 图形面板（常驻窗口：服务矩阵 / 请求流水 / 服务日志 / 操作输出） |

**首次初始化（新机器必做）：**

```powershell
cd <repo>\backend\deploy
start-all.bat -Setup -Yes
```

`-Setup` 会：创建各服务 venv → 安装 requirements（走清华镜像）→ 预构建 business jar（有 mvnw 且无 jar 时）。

**日常启动：**

```powershell
start-all.bat -Smoke      # 启动 + 冒烟（GET /api/gw/health、/api/gw/routes）
```

**退出码语义：**

| 码 | 含义 | 处理 |
|---|---|---|
| 0 | 全绿（就绪 / 已在运行跳过） | — |
| 1 | 有服务运行期失败（启动后退出 / 健康等待超时） | 看 `logs\<名>.log` 尾部 |
| 2 | 前置未过（MySQL 不可达 / venv 未初始化 → 不启动任何服务）；或个别服务前置缺失（产物未交付 / 端口冲突 → 其余照常启动） | 按行内中文指引处理 |

**幂等**：已在运行且健康 OK → 跳过（含 IDE/手工启动的实例，健康可达即跳过）；`stop-all` 绝不回收非本工具进程；端口被占且健康失败 → 冲突提示（不杀进程）。

## 六、手动启动各服务（排查/单点调试用）

> 手动启动必须与一键脚本**同参数**，否则端口/健康判定不一致。三个服务都支持独立跑。

### 6.1 business-service（:8088）

```powershell
# 方式一：Maven Wrapper（开发）
cd backend\business-service
mvnw.cmd spring-boot:run

# 方式二：打包后运行（先用 -Setup 或手动 package）
mvnw.cmd -q -DskipTests package
java -jar target\business-service-0.1.0-SNAPSHOT.jar
#   ⚠️ 从仓库根 java -jar 必须显式传 APP_RESOURCES_DIR 绝对路径
```

健康探针：`GET http://127.0.0.1:8088/actuator/health` → 期望 `{"status":"UP"}`。
环境变量：`MYSQL_URL / MYSQL_USER / MYSQL_PASSWORD / PHONE_KEY_BASE64 / SERVER_PORT / SPRING_PROFILES_ACTIVE`（dev profile 加载种子）。
Flyway 自动迁移：首次启动会建全部表 + 种子数据。

### 6.2 ai-service（:8001）

```powershell
cd backend\ai-service
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

健康探针：`GET http://127.0.0.1:8001/internal/health/live` → 期望含 `"status"`。
**启动必看一行**：`启动配置摘要 | version=… | cache=… | rag=… | asrEngine=… | ttsEngine=… | llmStream=… | …` —— 用于核对开关到底开没开（不含地址/路径/密钥值）。

### 6.3 edge-gateway（:8080）

```powershell
cd backend\edge-gateway
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8080
```

健康探针：`GET http://127.0.0.1:8080/api/gw/health`（三上游聚合：java / python / ollama；任一不可达 → `degraded`）。
环境变量：`GW_BUSINESS_URL / GW_AI_URL / GW_PORT / GW_PROXY_TIMEOUT_SECONDS / GW_ASSETS_DIR` 等（config.json 优先）。

### 6.4 若 venv 缺失（手动重建）

```powershell
cd backend\ai-service
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
# edge-gateway 同理（requirements.txt）；business 不需要 venv
```

## 七、AI 快速启动向导（给 AI Agent 的「一行启动」流程）

> 目的：另一个 AI Agent 拿到本仓库后，用最少读取、最快把后端跑起来并自验。

**AI 必读清单（按序，读完即停，不要全文通读）：**

1. `AGENTS.md`（项目速览 + 省 Token 规定 + 文档体系）
2. `AI_CONTEXT.md`（版本 / 契约 / 红线 / 验证脚本清单）
3. `DEV_LOG.md` 尾部 30~80 行（最近进展）
4. `backend/deploy/README.md`（一键启动行为与排障表）
5. `backend/deploy/config.json`（启动命令/端口/健康 URL）与 `backend/deploy/env.local`（**只看键名与生效情况，不打印值**）

**标准命令序列（新机器）：**

```powershell
# 0. 自检依赖：java -version / python --version / mysql 服务 / ollama serve / redis
# 1. 检查环境文件存在且已填（env.local 缺失 = 先从原机复制或按 env.example 重建）
Test-Path backend\deploy\env.local

# 2. 一键启动（首次加 -Setup -Yes；之后 -Smoke）
backend\deploy\start-all.bat -Setup -Yes -Smoke

# 3. 若退出码非 0：
#    2 → 前置未过（先看 MySQL/venv，按行内中文指引）
#    1 → 看 logs\business.log / logs\ai.log / logs\gateway.log 尾部

# 4. 健康矩阵
backend\deploy\status.bat

# 5. 资源端点自验（迁移后必做，见 4.3）
python tools/check-resource-consistency.py
```

**AI 启动自检清单（全部满足才算「后端已就绪」）：**

- [ ] `start-all.bat` 退出码 0
- [ ] `status.bat` 三服务（business/ai/gateway）状态「正常」
- [ ] `GET /api/gw/health` 返回 `ok`（upstreams 含 java/python/ollama）
- [ ] `GET /api/v1/departments` 经网关返回科室列表（种子 16 个，2026-10-24 起）
- [ ] 医生登录 `POST /api/v1/doctor/login {username:"13900139001", password:"doc123"}` 返回 200（dev 种子）
- [ ] 资源清单 `GET /api/v1/resources/manifest` 返回非空（迁移后必须）

## 八、验证清单（改动后必跑）

```powershell
# 后端 AI 服务回归门（cd backend\ai-service，改 prompt/知识库/TTS 后必跑）
.venv\Scripts\python.exe -m pytest tests -q                      # 全量（当前 200+ 项）
```

## 九、常见问题与排障

| 现象 | 处理 |
|---|---|
| `venv 未初始化` | `start-all.bat -Setup -Yes` |
| `MySQL 不可达`（退出码 2） | 启动 MySQL 服务；核对 `env.local` 的 `MYSQL_HOST/MYSQL_PORT` |
| 某服务 FAIL | 看 `logs\<名>.log` 与 `<名>.error.log` 尾部 |
| 端口占用且健康失败 | `status.bat` 看 PID；用任务管理器/`taskkill` 处理被占端口的**非本工具**进程 |
| 服务显示「已在运行…跳过」但想重启 | 它是外部实例（如 IDE 里跑着），本工具不接管——先在外部停掉再 `start-all.bat` |
| 首装依赖很慢 | `config.json` 的 `pipIndexUrl` 已默认清华镜像；可换/留空用官方源 |
| 资源端点全 404 | `backend/deploy/resources/` 为空 → 跑 `resource-import.py --write --version V<N>` 后 `restart.bat`（见 4.3） |
| 从仓库根 `java -jar` 资源全 404 | 未传绝对路径 `APP_RESOURCES_DIR` |
| AI 能力 503（TTS/ASR/RAG 不可用） | 查 `AI_TTS_ENGINE` / `AI_ASR_MODEL_PATH` / `AI_RAG_ENABLED` 配置与依赖（edge-tts 需外网、FunASR 需权重、RAG 需 Redis/Qdrant + 已入库） |
| `AI 登录 503 WECHAT_PROVIDER_UNAVAILABLE` | 生产缺 `WECHAT_MINIPROGRAM_APP_ID/SECRET`；dev 档用 `DevWechatSessionProvider`，不受影响 |
| `healthContains` 判定不稳 | 只改 `config.json` 对应服务的 `healthUrl/healthContains/healthAcceptStatus` |
| 双击 bat 窗口关闭前停住等你按键 | 正常行为（传参数调用则不停）；`start-gui.bat` 是常驻面板 |
| 面板/日志乱码 | 编排器输出恒 UTF-8；服务自身日志编码问题看「服务日志」页签 |
| 启动成功但某 AI 任务报 `MODEL_TIMEOUT` | Ollama 模型未装 / CPU 太慢：先 `ollama pull qwen2.5:7b`；或调大 `AI_TRIAGE_TIMEOUT_SECONDS` |

## 十、迁移红线（务必遵守）

1. **只改 `backend/deploy/env.local` + `config.json`** 两处配置；`env.local` 不入库、不打印值、不散落到文档/聊天。
2. **前端只认 `miniprogram/config/env.js` 的 gateway**（local=PC 模拟器直连本机 :8080 / development=隧道域名 / production=正式 HTTPS+备案+合法域名）；代码禁止出现 8001/8088/127.0.0.1/localhost。
3. **AI 服务只内网可达**：客户端永不直连 8001；缓存/鉴权纪律（O-03）不允许把缓存下沉到客户端可触达路径。
4. **资源目录是构建产物**：部署前必须生成（4.3），不要手改副本（会被 `--write` 覆盖），包内原件不移动不删除。
5. **密钥类（AI_SERVICE_TOKEN / AI_TENANT_SECRET / APP_ATTACHMENT_SIGN_SECRET / PHONE_KEY_BASE64）**：生产多实例必须一致且强随机；本地 dev 也建议固定（避免每次重启后签名 URL 失效）。
6. **知识库改内容必须 bump `version`**（`hospital-knowledge.json` 的 `version` 参与缓存键），否则旧答案继续命中；改完跑 `check-knowledge-base.py` + 注入测试 + 重启 ai-service。
7. **RAG 上线顺序不可颠倒**：装存储 → 建 collection（维度=embedding 模型维度）→ 装 embedding 模型 → 入库（`rag_ingest.py --apply` / `rag_redis_seed.py`）→ 才开 `AI_RAG_ENABLED`。
8. **生产档差异**：`APP_AUTH_MODE=strict`、`mockReadFallback=false`、微信凭证由部署环境注入、`AI_TTS_PUBLIC_BASE` 指向正式域名、资源 `public-base-url` 配置为同源 HTTPS。
