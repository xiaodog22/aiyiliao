## 0. 全局约束（先记这 6 条）

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | **网络资源必须是绝对 HTTPS**（`https://` 开头） | `<image src="/api/...">` 会被当包内路径 → 裂图 |
| 2 | **头像一律走 `resolveAvatar()`** | 站内相对路径被当包内路径 → 裂图；空头像渲染成灰块 |
| 3 | **附件一律走 `resolveAttachmentUrl()`** | 签名 URL 缺网关前缀 → 404 |
| 4 | **内容图/封面走 `resolveResource()` 或 `resolveAttachmentUrl()`** | 远端 URL 被当本地路径 → 裂图 |
| 5 | **PDF 一律 `wx.downloadFile` → `wx.openDocument(tempFilePath)`** | `openDocument` 只吃本地路径，直传 https 必失败 |
| 6 | **图标必须来自 `icons.js`**（禁止 emoji、禁止硬编码路径） | 跨设备字形不一致 / 键名拼错取到 `undefined` |

**唯一网关地址**：`config/env.js` 的 `gateway`（三档：local / development / production）。
页面里**禁止**出现 `127.0.0.1`、`8000`、`8080`、`8088`、域名硬编码 —— 域名由后端清单下发，前端只拼网关。

## 2. `avatarUrl`

**语义**：用户 / 医生 / 家庭成员的头像地址。后端只保证"能给就给"，**不保证一定是绝对地址**。

### 2.1 调用方写法（两种等价）

```js
// 推荐（当前实现：兜底已内聚在函数内）
const src = userService.resolveAvatar(avatarUrl)

// 等价展开（防御写法，与推荐写法结果完全一致）
const src = userService.resolveAvatar(avatarUrl) || '/assets/img/avatar-default.png'
```

**为什么两种都对**：`resolveAvatar` 内部第一行就是 `if (!u) return DEFAULT_AVATAR`，
因此它**永远不会返回空串**，`|| DEFAULT` 是冗余但安全的双重保险。
新增页面用推荐写法即可；若团队规范要求显式兜底，写展开式也不影响行为。

### 2.2 解析规则（`services/user.js`，与 `resolveAttachmentUrl` 同构）

```js
const DEFAULT_AVATAR = '/assets/img/avatar-default.png'

function resolveAvatar(avatarUrl) {
  const u = String(avatarUrl || '')
  if (!u) return DEFAULT_AVATAR                // ① 空 → 包内默认头像
  if (/^https?:\/\//.test(u)) return u          // ② 绝对 URL → 原样（远端优先）
  if (u.charAt(0) === '/') return ENV.gateway + u  // ③ 站内相对 → 拼唯一网关
  return u                                       // ④ 其它形态 → 原样
}
```

### 2.3 为什么必须这样做

- 后端返回的是 `/api/v1/avatars/x.png` 这样的**站内相对路径**；
  `<image src="/api/v1/avatars/x.png">` 在小程序里会被当成**包内路径** → 直接裂图。
- 返回包内默认头像而不是空串：`<image src="">` 在部分机型渲染成空白灰块，
  `wx:if` 判空又会让布局抖动。

**已接入页面**：`profile/personal-info`、`profile/health-records`、`doctor/personal`。
**鉴权**：`GET /api/v1/avatars/*` 在 `AuthInterceptor` 匿名白名单（`<image>` 无法带 Authorization）。

## 3. `coverUrl` 与 `heroImage`

### 3.1 `coverUrl`（科普封面）—— 签名 URL，**没有本地兜底图**

后端生成（`HealthArticleService` → `AttachmentStorage#signedUrl`）：

```
/api/v1/attachments/{objectKey}?expires={epochSeconds}&sig={HMAC-SHA256}
```

| 项 | 值 |
|---|---|
| `objectKey` | 32 位 hex + 白名单扩展名（jpg/jpeg/png/webp/pdf） |
| TTL | **15 分钟** |
| 为空时 | 字段**省略**（NON_NULL）→ 前端不渲染封面 |
| 解析 | `resolveAttachmentUrl(coverUrl)` → 站内相对拼网关 |

**优先级（与资源清单不同，注意别混）**：

```
后端签名 URL（站内相对，必须拼网关） → 无兜底 → 为空则不渲染
```

**为什么不像清单那样"本地兜底"**：封面是内容的一部分，拿一张不对的图兜底等于**展示错误内容**，
比留白更糟。所以这里只有"有/无"，没有"退到包内某张图"。

**三条红线**：
1. **不能缓存签名 URL**（15 分钟失效）；每次拉列表用新响应里的 URL；
2. **不能手工拼 query**：`expires`/`sig` 必须原样透传（网关已实测不丢）；
3. 错误码：过期 `410`、签名伪造 `403`、不存在 `404`。前端收到 410 应**重新拉列表换新 URL**。

### 3.2 `heroImage` —— 当前**不存在**这个后端字段

本轮全仓检索确认：`backend/.../java` 与 `miniprogram/**` 均无 `heroImage`。

首页 hero 的实际实现：

| 视觉 | 实现 |
|---|---|
| 背景 | CSS 渐变（`app.wxss` 的 `--hero-*` / `.grad-hero`） |
| 医院插画 banner | 包内 `assets/home/banner-hospital.jpg`（480×312，由 `tools/build-home-assets.py` 生成），
运行时通过 `resolveResource('home.banner-hospital', ...)` **远端优先、失败回退包内** |

**记录目的**：避免下次有人看到设计稿写 `heroImage` 就去读一个永远为空的后端字段。
若未来后端真要下发 hero 图，语义应与 `coverUrl` 一致（站内相对 → 拼网关），并在 `resource_asset` 登记 key。

## 4. 资源清单（`/api/v1/resources/manifest`）

### 4.1 请求

```
GET /api/v1/resources/manifest?platform=wechat-miniprogram
```
- `platform` 只接受 `wechat-miniprogram`（其它值 → 422）；
- 匿名可读；失败**不阻断启动**（前端有缓存 + 包内兜底）。

### 4.2 字段（与代码逐字段对齐）

| 字段 | 类型 | 能否为空 | 语义 |
|---|---|---|---|
| `manifestVersion` | string | 否 | 语义版本，当前 `v1.1.0`（内容变化必须递增） |
| `generatedAt` | ISO Instant | 否 | 生成时刻 |
| `items[].key` | string | 否 | 业务 key，**单段点分**（`home.banner-hospital`），不含 `/` |
| `items[].level` | `A` \| `B` | 否 | 契约完整性等级（A=客户端必须保留本地兜底） |
| `items[].mime` | string | 否 | 仅 `image/png` / `image/jpeg` / `image/webp` |
| `items[].size` | long | 否 | 字节数，与 `Content-Length` 一致 |
| `items[].sha256` | 64 位小写 hex | 否 | 与端点 `ETag` 一致，可用于下载后校验 |
| `items[].url` | string | **可空** | **绝对 HTTPS**（配置了 `public-base-url` 且 `delivery=remote`）；否则 `null` |
| `items[].fallbackKey` | string | 可空 | **小程序包内路径**（DB 列 `bundle_path` 的投影），如 `/assets/home/banner-hospital.jpg` |
| `items[].version` | string | 否 | 条目版本（当前同 `manifestVersion`） |
| `items[].expiresAt` | ISO Instant | 可空 | 当前恒 `null`（不做配额过期） |

**三个名字别混**：

| 出现位置 | 名字 | 含义 |
|---|---|---|
| DB 列 | `bundle_path` | 包内路径（存储侧） |
| 清单字段 | `fallbackKey` | 同一个值的下发名（契约侧） |
| 前端参数 | `builtinFallback` | 调用方传入的兜底路径（代码侧） |

### 4.3 前端解析（**远端优先、本地兜底**）

```js
function resolveResource(key, builtinFallback) {
  const manifest = readCachedManifest()
  const item = manifest && manifest.items.find((it) => it.key === key)
  if (!item || !item.url) return builtinFallback || (item && item.fallbackKey) || ''
  return item.url
}
```

**优先级（严格按此顺序）**：

```
① items[].url（绝对 HTTPS，非空才用）
② builtinFallback（调用方传入的包内路径）
③ items[].fallbackKey（清单里登记的包内路径）
④ ''（不渲染）
```

> ② 优先于 ③：调用方更清楚"这个位置原来放的是什么图"，清单兜底只是最后一道保险。

### 4.4 什么时候用远端、什么时候用本地（2026-10-19 分类）

清单**只下发 `delivery=remote`** 的资源，当前共 **10 条**：

| key | mime | 场景 |
|---|---|---|
| `home.banner-hospital` | image/jpeg | 首页 banner |
| `health.wash-hands` / `health.measure-bp` / `health.stand-up` | image/jpeg | 科普视频封面 |
| `home.kb-cover-person-leaf` | image/png | 科普列表封面 |
| `content.cover-sleep` / `cover-nutrition` / `cover-exercise` / `cover-wellness` | image/png | 分类封面 |
| `content.detail-hero-sleep` | image/png | 详情页 hero 大图 |

**219 个图标 + 默认头像 + 空态图 + 导航底图 + 首页高频小图 + 3 个视频**（共 237 条）是 `delivery=local`：
**不在清单里、`url` 为 `null`**，前端直接用 `bundlePath`。它们仍可通过
`GET /api/v1/resources/{key}` 按 key 直取（200），只是清单不下发。

> **视频不走清单、但已出包直取**（V17 起 `video.*` = `local`，清单契约保持只含图片）：
> 2026-11-05 F2 Phase B 起，包内 `packageContent/videos/*.mp4` **已删除**，前端播放源 =
> `resource.staticResourceUrl('video.*')` 直拼 `GET /api/v1/resources/{key}`（端点白名单含
> video/mp4、匿名可读、视频 1 天缓存 + ETag）；article 签名链（V19 `video_key`）命中时覆盖为第一优先。
> 换视频文件后最多 1 天缓存生效，需立即生效时换 key（同步改 knowledge-kb 的 videoKey 并发版）。

### 4.5 服务端边界

- `app.resources.public-base-url` 为空 → 所有 `url=null`（前端行为与改造前一致，可作灰度回滚）；
- 表为空 → 回退旧内置 7 条（清单不空）；
- `status=0` 的资源**既不在清单、直取也 404**；
- 清单不出现视频/PDF（mime 过滤）与可执行资源（红线校验）。

## 5. 资源直取端点（`GET /api/v1/resources/{key}`）

| 项 | 值 |
|---|---|
| 鉴权 | **匿名**（`<image>` / `wx.downloadFile` 无法带 Authorization；只返回 `status=1`） |
| `Content-Type` | 取库内 `mime_type`（不写死 octet-stream） |
| `Content-Length` | 显式给出，等于清单 `size` |
| `Cache-Control` | 图片 `max-age=604800, public` / 视频 `max-age=86400` / 其它 `max-age=3600` |
| `ETag` | `"<sha256>"`；带 `If-None-Match` 命中 → `304` |
| `Accept-Ranges` | `bytes`（视频可拖动） |
| 错误 | key 非法 `400`；停用/不存在/文件缺失 `404` |

**前端用法**：图片 `<image src="{{item.url}}">`；PDF `wx.downloadFile({ url })`。
两者都要求域名在 **`downloadFile` 合法域名**里（不是 `request`）。

## 6. 健康档案附件专章

### 6.1 端点

| # | 方法与路径 | 用途 | 鉴权 | 关键约束 |
|---|---|---|---|---|
| 1 | `POST /api/v1/attachments` | 暂存上传 | Bearer | multipart part 名固定 **`file`**；`jpg/jpeg/png/webp/pdf`；**≤10MB** |
| 2 | `GET /api/v1/attachments/{objectKey}` | 匿名读取（签名 URL） | 公开 + HMAC | 判定见 §6.3 |
| 3 | `POST /api/v1/health-records/{recordId}/attachments` | 挂载到档案（或直传） | Bearer | `attachmentKeys` 挂载 与 直传双路径 |
| 4 | `DELETE /api/v1/health-records/{recordId}/attachments/{attachmentId}` | 删除 | Bearer | 越权返回 **404**（不泄露存在性） |

### 6.2 图片附件：`<image>` + `resolveAttachmentUrl`

```js
// 列表：把签名 URL 拼成绝对地址
url: userService.resolveAttachmentUrl(a.url)

// 查看：previewImage（原生支持 https，不需要先下载）
wx.previewImage({ urls: [url], current: url,
  fail: () => wx.showToast({ title: '图片打不开，链接可能已过期', icon: 'none' }) })
```

**为什么图片可以直接给 URL**：`wx.previewImage` / `<image>` 支持 https。
**为什么仍要 `resolveAttachmentUrl`**：后端给的是 `/api/v1/attachments/...` 站内相对路径，不拼网关就是包内路径。

### 6.3 PDF 附件：`wx.downloadFile` → `wx.openDocument`

```js
_openPdf(url) {
  wx.showLoading({ title: '正在打开', mask: true })
  wx.downloadFile({
    url,
    success: (res) => {
      wx.hideLoading()
      if (res.statusCode === 410) {                    // 签名过期
        wx.showToast({ title: '链接已过期，请重新打开档案', icon: 'none' }); return
      }
      if (res.statusCode !== 200 || !res.tempFilePath) {
        wx.showToast({ title: '文件下载失败（' + res.statusCode + '）', icon: 'none' }); return
      }
      wx.openDocument({ filePath: res.tempFilePath, fileType: 'pdf', showMenu: true,
        fail: () => wx.showToast({ title: '文件打开失败', icon: 'none' }) })
    },
    fail: () => { wx.hideLoading(); wx.showToast({ title: '下载失败，请检查网络', icon: 'none' }) }
  })
}
```

**两个必须记住的点**：
1. `wx.openDocument` 的 `filePath` **只接受本地文件路径**，直接传 https 地址真机必失败
   （开发者工具偶发"能打开"是它的容错，不能作为真机依据）；
2. `wx.downloadFile` 对 **4xx/5xx 也走 `success`**（只有网络层错误走 `fail`），
   所以必须在 `success` 里判 `statusCode`。

### 6.4 判定顺序与错误码（前端据此提示）

| 顺序 | 条件 | 状态 | code | 前端动作 |
|---|---|---|---|---|
| ① | 缺 `expires` 或 `sig` | `400` | `VALIDATION_FAILED` | 不应出现（前端只用后端给的 URL）；出现则记录日志 |
| ② | `expires` 已过期 | `410` | `ATTACHMENT_URL_EXPIRED` | **重新拉档案列表换新 URL**，不要重试旧链接 |
| ③ | `sig` 不符 | `403` | `ATTACHMENT_SIGNATURE_INVALID` | 同上（URL 被篡改或密钥变更） |
| ④ | `objectKey` 不存在 | `404` | `ATTACHMENT_NOT_FOUND` | 提示"文件已删除"，刷新列表 |
| ⑤ | 正常 | `200` | — | 图片 `previewImage` / PDF `openDocument` |

**响应头**：`Cache-Control: no-store`（签名 URL 不缓存）、`Content-Type` 按扩展名、
`Content-Disposition: inline; filename="<objectKey>"`。

## 7. 科普详情视频（V19 · 方案 B）

详情页在 `type === 'video'` 时，额外拉一次 `GET /api/v1/health-articles/{id}` 取签名 `videoUrl`。

### 7.1 字段

| 字段 | 来源 | 语义 |
|---|---|---|
| `videoUrl` | 详情接口 | **站内相对**签名路径 `/api/v1/attachments/{key}.mp4?expires=&sig=`，TTL **7200s**；无视频时**字段省略** |
| `videoDurationSec` | 详情接口 | 当前**恒 null**（表无时长列）→ 字段省略 |

### 7.2 前端绑定（远端优先、包内兜底）

```js
videoSrc  = resolveAttachmentUrl(a.videoUrl) || it.video    // 站内相对拼网关；空值回退包内 mp4
posterSrc = resolveAttachmentUrl(a.coverUrl) || it.cover    // 同一规则
```

```xml
<video src="{{item.videoSrc}}" poster="{{item.posterSrc}}" binderror="onVideoError"
       object-fit="contain" show-center-play-btn="{{true}}" enable-play-gesture="{{true}}" />
```

首屏先渲染包内 mp4（秒开），拿到远端后覆盖；切换时 `<video>` 会重载一次，属正常。

### 7.3 失败与过期处理（必须按此实现）

| 场景 | 行为 |
|---|---|
| 详情 404 / 网络失败 | **静默**保持包内 mp4，不弹错、不空白 |
| 播放失败（首次） | `videoRetried` 置位 → 重拉详情换新 URL（处理签名过期 / 拖动到一半 403） |
| 重试拿到的 URL 与上次**相同** | 直接回退包内（比较**原始 raw**，不是拼过网关的绝对地址） |
| 回退包内仍失败 | 显示「视频加载失败，请稍后重试」，**不再改 src**（防死循环） |
| `videoDurationSec` 为 null | 用本地 KB 的 `durationSec` 兜底，**不渲染 "null 秒"** |

**取舍**：`videoRetried` 每个页面生命周期只允许重试一次——这是刻意设计，不是 bug。
无限重试会在服务端持续 403 时形成请求风暴。

### 7.4 边界

- 视频**不进** `resources/manifest`（清单只下发图片 mime）；
- 不放开 `ALLOWED_MIME` 给 `video/mp4`（走附件通道，独立限额与 TTL）；
- 列表接口**不下发** `videoUrl`（列表无播放器；2 小时后必然过期，缓存里会变死链）。

## 8. 常见错误对照

| 现象 | 根因 | 正确做法 |
|---|---|---|
| `<image>` 空白、无报错 | 用了站内相对路径（被当包内路径） | 过 `resolveAvatar` / `resolveAttachmentUrl` / `resolveResource` |
| 真机裂图，工具正常 | 只勾了「不校验合法域名」；后台只配了 `request` 域名 | 配 `downloadFile` 合法域名；关掉不校验再测 |
| 封面过一会儿全裂 | 缓存了 `coverUrl`（15 分钟过期） | 每次拉列表用新 URL；410 重新拉 |
| 清单 `url` 一直 `null` | `public-base-url` 未配置，或该资源是 `delivery=local` | 前者配 `APP_RESOURCES_PUBLIC_BASE_URL`；后者是**设计如此** |
| 资源全 404 | `APP_RESOURCES_DIR` 指向错误（相对工作目录） | 传绝对路径；配错时**启动会直接失败**（已加校验） |
| 下载文件叫 `f.txt` | 端点未设 `Content-Disposition` | 已修：`inline; filename="<真实名>"` |
| PDF 点开无反应 | 把 https URL 直接传 `openDocument` | 先 `downloadFile` 再 `openDocument(tempFilePath)` |
| 图标显示成方块/问号 | 用了 emoji 或拼错 key | 只用 `icons.js` 的键；校验脚本会报未定义引用 |
