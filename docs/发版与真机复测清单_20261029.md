## 一、发版前置硬卡点（必须人工执行，按顺序）

### 1. 构建档位门禁

```bash
node tools/check-build-env.js
```

| 退出码 | 含义 | 动作 |
| --- | --- | --- |
| **0** | `BUILD_ENV=production` + `production.gateway` 为正式 HTTPS + 后端默认档位/闸门 fail-closed | ✅ 允许出包 |
| **1** | 仍是非生产档（当前仓库即 `development`）、或网关为空/临时域名、或后端安全默认被改坏 | ❌ **禁止出包**，按提示修正 |

> ⚠️ 口径澄清：**发版要求 exit=0**。早期口头说法"预期 exit=1"是反的 —— exit=1 恰恰说明包还是开发档。
> 联调包（走隧道、需要手输登录）才用 `node tools/check-build-env.js --allow-dev`，它只把"档位/生产网关"两项降级为提示，
> **后端 profile 与联调闸门仍然必须 fail-closed**。

### 2. 后端档位

- `application.yml` 的 `spring.profiles.default` 已改为 **`prod`**（2026-10-29）。
- 本地联调必须在 `backend/deploy/env.local` 显式声明：

```ini
SPRING_PROFILES_ACTIVE=dev
```

- 漏写后果：不加载 `db/dev` 种子；登录走 `ProdWechatSessionProvider`，无 AppID/Secret 时如实 503（**不会**退化成假身份）。这正是要的 fail-closed。

### 3. 联调登录闸门（dev 档专属）

dev 派生 code（`dev-user-*` / `dev-phone-*`）现在必须带请求头 `X-Dev-Login-Key`：

```ini
# backend/deploy/env.local（prod 不配这两项）
APP_AUTH_DEV_LOGIN_ENABLED=true
APP_AUTH_DEV_LOGIN_KEY=<与 miniprogram/config/env.js 的 DEV_LOGIN_KEY 完全一致>
```

- 未开启 / 密钥为空 / 头不匹配 / 无请求上下文 → `403 DEV_LOGIN_FORBIDDEN`，不签发会话。
- 换密钥：**同时**改 `env.local` 与 `miniprogram/config/env.js`，两处不一致 → 真机 403。
- 残余风险（如实声明）：该 key 随联调包分发，可被逆出，只挡"不带密钥的盲扫"；
  真正的边界是 `SPRING_PROFILES_ACTIVE=prod` + 闸门默认关闭。
