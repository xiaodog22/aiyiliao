## 1. 功能背景与目标

### 1.1 问题陈述（Why）

- **待确认**：谁在什么场景下提交什么对象、提交完成后当前遇到什么阻碍、发生频率多高。
- **待确认**：不做这件事的代价（用户痛点、业务影响、合规或竞争风险）。
- 已知事实：仓库内不存在「提交 → 审核 / 评定」模块与审批端点，因此本次交付的是**可复用前端能力**，不是已上线的完整业务闭环。

### 1.2 目标

| 编号 | 目标 | 类型 | 如何判断成功 | 状态 |
| --- | --- | --- | --- | --- |
| G1 | 提交完成后才向用户开放后续操作入口，避免未完成态误导 | 用户目标 | 未完成态下入口不渲染；见 §10 AC-01/AC-02 | 已由离线单测覆盖 |
| G2 | 「通过」操作状态一致、可重复触发不产生重复结果 | 用户目标 / 质量目标 | 见 §10 AC-04/AC-05 | 已由离线单测覆盖 |
| G3 | 「去评定项目」把用户带入评定流程 | 用户目标 | 见 §10 AC-06 | **目标流程待确认**，仅有跳转能力 |
| G4 | 缩短提交完成到后续动作的操作路径 | 用户目标 | 基线与目标值：待确认 | 待确认 |
| G5 | 降低因状态不一致导致的重复操作 / 客诉 | 业务目标 | 基线与目标值：待确认 | 待确认 |

> 目标均为结果而非产出；G4/G5 的量化目标值在取得基线数据前不填写。

## 5. 用户操作流程

### 5.1 主流程

| 步骤 | 用户动作 | 系统响应 | 备注 |
| --- | --- | --- | --- |
| 1 | 发起提交 | 状态 `DRAFT → SUBMITTING`，无入口 | 提交动作本身不在本功能范围 |
| 2 | 提交完成 | 状态 `SUBMITTED`，渲染两个入口 | 完成判定依据：待确认 |
| 3a | 点「通过」 | 状态 `PASSED`，展示「已通过」，发出一次 `pass` 事件 | 落库由宿主处理，待接线 |
| 3b | 点「去评定项目」 | 跳转到 `assessPath` 对应页面 | 目标流程见关联文档 |
| 4 | 重复点击任一入口 | 状态不变；通过不重复通知；导航在途不叠栈 | 见 §9 |

### 5.2 异常流程

| 触发 | 系统响应 |
| --- | --- |
| 提交失败 / 取消 | 状态回 `DRAFT`，入口不出现 |
| 提交中收到完成态脏数据 | 仍不开放入口 |
| 未配置评定路由 | 中文提示「评定入口未配置」，不跳转 |
| 跳转失败 | 中文提示「暂无法打开评定页面」，释放导航锁 |
| 服务端审批落库失败 | **待确认**（当前未接线，需定义回退与提示） |

## 7. 状态与权限

### 7.1 状态定义（已实现）

| 状态 | 含义 | 是否开放入口 |
| --- | --- | --- |
| `DRAFT` | 草稿 / 未完成 | 否 |
| `SUBMITTING` | 提交在途 | 否 |
| `SUBMITTED` | 提交完成，待处理 | 是 |
| `PASSED` | 已通过 | 是（「通过」变为「已通过」） |

### 7.2 状态转移（已实现）

| 起点 | 事件 | 终点 |
| --- | --- | --- |
| `DRAFT` | 开始提交 | `SUBMITTING` |
| `SUBMITTING` | 提交成功 | `SUBMITTED` |
| `SUBMITTING` | 提交失败 | `DRAFT` |
| `SUBMITTED` | 通过 | `PASSED` |
| 任意 | 重置 | `DRAFT` |

> 未知状态、`null`、非对象输入一律归一化为 `DRAFT`，不抛异常，不误判为完成态。

### 7.3 权限

| 项 | 状态 |
| --- | --- |
| 谁可以看见入口 | **待确认** |
| 谁可以执行「通过」 | **待确认** |
| 谁可以进入评定流程 | **待确认** |
| 前端是否做权限隐藏 | **待确认** |
| 服务端是否做权威校验 | **待确认**（建议必须有，但需安全与后端确认） |
| 越权访问的提示与日志 | **待确认** |

> 现有实现只做状态校验，**不含任何权限判定**；权限模型未定义前不得宣称功能具备权限控制。

## 9. 验收标准

采用 Given / When / Then；AC-01～AC-08 已有离线自动化断言（`tools/test-submission-actions.js`，42 项），AC-09 起依赖接线。

| 编号 | 验收标准 | 状态 |
| --- | --- | --- |
| AC-01 | Given 状态为 `DRAFT` 或 `SUBMITTING`，When 页面渲染，Then 不出现「通过」「去评定项目」 | 已验证 |
| AC-02 | Given 状态为 `SUBMITTED` 且 `submitting=false`，When 页面渲染，Then 两个入口均出现 | 已验证 |
| AC-03 | Given 未完成态，When 直接调用两个操作方法，Then 不发 `pass` 事件、不跳转，并给出中文拒绝提示 | 已验证 |
| AC-04 | Given `SUBMITTED`，When 点击「通过」，Then 状态变为 `PASSED`、显示「已通过」、恰好发出一次 `pass` 事件且携带正确的 `submissionId` | 已验证 |
| AC-05 | Given 已 `PASSED`，When 再次点击「通过」，Then 状态对象保持一致、不产生新事件 | 已验证 |
| AC-06 | Given `SUBMITTED` 且已配置 `assessPath`，When 点击「去评定项目」，Then 跳转到该目标且只跳转一次 | 已验证（目标页面待确认） |
| AC-07 | Given 导航在途，When 连续点击，Then 只发起一次跳转 | 已验证 |
| AC-08 | Given 未配置目标 / 跳转失败 / 宿主禁用，When 触发，Then 无跳转且提示为中文 | 已验证 |
| AC-09 | Given 真实页面已接线，When 点击「通过」，Then 服务端记录该提交为通过，且刷新后状态仍为通过 | **待确认**（需审批契约） |
| AC-10 | Given 无权限用户，When 访问，Then 入口不可见且服务端拒绝操作 | **待确认**（需权限模型） |
| AC-11 | Given 真机与弱网环境，When 执行主流程，Then 交互与提示符合适老化要求 | **待确认**（需真机验证） |
