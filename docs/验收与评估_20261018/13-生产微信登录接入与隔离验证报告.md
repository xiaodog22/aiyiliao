## 二、实现说明

### 2.1 采用的官方接口（与项目当前登录方式一致）

小程序 `wx.login()` 拿到一次性 `code`，服务端调用官方
「小程序登录凭证校验」`GET https://api.weixin.qq.com/sns/jscode2session`：

| 参数 | 值 |
|---|---|
| `appid` | 小程序 AppID |
| `secret` | 小程序 AppSecret |
| `js_code` | `wx.login` 的临时 code（**一次性**） |
| `grant_type` | `authorization_code` |

成功响应字段：`openid`（必需）、`session_key`（服务端内部用）、`unionid`（可选）；业务失败以 `errcode`/`errmsg` 表达（`errcode=0` 为成功）。参考官方文档：
[auth.code2Session（小程序服务端 API）](https://developers.weixin.qq.com/miniprogram/dev/server/API/user-login/api_code2session.html)、
[小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)。

> 手机号（`getPhoneNumber` 动态令牌）链路的契约路径是 `login.phoneCode`，前端登录页确实会上送，因此本轮一并接入：
> `GET /cgi-bin/token?grant_type=client_credential&appid=&secret=` 取 `access_token`（**进程内缓存**，到期前 5 分钟视为过期），
> 再 `POST /wxa/business/getuserphonenumber?access_token=` 取 `phone_info.purePhoneNumber`。
> **唯一允许的重试**：`access_token` 失效（`40001/40014/42001`）→ 换票后重试 **一次**；登录 code 永不重放。

### 2.3 错误分类与对外语义

| 情形 | HTTP | 对外 code | retryable | 客户端可做什么 |
|---|---|---|---|---|
| 凭证未配置 | 503 | `WECHAT_PROVIDER_UNAVAILABLE` | false | 提示"服务未就绪"，不要退避重试 |
| 微信 `40029`（code 无效/过期）、`40163`（code 已使用） | 422 | `WECHAT_CODE_INVALID` | false | 重新 `wx.login()` 取新 code |
| 微信 `40013/41002/41004/40125/40164`（AppID/Secret/IP 白名单错误） | 503 | `WECHAT_PROVIDER_UNAVAILABLE` | false | 同上（把"我们配错密钥"隐藏在"未就绪"后面，不向小程序泄露运维信息） |
| 网络异常 / 建连超时 / 读取超时 / 上游 4xx-5xx / `-1` / `45011` | 503 | `WECHAT_UPSTREAM_UNAVAILABLE` | **true** | 可有限重试（但**必须换新 code**） |
| 非 JSON / JSON 非对象 / 缺 `openid` / 缺手机号字段 | 503 | `WECHAT_RESPONSE_INVALID` | false | 提示稍后重试 |
| 手机号令牌无效（`40029/40163`） | 422（由 `AuthService`） | `PHONE_CODE_INVALID` | false | 重新授权手机号 |
| 用户映射失败 / 会话签发失败 | 500 | `INTERNAL_ERROR` | true | 统一兜底，细节只进服务端日志 |

统一信封由既有 `GlobalExceptionHandler` 生成（`code/message/requestId/details/retryable/serverTime`），**不含任何凭证**。

### 2.4 安全红线落实

| 要求 | 落实 |
|---|---|
| AppID/Secret 不硬编码 | 只来自 `WechatMiniProgramProperties`；源码/测试/样例均为空或测试假值 |
| 配置缺失不伪造成功 | 抛 503，登录前直接短路（不发上游请求） |
| 不用 code 当长期凭证 / 不无限重试 | 每次登录请求最多 1 次上游调用；code 不落库、不缓存；仅 `access_token` 换票重试一次 |
| 不记录敏感数据 | 日志只有 `operation` / `errcode` / `category` / `elapsedMs` / 上游 HTTP 状态；**不记** code、AppSecret、session_key、URI（含 query）、响应正文 |
| 不回传 session_key | `WechatSessionInfo.sessionKey` 仅内存传递；`SessionData`/`UserData` 均无该字段（测试断言响应体不含 `session_key`/`sessionKey`/`"openid"`） |
| 不回退模拟登录 | 生产档 `@Profile("!dev & !itest")`；失败即失败，无降级分支 |
| 角色不由客户端决定 | 医生端仍走 `DoctorService.login` → `doctorRepository.findActiveByUserId`（数据库任职关系），请求体无角色字段 |
| 保留现有会话/鉴权 | 完全复用 `AuthSessionStore`（库内存 SHA-256）、`AuthInterceptor` strict 模式、Token/refresh/logout 机制，**零改动** |

// 之前：TODO 骨架，任何档位都抛 503
public WechatSessionInfo getSessionByCode(String code) {

public WechatSessionInfo getSessionByCode(String code) {
    requireConfigured("code2session");                 // 缺配置 → 503，且不发请求
    if (code == null || code.isBlank()) throw codeInvalid();
    long t0 = System.nanoTime();
    Response response = call("GET", code2SessionUri(code), null, "code2session", t0);
    JsonNode root = readObject(response, "code2session");   // 非 200/非 JSON/非对象 → 503
    int errcode = root.path("errcode").asInt(0);
    if (errcode != 0) throw businessFailure(errcode, "code2session", t0);  // 40029→422，-1→503可重试

## 八、尚未解决的风险

| # | 风险 | 影响 | 建议 |
|---|---|---|---|
| R1 | **真实微信未联调**（无凭证） | 生产登录真实性未验证；参数/错误码行为仅依据官方文档 | 拿到测试小程序后做一次真实登录 + 手机号联调，再判定"生产登录恢复" |
