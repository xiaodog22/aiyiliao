## 3. `test-nav-page` 修复

### 3.1 根因（已复现，非猜测）

`tools/test-nav-page.js:219` 的 `cssBlock(css, selector)` 用「选择器字样 + `[^{]*{`」定位规则块：

```js
const re = new RegExp(selector.replace(...) + '[^{]*\\{', 'g')
```

而 `miniprogram/packageNav/pages/nav/nav.wxss:75-76` 的注释里**合法地**出现了 `.nv-sheet` 字样：

```css
/* 选中目的地后路线弹层（.nv-sheet，占 56vh 下半屏）会盖住居中的按钮堆叠 →
   把工具栏贴到地图上沿，四个按钮全部留在弹层之上（手机端；平板弹层是就地占位面板，见下方断点）。 */
.nv-tools-up {
  top: 16rpx;
  transform: none;
}
```

注释内没有 `{`，正则便从注释里的 `.nv-sheet` 一路吃到 `.nv-tools-up {`，于是 `cssBlock(css,'.nv-sheet')` 返回的是 **`.nv-tools-up` 的块**：

```
解析到的块首 60 字: " top: 16rpx; transform: none; "
```

真实 `.nv-sheet` 在 `nav.wxss:229-244`，确实是 `height: 56vh` + `overflow: hidden`（正确）。

**因此 3 条失败中的 2 条是纯误报**；第 3 条（平板工具栏）是**断言过期**，见 §3.3。

### 3.2 修复内容（`tools/test-nav-page.js`）

1. 新增 `stripCssComments(css)`：`String(css).replace(/\/\*[\s\S]*?\*\//g, '')`。
2. `cssBlock()` 内部**先剥注释再匹配**（自防御：任何未来调用点都不会再踩）。
3. `cssBlock()` 增加**选择器右边界**：类/ID 选择器用 `pat + '(?![\\w-])[^{]*\\{'`，避免 `.nv-sheet` 命中 `.nv-sheet-h` / `.nv-sheet-ops`；`@media` 仍保留 `[^{]*\\{`（条件串里允许出现其它内容）。
4. `styleChecks()` 读取 `nav.wxss` 后立即 `stripCssComments`，使 `media` / `mediaHead` 等**所有**直接正则也在无注释文本上运行。
5. **未删除任何测试规则**；断言总数 75 → 78（新增 3 条自测）。

`nav.wxss` **一个字节都没改**（`git status` 可证：`packageNav/pages/nav/nav.wxss` 不在修改列表中）。

### 4.4 幂等声明决策（本轮唯一"规则权衡"）

检查器要求：写操作必须声明 `Idempotency-Key` 参数，或显式 `x-idempotency: not-required`。

**本轮实测结论：这 6 个写端点在后端都不消费幂等键。**

- `MeController` 的 6 个方法**都没有** `@RequestHeader(IdempotencyKeys.HEADER)`；
- `IdempotencyKeys.require(...)` 只出现在 appointment / consent / 家庭成员**创建**；
- `WebMvcConfig` 只注册 `AuditInterceptor`、`AuthInterceptor`、`RateLimitInterceptor`，**无幂等拦截器**。

因此一律标注 `x-idempotency: not-required`，并在 `description` 里写明"整体覆盖写，同载荷重复提交得到同一终态"——**描述服务端真实行为，而不是声明一个它不兑现的承诺**。

同时给 `PUT /api/v1/voice/voices/default` 补上 `x-idempotency: not-required`（同为覆盖写，原契约漏声明）。

> ⚠️ **遗留不一致（不在 B0 修）**：`services/user.js:182,188` 为 identity/insurance 生成了 `Idempotency-Key` 并发出，但后端忽略它。若要让幂等真正生效，需要在后续批次让后端消费该键，再把契约从 `not-required` 升级为 `Idempotency-Key` 参数。**不能只改契约不改实现。**

### 6.4 后续提交 `miniprogram/` 时，顶层如何更新 gitlink

**必须两步，顺序不能反**（B0 不执行，仅给出规程）：

```bash
# ① 在前端仓库提交（先确认分支与工作区）
cd miniprogram
git add -A
git commit -m "<批次说明>"
git rev-parse HEAD          # 记下新 sha，记作 <NEW_SHA>

# ② 回顶层，只更新指针（顶层不保存子仓文件内容）
cd ..
git add miniprogram         # 暂存的就是 gitlink 变更
git commit -m "更新 miniprogram 子模块指针（<NEW_SHA 前 7 位>）"
```

要点：
- `git add miniprogram` **只会**把 gitlink 从旧 sha 改成新 sha，不会把前端文件塞进顶层。
- 若只做 ①，顶层 `git status` 会长期显示 ` M miniprogram`（"new commits"），**交付物与源码不一致**。
- 若只做 ②（未在子仓提交），gitlink 会指向一个**没有新改动**的旧 sha，等于白提交。
- **不要**用 `git submodule update --init`：当前无 `.gitmodules`，该命令会报 `no submodule mapping found`。
