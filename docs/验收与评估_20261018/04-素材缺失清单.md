# 04 · 图片、图标及视觉素材缺失清单

> 本报告独立成篇：素材问题不是"前端开发没做完"，而是**资产交付与工程约束的错配**。
> 所有"已有/缺失"均以**代码实际引用**为准（脚本扫描 `icons.xxx`、`icon:'xxx'`、硬编码 `src`、`app.json` tabBar）。

| 主包体积 | 1545.2 KB / 2048 KB | 见 `00` §二 |

**结论**：素材问题不是"缺得多"，而是"**缺的没做、做了的没用、用不上的还在包里**"。

## 二、设计稿交付素材的三个硬伤（必须先解决才能复用）

| 问题 | 证据 | 后果 |
|---|---|---|
| 扩展名与内容不符 | 8 张插画 + 2 张图标总表文件头均为 `FF D8 FF`（JPEG），扩展名 `.png` | 工具链/审核会按 PNG 处理；无法透明；`<image>` 虽可按内容解码但无 alpha |
| 尺寸过大 | 全部 2048×2048（图标表 1773×2364） | 8 张合计 3.1 MB，**单张即可吃掉主包 1/6**；小程序卡片实际只需 ≤360px 宽 |
| 无 alpha 通道 | JPEG 不支持透明 | 设计稿要求"透明底机器人/Logo"无法直接实现；放在 `#F1F8FD` 页底会出现白方块 |

> 已在项目中验证的**正面样例**：`assets/home/xiaoan-robot.png`（720×911，调色板 PNG + `tRNS` 全透明表，60 KB）——这才是可用的交付形态。

## 九、统一素材规范（建议）

### 9.1 图标
| 项 | 规范 |
|---|---|
| 风格 | 线性描边，线宽 1.5–2px（96 画布上 2px），圆角端点与圆角连接，闭合图形不封口 |
| 尺寸 | 统一 96×96 PNG（三档显示：24/32/44/56rpx 通过 `.ic-*`） |
| 颜色 | 基色 `#0B6EF8`；派生 `_gray #8A9BB8`、`_white #FFFFFF`、彩色变体仅用于语义（红=紧急、绿=成功） |
| 命名 | `<glyph><Variant>.png`，Variant ∈ `''/Gray/White/Amber/Mint/Purple/Pink/Green/Red`，与 `icons.js` 键一一对应 |
| 目录 | `assets/icons/`（唯一） |
| 禁用 | SVG、emoji、字符图标（`› ＋ ×` 等现存的 3 处应替换为 `chevronRight`/`plus`） |

### 9.2 插画
| 项 | 规范 |
|---|---|
| 语言 | 浅色扁平 + 单色线性主体 + 一处点缀色（绿/薄荷），不写实、不渐变过多 |
| 底色 | `#E4F1FF`（蓝）/ `#E0F7F0`（薄荷）圆角方（48rpx） |
| 尺寸 | 卡片缩略 360×270（4:3）；空状态 320×320；详情主图 686×360（2:1） |
| 透明 | **仅**机器人/Logo/空状态需要 alpha；卡片封面不需要（由容器裁圆角） |
| 格式 | PNG-8（≤64 色）优先；照片类用 JPG q80；**禁用 WebP**（微信基础库兼容性不稳） |
| 单张上限 | 插画 ≤60 KB；空状态 ≤45 KB；Logo ≤40 KB；封面 ≤60 KB |

### 9.3 体积与目录
| 项 | 规范 |
|---|---|
| 主包 | ≤1.6 MB（产出素材后为 **1610.8 KB**，余 437.2 KB；**新增插画优先进分包**） |
| 分包 | 科普图片/视频一律 `packageContent/assets/`；导航底图 `packageNav/assets/` |
| 命名 | 语义化 kebab：`cover-sleep.png`、`empty-records.png`、`logo-mark.png`；禁止 `1.png`/`图1.png` |
| 去重 | 同图多用途复用同一个 key（如 `volume` 用于音量/音色/播报）；派生色走脚本生成，不手工存多份 |

### 9.4 微信小程序兼容性（硬约束）
1. `<image>` 与 tabBar **不支持 SVG**（67 个 svg 已在包里但永远用不上）。
2. 不支持给 PNG 着色（无 tintColor）→ 同形状不同色必须预先出多份 PNG。
3. `background-image` 不支持本地路径（须网络图或 base64）→ 装饰一律 CSS 渐变/伪元素。
4. `mode="aspectFill"` 会裁切，插画主体需留 ≥8% 安全边。
5. tabBar 图标 81×81 建议、≤40 KB，且**必须**提供选中/未选两版。
6. "图片和音频资源 ≤200K" 是**全包（含分包）字节总和**审计口径 → 唯一出路是图标字体化或远端化，压缩无法达标。
