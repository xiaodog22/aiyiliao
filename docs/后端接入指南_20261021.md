# 楚大夫后端接入指南（V1.19 / V21）

> 面向：微信小程序前端、联调人员、部署人员。  
> 更新时间：2026-10-21  
> 契约事实源：`backend/contracts/business-openapi.yaml`、`backend/contracts/ai-openapi.yaml`。本文按当前仓库实现整理，已明确区分“已实现”和“需配置/待前端迁移”，不把 mock 数据或规划接口当成已接通能力。

## 1. 架构与调用边界

```text
微信小程序
  │ 只访问 config/env.js 的 gateway（统一网关）
  ▼
edge-gateway :8080
  ├─ /api/gw/**       网关自身能力（健康、路由、公开资源/音色别名）
  └─ /api/**          代理 business-service :8088
                         └─ 通过内网调用 ai-service :8001
                                      └─ Ollama :11434
```

- 小程序禁止直连 `8001/8088/11434`，也禁止把内网地址写进前端；所有业务请求经 `services/request.js` → gateway。
- ai-service 只提供 `/internal/**`，不是客户端 API；患者/医生鉴权、权限、幂等和业务数据由 Spring Boot 负责。
- Java/FastAPI 成功信封分别兼容 `{code,message,data}`；客户端由 `request.js` 统一脱壳。错误按稳定 `code` 分支，不解析错误文案来判断业务。
- 写请求使用 `Idempotency-Key`；问诊消息、AI 解读、挂号、家庭邀请等不得因重试造成重复数据。

## 2. 公共请求约定

| 项目 | 约定 |
|---|---|
| 基础地址 | `ENV.gateway`，路径直接使用下表 `/api/v1/...` 或 `/api/gw/...` |
| 登录 | 患者微信登录 `POST /api/v1/auth/wechat/login`；医生 `POST /api/v1/doctor/login`，字段是 `username/password`，不是 phone |
| 请求头 | `Authorization: Bearer <accessToken>`、`X-Request-Id`（客户端可生成）、写操作 `Idempotency-Key`（建议 UUID） |
| 超时 | 普通请求按网关配置；AI 问诊 90s、养生 180s、TTS 120s。AI 采用“提交任务 → 轮询”，不要让页面无限等待 |
| 成功 | `code=200`（或契约约定成功码），业务结果在 `data` |
| 常见错误 | `401` 未登录、`403` 无角色/无权限、`404` 资源不属于当前用户、`409` 状态/版本冲突、`422` 参数或业务状态不可用、`429` 限流、`503` AI/模型不可用 |
| 降级红线 | 后端失败时可展示错误态或本地规则结果，但不能用 mock 文本冒充 AI、不能伪造医生/预约/解读结果 |

## 3. 患者端接口

### 3.1 首页、用户与账号安全

| 功能 | 方法与路径 | 说明 |
|---|---|---|
| 首页汇总 | `GET /api/v1/home/summary` | 返回 `greeting`、`blocks`；可能包含 `NEXT_APPOINTMENT`，没有未来预约时不返回该块 |
| 当前用户 | `GET /api/v1/me` | 姓名、手机号绑定状态、角色、完整度；头像/性别/生日字段以当前契约实际返回为准 |
| 更新偏好 | `PUT /api/v1/me/preferences` | 字号、主题等偏好 |
| 更新扩展资料 | `PUT /api/v1/me/extended` | 邮箱、住址、户籍等，按 DTO 校验 |
| 更新姓名/账号 | `PUT /api/v1/me/account` | 账号资料更新 |
| 绑定实名 | `POST /api/v1/me/identity` | 身份证信息服务端加密保存；前端不得记录明文 |
| 绑定医保 | `POST /api/v1/me/insurance` | `insuranceType` + `insuranceNo` |
| 上传头像 | `POST /api/v1/me/avatar` | multipart；返回服务端头像引用/URL |
| 撤销授权 | `POST /api/v1/user/auth/revoke` | `scope`：`PROFILE` / `HEALTH_RECORDS` / `FAMILY`；撤回后健康解读等处理应返回 422 |
| 注销申请 | `POST /api/v1/me/deletion-requests` | 按契约完成短信挑战，不在前端自行删除数据 |
| 发送验证码 | `POST /api/v1/auth/sms/send` | `scene` 仅 `DOCTOR_LOGIN` / `ACCOUNT_DELETION` |
| 刷新/退出 | `POST /api/v1/auth/refresh`、`POST /api/v1/auth/logout` | 由统一登录服务管理令牌 |

**账号安全前端建议**：密码/验证码/身份证/医保号只走 HTTPS 网关；日志、埋点和错误提示不得打印原值；退出登录同时清理本地 token 和页面缓存。后端已具备账号更新、短信挑战、授权撤回、注销申请能力，当前“账号安全”页面主要是前端编排，不需要另造 `/security` 端点。

### 3.2 AI 导诊、AI 问诊与 AI 养生

#### 导诊

- `POST /api/v1/triage/recommendations`：输入症状文本，返回推荐科室及依据。
- `POST /api/v1/triage/emergency-check`（兼容复数路径 `/emergency-checks`）：风险判断用 **POST**，不是 GET。
- 本地红旗规则必须先于网络调用；命中急症直接提示 120。后端 AI 结果是补充，不替代本地安全规则和医生诊断。

#### AI 问诊（真实 Ollama）

1. 创建会话：

```http
POST /api/v1/consultations
Authorization: Bearer <token>
Idempotency-Key: <uuid>
Content-Type: application/json

{"initialMessage":"最近饭后胃胀，持续三天","inputMode":"TEXT","locale":"zh-CN"}
```

返回 `data.consultation`（含 `id/status/messageCount`）和 `data.task`（含 `taskId/status`）。

2. 继续对话：

```http
POST /api/v1/consultations/{consultationId}/messages
Idempotency-Key: <uuid>
{"content":"没有发热，但晚上更明显","inputMode":"TEXT","locale":"zh-CN"}
```

用户消息先持久化，再创建 AI 任务；生成失败不会删除用户消息。

3. 轮询任务：

```http
GET /api/v1/ai/tasks/{taskId}
```

终态为 `SUCCEEDED|FAILED|CANCELLED|EXPIRED`。成功结果为 `CHAT` 结构（`text/citations/provenance/refused/refusalReason/language`）；当前无检索链路，`citations` 为空数组，不得展示虚构来源。失败显示稳定错误码和可重试提示。

4. 查询会话：`GET /api/v1/consultations`、`GET /api/v1/consultations/{consultationId}`、`GET /api/v1/consultations/{consultationId}/messages`。

> 前端必须把问诊页从“只保存在内存”迁移到上述三个步骤，否则“我的问诊”只能看到种子数据。

#### AI 养生

```http
POST /api/v1/care-plans
Idempotency-Key: <uuid>
Content-Type: application/json

{"goal":"改善睡眠","constraints":["少油少盐"],"ageBand":"elderly","locale":"zh-CN"}
```

返回 `suggestions`、`days[]`、`ageGroup`、`limitations`、`refused` 等。`limitations` 是生活方式建议免责声明，不构成处方、治疗方案或用药指导。旧路径 `/api/v1/case/health/care-plan` 已废弃并可能返回 `501 COMPAT_PENDING`，前端必须使用新路径；当前 DTO 已支持 `ageBand=child|adult|elderly`。

### 3.3 语音识别（ASR）与语音播报

业务入口：`POST /api/v1/voice/asr`，按契约使用 `multipart/form-data`：`audio`（必填二进制）、`durationMs`、`locale`、可选 `consultationId`；携带 `Authorization`、`X-Request-Id`、`Idempotency-Key`。当前契约返回同步识别结果 `transcript/language`，不是客户端自行上传文件路径，也不是必须轮询 AI 任务。音频不可加入生成缓存。

当前实现事实与契约差异：

- 契约文案声明本地 `qwen3-asr-0.6b`，但仓库实际执行器是本地 **FunASR**，不是已接通的 Qwen ASR；默认 `AI_ASR_ENGINE=none`，未配置权重时返回 `CAPABILITY_UNAVAILABLE`，不伪造转写。
- 若产品明确要求 qwen_asr，需要新增/替换 ASR 适配器，保持 multipart 与 `OkAsrResult` 结果契约，不能只把 `modelId` 改成 `qwen-asr`。
- 客户端收到识别文本后必须先让用户确认，再提交问诊相关流程；失败时保留重录与文字输入，不能自动切第三方云 ASR。

最小配置（FunASR 现实现）：

```dotenv
AI_ASR_ENGINE=funasr
AI_ASR_MODEL_PATH=/absolute/path/to/model
AI_ASR_AUDIO_DIR=/absolute/path/to/audio
AI_ASR_TIMEOUT_SECONDS=60
```

### 3.4 健康档案与 AI 解读

| 功能 | 方法与路径 | 说明 |
|---|---|---|
| 档案列表 | `GET /api/v1/health-records` | 当前用户范围过滤 |
| 档案详情/修改/删除 | `GET/PUT/DELETE /api/v1/health-records/{recordId}` | 越权按 404 处理 |
| AI 解读 | `POST /api/v1/health-records/{recordId}/interpret` | 必填 `Idempotency-Key`；body `{ "scope":"SUMMARY" }`，支持 `SUMMARY/DETAIL` |
| 附件列表 | `GET /api/v1/health-records/{recordId}/attachments` | 返回短期签名 URL |
| 上传附件 | `POST /api/v1/health-records/{recordId}/attachments` | multipart `file`，≤10MB，jpg/png/webp/pdf，必填幂等键 |
| 删除附件 | `DELETE /api/v1/health-records/{recordId}/attachments/{attachmentId}` | 成功 `data=null` |

解读端点必须原样展示免责声明；报告 `PENDING/REVIEWING`、不支持 scope、健康数据处理授权已撤回时返回 `422`。后端调用 AI 的结果只能是通俗解释，禁止诊断、处方和用药剂量；未配置 Ollama 时按 `503`/稳定错误码显示可见失败态，不能写本地假解读。

### 3.5 挂号、取消挂号与通知

- 科室：`GET /api/v1/departments`
- 医生号源：`GET /api/v1/doctors/{doctorId}/slots`
- 创建：`POST /api/v1/appointments`（必填幂等键）
- 我的预约：`GET /api/v1/appointments/me`
- 取消（推荐）：`POST /api/v1/appointments/{appointmentId}/cancel`，body 可选 `{reason}`
- 兼容删除：`DELETE /api/v1/appointments/{appointmentId}`，语义同取消
- 按幂等键恢复：`GET /api/v1/appointments/by-idempotency/{key}`（以契约登记路径为准）

取消是状态机操作：允许取消的状态才接受；重复取消返回同一终态，号源回补；已签到/已完成等不可取消状态返回 `409`。前端不应再使用旧的“只弹提示”实现，也不要调用医生状态端点替代患者取消。

消息中心：`GET /api/v1/messages`（cursor/limit）、`GET /api/v1/messages/unread-count`、`POST /api/v1/messages/{messageId}/read`。挂号成功、医生叫号/完成等由服务端生成通知；已读接口幂等且不泄露他人消息存在性。

## 4. 医生工作台与在线问诊

| 功能 | 方法与路径 | 说明 |
|---|---|---|
| 医生登录 | `POST /api/v1/doctor/login` | `{username,password}` |
| 医生资料 | `GET /api/v1/doctor/me` | 姓名、头像、科室、职称、工号等 |
| 工作台汇总 | `GET /api/v1/doctor/workbench` | 今日总量、候诊、完成、可用床位等统计 |
| 旧版汇总 | `GET /api/v1/doctor/overview` | 兼容统计口径；新页面优先使用 workbench |
| 待办 | `GET /api/v1/doctor/todos` | 含在线问诊待回复 `CONSULT_REPLY` |
| 医生预约 | `GET /api/v1/doctor/appointments` | 医生权限范围过滤；返回 `version` |
| 更新预约状态 | `POST /api/v1/doctor/appointments/{appointmentId}/status` | 按契约使用状态与 `expectedVersion`，处理 `409` 乐观锁冲突 |
| 床位列表 | `GET /api/v1/beds` | 医生/病区权限过滤 |
| 床位分配 | `POST /api/v1/beds/{bedId}/assignment` | 使用契约请求体、幂等键和版本字段 |
| 在线问诊列表/详情 | `GET /api/v1/consultations`、`GET /api/v1/consultations/{id}` | 医生只能读归属/授权范围 |
| 在线问诊回复 | `POST /api/v1/consultations/{id}/messages` | 与患者消息端点相同，服务端按角色记录 |
| 排班设置 | **当前没有已登记的排班/在线状态端点** | 不要新增或调用未在 `business-openapi.yaml` 登记的 `/schedule`、`/online`；前端页面应显示待接入，或先补充契约与持久化状态机 |

当前医生工作台前端仍在用预约列表本地聚合统计，并将在线问诊列表中的 `ACTIVE` 会话派生为待办；若要使用服务端统一口径，应迁移到 `GET /api/v1/doctor/workbench` 与 `GET /api/v1/doctor/todos`。消息提醒当前前端也仍显示“消息中心：待接入”，应接入消息列表和未读数接口。

医生状态变更成功后，Java 服务在同一业务事务内给患者写消息；医生工作台不应使用旧路径 `/api/appoint/updateStatus`。旧路径与新契约不等价的原因是新接口需要 `expectedVersion`、幂等键且状态枚举不同。

## 5. Ollama 与模型配置

### 5.1 模型档位

| `modelProfile` | 默认模型 | 用途 |
|---|---|---|
| `small-default` | `qwen2.5:0.5b` | 默认导诊补充、普通问诊/轻量任务 |
| `large-upgrade` | `qwen2.5:7b` | 需要更高生成质量时由业务显式选择 |

ai-service 环境变量：

```dotenv
AI_OLLAMA_URL=http://127.0.0.1:11434
AI_SMALL_MODEL=qwen2.5:0.5b
AI_LARGE_MODEL=qwen2.5:7b
AI_CHAT_TIMEOUT_SECONDS=30
AI_CAREPLAN_TIMEOUT_SECONDS=60
AI_TRIAGE_TIMEOUT_SECONDS=20
```

部署前确认 `GET http://127.0.0.1:11434/api/tags` 同时能看到两个模型，并分别用 `ollama run qwen2.5:0.5b`、`ollama run qwen2.5:7b` 预热。未安装/不可达时，健康探针为 degraded/unavailable，任务快速返回 `CAPABILITY_UNAVAILABLE`，而不是返回演示文本。

### 5.2 业务到 AI 任务映射

| 页面能力 | Java 业务动作 | ai taskType | 结果 |
|---|---|---|---|
| 导诊 AI 补充 | triage recommendations | `TRIAGE` | recommendedDepartments/reason |
| AI 问诊 | consultation create/messages | `CHAT` | text/safety/refusal |
| AI 养生 | care-plans | `CARE_PLAN` | suggestions/days/limitations |
| 健康档案解读 | health-record interpret | `CHAT`/业务解读编排 | 通俗解释 + disclaimer |
| 语音识别 | voice/asr | `ASR` | transcript/language |
| 语音播报 | voice/tts | `TTS` | audioUrl 或 WAV/JSON |

当前 `RAG` 执行器尚未接入；不要在前端声明“知识库引用”或伪造 citations。

## 6. 健康检查、部署与联调顺序

1. 启动 Ollama，确认两个 Qwen 模型存在。
2. 配置 FunASR（若需要语音识别）和 `AI_ASR_AUDIO_DIR`；未配置时先按文字路径联调。
3. 使用 `backend/deploy/start-all.bat` 启动 business、ai、gateway，前端只把 `config/env.js` 的 gateway 指向网关。
4. 检查 `GET /api/gw/health` 与 `/ai/health`；重点确认 dependencies 中 `ollama`、`asr_model` 状态。
5. 依次验证：登录 → 首页汇总 → 创建问诊并轮询 → 养生 → 健康档案解读 → 挂号/取消 → 医生登录/工作台/状态变更 → 消息未读/已读 → ASR。
6. 任一 AI 失败时记录 `requestId/taskId/code`，不要记录患者原始病历、身份证、手机号或音频内容。

## 7. 当前接入结论与剩余工作

### 已实现/可直接接入

- 统一网关、患者/医生认证、首页汇总、患者档案/附件、挂号与取消、医生工作台/待办/预约/床位、消息中心、问诊会话落库与 AI 任务轮询。
- Ollama `qwen2.5:0.5b`/`qwen2.5:7b` 档位解析及 `CHAT`/`CARE_PLAN`/`TRIAGE` 执行器。
- 健康档案 AI 解读端点及医疗安全免责声明约束。

### 必须配置或迁移

- **ASR 不是现成 qwen_asr**：当前为 FunASR 适配器，需配置权重；若必须 Qwen ASR，另做引擎适配。
- 前端问诊页需要迁移到 consultations + messages + ai task polling，不能只调用本地导诊。
- 前端养生页需从旧 `/case/health/care-plan` 迁移到 `/care-plans`。
- 医生端需从旧预约/床位写路径迁移到 `/doctor/appointments/{id}/status`、`/beds/{id}/assignment`，携带版本和幂等键。
- 账号安全页面复用现有 `/me`、`/auth`、`/consents`、`/deletion-requests`，不新增无契约的 `/security`。
- 首页的静态服务宫格、科普、导航仍有本地配置；它们不是本次 AI/业务真实接口接入的必要条件，若要后端化需另立内容/导航数据需求。
