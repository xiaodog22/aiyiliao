针对“更新了矩阵计算后，控制台依然显示 60fps 但页面仍然一片蓝、看不到模型”的情况，说明问题已经**从 JS 矩阵计算层推演到了 WebGL 底层管线与小程序 Canvas 的交汇层**。

结合这份**2026-08-31 第二十批修复**的完整文件清单与运行链路，**在控制台没有 throw 任何 JS 报错且 Core 加载成功（260 drawables）的前提下**，导致“60fps 蓝屏”的致命隐藏原因如下：

### 🚨 最有可能引发“60fps 蓝屏”的 3 个底层细节

#### 1. 致命缺陷：Canvas 容器样式与 WebGL 默认 Clear Color 重叠

- **现象**：`avatar.wxss` 或 Page 父容器设置了蓝色背景（`background-color: #1989fa` 或类似蓝色），而 Canvas 的 `render()` 循环中没有设置 Alpha 混合，或者清屏色 `gl.clearColor(0,0,0,0)` 与 `gl.clear()` 没生效。
- **排查**：

  打开 `avatar.wxss`，检查 `.live2d-canvas` 或 `page` 是否含有背景色：

  CSS
  ```
  /* 必须显式将 canvas 设为透明 */
  .live2d-canvas {
    background-color: transparent !important;
  }
  ```

#### 2. 小程序 WebGL 上下文未配置 `alpha: true` 和 `premultipliedAlpha`

- **现象**：小程序 `canvas.getContext('webgl')` 如果没有开启 alpha 属性，WebGL 默认会将 alpha 离屏缓冲区当作不透明（Opaque）处理，导致绘制出来的 Live2D 顶点颜色被硬件直接丢弃或被清屏色覆盖。
- **排查**：检查 `avatar-renderer.js` 中 `init` 获取上下文的代码：

  JavaScript
  ```
  const gl = canvas.getContext('webgl', {
    alpha: true,
    depth: true,
    stencil: true,
    antialias: true,
    premultipliedAlpha: true,
    preserveDrawingBuffer: true
  });
  ```

#### 3. 纹理图片 `0.png` 异步加载“半路空挂”

- **现象**：`avatar-renderer.js` 的 `_loadTextures()` 内部使用了 `canvas.createImage()`。

  如果 `requestAnimationFrame` 的 `render()` 循环**在 `img.onload` 触发前就已经跑起来了**，WebGL 绑定的是一个尺寸为 $0 \times 0$ 的空纹理句柄（`gl.createTexture()` 未填入数据）。由于 WebGL 采样失败，顶点会被渲染成全透明或被丢弃 —— 这完美解释了“为什么矩阵是对的、FPS 是 60，但画面是纯蓝”！
- **排查**：

  在 `avatar-renderer.js` 的 `render()` 方法最开始加一行防挂逻辑：

  JavaScript
  ```
  if (!this.isTextureReady) {
    return; // 纹理尚未 onload 完成，绝对不要执行 gl.drawElements
  }
  ```

### 🔍 5 分钟精准定位排查步骤

请在**微信开发者工具**中打开 **Console（控制台）**，运行以下 3 行断点/打印：

1. **检查纹理真正加载状态**：

   在 `img.onload` 回调里加上 `console.log('纹理加载成功，尺寸：', img.width, img.height)`。
   - 👉 **如果打印为 0 或没打印**：说明图片未解压完成，绘制管线就空转了（命中第 3 点）。
2. **检查 Viewport 实际像素**：

   在 `render()` 初始化后打印 `console.log(gl.getParameter(gl.VIEWPORT))`。
   - 👉 **如果输出 `[0, 0, 0, 0]`**：说明 `canvas.width` 没有乘以 `dpr`（Device Pixel Ratio），导致渲染视口被压缩到 0 像素。
3. **强行改成红色清屏测试**：

   在 `avatar-renderer.js` 的 `render()` 第一行写死：

   `gl.clearColor(1.0, 0.0, 0.0, 1.0); gl.clear(gl.COLOR_BUFFER_BIT);`
   - 👉 **如果屏幕变成了红色**：说明 WebGL 渲染管线正常，纯粹是纹理（Texture）未绑定成功或 Shader 混合模式（Blend Func）失效。
   - 👉 **如果屏幕依然是蓝色**：说明当前的 Canvas 被外层的 `<view>` 蓝色背景组件盖住了，或者 Canvas 的 CSS 节点尺寸根本没生效。
