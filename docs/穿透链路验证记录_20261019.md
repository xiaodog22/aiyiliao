```
[2026-10-19 21:56:08.589][INFO] [maps] 网站, via: phfwba-std-g4.oray.net(tcp,udp),
                                        qv56gv32944.vicp.fun:443(10.103.103.101:8080)

[2026-10-19 22:07:24.584][INFO] sock_getaddrinfofornetwork resolve 10.103.103.101 -> 0
[2026-10-19 22:07:24.584][INFO] [fw] tunnel connected, map: qv56gv32944.vicp.fun:443

[2026-10-19 22:07:24.584][INFO] [fw] forward stats(qv56gv32944.vicp.fun:443) up:0 down:0 closetun:0 sendq:0
```

判读：
- `[maps]` 行是**映射定义**：类型「网站」（HTTP/HTTPS），外网 `:443`，内网 `10.103.103.101:8080`；
- 该行在 20:36、20:51、21:56 三次 `deploymaps` 后**值完全相同** → 是**账号侧持久配置**，客户端每次登录都会下发；
- `up:0 down:0` = 该隧道**从未传输过任何字节**；
- 网关 access log 在域名请求前后**行数不变（9→9）** → 请求没到达本机。

## 4. 根因判定（三重独立验证）

| 假设 | 验证方法 | 结果 |
|---|---|---|
| A. 网关只监听 127.0.0.1 | 改绑 `0.0.0.0` 后重测 | ❌ 排除：`0.0.0.0:8080` 已监听，`127.0.0.1` 与 `172.29.188.115` 都 200 |
| B. 防火墙拦截 | 查三个 profile | ❌ 排除：全部 Enabled=False |
| C. 映射端口指错（如仍指 8000） | 在 `3000/5000/8000/8081/8090/9000/9090/10000/8082/8888` **同时挂探针**，另加 8080 网关 | ❌ 排除：**11 个端口零命中** |
| D. 映射内网主机不是本机 | 读 phtunnel 日志 `[maps]` 行 | ✅ **成立**：目标是 `10.103.103.101`，本机是 `172.29.188.115` |

补充：`10.103.103.101` 在本机 **ping 不通、ARP 无记录、无 10.103.103.0/24 路由** → 该地址已不存在
（典型成因：换网络/换路由器后 DHCP 网段变了，映射没跟着改）。

## 5. 修复：把映射内网主机改成本机地址

### 5.1 操作（二选一，推荐 A）

**A. 花生壳客户端**
1. 打开花生壳客户端 → 左侧「内网穿透」；
2. 找到映射名为 **「网站」**、外网地址 `qv56gv32944.vicp.fun` 的那一条 → 点「编辑」；
3. 把 **内网主机** 从 `10.103.103.101` 改为 **`172.29.188.115`**（本机当前以太网 IP）；
4. **内网端口保持 `8080`**（不要改）；
5. 保存 → 确认列表状态为「在线」；
6. 若客户端提示"映射修改需重新部署"，等它显示已生效（约 5–10 秒）。

**B. 网页控制台**
`console.hsk.oray.com` → 内网穿透 → 找到该映射 → 编辑 → 同样改内网主机为 `172.29.188.115`、端口 `8080`。

> **若希望不受 DHCP 影响**：把内网主机填 `127.0.0.1`（花生壳客户端与网关同机，回环最稳）。
> 前提是网关监听 `0.0.0.0` 或 `127.0.0.1` —— 当前已是 `0.0.0.0`，两种填法都通。
> ⚠️ 填局域网 IP 时，请确认该 IP 不是 DHCP 临时分配，否则重启换 IP 后映射再次失效。

### 5.2 改完立刻自检（三条，必须全绿）

```bash

  http://127.0.0.1:8080/api/v1/resources/home.ai-doctor

  https://qv56gv32944.vicp.fun/api/v1/resources/home.ai-doctor

# ③ 附件签名 query（应 410 或 403，不能 404/502/000）
curl -sS --noproxy '*' -o /dev/null -w "sig=%{http_code}\n" \
  "https://qv56gv32944.vicp.fun/api/v1/attachments/test?expires=1&sig=deadbeef"
```

## 9. 诊断方法备忘（下次复用）

```powershell
# 1) 映射到底指向哪 —— 最权威
Get-Content C:\Users\Administrator\AppData\Local\HskDDNS\log\phtunnel.log -Tail 200 |
  Select-String "\[maps\]|connecting"
# 期望看到：qv56gv32944.vicp.fun:443(<本机IP>:8080)

# 2) 流量到底有没有到本机 —— 看网关 access log 行数是否变化
(Get-Content backend\deploy\logs\gateway-8080.log).Count

# 3) 本机监听是否覆盖映射用的地址
Get-NetTCPConnection -State Listen -LocalPort 8080 | Select-Object LocalAddress

# 4) 花生壳本地管理口（只读，返回 unknow service 说明需要 service 名，不可用于改配置）
curl -s --noproxy '*' http://127.0.0.1:16062/
```

**判读口诀**：
- `up:0 down:0` + 网关日志无新增 → **映射目标错/未生效**，别去查证书和端口；
- `502` → 目标可达但拒绝（端口没服务/进程挂了）；
- `Empty reply` → 隧道到了但目标立即断开；
- `timeout` → 隧道到了但目标不回包。
