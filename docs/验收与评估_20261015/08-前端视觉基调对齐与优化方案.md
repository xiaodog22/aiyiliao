## 2. 对齐总策略与边界

### 2.1 三条总则

1. **色值一源、不混用**：三项色值裁决（D-01）后，全仓只保留**一套**主蓝/底色/标题色；替换走"token 一处改 + 全仓扫描归零"（VF-01）。
2. **结构不推倒重来**：页面信息架构（路由、模块顺序、交互资产）**保持现状**；只对齐 hero 形态、组件形态、色彩与装饰。首页四宫格/八宫格/小贴士等已定稿结构**不改为**参考图的通栏卡列表。
3. **先样板、后批量**：先在一个小页面（「我的」）完整验证基调（≈04 的批次 A 思路），真机复核通过后再铺到其余页面（VF-08~11）。

### 2.2 负面清单（明确不做）

- ❌ 不引入任何新框架/组件库/CSS 预处理器/UI 库；自定义组件仅沿用 `components/skeleton` 先例（`Component()` + 全局类组合）。
- ❌ 不引入字体包（手写标注继续用"斜体+旋转+CSS 弧线"近似，首页已有先例）。
- ❌ 不引入 emoji、SVG 运行时着色（微信不支持，维持 PNG 多色预生成路线）。
- ❌ 不做深色模式；不把图内英文/长文案照搬。
- ❌ 不新造跳转：`section-header` 的「查看更多」**只在存在真实目标页时渲染**（如首页预约动态 → `records`）；无真实目标的页面不渲染该入口（内容红线：不伪造）。
- ❌ 不用装饰条替换合规免责文案：`UIUX §6.1` 要求的「AI 生成内容，仅供健康参考」类标识**原样保留在内容旁**；`.notice-bar` 只承载"守护/提示"类非强制文案。
- ❌ 按钮全站不改胶囊：仅**新增 hero/卡片内元素**允许胶囊化（`.hm-banner-btn` 先例）；全局 `.btn` 维持 20rpx 圆角，与 `UIUX §8.4` 通用约束「圆角 20/12px」保持一致。

### 二、关键实现决策（供复核）

1. **`.flow-doc` 免改 WXML 的浅色化手法**：浅底上白色听诊器会消失。解法是在 CSS 里给 `<image>` 加
   `border-box + padding + background: var(--primary) + 圆角` —— 变成「品牌蓝圆角底板 + 白字形」，
   于是 `consultation`/`triage` **两页 WXML 的图标引用都不用动**，收敛风险面最小化。
2. **`.flow-dot-on` 由「白底白边」改「白底蓝边」**：使页内既有的 `check.png`（蓝）在新底色上仍可见，
   同样避免了 WXML 改动（否则要换成 `check_white.png`）。
3. **`triage` 页仅删样式、WXML 只摘一个类**：`triage.wxml` 的 `.flow-dot` 无子元素，
   新实现下呈「空心环 → 白底蓝边 → 蓝底+halo」，与原实心点**语义一致且浅底对比更强**。
4. **F-2 用「屏宽 − 胶囊左边界 + 8px」而非固定值**：胶囊恒贴屏幕右边，故安全宽 ≈103px 与屏宽无关；
   平板窗口更宽但胶囊仍贴右，因此同一条计算在平板也必须生效（`consultation.wxss` 横屏档的
   `padding-right: 0` 有意让位给 inline 值）。取不到胶囊信息时返回 0 = 完全退回旧行为。
5. **`--hero-title-boost` 令牌**：原 `.hero-title-lg` 写死 `calc(var(--font-title) + 8rpx)`，
   宽屏下 8rpx 被等比放大（1200pt ≈12.8px）→ 标题虚大。改为走变量，≥600px 档切 4px。
   这类「`calc()` 里的 rpx 漏改」是既有 px 化纪律的一个盲区，已在此处补上。
