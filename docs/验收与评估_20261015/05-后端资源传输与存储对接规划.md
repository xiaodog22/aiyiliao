## 2. 待决事项 O-01 收敛建议（三方案对比）

| 方案 | 做法 | 优点 | 缺点 | 本项目的适应性 |
|---|---|---|---|---|
| **A. MinIO 预签名直传** | 业务端签发预签名 URL → 客户端 `PUT` 直连 MinIO | 吞吐高、不经业务带宽 | MinIO 需公网暴露 → **直接违反 `07` 文档 4.4「MinIO 不公网暴露」与「网关单入口」红线**；域名/备案/证书另起一套；上传结果无法在网关侧审计 | 🔴 **不可行**（红线冲突） |
| **B. 经网关代理上传**（推荐） | 客户端 `POST /api/v1/resources/uploads/{id}/content`（multipart）→ 网关 :8000 → business :8088 → MinIO 私有桶 | ① 保持**网关单入口**（现有架构不变）② MinIO 内网不暴露 ③ 网关侧可统一限流/审计/记录 ④ 客户端无需新增服务器域名白名单（微信小程序 `uploadFile` 合法域名数量有限且需配置）⑤ 与 `07` 文档「经反向代理的受控对象数据端点」表述兼容 | 业务带宽被占用（需限大小 ≤10MB + 限流） | ✅ **推荐** |
| **C. 独立对象数据端点**（受控反向代理） | 额外暴露 `upload.xxx` 域名 | 带宽与业务分离 | 需独立域名 + **备案**（本项目为个人主体、无备案域名）+ 小程序需再加合法域名 | 🔴 **当前不可行**（无备案域名） |

**结论：采纳方案 B**，并在 O-01 记录中写明理由：*「个人主体 + 无备案域名 + MinIO 不公网暴露 + 网关单入口」四项约束下，B 是唯一同时满足的方案*。

## 3. 目标架构

```
【上传】
小程序 wx.chooseMedia
   → (1) 申请票  POST /api/v1/resources/uploads            [business]
   ← uploadId, expiresAt, maxBytes, allowedMime
   → (2) 传内容  POST /api/v1/resources/uploads/{id}/content  (multipart, 经网关 :8000 → business :8088)
   → 服务端：MIME 嗅探 → EXIF 剥离 → 尺寸/体积校验 → 转码 → 内容安全审核 → 落私有桶 → 状态 AVAILABLE
   → (3) 确认    POST /api/v1/resources/uploads/{id}/confirm
   ← objectKey, mime, size, sha256, md5, level, width, height
   → (4) 引用    业务接口只传 objectKey（如 HealthRecordCreate.attachmentKeys）

【下载】
   GET /api/v1/resources/manifest  （304 + If-None-Match）
   → 客户端比对 manifestVersion / 逐 key 比对 version
   → 缺/变 → wx.downloadFile 取短期签名 URL → saveFile 到 USER_DATA_PATH/resources/{key}-{version}
   → 按 key 渲染；失败 → fallbackKey → 内置 A 级资源

【失效】
   用户撤回同意 / 删除申请 → 服务端物理删除 + 清单 version 递增 + 客户端缓存按 key 清除
```

**两条铁律（继承自 `07` 文档，写入验收）**：
1. **对象级授权**：每次签发 URL 都要校验「当前主体对目标对象」的权限，禁止只在列表入口过滤；`404`/`403` 策略避免暴露他人对象存在性（`:105`）。
2. **URL 不入日志**：`07 §7` 已把「图片签名 URL」列入**禁止记录**项。

## 4. 接口契约草案（新增 5 条）

> 全部沿用现有信封（`EnvelopeBase`）与 `RequestId` / `IdempotencyKey` 参数；下列路径为**草案**，需合入 `contracts/business-openapi.yaml` 后冻结。

### 4.1 申请上传票

| 项 | 内容 |
|---|---|
| 方法 / 路径 | `POST /api/v1/resources/uploads` |
| 入参 | `{ purpose: 枚举[AVATAR, HEALTH_RECORD_ATTACHMENT, CONTENT_COVER, FEEDBACK_IMAGE], mime, size, width?, height?, sha256? }` |
| 出参 | `{ uploadId, expiresAt(≤900s), maxBytes, allowedMime[], uploadPath }` |
| 幂等 | 需要 `Idempotency-Key`（与 `/appointments` 同规） |
| 错误码 | `RESOURCE_MIME_REJECTED` / `RESOURCE_TOO_LARGE` / `RATE_LIMITED` / `UNAUTHORIZED` |
| 说明 | **purpose 决定后续走向**：不同 purpose 对应不同私有桶前缀、不同审核强度、不同保留期（`07 §8`） |

### 4.2 传输内容（经网关代理）

| 项 | 内容 |
|---|---|
| 方法 / 路径 | `POST /api/v1/resources/uploads/{uploadId}/content` |
| 网关行为 | `/api/**` 全量代理 business（现有路由规则），**仅对 multipart 放宽超时至 120s**（与 tts 同级） |
| Content-Type | `multipart/form-data`，字段 `file`（二进制） |
| 服务端处理 | ① 校验票有效/未用/未过期 ② **MIME 嗅探**（不信任客户端） ③ **EXIF 全量剥离**（含 GPS，隐私硬项） ④ 体积/尺寸上限 ⑤ 转码（§6） ⑥ 内容安全（§8） ⑦ 落私有桶 ⑧ 置 `AVAILABLE` |
| 错误码 | `UPLOAD_TICKET_INVALID` / `UPLOAD_TICKET_EXPIRED` / `RESOURCE_MIME_REJECTED` / `RESOURCE_TOO_LARGE` / `RESOURCE_CONTENT_REJECTED` |
| 说明 | **不信任客户端声明的格式**——与 `/api/v1/voice/asr` 的 `durationMs` 同款纪律（`:1054`） |

### 4.3 确认（必须与 4.2 分离）

| 项 | 内容 |
|---|---|
| 方法 / 路径 | `POST /api/v1/resources/uploads/{uploadId}/confirm` |
| 出参 | `{ objectKey, mime, size, sha256, md5, level, width, height, variantUrls? }` |
| 为什么分离 | 便于服务端在**落桶成功但审核未过**时返回 `RESOURCE_CONTENT_PENDING`，客户端可轮询状态而不重复传字节 |

### 4.4 主动放弃

`POST /api/v1/resources/uploads/{uploadId}/abort` —— 释放未确认对象，避免孤儿对象堆积（必须配定时任务兜底清理）。

### 4.5 短期签名 URL 换取

| 项 | 内容 |
|---|---|
| 方法 / 路径 | `GET /api/v1/resources/objects/{objectKey}/url` |
| 出参 | `{ url, expiresAt }`，**有效期建议 300s，硬上限 900s** |
| 权限 | 每次调用都做对象级授权校验（铁律 1） |
| 频率 | 清单下发 `url` 已足够时**不要**逐图再调；仅当清单 URL 已过期时按 key 按需换取 |

### 4.6 契约字段增补（对现有 schema 的修正案）

| 字段 | 现状 | 建议 |
|---|---|---|
| `ResourceManifest.items[].sha256` | 存在，且契约描述「客户端下载后必须校验」 | 🔴 **与微信能力冲突（双重阻塞）**：① 小程序 `wx.getFileInfo` 的 `digestAlgorithm` **仅支持 `md5` / `sha1`，不支持 sha256**；② 前端 `services/resource.js:8` 自述 `TODO(接入下载链路时)：按契约实现 sha256 下载后校验`，即**连下载链路都还没有**。修正案：**清单增加 `md5` 字段供客户端 `wx.getFileInfo` 校验；`sha256` 保留为服务端/CDN 侧与审计依据；契约描述改为「服务端保证 sha256，客户端以 md5 校验」** |
| `ResourceManifest.items[]` 图片维度 | 无 | 建议增 `width` / `height` / `variant`（thumb/card/original），供客户端按容器选档，避免下载原图浪费流量 |
| `ResourceManifest.items[].level` | A/B | 建议增 `C`（音频/视频，如 TTS 产物），与现有 `/api/gw/tts/audio/{filename}` 公开通道统一纳管 |

## 5. 客户端缓存策略（A/B 级真正落地）

| 级 | 内容 | 位置 | 失败行为 |
|---|---|---|---|
| **A** | TabBar 图标 ×8、返回/重试/录音图标、默认头像、空态插画 ×3、骨架 | **内置于包**（不入清单、不下载） | 不适用（包内必有） |
| **B** | 科普封面、医生头像、首页 banner 插画、科室插图 | `wx.env.USER_DATA_PATH/resources/{key}-{version}` | 按 `fallbackKey` 回退 A 级占位 |
| **C**（建议新增） | TTS 音频、科普视频 | 同上，独立上限 | 音频→改用本地 TTS 或文字；视频→显示可见失败 |

**缓存管理规则**：

| 规则 | 值 |
|---|---|
| 业务缓存上限 | **20 MB**（小程序本地文件总容量远大于此，留足余量） |
| 淘汰 | LRU（按 lastAccess 排序，超限时清最久未用，且**优先清 B 级，A 级永不清**） |
| 更新触发 | `onLaunch` 拉清单（带 `If-None-Match` → 304 免传输）+ 进入目标页前兜底检查 |
| 校验 | `wx.getFileInfo` 校验 **md5**（见 §4.6 修正案）+ size；不匹配 → 删除重下 |
| 清理时机 | 清单 `manifestVersion` 变化 → 逐 key 比对 `version` → 删旧存新；用户撤回同意 / 删除申请 → 按 key 精确清除 |
| 禁止 | **清单失败不得阻断启动/登录/业务 API**（契约原文要求，`business-openapi.yaml:1293-1295`） |

## 6. 图片规格与处理流水线

### 6.1 客户端（上传前）

| 步骤 | 做法 |
|---|---|
| 选图 | `wx.chooseMedia({ mediaType:['image'], sizeType:['compressed'] })`（`chooseImage` 已废弃） |
| 压缩 | `wx.compressImage({ quality: 80 })`，长边 ≤ 1920 |
| 上限 | 单图原图 ≤ 10 MB，压缩后建议 ≤ 500 KB 再上传 |
| 格式 | 白名单 `image/jpeg` / `image/png` / `image/webp`；**HEIC 由系统转 JPEG 后再传** |
| 禁止 | 不做客户端 EXIF 剥离（做不到），**交给服务端**（见 6.2） |

### 6.2 服务端（落桶前，顺序不可颠倒）

```
MIME 嗅探 → EXIF 全量剥离（含 GPS/Orientation，Orientation 需先应用到像素再删）
   → 体积/尺寸校验 → 缩放 → 转码（统一 JPEG/WebP） → 内容安全 → 私有桶 → AVAILABLE
```

| 产物档 | 规格 | 用途 |
|---|---|---|
| `original` | 长边 ≤ 1920，≤ 500 KB | 报告/附件原图查看 |
| `card` | 长边 640 | 列表卡片封面 |
| `thumb` | 长边 200 | 头像、缩略 |

> **隐私关键**：EXIF 常含拍摄 GPS 与设备信息，医疗类图片尤甚。**必须服务端剥离**，且剥离要在缩放**之前**（缩放会丢弃 EXIF 但也会丢 Orientation）。

## 7. 内置 vs 远端：体积账（避免把主包撑爆）

当前实测：主包 **1.187 MB** / 上限 2 MB → **余量 ≈ 813 KB**；`packageContent` 252 KB、`packageNav` 87 KB。

| 资源 | 现状 | 建议 | 理由 |
|---|---|---|---|
| TabBar 图标 ×8（蓝/灰双态） | 主包 PNG | **保持内置（A 级）** | 启动即用，远端化会导致首屏图标闪烁 |
| 65 基础图标 ×3 色 | 主包 PNG | 保持内置（A 级） | 全页依赖，回退成本高于收益 |
| 默认头像 / 空态 / 骨架 | 主包 | 保持内置（A 级） | 契约要求 |
| **科普封面（图文 12 + 视频 3）** | `packageContent` 静态 | **改为 B 级远端** | 可释放 `packageContent` 约 180~220 KB |
| 首页 banner 插画 | 主包 | **改为 B 级远端**（保留内置 1 张作 A 级回退） | 大图最占体积，且常换 |
| 医生头像 | 无 | **B 级远端 + 内置占位（A）** | 契约 `avatarUrl` 已定义"失败用内置占位" |
| 健康档案附件 | 无 | B 级远端（purpose=`HEALTH_RECORD_ATTACHMENT`） | 用户数据，绝不内置 |

> 决策原则：**A 级只放「回退时必须存在」的少量资源；常换、量大、与用户数据相关的，全部远端化。**
