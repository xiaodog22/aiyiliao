## 5. 设计方案（推荐默认，待 §6 确认）

### 5.1 设计原则

1. **锚定真实就诊**：只有本人（或获授权家庭成员）已 `COMPLETED` 的预约可评价，杜绝"未就诊也评"与刷分入口。
2. **隐私默认安全**：默认匿名；文本评价**审核后**才公开；评分聚合公开（满足医生列表展示位）。
3. **复用既有范式**：审核态复用 `contents.reviewStatus`；幂等键/乐观锁/信封/游标分页复用 `common/` 既有组件；删除衔接复用 `deletion_requests`。
4. **不破坏契约既有字段**：`Doctor` schema 采用**追加可选字段**（`ratingAvg` / `ratingCount`）而非改语义，保持旧客户端兼容。

### 5.2 表结构设计（新迁移 `V6__doctor_reviews.sql`）

```sql
-- 医生就诊评价：一人一约一评；文本审核后公开；默认匿名
CREATE TABLE doctor_reviews (
    id             VARCHAR(64)  NOT NULL,
    appointment_id VARCHAR(64)  NOT NULL,              -- 锚定预约（幂等唯一）
    doctor_id      VARCHAR(64)  NOT NULL,              -- 冗余自 appointment.doctor_id，防改单漂移
    user_id        VARCHAR(64)  NOT NULL,              -- 评价人；展示时脱敏
    rating         TINYINT      NOT NULL,              -- 1..5 星级
    content        VARCHAR(1000) NULL,                 -- 文本评价，可空（纯星级亦可）
    status         VARCHAR(16)  NOT NULL DEFAULT 'PENDING_REVIEW', -- PENDING_REVIEW/APPROVED/REJECTED/RETIRED
    is_anonymous   TINYINT(1)   NOT NULL DEFAULT 1,    -- 隐私默认：匿名
    reviewed_by    VARCHAR(64)  NULL,                  -- 审核人（内部）
    reviewed_at    DATETIME(3)  NULL,
    reject_reason  VARCHAR(200) NULL,
    version        INT          NOT NULL DEFAULT 1,    -- 乐观锁：允许修改评价
    created_at     DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    updated_at     DATETIME(3)  NULL DEFAULT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_doctor_reviews_appt (appointment_id),                     -- 一约一评（幂等防线）
    KEY idx_doctor_reviews_doctor_status (doctor_id, status, created_at),   -- 医生评价列表（只取 APPROVED）
    KEY idx_doctor_reviews_user_time (user_id, created_at),                 -- 我的评价
    CONSTRAINT fk_doctor_reviews_appt   FOREIGN KEY (appointment_id) REFERENCES appointments (id),
    CONSTRAINT fk_doctor_reviews_doctor FOREIGN KEY (doctor_id)     REFERENCES doctors (id),
    CONSTRAINT fk_doctor_reviews_user   FOREIGN KEY (user_id)       REFERENCES users (id),
    CONSTRAINT chk_doctor_reviews_rating CHECK (rating BETWEEN 1 AND 5)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_unicode_ci;

-- 医生聚合评分（列表展示位）：只统计 APPROVED
ALTER TABLE doctors
    ADD COLUMN rating_avg   DECIMAL(2,1) NOT NULL DEFAULT 0.0,
    ADD COLUMN rating_count INT          NOT NULL DEFAULT 0;
ALTER TABLE doctors ADD KEY idx_doctors_rating (rating_avg, rating_count);
```

**索引取舍**：`uk_doctor_reviews_appt` 是幂等唯一防线（替代"先查后插"的竞态）；`idx_doctor_reviews_doctor_status` 覆盖"医生页只读 APPROVED 列表 + 游标翻页"；`idx_doctors_rating` 支撑"按评分排序/筛选"。**不为 `content` 建全文索引**（数据量小，`LIKE` 可接受；涉敏文本不引入额外检索面）。

### 5.3 关联关系

```
users 1───N doctor_reviews N───1 doctors
              │
appointments 1───1 doctor_reviews   （UNIQUE on appointment_id）
```
- 与 `appointments`：一对一（一约一评），评价时校验 `appointments.user_id = 当前用户` 且 `status = 'COMPLETED'`。
- 与 `doctors`：多对一；`doctor_id` 冗余存储（即使医生排班变更，评价仍归属原接诊医生）。
- 与 `deletion_requests`：用户删除权触发时，评价文本按"可删除"处理，**聚合分需重算**（见 5.5）。
- 与 05 号文档：本期**不支持晒图**（避免依赖尚不存在的上传端点）；`attachmentKeys` 留待 O-01 定稿后扩展。

### 5.4 业务逻辑规则

| 规则 | 定义 |
|---|---|
| **可评价条件** | 预约属于当前用户（或经授权的家庭成员）、`status = COMPLETED`、该预约尚无评价行 |
| **提交** | `POST /api/v1/appointments/{appointmentId}/review`，带 `Idempotency-Key`；评分必填 1–5，文本可选（≤1000 字） |
| **修改** | 同一预约重复提交 → **更新**原行（`version` 乐观锁，冲突 409），而非新增；不改变"一约一评" |
| **删除** | 用户可删除自己的评价（软删 `RETIRED` + 聚合重算）；删除权与账号删除分离（沿用 consent 域 §9.3 口径） |
| **审核** | 新评价默认 `PENDING_REVIEW`；`APPROVED` 后才进入医生公开列表与聚合统计；`REJECTED` 对作者可见原因、不公开 |
| **聚合重算** | 事务内 `SELECT AVG(rating), COUNT(*) FROM doctor_reviews WHERE doctor_id=? AND status='APPROVED'` 回写 `doctors.rating_avg/rating_count` |
| **可见性** | 列表接口只返回 `APPROVED`；`is_anonymous=1` 时不返回任何用户标识（无昵称/头像/手机号） |
| **越权** | 非预约本人 → `404`（不泄露预约存在性）；非医生评价他人预约 → `403` |

### 5.5 隐私与合规

- **默认匿名**：`is_anonymous` 默认 1；即使关闭匿名，也只展示脱敏昵称（不回显 `users.display_name` 原文、不回显手机号）。
- **文本先审后公开**：复用 `contents.reviewStatus` 状态机；审核通过前任何人（含作者之外的客户端）不可见。
- **不进日志/埋点**：`content` 属敏感健康相关文本，与 `symptomSummary` 同级处理，不打点、不入 access log。
- **保留策略**：在 `deletion_requests` 法定保留清单中增列"评价文本=可删除；聚合分随删除重算"（对齐 M3 `DeletionService` 的逐项列明口径）。

### 5.6 API 契约草案（对 `business-openapi.yaml` 的变更）

**新增路径（3 条）**：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/appointments/{appointmentId}/review` | 提交/修改评价（`Idempotency-Key` + `version` 乐观锁） |
| GET | `/api/v1/doctors/{doctorId}/reviews` | 已审核评价列表（游标分页，默认匿名） |
| GET | `/api/v1/doctors/{doctorId}/rating-summary` | 聚合评分（`ratingAvg` / `ratingCount` / 分布可选） |

**修改 schema（2 处，追加可选字段，向后兼容）**：

```yaml
Doctor:                      # business-openapi.yaml:1879
  properties:
    ...
    ratingAvg:   {type: [number, 'null'], description: 聚合评分 0.0~5.0；无评价时为 null，界面不得显示猜测值。}
    ratingCount: {type: integer, minimum: 0, description: 已审核评价数；0 时界面不显示评分。}
```

> ⚠️ 这是**契约变更**（非纯实现）。按项目约定，契约与实现必须同批落地，并过 `tools` 契约门禁；`additionalProperties: false` 保留，故**必须同步改 schema**，否则后端返字段即被门禁拒（这正是 RV-P0-2 的解法）。

**新增 schema（4 个）**：`ReviewSubmitRequest` / `ReviewData` / `OkReviewList` / `RatingSummary` / `OkRatingSummary`。
**错误码**：`VALIDATION_FAILED`(422) / `REVIEW_NOT_ALLOWED`(409，预约非本人或非 COMPLETED) / `REVIEW_CONFLICT`(409，乐观锁) / `NOT_FOUND`(404)。

### 5.7 数据迁移方案

| 阶段 | 动作 | 风险控制 |
|---|---|---|
| M1 | 新增 `V6__doctor_reviews.sql`（新表 + `doctors` 两列 + 索引） | **纯追加，不改不删既有对象**；版本号递增（V5 → V6，避免 out-of-order——本项目曾因插 V2 致启动失败） |
| M2 | 回填：既有数据无需回填（无历史评价），`rating_avg=0.0 / rating_count=0` 为默认值 | 零数据迁移，零停机 |
| M3 | dev 种子 `V9003__doctor_reviews_dev_seed.sql`（2 位医生 × 数条 APPROVED/PENDING 评价，覆盖匿名/非匿名、空文本、5 分/1 分） | 仅供本地开发与 E2E |
| M4 | 若后续需支持"改单后评价归属"：新增迁移 ALTER，**禁止**改 V6 | 遵循"迁移只追加"铁律 |

**回滚**：V6 为纯追加，回滚 = `DROP TABLE doctor_reviews` + `ALTER TABLE doctors DROP COLUMN rating_avg, DROP COLUMN rating_count`（无既有数据依赖，可安全回滚）。

## 6. 待决策项（**实施前必须拍板**）

以下两项直接决定表结构边界与合规口径，**我不代为假设**，请明确后我再动手写代码：

### 决策 A：评价对象范围

| 选项 | 含义 | 影响 |
|---|---|---|
| **A1 · 医生就诊评价（推荐）** | 仅锚定 `COMPLETED` 预约评价医生 | 与前端既有展示位吻合；外键清晰；隐私模型最简单 |
| A2 · 医生 + AI 问诊满意度 | 追加 `consultations` 维度评价 | 需第二套锚点表或 `target_type` 多态列；AI 满意度是否公开需另行评估 |
| A3 · 医生 + 问诊 + 科普内容互动 | 再追加 `contents` 点赞/收藏 | 依赖 05 号文档与内容域改造，工作量最大 |
| A4 · 只做平台/医院整体评价 | 不锚具体医生 | 与现有挂号闭环脱节，价值最低 |

### 决策 B：文本评价可见性模型

| 选项 | 含义 | 影响 |
|---|---|---|
| **B1 · 审核后公开 + 默认匿名（推荐）** | 复用 `contents.reviewStatus`；`is_anonymous` 默认 1 | 兼顾"医生有口碑可见"与隐私；需审核动作（本期可先由 dev 种子模拟，管理端后续） |
| B2 · 仅自己可见 + 仅聚合分公开 | 文本永不公开，只回给作者 | 最安全，无需审核链路；但"医生口碑"只剩一个数字 |
| B3 · 不收集文本，只收星级 | 无 UGC，无审核、无内容安全风险 | 实现最简；但失去评价信息量，且涉医场景仍可能被用于舆情 |
