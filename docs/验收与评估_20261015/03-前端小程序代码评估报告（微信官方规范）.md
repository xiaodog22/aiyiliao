## 5. 网络层（官方《网络》章节）

### 5.1 结构（优秀）

`services/request.js` 一个封装覆盖官方四类网络 API 场景：

| 能力 | 方法 | 官方 API |
|---|---|---|
| JSON 请求 | `get/post/put/del` | `wx.request` |
| UTF-8 手写 multipart（不依赖第三方） | `postForm` + `encodeUTF8` | `wx.request` |
| 二进制下载（音频） | `getBinary` | `wx.request`（`responseType:'arraybuffer'`） |
| 文件上传（ASR） | `uploadFile` | `wx.uploadFile` |
| 401 自动刷新（并发去重 `refreshPromise`） | `refreshAccessToken` | — |

其它符合官方习惯的做法：`del` 而非 `delete`（`delete` 是 JS 保留字）；`X-Request-Id` 自生成；`rawEnvelope` 保留未脱壳响应以应对「信封里除 `data` 还有并列字段」。

### 5.2 🔴 缺陷：二进制/multipart 通道缺认证与幂等

| 方法 | `Authorization` | `Idempotency-Key` | 后果 |
|---|---|---|---|
| `request()`（JSON） | ✅ 有（`authHeader`） | ✅ 调用方传 | — |
| `postForm()` | 🔴 **无**（header 只有 Content-Type + ngrok 跳过头，`request.js:296-299`） | 🔴 无 | TTS / 音色试听在鉴权收口后（U-02 / A-2）会 401 |
| `getBinary()` | 🔴 **无**（`request.js:347`） | — | 音频直链（`/api/gw/tts/audio` 设计上不要求登录态，属合理例外，但需在兼容层显式豁免） |
| `uploadFile()` | 🔴 **无**（`request.js:405`） | 🔴 **无** | 后端 `/api/v1/voice/asr` 契约要求 `Idempotency-Key` + `in: header`（N-3 已对齐）→ **ASR 恒 400**（`08H` §9.4 已登记） |

### 5.3 域名与安全（官方《网络》红线）

| 检查项 | 现状 | 结论 |
|---|---|---|
| 请求必须 HTTPS | `env.js` development 用 `https://qv56gv32944.vicp.fun`；production 强制 HTTPS 且拒绝临时域名 | ✅ |
| 生产域名必须**已备案 + 后台配置为 request 合法域名** | production `gateway` 为空 → 构建即抛错，**不会误发** | ✅（属未完成而非缺陷，见 01 文档 U-18） |

## 7. 用户隐私保护 —— 🔴 **不符合**（最高优先级）

| 官方要求 | 本项目 | 结论 |
|---|---|---|
| 涉及处理用户个人信息，须在小程序管理后台配置**《用户隐私保护指引》** | 代码侧无对应实现 | 🔴 |
| 基础库 2.32.3+ 支持 `wx.requirePrivacyAuthorize` / `wx.getPrivacySetting` / `onNeedPrivacyAuthorization` | **全仓 0 命中**（含 `app.json` 的 `__usePrivacyCheck__`） | 🔴 |

## 9. 自定义导航栏 —— 🔴 **不符合**

`pages/consultation/consultation.json:2` 与 `pages/triage/triage.json:2` 设了 `"navigationStyle": "custom"`，自绘 `.nav-bar`：

```html
<view class="nav-bar" style="padding-top: {{statusBarHeight + 8}}px;">
  <view class="nav-left">…</view>
  <view class="nav-tabs">…</view>
  <view class="nav-right"><view class="nav-clear" bindtap="onClear">清空</view></view>   <!-- consultation -->
</view>
```

**问题**：官方明确——使用自定义导航栏时，**右上角胶囊按钮（`…` + `○`）由微信客户端固定绘制且不可覆盖**，开发者必须通过 `wx.getMenuButtonBoundingClientRect()` 获取其位置，并**预留右侧安全区**（通常约 87px 宽 + 上边距对齐）。

本项目：
- 实测 **全仓 0 处调用 `wx.getMenuButtonBoundingClientRect()`**；
- `.nav-bar` 右侧仅 `padding-right: 24rpx`（`consultation.wxss:36`）；
- 因此 `.nav-right` 内的「**清空**」（`onClear`）在真机上会**压在胶囊按钮下方** → 用户几乎点不到，且它是个**破坏性操作**（清空会话）。

**修复建议**：`.nav-bar` 右侧改用动态安全宽度 `right-safe = windowWidth - rect.right + rect.width + gutter`，或直接把右侧操作移入内容区首行。

## 15. 结论

1. **分层与配置治理达到工程化水准**：唯一地址、唯一路径表、页面零直连、错误文案中文化、禁址扫描全绿 —— 这些是「**可维护**」的地基，且大部分由 `tools/check-*.js` 静态门禁固化。
2. **平板与适老化适配的思路领先于多数同类项目**：用 `rpx` 编码 + 断点转 `px` + **无头浏览器量化验收**（空白率、主栏占比、重叠判定）替代「目测截图」，这套方法本身就是资产。
3. **两项硬伤必须先修**：**隐私合规链缺失（F-1）** 属审核阻断；**自定义导航栏未避让胶囊（F-2）** 属真机可用性阻断（且压在「清空」这种破坏性按钮上）。
4. **一处系统性警告**：项目已形成的正确范式（`consultation` 的增量 `setData`、`session.js` 的 token 态、契约路径）**没有横向推广**，导致同类问题在 `health` / `triage` / `app.js` / `api.js` 里复发。建议把「范式 → 静态门禁」补上（如新增 `tools/check-setdata.js` 拦截 `setData({ messages: ... concat })`），用工具替代人工守约。

> 量级参考：**7.4 / 10** —— 结构优秀、适配扎实；**隐私合规与自定义导航栏两项须在上线前闭环**。
