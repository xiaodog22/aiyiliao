## 四、发现的问题

| # | 问题 | 定性 | 处理 |
| --- | --- | --- | --- |
| 1 | SITE-11 首轮报「界面截图应为 6 张，实际 5」 | **测试自身缺陷**：首屏那张是 `class="shot on"`，我按 `class="shot"` 精确匹配漏掉了它 | 改为按 `<img class="shot` 计数（6 张）。页面无问题 |
| 2 | Java 全量首轮 1 error：`M4ContractConsultTest.aiTasks域_查询与SSE与取消` 抛 `ConcurrentModificationException` | **测试框架竞态**（非业务缺陷）：SSE 端点由 daemon 工作线程异步写 `MockHttpServletResponse`，Spring Boot 默认 `PrintingResultHandler` 在每次 `perform` 后遍历同一响应头 → `LinkedCaseInsensitiveMap` 迭代器 CME。单跑该类 4/0 通过，确认偶发 | 两个调用 `/events` 的测试类（`M4ContractConsultTest`、`M2IntegrationTest`）改为 `@AutoConfigureMockMvc(print = MockMvcPrint.NONE)` 关闭诊断打印；**所有状态码、响应头、契约断言原样保留**。全量复测 322/0 |
| 3 | `db-verify.js` 报 `ERROR 2003 Can't connect ... 10061` | **环境限制**：`MySQL80` 服务为 `Stopped`；`Start-Service` 拒绝访问，`sc.exe` 被安全策略禁止且不允许绕过 | 本轮不执行真库门禁，登记为环境项；本次改动只涉及静态 HTML + 测试脚本，不改任何 SQL/DB 代码。MySQL 启动后 `node tools/db-verify.js` 即可补跑（上一轮 37/0） |
| 4 | 需求中的「清理因此不再使用的相关逻辑」 | **核查结论：无可清理对象**。`site/index.html` 原本就没有手机号/验证码输入框、按钮或相关 JS（脚本只有滚动渲染/菜单/跳转逻辑） | 不做无意义改动；用 SITE-06~10 五条断言把「不得保留/新增」锁死，防止后续回归 |
| 5 | 线上页面与仓库不同步 | **部署缺口（未修，需授权）**：`gh-pages` 分支仍是 11-01 旧版（标题「楚大夫」），本次改动在 `main` 的 `site/index.html`，线上尚无新免责声明 | 见 §七，需单独授权推送 `gh-pages` |

## 五、修复内容

1. `site/index.html`
   - 首屏 `.hero-copy` 内、`.hero-lead` 之后新增 `<p class="hero-notice" role="note">本页面为开源项目演示，不提供医疗服务，不构成诊断依据</p>`（**原样，未增删字词**）。
   - 新增 `.hero-notice` 样式：沿用现有 `--bg-soft`/`--ink-2` 色板令牌，静态胶囊，无动画、无交互、不影响滚动渲染。
   - `≤720px` 补一条专属规则，确保窄屏（`.hero-lead` 被隐藏时）声明仍可见。
   - **未改动**任何既有结构、导航、章节、脚本与页脚原有免责声明；未新增/保留任何手机号或验证码控件。
2. `tools/test-site-index.js`（新增）：16 项专项断言，含进程内静态 HTTP 服务验证。
3. `tools/test-fe-all.js`：把专项用例登记进一键回归（单测文件 7 → 8）。
4. `M4ContractConsultTest.java` / `M2IntegrationTest.java`：关闭 MockMvc 诊断打印，消除 SSE 异步响应头遍历竞态；断言逻辑不变。
