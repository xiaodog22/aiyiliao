### 2.2 对外暴露方式

| 场景 | 连接方式 | 备注 |
| --- | --- | --- |
| 开发者工具/模拟器 | `ws://127.0.0.1:8003` | 当前 `config/env.js` 默认，已验证 |

改造原则：现有 `gateway.py` 的回声/静态/TTS 接口保持不动（小程序 POC 页面不受影响），新能力全部加在新包内。

## 4. WS 协议正式定义（V0 落地，V1 兼容扩展）

连接：`ws(s)://<host>:8003/ws/avatar`；文本帧 = JSON（opcode 0x1），音频帧 = 二进制（opcode 0x2）。

### 4.1 客户端 → 服务端

| type | 载荷 | 说明 |
| --- | --- | --- |
| `hello` | `{ver:1, device:{model,sys,fpsTier}}` | 握手；服务端回 `ack`（含 session_id） |
| `audio_start` | `{sampleRate:16000, format:"mp3"\|"pcm", frameMs}` | 开始录音（V1 用于切流式 ASR 会话） |
| （二进制） | mp3/pcm 音频帧 | 30~60ms/帧；服务端回 `audio_ack{seq,bytes}` |
| `audio_end` | `{}` | 结束本轮录音 → 触发 ASR 最终结果 |
| `interrupt` | `{turnId}` | 打断：停 LLM 生成 + 停 TTS + 保留已播文本 |
| `ping` | `{ts}` | 心跳（15s），回 `pong` |
| `text_input` | `{text}` | 文字输入兜底（绕过 ASR） |

### 4.2 服务端 → 客户端

| type | 载荷 | 说明 |
| --- | --- | --- |
| `ack` | `{session_id, ts}` | 握手应答 |
| `audio_ack` | `{seq, bytes, total}` | 每音频帧回执（POC 已实现） |
| `asr_partial` | `{turnId, text}` | ASR 增量（字幕实时显示） |
| `asr_final` | `{turnId, text}` | ASR 最终 |
| `llm_delta` | `{turnId, delta, sentenceDone}` | LLM 流式 token；句号切分时带 sentenceDone |
| `tts_start` | `{turnId, format:"mp3"}` | TTS 音频流开始 |
| （二进制） | mp3 chunk | 顺序拼接可播（V0 整段；V1 流式） |
| `tts_end` | `{turnId, durationMs}` | 本轮语音结束 → 客户端回 IDLE |
| `interrupted` | `{turnId, playedMs}` | 服务端确认打断 |
| `emotion` | `{turnId, emotion}` | 情感标签（LLM 输出解析）→ 驱动表情 |
| `error` | `{code, msg}` | `LLM_TIMEOUT/TTS_FAIL/ASR_EMPTY/SAFE_BLOCK/...` |
| `pong` | `{ts}` | 心跳应答 |

### 4.3 一轮对话时序（V0 目标形态）

```
client: audio_start → (二进制帧…) → audio_end
server: asr_partial* → asr_final → [safety] → llm_delta*(首句完整即) → tts_start
        → (mp3 chunk*) → tts_end → emotion
client: 随时可 interrupt → server: interrupted（并停止 LLM/TTS）
```

超时基线（V0，可配）：ASR 最终 5s / LLM 首 token 6s（超时自动降 0.5b 重试一次）/ TTS 首 chunk 5s。
任一超时 → `error{code}` → 客户端按异常态表提示并可重试（不静默卡死）。

## 5. ASR 改进：FunASR 非流式 → 流式 2pass（V1 核心）

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 模型 | paraformer-zh 离线（整段 3.5s@6s） | **paraformer-zh-streaming（流式）+ paraformer-zh（2pass 纠正）+ fsmn-vad** |
| 接入方式 | 网关进程内 AutoModel | **独立子进程 `funasr-wss-server`**（funasr 自带），网关按会话转发；避免 ~2GB 模型内存拖垮网关 |
| 热词 | 无 | 医疗热词表（科室/常见病/药名）写入 hotword 参数，提升「复查血压/处方」类词准确率 |
| VAD | 无 | 服务端 fsmn-vad 自动断句（与端上能量 VAD 双保险，端上为主） |
| 首字延迟 | 无增量 | 流式 partial 300~800ms 出首字（字幕即时反馈，掩盖总延迟） |

配置示例（funasr-wss-server 启动参数）：
```bash
python -m funasr.bin.websocket_server \
  --host 127.0.0.1 --port 8005 \
  --asr-model paraformer-zh-streaming --asr-model-revision v2.0.4 \
  --vad-model fsmn-vad --vad-model-revision v2.0.4 \
  --punc-model ct-punc \
  --ngpu 0 --ncpu 4
```
> ⚠️ 端口 8005 仅本机内部（网关 ↔ FunASR），不对公网暴露；模型名/revision 以 `funasr` 文档为准，POC 已验证离线版可用，流式版为 M1 首任务。

## 6. LLM 改进：Ollama 编排（V0 落地）

1. **模型选择**：默认 `qwen2.5:0.5b`（CPU 实测首 token 2.3s）；`7b` 仅在配置开启且预热时使用。`/api/chat` 在本机异常（`done_reason:"load"`），**统一走 `/api/generate`**（POC 实测结论）。
2. **预热**：网关启动与每 4 分钟对所选模型发一次 `keep_alive` 空请求（`num_predict:1`），消除冷启动。
3. **句级流水线**（降首字延迟的关键）：LLM 流式输出按 `。！？；\n` 切句，**首句完整立即送 TTS**，不等全文；同时把首句文本经 `llm_delta{sentenceDone}` 推给字幕。
4. **系统提示词**（医疗助手人设，≤200 字，放在 config.py）：
   - 角色：健康小助手「小安」；只做健康科普与就医建议，不做诊断/处方；
   - 风格：口语化短句（每句 ≤20 字为宜，利于 TTS 断句）、先答后释、带共情；
   - 输出末尾固定免责句（每次生成加一次，不重复堆叠）。
5. **上下文**：见 §8 会话管理。
6. **取消**：打断时网关直接 `close()` 对 Ollama 的 HTTP 连接 —— Ollama 检测到客户端断开会终止生成（省 CPU）。

---

## 7. TTS 改进：EdgeTTS（V0 落地）

1. **句级合成**：配合 §6 流水线，按句请求（每句一次 `Communicate`），逐句返回 mp3 chunk。
2. **LRU 缓存**：`hash(voice+text) → mp3`，容量 200 条 —— 重复问句/免责句零延迟。
3. **降级链**：接口失败/超时 3s → 换备用音色重试一次 → 仍失败回 `error{TTS_FAIL}`，客户端降级纯文字模式。
4. **频控自保**：并发 ≤2；同句 500ms 内去重。
5. 音色默认 `zh-CN-XiaoxiaoNeural`（已实测）；可配置为 `XiaoyiNeural`（更年轻）等。

## 8. 会话与轮次管理（V0 核心新增 `session.py`）

```python
Session {
  session_id: str          # ack 下发
  created_at / last_active
  turns: [ Turn ]          # 滑动窗口 8~10 轮
  summary: str | None      # 更早轮次的滚动摘要（V1）
}
Turn {
  turn_id: str             # asr_final 时生成，幂等键
  user_text / assistant_text
  played_ms: int           # 已播放时长（打断截断用）
  interrupted: bool
  emotion: str
  ts_first: {asr, llm, tts}  # 分环节延迟
}
```

- 过期：30min 无交互清理（音频缓冲与 ASR 会话一并释放）。
- 幂等：服务端维护 `active_turn_id`，丢弃过期轮次的迟到 TTS chunk / llm_delta。
- 打断轮：`assistant_text` 只保留已播放部分并追加「（用户打断）」。

## 9. 打断编排（V1 核心，orchestrator.py）

```
收到 client interrupt{turnId}
 1) 停止向客户端发 TTS chunk（丢弃队列）
 2) close() 对 Ollama 的连接（终止生成）
 3) 取消未完成的 TTS 句任务（asyncio task.cancel）
 4) FunASR 会话保持（录音继续，端上不重开）
 5) 回 interrupted{turnId, playedMs}；该轮 assistant_text 截断入库
目标：从收到 interrupt 到停发音频 ≤100ms（本机内存操作，可达）；
     客户端本地「淡出停播」仍由端上先行（<100ms 视觉反馈，见方案 §6.1）
```

## 10. 安全与合规（V1，上线前必须）

| 项 | 方案 |
| --- | --- |
| 鉴权 | `/api/avatar/ticket`：wx.login code 换一次性 ticket（60s 有效、单次使用），WS 握手首帧 `hello{ticket}` 校验；演示阶段可配置关闭 |
| 内容安全 | 输入/输出过 `safety.py`（复用 :8000 现有过滤逻辑或关键词+规则）；命中 → `error{SAFE_BLOCK}` + 固定话术 |
| 医疗红线 | prompt 硬约束（不做诊断/处方）+ 输出正则拦截「确诊/处方药名+剂量」类表述；每轮回复固定免责句 |
| 数据 | 语音/文本默认不落盘；metrics 只记延迟数字与轮次数，不含内容；日志脱敏 |
| 传输 | ngrok 仅调试；正式对外必须 WSS + 备案域名 |

## 11. 可观测与验收指标（V0 建好埋点，V1/V2 看板）

分环节延迟（每轮记录 P50/P90）：

| 指标 | 定义 | V0 目标 | V1 目标 |
| --- | --- | --- | --- |
| `asr_final` | audio_end → 最终文本 | ≤3.5s（非流式实测） | ≤1.5s（流式） |
| `llm_first` | asr_final → 首 token | ≤2.5s（0.5b 实测） | ≤2.5s |
| `tts_first` | 首句完整 → 首音频 chunk | ≤1.5s（实测 1.1s） | ≤1.2s |
| **`e2e_first_audio`** | audio_end → 客户端出声 | **≤4.5s** | **≤3.2s** |
| 打断响应 | interrupt → 停发音频 | —— | ≤300ms |
| 稳定性 | WS 心跳存活 ≥30min 无断 | 是 | 是 |

实现：`metrics.py` 每轮 `print` 结构化 JSON（演示阶段够用），后续可接 Prometheus。

## 14. 风险与对策（后端视角）

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| Ollama CPU 首 token 2.3~3.8s（最大瓶颈） | 🔴 | 0.5b 默认 + 预热 + 句级流水线掩盖感知；路演机建议插 GPU 或临时切云 API |
| FunASR 内存 ~2GB + 加载 2min | 🟠 | 独立子进程常驻（一次性加载）；网关加健康检查，未就绪时 `error{ASR_NOT_READY}` |
| EdgeTTS 无 SLA/频控 | 🟠 | LRU 缓存 + 降级链 + 文字模式兜底；路演前预热缓存常用句 |
