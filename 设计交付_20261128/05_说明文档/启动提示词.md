# 启动提示词（创意设计 + 说明文档）

> 适用：Gemini 4 Hydrogen（high / xhigh 档）为主，Carbon/Argon 仅在需要深度审美判断时用 xhigh。
> 用法：**一次会话只干一件事**，按 P1 → P2 → P3 → P4 → P5 顺序推进；每段提示词单独粘贴，别叠在一轮里。
> 关键前提：Hydrogen 只输出文本，不出图。出图走 P2 产出的图像提示词，交给绘图模型执行。

## 上下文预算（贴之前先确认）

只给它这 5 个文件的**片段**，不要整仓：
1. `01_设计基线/设计令牌/设计令牌卡_V4.md`（全给）
2. `02_页面截图/页面清单.md`（只给关键页 7 行）
3. `03_创意设计/概念提案/00_提案模板.md`（全给）
4. `04_代码快照/pages/<页面key>/<页面key>.wxml` 与 `.wxss`（只给当次要改的那一页）
5. `02_页面截图/00_现状/<对应截图>`（图像输入）

## P1 · 创意方向提案（第一步，一次出 3 套）

```text
你是「康诊云」医疗小程序的视觉总监，同时是适老化与无障碍专家。项目是原生微信小程序，用户主体是 50–70 岁中老年患者。

【任务】在现有 V4 设计令牌体系内，产出 3 套**互不重复**的视觉方向提案，供评审选一套。只出提案，不写代码，不出图。

【必须遵守的基线，不许改】
- 唯一色源是 app.wxss 的 page 块；主色 #5F78C4，渐变 #5F78C4→#8BA0DC，页面底 #EDF2FB，文字 #28324F / #5E6A8C，玻璃卡 rgba(255,255,255,.78)。
- 字号三档：standard 40/34/30/24 rpx，large 44/36/32/26，xlarge 52/42/38/30。
- 圆角 32/24/16 rpx；触控热区 ≥88rpx（适老 ≥96rpx）；正文对比度 ≥4.5:1。
- 禁止 emoji 作图标；图标只能取 utils/icons.js。
- 禁止跨端框架（不许出现 Vue/React/UniApp/组件库）。

【三套方向的要求】
- 差异必须体现在**信息层级与叙事方式**上，不是换一套配色。
- 三套分别偏：①流程确定感 ②陪伴温度 ③AI 能力可视化。
- 每套只在 7 个关键页里挑 3–5 页说明怎么改：home / consultation / appointment / settings / triage / nav / detail。

【输出格式】严格按 03_创意设计/概念提案/00_提案模板.md 的 8 节，三份分开写，标题为「方向A/B/C_主题名」。
每份结尾追加两行：
- 「这套最容易被评审否掉的一点：___」
- 「实施代价：改 __ 页，是否动令牌：是/否」

【额外产出】三套写完，给一张 3 行 × 5 列的选型打分表（主张契合 / 适老风险 / 实施代价 / 视觉辨识度 / 可延展性），每格只填 高/中/低 + 4 字理由，最后用一句话给出你的推荐及理由。

【禁止】不要复述我给你的约束；不要罗列 38 个页面；不要给像素级 CSS；不要写「建议进一步调研」这类空话。
```

## P2 · 关键页高保真：图像提示词 + 逐页规格表

```text
你是视觉设计执行者。选定方向是【方向X_主题名】，请把 3 个关键页【home / consultation / appointment】转成可出图、可落地的规格。

【输入】已选定的方向提案 + 设计令牌卡 + 该页现有 wxml/wxss + 该页现状截图（按文件名标注哪张是现状）。

【每页输出两块，缺一不可】
A. 图像提示词（给绘图模型用，中文，120–180 字）：
   写清机型画幅（390×844 竖屏）、页面分区自上而下的顺序、每个区块的底色/圆角/描边、主按钮位置与文案、留白比例、禁止出现的元素（emoji、渐变过度、玻璃反光过强、文字糊）。
B. 逐页规格表（表格，列：区块 | 尺寸(rpx) | 颜色令牌 | 圆角 | 字号令牌 | 备注）
   尺寸必须是 8 的倍数；引用令牌名（--primary / --glass / --font-h2），不要写死十六进制，除非该值确实不在令牌内。

【大字档】每页补一行说明：large / xlarge 下布局怎么变（哪块收起、哪块换成两行、哪个按钮加高），不是"整体放大"。
【禁止】不要输出 WXSS；不要发明新令牌；不要建议换主色。
```

## P3 · 设计稿转 WXML/WXSS（逐页，一次一页）

```text
只改一页：miniprogram/pages/<页面key>/<页面key>.wxml 与 .wxss。保持 .js 与 .json 不动。

【输入】选定方向的关键页高保真说明 + 该页现有三件套 + 令牌卡。

【硬约束】
1. 只用 WXML / WXSS / 原生语法；禁止任何跨端框架与第三方组件库。
2. 颜色、字号、圆角、间距一律引用 CSS 变量（var(--primary) 等），不新增十六进制。
3. 图标用 <image src="{{icons.xxx}}">，键名必须真实存在于 utils/icons.js；禁止 emoji。
4. 不改接口调用、不改 data 字段、不动 .js；页面数据只能来自原有 services。
5. 每页必须有 ≥600px 与 900px 两个断点，断点内所有 rpx 宽高间距用 px 重写（rpx 在平板会被等比放大）。
6. 触控热区 ≥88rpx；正文对比度 ≥4.5:1；三档字号下不溢出、不挤压。

【输出】
1. 完整 wxml（不要省略号，不要"其余不变"）
2. 完整 wxss（新增/修改选择器用注释标出 /* [改] ... */）
3. 改动点清单：文件:行 → 改了什么 → 为什么
4. 自检表：热区、对比度、断点、三档字号、图标键名，逐项 通过/风险

【禁止】不要顺手重构其它选择器；不要改 app.wxss 令牌；不要输出解释性长文。
```

## P4 · 说明文档正文（写说明书，一次成稿）

```text
你是设计说明书撰写者兼技术文档工程师。请为「康诊云」小程序本轮改版写完整设计说明书。

【输入】
- 已选定方向：【方向X_主题名】提案
- 设计令牌卡（01_设计基线/设计令牌/设计令牌卡_V4.md）
- 页面清单（02_页面截图/页面清单.md）
- 截图登记表（06_验证记录/截图清单.md）
- 7 个关键页代码快照（04_代码快照/pages/）
- 说明文档大纲（05_说明文档/00_说明文档大纲.md）

【输出】单个 Markdown 文件，严格按大纲六节（0 文档信息 → 1 理念 → 2 信息架构 → 3 令牌与组件 → 4 关键页交互与状态 → 5 适老化验收 → 6 落地映射与验证 + 附录）。正文控制在 15–25 页。

【写作硬规则】
1. 每个论断后面必须能落地：要么给出数值判据（≥88rpx、≥4.5:1、40rpx），要么给出文件与选择器。
2. 第 3 节的每个组件必须带一小段 WXML 骨架（10 行以内），骨架里的类名要从 04_代码快照 里真实存在的那份抄，不许编。
3. 第 4 节对 7 个关键页逐页写表：页面目标 / 结构分区 / 主次操作 / 五态（default·loading·empty·error·弹层）/ 大字档差异。
4. 第 6 节的落地映射表用真实路径与真实选择器，例如 miniprogram/pages/home/home.wxss 的 .hero；验收脚本写实际命令。
5. 不确定的写「待确认：___（需要谁定）」，不许把猜测写成结论。

【禁止】
- 不要复述项目背景、不要写"随着医疗信息化发展"这类开头。
- 不要编造接口名、类名、令牌名、数值。
- 不要为每页重复贴完整代码。
- 不要超过 25 页；宁可砍章节也不灌水。

【交付前自检，逐条回答 通过/不通过】
① 六节齐全，0 节有变更记录表
② 所有数值均能在令牌卡或截图实测中找到出处
③ 组件骨架类名全部真实存在
④ 7 个关键页五态齐全（缺的明确标"本页无此态"）
⑤ 落地映射表路径可点击打开
⑥ 全文无"进一步优化""加强体验"类空话
```

## P5 · 验收审查（只读审，不许改代码）

```text
你只做审查，不产出任何代码。审查对象：04_代码快照 与本轮改动稿。

逐项判定，每项给「通过 / 不通过 + 证据（文件:行 或 实测值）」：
1. 是否出现跨端框架、emoji 图标、写死十六进制色值
2. 图标键是否都在 utils/icons.js 内
3. 触控热区是否 ≥88rpx（适老 ≥96）
4. 正文对比度是否 ≥4.5:1（含 xlarge 档 --text-weak）
5. 600px / 900px 断点是否把 rpx 宽高改写成 px
6. 三档字号下是否溢出（标题换行、按钮文字截断、列表行挤压）
7. 是否改了 .js 业务逻辑或接口字段

最后输出一张表：问题 | 等级(P0/P1/P2) | 位置 | 修法一句话。P0 是"上真机会坏"的项。
```
