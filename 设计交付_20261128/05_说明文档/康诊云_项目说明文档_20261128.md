## 第 1 章 项目一览

### 1.1 一句话定位

康诊云是一套面向中老年患者的医疗健康 AI 微信小程序。患者不必先了解医院的组织架构，只需用日常语言描述哪里不舒服，系统即可给出三个答案：挂哪个科、有多急、到了医院怎么走。围绕这句话，后续的预约挂号、院内导航、在线问诊、检查报告均被串联在同一条路径上。

患者端 AI 助手名为「小安」。它在导诊、问诊、养生三个场景中以对话形式出现，语气克制；遇到不确定情况时会明确提示「建议到院由医生判断」，而非强行给出结论。

### 1.2 要解决的三道坎

医院小程序的常见做法是将所有科室与功能平铺在首页。对年轻用户而言这只是多点两下，但对视力与操作精度下降的中老年患者来说，往往意味着放弃使用。项目将问题拆解为三道坎，每道坎对应一组能力。

| 坎 | 患者的原话 | 项目怎么接 |
| --- | --- | --- |
| 不会选科 | 「肚子疼该挂消化内科还是普外科？」 | 智能导诊按部位、时长、程度、伴随症状匹配科室画像，输出推荐科室与命中理由；仅在无法识别归属时追问，避免患者反复描述 |
| 不知多急 | 「这点疼要不要现在就去？」 | 先以 15 条红旗规则筛查急症，再给出五级分级；紧急项在结果页置顶红条提示，并提供一键拨号入口 |
| 不知往哪走 | 「号挂好了，二楼怎么走？」 | 院内导航基于 1F 实绘平面图呈现路径动画，并配文字步骤与语音播报；楼上科室先引导至电梯厅，再给出换层提示 |

这三件事解决后，挂号、缴费、报告才有实际意义。因此首页未做「功能大全」，仅保留一个症状输入行和少量高频入口。

### 1.3 形态与技术边界

- 形态：原生微信小程序（WXML + WXSS + JavaScript）。项目明确禁止 Vue、React、UniApp 等跨端框架，页面与组件均按微信原生规范编写。
- 规模：全量 38 页，由主包 23 页与 8 个分包共 15 页组成；底部 4 个 tab 分别为首页、AI 问诊、预约挂号、我的。
- 适老化：支持标准、大字、超大字三档字号，由全局令牌驱动；触控热区、对比度与宽屏布局配有独立验收脚本。
- 后端：统一网关单入口，网关反向代理 Python FastAPI 与 Java Spring Boot 两套服务；前端仅对接一个网关地址。
- 已下线：手势识别、Live2D 数字人。仓库中可能仍保留备份素材，但已不在现有功能链路上，演示时请勿提及。

### 1.4 目标用户与使用场景

核心用户为中老年患者，其视力与操作精度有所下降，且不熟悉医院科室划分。第二类用户群是代父母操作的子女，他们熟悉手机操作，但不一定掌握父母的症状细节与就诊记录。

| 场景 | 谁在用 | 典型动作 |
| --- | --- | --- |
| 家中不适，先判断要不要去医院 | 患者本人或子女 | 首页输入症状 → 查看分级与科室 → 决定观察或就诊 |
| 已到院，找不到诊室 | 患者本人 | 选择目的地 → 查看路线动画 → 按文字步骤前往 |
| 复诊前查报告、看历史问诊 | 患者或子女 | 我的 → 检查报告 / 我的问诊 → 查看详情 |
| 子女代管父母档案 | 家属 | 我的 → 家庭成员 → 添加成员 → 申请代管授权 |
| 候诊时打发时间、学习健康知识 | 患者 | 健康科普 → 浏览图文或短视频，断网亦可阅读 |

家属代操作设有明确的授权闸门：仅当成员状态为「已授权」时，才允许携带该成员标识读写档案与预约；「未授权」「授权待确认」「授权已撤销」均会被拦截并给出申请入口，不依赖前端隐藏按钮兜底。

### 1.5 它不是什么

康诊云输出的是健康咨询与分诊建议，不是诊断结论，不开具处方，也不替代医生面诊。系统内无真实处方流转，不具备医疗器械注册资质，亦不承诺任何临床效果。演示中出现的科室、医生、号源、账单均为演示数据或院内模拟系统数据，不可作为真实就医凭据。

## 第 2 章 功能与使用指南

本章按患者的真实操作路径组织，而非按代码模块划分。每节统一说明四项内容：入口、操作步骤、页面反馈与能力边界。所有页面均支持三档字号，下文不再逐节重复。

### 2.1 智能导诊：一句话落到科室

**入口**：首页顶部症状输入行；也可从首页四宫格「智能导诊」或常用服务中的同名入口进入。点击首页快捷症状词（咳嗽、头晕、睡眠不好）会直接携带该语句进入导诊页并立即生成结论。

**操作**：

1. 在输入行填写症状描述，例如「嗓子疼三天，有点发烧」；也可点击麦克风语音输入。
2. 首次使用会弹出隐私告知，说明症状文字将发送至院内导诊服务、不上传身份信息且记录仅存本机，确认后继续。
3. 系统先运行本地规则引擎，识别出科室归属即直接给出结论；无法识别时才进行追问，最多 2 轮。
4. 在结果页查看分级、推荐科室、命中理由与下一步建议。
5. 如需前往院内对应科室，点击「去医院导航」即可携带目的地直接进入导航页。

**看到什么**：结果页顶部为分级徽标，五档分别为「紧急 · 请立即就医」「较急 · 建议今日就诊」「一般 · 建议近 1~3 天就诊」「常规 · 建议门诊就诊」「居家观察 · 有变化再就诊」。下方依次为推荐科室卡片、命中理由与下一步动作。命中红旗时，页面置顶红条并提供一键拨打 120 入口，无需等待后端返回。

**边界与提示**：知识库包含 15 条红旗规则、19 条科室画像，其中 16 条可推荐、18 条可导航；分级共五档，追问最多 2 轮。导诊不给出病名，也不判断「是否患有某病」，仅提示「建议挂某科、建议多久内就诊」。急诊科走大门旁绿色通道，不在 1F 平面图内，导航页会给出明确文字提示，不绘制虚拟路线。

### 2.2 AI 问诊：本地先判、远端融合

**入口**：底部 tab「AI 问诊」；首页四宫格的「在线问诊」对应另一页面（图文问诊），注意区分。

**操作**：

1. 进入页面后直接描述症状，支持文字与语音输入，单次输入上限 2000 字。
2. 本地规则引擎先给出分诊结论并立即渲染，无需等待网络。
3. 同时并发请求后端导诊接口，将远端科室建议与本地结果融合，并在融合结果中标明来源。
4. 第 2 轮起携带会话上下文继续追问，用户可补充时长、程度、伴随症状。
5. 结论卡给出建议科室、紧急程度与就医参考，可直接跳转挂号或导航。

**看到什么**：先展示本地结论，待远端结果返回后局部刷新；置信度不足时回落至兜底科室「全科医学科」，并明确说明「暂无法判断具体科室」，不强行拼凑答案。会话快照保存在本机，保留 6 小时、最多 40 条，异常退出后可恢复。

**边界与提示**：急诊判定目前仅走本地单通道。远端 TRIAGE 结果不含 emergency 字段，不参与急症并集；本地红旗一旦命中即刻置顶报警。所有输出均为分诊建议，不构成诊断。

### 2.3 AI 养生：体质辨识到三天方案

**入口**：首页常用服务「更多服务」→ AI 养生；该页面已移出底部 tab，只能从入口或历史记录进入。

**操作**：

1. 与小安进行选项化对话，依次回答体质偏向、年龄段、主要诉求三类问题。
2. 提交后进入生成态，页面按阶段提示「正在分析体质与诉求」「正在生成三天膳食与功法方案」，预计耗时 1~2 分钟。
3. 生成完成后，方案卡内联展示在对话流末尾，分为膳食、功法、睡眠三节。
4. 如需与家人同看，可点击「投屏」进入电视大屏互动页。

**看到什么**：方案卡带有「今日方案」标签，每节提供具体建议与注意事项；底部附免责声明，说明方案仅作健康调理参考，不替代诊疗。后端拒答时，页面提示「暂无法生成方案」并说明原因，不展示空卡片。

**边界与提示**：生成接口超时为 180 秒，生成期间输入栏置灰，防止新增输入影响当前生成参数。开发档提供演示兜底，上线档失败时如实报错，不伪造方案。投屏为本地模拟，暂未接入 DLNA 与局域网协议。

### 2.4 分步挂号：四步到确认

**入口**：底部 tab「预约挂号」；首页四宫格及「找医生」「找科室」入口同样进入该流程。

**操作**：

1. 选科室：列表按院内部室组织，支持搜索。
2. 选医生：医生卡片展示姓名、职称及是否有可约号源；无字段支撑的状态（如「今日号源紧张」）不予展示。
3. 选时段：先选日期，再选具体时段；各时段显示余量与挂号费。
4. 确认：核对就诊人、科室、医生、时间与费用后提交。
5. 成功页支持去缴费（演示）、查看预约记录或取消预约。

**看到什么**：顶部四步进度条随操作推进。成功页展示预约单号、就诊时间与院区提示；当预约来源为 `HIS_MOCK` 或 `LOCAL_DEMO` 时，页面固定显示「演示预约」标识，仅 `HIS_LIVE` 隐藏。取消预约会联动撤销院内部署的受理单，并将状态同步回列表。

**边界与提示**：号源余量为快照数据，页面展示的剩余数仅供参考，最终能否约上以服务端原子扣减为准；并发提交失败时提示「该时段刚刚约满」，不会出现超卖后仍显示成功的情况。挂号单号来自院内模拟系统或本地演示，非真实医院挂号凭据。

### 2.5 门诊缴费（演示）

**入口**：挂号成功页的「去缴费（演示）」；开发或演示档首页另设有「演示模式 → 模拟支付（本地演示）」区块，可直接进入收银台，生产构建不渲染该入口。

**操作**：

1. 选择待缴费挂号单，查看费用明细。
2. 点击「确认支付」，弹出演示支付确认框。
3. 确认后订单状态更新为已支付，页面给出成功提示。
4. 如需退款，在订单详情点击「申请退费」，状态由已支付变为已退款。

**看到什么**：成功文案固定为「演示支付成功（未真实扣款）」；退费成功标注「未发起真实退款」。缴费入口关闭时，页面仅显示「演示支付未开启，请到院窗口缴费」，并额外提供一个 0.01 元的本地模拟收银台，不写入后端。

**边界与提示**：页面不调用 `wx.requestPayment`，不接入微信商户号，不产生真实扣款；退费仅修改本地与演示库状态，不触发支付渠道退款。演示时应主动说明该边界，避免观众误以为已打通真实支付。

### 2.6 检查预约（演示）

**入口**：首页常用服务「检查预约」；该入口在演示档可用，关闭时页面提示「检查预约暂未开放，请到院窗口办理」。

**操作**：

1. 选择检查项目，列表来自院内演示系统的项目目录。
2. 选择日期与时段。
3. 确认就诊人与项目后提交预约。
4. 在「我的就医安排」中查看或取消预约单。

**看到什么**：页面顶部固定显示「演示预约（未真实排期，不产生检查费用）」。提交成功后返回预约号与到院提示；取消后状态同步更新。

**边界与提示**：不接入真实医院检查号源，不产生费用，不与 PACS/RIS 打通。功能关闭时仅显示「检查预约暂未开放，请到院窗口办理」。

### 2.7 院内导航：从大门到诊室

**入口**：导诊结果页「去医院导航」、首页常用服务「找科室」，或预约成功页。

**操作**：

1. 进入后默认定位在「医院大门」，1F 平面图上显示起点光晕。
2. 在目的地列表或平面图圆点中选择科室；也可先切换楼层 tab 再选择。
3. 点击「开始导航」，页面绘制路径动画并给出分步文字指引。
4. 点击扬声器图标可语音播报当前步骤；点击「回到当前位置」可将大门移回视野中心。
5. 到达后路径与标记保留，便于对照诊室门牌。

**看到什么**：底图为项目自绘的 1F 平面图（1440×860），路径、起点、终点及电梯厅标记绘制在同一张 canvas 上，支持缩放与拖动。路线下方为文字步骤，例如「从医院大门出发，直行至导医台，右转向东」。

**边界与提示**：仅 1F 具备实绘底图；14 个目的地数据均已内置包内，1F 目的地直接生成路线，2F 及以上先引导至电梯厅，再给出「乘电梯上几楼后按指示牌找到诊室」的文字提示，不绘制不存在的房间。路线在本地计算，不调用后端，断网仍可使用。急诊绿色通道不在本层平面图内，页面会单独提示。

### 2.8 在线问诊：图文、报告与语音

**入口**：首页四宫格「在线问诊」、医生列表页「咨询」，或消息中心的问诊回复。

**操作**：

1. 选择医生并进入会话。
2. 用文字描述病情，或按住说话发送语音；也可从健康档案选图，发送检查报告或患处照片。
3. 医生接单前可继续补充病情与资料；接单后双方进入会话。
4. 等待回复期间页面每 2 秒轮询一次；网络失败时退避重试。
5. 收到回复后可在同一会话继续追问；医生结束问诊后输入栏锁定，提示重新发起咨询。

**看到什么**：会话页顶部显示医生信息与接诊状态，中部为消息流，底部为输入区与「+」资料入口。图片发送前会校验来源必须为健康档案、格式为 jpeg/png/webp、大小不超过 10MB；服务端再按 objectKey 归属与资源白名单进行二次校验，不信任前端声明。

**边界与提示**：双方采用 2 秒轮询，而非实时长连接；弱网环境下消息可能延迟数秒。医生端查看的是患者所选档案中的同一张图片，不另存副本。问诊记录归档至「我的问诊」，支持回看。

### 2.9 消息通知

**入口**：底部 tab「我的」→ 消息中心；未读红点显示在「我的」页面的消息入口上。

**操作**：

1. 进入消息中心，列表按时间倒序展示。
2. 未读消息带有圆点标记，顶部显示未读总数。
3. 点击消息，按类型跳转对应对象：问诊会话、挂号记录或报告详情。
4. 无对应对象的系统通知仅标记已读并展示正文，不猜测目标页面进行跳转。

**看到什么**：消息类型涵盖报告出具、预约状态、医生回复、系统通知等。报告出具类消息由后端幂等写入，同一份报告仅生成一条；演示报告标题带有「（演示）」字样。

**边界与提示**：未读数取自服务端下发的 `unread-count`，非本地累加。消息跳转仅识别已知的 `refType`，未知类型不会跳转至空白页。

### 2.10 健康科普

**入口**：首页常用服务「更多服务」→ 健康科普；首页科普推荐卡也可直接进入对应详情。

**操作**：

1. 进入科普列表，支持按图文、视频筛选或按分类浏览。
2. 点击内容进入详情；图文直接阅读，视频点击播放。
3. 断网时仍可打开随包发布的内容。

**看到什么**：列表展示封面、标题、摘要、阅读时长或视频时长。详情页正文分节展示，关键要点单独列出；视频附带时长与提示条。

**边界与提示**：内容采用双源机制：优先读取服务端 `/api/v1/health-articles`，失败时回退至包内 `utils/knowledge-kb.js` 的随包内容。因此断网可读，但服务端新增内容在离线状态下不可见。科普内容不构成诊疗建议。

### 2.11 健康档案与家属代管

**入口**：底部 tab「我的」→ 健康档案；家庭成员位于「我的」→ 家庭成员。

**操作**：

1. 在健康档案查看过敏史、既往病史、用药、体征与检验检查报告。
2. 点击记录查看详情；检查检验类记录可打开结构化报告单。
3. 需要家属代管时，进入家庭成员页点击「添加家庭成员」，填写姓名、关系与可选手机号。
4. 由家人在场确认后点击「申请代管授权」，系统生成并核销一次性授权码。
5. 授权状态变为「已授权」后，方可代管其档案与预约。

**看到什么**：档案按类别分组，报告状态以徽标区分「已出具」「待出具」；无报告文件的记录不显示「查看报告」按钮。家庭成员卡片展示姓名、关系徽章、年龄段与授权态；未授权时提供「申请授权」入口，避免死路提示。

**边界与提示**：添加成员遵循最小必要原则，不采集身份证号；成员档案的独立视图尚未上线，当前授权后可维护成员信息，但代看完整档案的能力有限。携带成员标识的写路径必须处于「已授权」状态，后端设有独立授权闸门校验。

### 2.12 音色与朗读设置

**入口**：「我的」→ 设置 → 音色管理；设置页同时提供「自动朗读」开关。

**操作**：

1. 进入音色管理，查看可用音色列表。
2. 点击「试听」播放示例音频。
3. 选中音色后点击「设为默认」。
4. 在设置页开启或关闭自动朗读；在音色页选择语速。

**看到什么**：当前仅提供两个普通话音色：温柔女声、沉稳男声；语速支持 0.8、1.0、1.25 三档。试听与朗读失败时给出中文提示并保留文字指引，不静默失败。

**边界与提示**：音色清单源自前端 `services/voice.js` 目录与服务端能力快照，不在页面中写死。粤语仅支持 `zh-HK` 识别分支，普通话之外暂无专项音色；潮汕话既无专项识别，也无专项音色，此为能力边界，非配置遗漏。

### 2.13 适老化三档与无障碍入口

**入口**：「我的」→ 设置 → 字号；设置页同时提供高对比开关。

**操作**：

1. 在字号行点开浮层，选择标准、大字、超大字。
2. 选定后全局即时生效，无需重启小程序。
3. 需要更强对比度时开启高对比开关。
4. 首页在大字档下会额外显示「紧急情况请拨打 120」提示条，可直接点击拨号。

**看到什么**：三档标题字号分别为 40/44/52rpx，卡片标题 34/36/42rpx，正文 30/32/38rpx，辅助文字 24/26/30rpx；按钮高度分别为 88/108/128rpx。布局并非简单等比放大，大字档下卡片间距、行高与折行策略会同步调整。

**边界与提示**：高对比开关目前仅在设置页自身完整生效，其余页面覆盖尚待补齐，演示时请勿表述为全局能力。无障碍完整验收口径见设计说明书第 5 节。

### 2.14 断网三态

**入口**：无需手动进入。应用启动及每次请求前均会探测网关健康状态。

**操作**：

1. 正常联网时无额外提示。
2. 网关可达但上游异常时，顶部显示「演示数据 · 未连接院内服务」或「院内服务未连接 · 当前只读」提示条。
3. 设备本身断网时，提示条变为「设备网络已断开 · 当前只读」。
4. 此时已加载内容仍可查看，提交类按钮会被拦截并说明原因。

**看到什么**：提示条支持展开，说明「已加载内容可继续查看，可能不是最新；提交类操作已暂停」。写操作返回结构化 `OFFLINE` 错误，页面据此展示中文说明，不排队、不无限重试，也不伪造成功。

**边界与提示**：三态指在线、降级、离线；探测超时为 5 秒、节流间隔 10 秒，避免频繁请求网关。断网不清除会话、不跳转登录页；网络恢复后提示条自动消失，用户可重新提交。

### 3.2 取得代码与导入前端

```bash
git clone https://github.com/xiaodog22/aiyiliao.git
cd aiyiliao
```

打开微信开发者工具，选择「导入项目」，目录指向仓库下的 `miniprogram/`，AppID 使用个人测试号或演示号。导入后进入「详情 → 本地设置」，勾选「不校验合法域名」——本地网关采用 HTTP，不勾选将被开发者工具拦截。

### 3.3 启动后端三服务

后端一键脚本位于 `backend/deploy/`。首次启动需先准备环境文件，再执行带 `-Setup` 参数的启动命令。

```bash
cd backend/deploy
cp env.example env.local
start-all.bat -Setup -Yes
```

Windows 命令提示符下请将 `cp` 替换为 `copy`。`env.local` 已列入 `.gitignore`，仓库仅提供模板，不含任何真实密钥；其中至少需填写 `MYSQL_PASSWORD`，否则业务服务无法连接数据库。

脚本按以下顺序启动：业务服务（:8088）→ AI 服务（:8001）→ 网关（:8080）。启动前会执行前置检查，若虚拟环境未初始化或 MySQL 不可达，脚本直接以退出码 2 退出，不启动任何服务，避免残留半启动状态。

常用命令：

| 目的 | 命令 |
| --- | --- |
| 启动全部 | `start-all.bat` |
| 首次初始化 | `start-all.bat -Setup -Yes` |
| 启动并冒烟 | `start-all.bat -Smoke` |
| 查看状态矩阵 | `status.bat` |
| 停止全部 | `stop-all.bat` |
| 重启 | `restart.bat` |

### 3.4 网关地址与端口

前端仅维护一个后端地址，配置在 `miniprogram/config/env.js` 的 `gateway` 字段。本机默认值为 `http://127.0.0.1:8080`，与 `backend/deploy/config.json` 中的 `ports.gateway` 保持一致。

注意：仓库部分历史文档的示例仍写 8000，系早期端口；请以 `backend/deploy/config.json` 与实际启动日志为准。若 8080 端口被占用，需同步修改 `config.json` 的 `ports.gateway`、网关启动参数及 `env.js` 的 `gateway`，确保三处一致。

健康检查：

```bash
curl http://127.0.0.1:8080/api/gw/health
```

返回 `status`（`ok` / `degraded` / `down`）与 `upstreams` 列表，逐项列出 Java、Python 与 Ollama 三个上游的可达性与延迟。`degraded` 表示网关本身正常、至少一个上游不可达，并非网关故障；Java 与 Python 均通但 Ollama 缺失时亦会判定为 `degraded`，如实反映 AI 生成能力受限。

### 3.6 首次启动常见问题

- 启动脚本直接退出且退出码为 2：检查提示是「venv 未初始化」还是「MySQL 不可达」。前者执行 `start-all.bat -Setup -Yes`，后者启动 MySQL 并核对 `env.local` 连接串。
- 页面可打开但数据全空：确认网关是否在 8080 端口监听，再通过健康检查确认两个上游均为 `reachable`。
- 开发者工具报错「不在以下 request 合法域名列表中」：本地开发需勾选「不校验合法域名」；真机预览须将网关域名加入小程序后台白名单。
- 点击登录按钮无反应：确认 `env.local` 存在且 `BUILD_ENV` 为 local；生产档缺少 HTTPS 网关会在启动阶段直接失败，此为有意的 fail-closed 设计。
- 挂号提交提示未登录：本地演示会话无服务端 token，提交前会校验会话；重新执行一次「模拟手机号登录」即可。

### 4.2 前端分层

前端遵循「页面只负责渲染，数据一律走 services」原则，分为四层：

- `pages/`：页面逻辑与 WXML/WXSS。页面负责交互状态、调用服务与展示转换，不直接拼接接口地址，也不内联业务数据。
- `services/`：数据访问层。按业务域划分文件（如 `appointment.js`、`consult.js`、`careplan.js`、`voice.js`），负责请求参数组装、错误归一与必要降级。
- `utils/`：纯逻辑与常量真源。导诊知识库、红旗规则、图标表、错误文案、格式化函数均置于此，不依赖页面生命周期。
- `config/`：`env.js` 为唯一网关地址配置，`api.js` 为唯一接口路径表。

组件存放于 `components/`，通过 `app.json` 全局注册，页面可直接使用标签。颜色仅取自 `app.wxss` 令牌块，页面不写字面色值；图标仅使用 `utils/icons.js`，禁止以 emoji 充当图标；后端错误码中文文案统一由 `utils/err-text.js` 管理。

### 4.3 分包划分

主包仅保留首页、问诊、养生、挂号、我的及登录相关页面，以控制冷启动体积。其余按使用频率拆分为 8 个分包：

| 分包 | 页数 | 内容 |
| --- | --- | --- |
| `pages/doctor` | 5 | 医生工作台、个人管理、问诊处理、排班设置、消息 |
| `pages/triage` | 2 | 智能导诊与导诊报告 |
| `pages/consult` | 2 | 在线问诊与医生选择 |
| `pages/exam` | 1 | 检查预约 |
| `pages/payment` | 1 | 门诊缴费 |
| `pages/tv` | 1 | 电视大屏互动 |
| `packageNav` | 1 | 院内导航 |
| `packageContent` | 2 | 健康科普列表与详情 |

首页配置了 `triage` 分包预下载，养生页在 Wi-Fi 下预下载 `packageContent` 与 `packageNav`。预下载仅影响首次打开速度，不影响功能可用性。

### 4.4 一次请求怎么走

以挂号列表为例：页面调用 `services/appointment.js`，服务层通过 `config/api.js` 路径拼接请求后交由 `services/request.js`。请求层统一附加平台头、客户端版本头、追踪 ID 与登录令牌，发送至 `env.js` 配置的 `gateway`。网关按路由表将 `/api/v1/**` 转发给 Java 业务服务，自身仅处理 `/api/gw/**`。响应返回时，请求层将非 2xx 状态归一为带业务码的结构化错误，页面再通过 `err-text.js` 转为中文提示。

该链路的设计意义在于：页面无需感知后端服务数量与端口，切换部署环境只需修改 `gateway` 一处。前端业务代码中出现 8001、8088、127.0.0.1 或 localhost 会被 `check-project.js` 判为失败，唯一例外是 `env.js` 中带 `DEV_DIRECT` 标记的本机直连常量。

## 第 5 章 配置说明

### 5.1 前端唯一配置 env.js

| 字段 | 作用 | 本机默认/说明 |
| --- | --- | --- |
| `BUILD_ENV` | 构建档位 | `local` / `development` / `production`，白名单校验，不在名单内直接失败 |
| `gateway` | 后端唯一地址 | local 档默认 `http://127.0.0.1:8080`；development 与 production 从 `env.local.js` 注入，且必须为 HTTPS |
| `aiTimeout` | AI 类请求超时 | 90000 毫秒 |
| `ttsTimeout` | 语音合成超时 | 120000 毫秒 |
| `carePlanTimeout` | 养生方案生成超时 | 180000 毫秒 |
| `mockReadFallback` | 读请求演示兜底 | 仅开发档可用，生产档禁止 |

`env.local.js` 已列入 `.gitignore`，仓库仅保留模板。development 与 production 档若缺失网关或网关非 HTTPS，将在 `require` 阶段直接失败，此为有意的默认安全策略，并非 bug。

### 5.2 后端配置

`backend/deploy/config.json` 是服务编排的唯一事实源，涵盖端口、上游地址、代理超时、限流、CORS、资源目录、各服务启动命令及健康检查。`env.example` 为环境变量模板，复制为 `env.local` 后填写，脚本仅打印键的数量而不打印值。

| 变量 | 作用 |
| --- | --- |
| `GW_PROXY_TIMEOUT_SECONDS` | 网关代理读超时，默认 220 秒；云托管要求显式注入，不得下调 |
| `MYSQL_URL` / `MYSQL_USER` / `MYSQL_PASSWORD` | 业务服务数据库连接，密码无默认值 |
| `APP_HIS_ENABLED` / `APP_HIS_MODE` | 是否启用院内模拟系统，模式为 `mock` 或 `http` |
| `APP_PAYMENT_ENABLED` / `APP_PAYMENT_MODE` | 演示支付开关与模式，模式只能是 `DEMO` |
| `APP_EXAM_ENABLED` / `APP_EXAM_MODE` | 检查预约开关与模式，模式只能是 `DEMO` |
| `AI_DEGRADE_ENABLED` | AI 能力降级总开关 |
| `AI_TTS_ENGINE` / `AI_TTS_ENGINES` | TTS 引擎选择与候选链 |
| `GW_DEV_LOGIN_PHONES` | 开发档登录手机号白名单 |
| `APP_AUTH_DEV_LOGIN_*` | 业务侧开发档登录与身份映射 |

### 5.3 HIS 演示模式

业务服务内置 `HisClient` 抽象，提供两种适配：`mock` 在进程内生成受理单，`http` 对接本地 `clinic-his`。仓库默认关闭（`APP_HIS_ENABLED=false`）；本机演示用 `env.local` 通常配置为 `true` + `http`，此时挂号回执带有 `CLN` 前缀的院内单号。关闭或使用 `mock` 时退回纯本地演示，单号前缀为 `HIS-MOCK-`。

预约来源 `bookingSource` 包含三个值：`HIS_LIVE`、`HIS_MOCK`、`LOCAL_DEMO`。仅 `HIS_LIVE` 代表真实受理，页面隐藏「演示预约」标识；其余两个值均须显示该标识。当前项目未接入真实医院 HIS，因此演示中看到的均为后两个值。

### 5.4 音色清单来源

音色目录以 `services/voice.js` 本地目录为兜底，优先读取服务端 `GET /api/v1/voice/voices`（内置音色 + 用户偏好 + 自定义）。当前内置两项：温柔女声、沉稳男声，均为普通话。页面不写死音色名称；能力快照 `GET /api/v1/voice/capabilities` 决定可用引擎，被否决的云端供应商不建连、不重试。语速三档在音色页选择，随朗读请求一并下发。

### 5.5 不能写死的东西

- 端口与上游地址：仅在 `backend/deploy/config.json` 与 `env.js` 中出现，页面与服务层不写。
- 令牌与密钥：微信 AppID/AppSecret、支付密钥、附件签名密钥仅从部署环境注入，不入库、不进代码、不进测试夹具。
- 网关地址：仅在 `env.js` 中配置；页面中任何硬编码地址均会被结构检查拦截。
- 业务数据：科室、医生、号源、科普均来自接口或随包知识库，不散写在 WXML 与页面 JS 中。

### 7.1 小程序

1. 在微信开发者工具中确认当前构建档位与网关地址正确，生产档必须为 HTTPS。
2. 点击「上传」，填写版本号与备注；版本号建议与仓库标签一致。

4. 验证通过后提交审核；审核通过后点击「发布」成为正式版。
5. 发布前确认小程序后台「开发设置 → 服务器域名」已添加网关域名，资源域名亦需加入 downloadFile 合法域名，否则真机图片加载将被拒绝。

审核材料与隐私配置不在仓库内：`app.json` 已开启隐私检查，录音前会调用隐私授权接口，但《隐私保护指引》仍需在小程序后台填写，并与实际采集范围保持一致。

### 7.2 后端

- 对外仅暴露网关。业务服务与 AI 服务监听本机或内网，AI 服务的 `/internal/**` 不经网关对外开放。
- 端口以 `backend/deploy/config.json` 为准：网关 8080、业务 8088、AI 8001。云托管必须显式注入 `GW_PROXY_TIMEOUT_SECONDS=220`，勿依赖代码默认值。
- 启动顺序为业务 → AI → 网关。网关先启动亦可运行，但健康检查会显示 `degraded`，直至上游就绪。
- 数据库迁移由业务服务迁移脚本负责；部署前应备份，迁移后执行一次健康检查与只读冒烟。
- 一键脚本仅覆盖 Windows。Linux 部署需按各服务 README 手工启动进程，仓库未提供 Linux 编排，演示时应予说明。

### 7.3 静态介绍页

## 第 9 章 常见问题（FAQ）

**Q1 为什么前端代码里看不到 8001、8088？**

现象：全局搜索仅能找到一个网关地址，找不到业务服务与 AI 服务的端口。原因：前端只与网关通信，上游分流由网关路由表负责，这样切换环境只需修改一处，也不会将内网拓扑暴露给客户端。处理：排查上游时请查看 `backend/deploy/config.json` 与网关健康检查，勿修改前端。

**Q2 演示数据是哪来的，是真医院的数据吗？**

现象：科室、医生、号源、账单均可正常展示。原因：数据源自数据库种子、院内模拟系统 `clinic-his` 与前端开发档兜底，全部为演示数据。处理：演示时应明确说明来源；需清空重建时按部署文档重建演示库，勿手工修改生产表。

**Q3 断网了还能用吗？**

现象：断开网络后首页仍可打开，但点击提交无反应。原因：应用具备三态保护，已加载内容与随包科普仍可读，写操作被拦截并返回 `OFFLINE`。处理：恢复网络后提示条消失，重新提交即可；勿反复点击，系统不会排队重放。

**Q4 挂号单号是真的吗，能拿去窗口用吗？**

现象：成功页显示 `CLN` 或 `HIS-MOCK` 开头的单号。原因：前者来自本地社区诊所演示系统，后者来自进程内模拟，均非真实医院受理。处理：仅用于演示与联调；只要来源非 `HIS_LIVE`，页面就会显示「演示预约」。

**Q5 语音为什么只读普通话？**

现象：音色列表只有温柔女声与沉稳男声，方言识别不够稳定。原因：当前音色均为普通话，识别侧仅支持粤语 `zh-HK` 分支，潮汕话无专项模型与音色。处理：演示请使用普通话或文字输入；方言能力作为后续规划说明，勿现场承诺。

**Q6 大字号在哪里切换？**

现象：找不到字号入口。原因：入口位于「我的 → 设置 → 字号」，为弹出式三档选择，并非独立页面。处理：选择后全局即时生效；若仅调整了系统字号而小程序未变化，说明修改的是微信字体设置，而非本应用的三档。

**Q7 页面打不开或白屏，怎么排查？**

现象：进入页面后空白，控制台可能报错。原因：常见于分包未下载完成、网关不可达、页面参数缺失或构建档位缺少网关地址。处理：先查看控制台第一条报错，再确认网关健康状态；随后检查该页是否已在 `app.json` 注册、分包是否已预下载；生产档还需确认 `env.local.js` 的网关为 HTTPS。

**Q8 check-styles 报缺样式怎么办？**

现象：`check-styles.js` 列出某个 WXML 类名在 WXSS 中不存在。原因：修改结构后遗漏样式，或类名拼写不一致。处理：按输出定位文件与类名，补齐定义或删除多余类名；勿使用全局通配符规避，脚本仍会报错。

**Q9 为什么首页只有几个入口，功能是不是不全？**

现象：首页未设置大型功能宫格。原因：首页刻意收敛为一个症状输入行加少量高频入口，以降低选择成本；完整功能分布在四个 tab 与「我的」中。处理：演示时建议按「先描述症状，再进入后续动作」的顺序讲解，避免从功能清单切入。

**Q10 医生端为什么登录不进去？**

现象：医生登录返回 403 或直接失败。原因：医生端采用独立鉴权，开发档需使用白名单内的 dev code；患者账号无法登录医生端。处理：按联调文档使用医生演示凭据；生产环境需对接医院侧账号体系，当前尚未接入。

**Q11 为什么有的报告点进去是空的？**

现象：报告详情显示「暂无报告文件」。原因：记录存在但报告尚未出具，或该记录本身非检查检验类、无附件。处理：页面仅在明确未出具时锁定，未下发状态时不禁用；遇到空态按提示稍后再看，勿伪造内容。

**Q12 修改了代码，真机预览没变化？**

现象：开发者工具中已更新，手机端仍为旧版。原因：真机运行的是已上传的体验版，或本地缓存未清理。处理：重新上传并更新体验版；开发调试可开启「真机调试」；必要时在设置中清除缓存（清缓存不会退出登录）。

**Q13 端口 8080 被占用怎么办？**

现象：网关启动失败，日志提示地址已被使用。原因：本机已有其他进程占用 8080 端口。处理：使用 `status.bat` 查看 PID，结束非本项目进程；或同步修改 `config.json` 的 `ports.gateway`、网关启动参数与 `env.js` 的 `gateway`，三处保持一致后重启。

| 分级 | 导诊结果的五档紧急程度：紧急、较急、一般、常规、居家观察 |
| 科室画像 | 每个科室对应的典型症状、部位与人群特征集合，用于加权匹配 |
| 号源 | 某位医生在某个时段的可预约名额，含余量与费用 |
| HIS | 医院信息系统；本项目以 `clinic-his` 模拟，未接入真实医院 |
| 网关 | 前端唯一入口，负责鉴权、转发与统一错误信封 |
| 分包 | 微信小程序按需下载的代码包，用于控制主包体积 |
| 演示模式 | 支付、检查等能力在无真实资质时的受限运行方式，页面显式标注 |
| 适老化 | 面向中老年用户的字号、触控、对比度与流程简化设计 |
